# 392. Is Subsequence

**🔗 Link:** [LeetCode 392](https://leetcode.com/problems/is-subsequence/)
**🟢 Status:** 🔄 Need Review


## 🔹 Problem Statement

Given two strings `s` and `t`, say whether `s` can be produced by deleting zero or more characters from `t` without reordering what is left. Return `true` if so, otherwise `false`.

* **Example:** `s = "abc", t = "ahbgdc"` → `true`
* **Constraints:** `0 ≤ s.length ≤ 100`; `0 ≤ t.length ≤ 10^4`; lowercase letters only

## 🔹 Quick Breakdown

* **Difficulty Level:** Easy
* **Main Approach:** **Greedy two pointers.** Walk through `t` once; whenever `t[j]` equals the next unmatched character `s[i]`, advance `i`. `s` is a subsequence iff `i` reaches `len(s)`.
* **Core Concept:** matching each character of `s` at its **earliest** possible position in `t` never hurts later matches
* **When to Use This Pattern?** "Can A be obtained from B by deleting characters?", merging/comparing two sequences in order, checking a pattern against a longer stream.
* **Mistakes to Avoid:**
  * Forgetting that the empty string `s = ""` is a subsequence of everything (including `t = ""`).
  * Using `t.find` from the start for each character — it must continue from just after the previous match.

## 🔹 Optimization Path

* **Brute Force:** LCS dynamic programming; `s` is a subsequence iff `LCS(s, t) == len(s)` — O(|s|·|t|).
* **Optimized Solution:** greedy two pointers — O(|t|).
* **Further Improvements Possible?** Follow-up (10⁹ strings `s` against one `t`): precompute, for every letter, the sorted list of its positions in `t`, then match each `s` with `bisect` for the next position after the current one — O(|t|) once plus O(|s| log |t|) per query.

## 🔹 Solution Breakdown

* **Optimal Approach:** `i = 0`; for each `ch` in `t`: if `i < len(s)` and `ch == s[i]`, `i += 1`. Return `i == len(s)`.
* **Why This Works?** Exchange argument: if some embedding matches `s[i]` at a later position of `t`, moving that match to the earliest available equal character keeps all later matches valid (they are still to its right). So the greedy embedding exists whenever any embedding exists.
* **Edge Cases Considered:**
  * `s = ""` → `True`.
  * `len(s) > len(t)` → the scan ends with `i < len(s)` → `False`.
  * Repeated characters (`s = "aa"`, `t = "ab"`) — each `t` character is used at most once.

## 🔹 Pattern Recognition

* **Belongs To:** Two Pointers — same-direction scan over two sequences
* **Common Problems Using This:**
  * 1143. Longest Common Subsequence (in this repo, the DP generalisation)
  * 792. Number of Matching Subsequences (the follow-up with many `s`)
  * 524. Longest Word in Dictionary through Deleting

## 🔹 Tricks & Patterns Used

* **Greedy earliest match** for subsequence checks.
* **Position lists + binary search** when the same `t` is queried many times.

## 🔹 Alternative Data Structures

* `next_pos[j][c]` table (next occurrence of `c` at or after `j`) — O(26·|t|) space, O(|s|) per query.
* Iterator trick: `it = iter(t); all(c in it for c in s)` — same greedy, consumed lazily.

## 🔹 Complexity Analysis

* **Time Complexity:** O(|t|) — one scan of `t`; `s` is only indexed
* **Space Complexity:** O(1)

## 🔹 Code Snippet (Brute Force)

```python
class Solution:
    def isSubsequence(self, s: str, t: str) -> bool:
        m, n = len(s), len(t)
        lcs = [[0] * (n + 1) for _ in range(m + 1)]
        for i in range(m):
            for j in range(n):
                if s[i] == t[j]:
                    lcs[i + 1][j + 1] = lcs[i][j] + 1
                else:
                    lcs[i + 1][j + 1] = max(lcs[i][j + 1], lcs[i + 1][j])
        return lcs[m][n] == m
```

## 🔹 Code Snippet (Optimized)

```python
class Solution:
    def isSubsequence(self, s: str, t: str) -> bool:
        i = 0
        for ch in t:
            if i < len(s) and ch == s[i]:
                i += 1  # earliest match is always safe
        return i == len(s)
```
