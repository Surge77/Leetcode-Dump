# 🔹 Problem Name: 216. Combination Sum III (Backtracking, Medium)

## 🔹 Quick Breakdown

* **Difficulty Level:** Medium
* **Main Approach:** **Backtracking over digits 1–9 in increasing order with sum bounds.** Pick `k` distinct digits summing to `n`. With `slots` digits still to choose, the smallest possible completion starting at `d` is `d + (d+1) + … + (d+slots−1)` and the largest possible is `9 + 8 + … + (10−slots)`. Break when the smallest overshoots, return when even the largest falls short.
* **Core Concept:** combinations by increasing value + arithmetic-series pruning
* **When to Use This Pattern?** Choose `k` items from a small ordered universe with a sum constraint — the bounds turn a blind search into near-direct generation.
* **Mistakes to Avoid:**
  * Allowing reuse (`dfs(d, …)`) — digits must be distinct, so recurse with `d + 1`.
  * Assuming `n ≤ 45`: LeetCode allows `n` up to 60, where the answer is simply `[]`.

## 🔹 Optimization Path

* **Brute Force:** `itertools.combinations(range(1, 10), k)` and keep those with sum `n` — at most C(9, 4) = 126 combinations, O(C(9, k) · k).
* **Optimized Solution:** backtracking with min/max sum pruning — visits only prefixes that can still complete.
* **Further Improvements Possible?** Not meaningfully; the universe has 9 elements. The point of the problem is the pattern, which matters when the universe is larger.

## 🔹 Solution Breakdown

* **Optimal Approach:** `dfs(low, remain)`: `slots = k − len(path)`; if `slots == 0` record when `remain == 0`; if `remain > slots·(19 − slots)/2` return; for `d` in `low..9`: break if `d·slots + slots·(slots−1)/2 > remain`; push, `dfs(d + 1, remain − d)`, pop.
* **Why This Works?** Increasing order makes each set appear once. The lower bound grows with `d`, so once it overshoots every larger `d` does too (break). The upper bound is the best any completion can do, so failing it means no completion exists (return). Neither cut removes a valid answer.
* **Edge Cases Considered:**
  * `n` too small (`k = 4, n = 1`) or too large (`n > 45`) → `[]`.
  * `k = 9, n = 45` → `[[1,…,9]]`.

## 🔹 Tricks & Patterns Used

* **Arithmetic-series bounds:** smallest `m` values from `d` sum to `m·d + m(m−1)/2`; largest `m` digits sum to `m(19 − m)/2`.
* **Increasing start** for combinations.

* **Space Complexity:** O(k) recursion depth, excluding the output.

## 🔹 Code Snippet (Brute Force)

```python
from itertools import combinations
from typing import List


class Solution:
    def combinationSum3(self, k: int, n: int) -> List[List[int]]:
        return [list(combo) for combo in combinations(range(1, 10), k) if sum(combo) == n]
```

## 🔹 Code Snippet (Optimized)

```python
from typing import List


class Solution:
    def combinationSum3(self, k: int, n: int) -> List[List[int]]:
        result, path = [], []

        def dfs(low: int, remain: int) -> None:
            slots = k - len(path)
            if slots == 0:
                if remain == 0:
                    result.append(path[:])
                return
            if remain > slots * (19 - slots) // 2:  # even the top `slots` digits fall short
                return
            for d in range(low, 10):
                if d * slots + slots * (slots - 1) // 2 > remain:
                    break  # the smallest completion from d already overshoots, larger d is worse
                path.append(d)
                dfs(d + 1, remain - d)
                path.pop()

        dfs(1, n)
        return result
```
