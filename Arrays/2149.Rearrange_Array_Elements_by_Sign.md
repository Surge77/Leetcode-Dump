# 🔹 Problem Name: 2149. Rearrange Array Elements by Sign (Two Pointers, Medium)

**🔗 Link:** [LeetCode 2149](https://leetcode.com/problems/rearrange-array-elements-by-sign/)
**🟢 Status:** 🔄 Need Review

## 🔹 Problem Statement

You get an even-length array with equally many positive and negative integers. Rearrange it so the signs alternate and the first value is positive, while the positives keep their original relative order and so do the negatives. Return the new array; it does not have to be done in place.

* **Example:** `nums = [3,1,-2,-5,2,-4]` → `[3,-2,1,-5,2,-4]`
* **Constraints:** `2 ≤ nums.length ≤ 2·10⁵`, `nums.length` is even, `1 ≤ |nums[i]| ≤ 10⁵`, equally many positives and negatives

## 🔹 Quick Breakdown

* **Difficulty Level:** Medium
* **Main Approach:** **Two write pointers into the answer.** Positives go to the even slots `0, 2, 4, …` and negatives to the odd slots `1, 3, 5, …`. Scan `nums` once and send each value to the next free slot of its sign.
* **Core Concept:** when a formula fixes where each class of element ends up, write it there directly instead of rearranging in place
* **When to Use This Pattern?** Interleaving or partitioning by a predicate while keeping relative order (a stable partition) — parity sorts, partitioning around a pivot with order kept.
* **Mistakes to Avoid:**
  * Swapping in place like a quicksort partition — breaks the rule that same-sign values keep their order.
  * Starting with a negative — the answer must begin with a positive.

## 🔹 Optimization Path

* **Brute Force:** fix the array left to right; when slot `i` has the wrong sign, find the next value of the right sign and shift the block between them one step right — O(n²) time; the shifts happen inside one working copy, though the slice assignment in the snippet builds O(n) temporaries.
* **Optimized Solution:** one pass with two write pointers into a new array — O(n) time, O(n) space for the output.
* **Further Improvements Possible?** No; each value is moved once and the output array is required anyway.

## 🔹 Solution Breakdown

* **Optimal Approach:** `pos, neg = 0, 1`; for each `x`: if `x > 0` write it at `pos` and add 2, else write it at `neg` and add 2.
* **Why This Works?** Alternating signs, starting positive, and keeping each sign's order together force the `k`-th positive (in input order) to index `2k` and the `k`-th negative to `2k + 1` — the answer is unique, and every value's slot is known the moment it is read.
* **Edge Cases Considered:**
  * `n = 2` (`[-1, 1]` → `[1, -1]`).
  * All positives before all negatives (`[1, 2, -1, -2]` → `[1, -1, 2, -2]`).
  * No zeros to worry about: `|nums[i]| ≥ 1`, and the counts are guaranteed equal.

## 🔹 Code Snippet (Brute Force)

```python
from typing import List


class Solution:
    def rearrangeArray(self, nums: List[int]) -> List[int]:
        arr = nums[:]
        for i in range(len(arr)):
            want_positive = i % 2 == 0
            if (arr[i] > 0) == want_positive:
                continue
            j = i + 1
            while (arr[j] > 0) != want_positive:
                j += 1
            arr[i:j + 1] = [arr[j]] + arr[i:j]  # shifting the block right keeps same-sign order
        return arr
```

## 🔹 Code Snippet (Optimized)

```python
from typing import List


class Solution:
    def rearrangeArray(self, nums: List[int]) -> List[int]:
        result = [0] * len(nums)
        pos, neg = 0, 1  # the k-th positive belongs at 2k, the k-th negative at 2k + 1
        for x in nums:
            if x > 0:
                result[pos] = x
                pos += 2
            else:
                result[neg] = x
                neg += 2
        return result
```
