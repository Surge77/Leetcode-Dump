# 🔹 Problem Name: 1161. Maximum Level Sum of a Binary Tree (Tree BFS, Medium)

**🔗 Link:** [LeetCode 1161](https://leetcode.com/problems/maximum-level-sum-of-a-binary-tree/)
**🟢 Status:** 🔄 Need Review

## 🔹 Quick Breakdown

* **Difficulty Level:** Medium
* **Main Approach:** **Level-order BFS with a running best.** Process the tree one level at a time, sum the level, and remember the level number with the largest sum. Update only on a strictly larger sum so the smallest level wins ties.
* **Core Concept:** BFS visits nodes level by level, so a per-level aggregate is a single loop over the current frontier
* **When to Use This Pattern?** Any per-level statistic — level sums or averages, largest value per row, right-side view, zigzag order.
* **Mistakes to Avoid:**
  * Initialising the best sum with `0`: all values can be negative, so use `-inf` (or the first level's sum).
  * Using `>=` when comparing: ties must return the **smallest** level.
  * Levels are 1-indexed.
  * Recursing with depth up to 10⁴ on a skewed tree — BFS needs no recursion.

## 🔹 Optimization Path

* **Brute Force:** for each depth `d = 1, 2, …` traverse the whole tree and sum the nodes at depth `d` — O(n · h).
* **Optimized Solution:** one BFS, each node visited once — O(n).
* **Further Improvements Possible?** No; every node's value must be read.

## 🔹 Solution Breakdown

* **Optimal Approach:** `level = [root]`; while the level is non-empty: `total = sum(node.val for node in level)`; if `total > best_sum` record it with the current level number; `level = [child for node in level for child in (node.left, node.right) if child]`.
* **Why This Works?** Replacing the level by the list of all its children gives exactly the next depth, so each iteration sees one full level. Strict `>` keeps the first (smallest) level among equal sums.
* **Edge Cases Considered:**
  * Single node → level 1.
  * All-negative values (the best sum is negative).
  * Several levels with the same maximum → the smallest index.

## 🔹 Tricks & Patterns Used

* **List-per-level BFS:** rebuilding the frontier as a list avoids tracking level sizes with a counter.
* **Strict comparison for the tie-break:** the first maximum is kept for free.

## 🔹 Alternative Data Structures

* `deque` with a `for _ in range(len(queue))` inner loop — the classic form.
* DFS with a `sums[depth]` array — works, but recursion depth is a problem at 10⁴ nodes.

## 🔹 Complexity Analysis

* **Time Complexity:** O(n)
* **Space Complexity:** O(w), `w` = the widest level (up to n / 2)

## 🔹 Code Snippet (Brute Force)

```python
from typing import Optional


class Solution:
    def maxLevelSum(self, root: Optional[TreeNode]) -> int:
        def sum_at_depth(target: int):
            total, found = 0, False
            stack = [(root, 1)]
            while stack:
                node, depth = stack.pop()
                if depth == target:
                    total += node.val
                    found = True
                    continue
                for child in (node.left, node.right):
                    if child:
                        stack.append((child, depth + 1))
            return total, found

        best_level, best_sum = 1, sum_at_depth(1)[0]
        depth = 2
        while True:
            total, found = sum_at_depth(depth)
            if not found:
                return best_level
            if total > best_sum:
                best_level, best_sum = depth, total
            depth += 1
```

## 🔹 Code Snippet (Optimized)

```python
from typing import Optional


class Solution:
    def maxLevelSum(self, root: Optional[TreeNode]) -> int:
        best_level, best_sum = 1, float("-inf")
        level, depth = [root], 1
        while level:
            total = sum(node.val for node in level)
            if total > best_sum:  # strict: on a tie the smaller level stays
                best_level, best_sum = depth, total
            level = [child for node in level for child in (node.left, node.right) if child]
            depth += 1
        return best_level
```
