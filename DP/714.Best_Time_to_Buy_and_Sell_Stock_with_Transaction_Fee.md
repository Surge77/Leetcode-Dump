# 🔹 Problem Name: 714. Best Time to Buy and Sell Stock with Transaction Fee (State Machine DP, Medium)

**🔗 Link:** [LeetCode 714](https://leetcode.com/problems/best-time-to-buy-and-sell-stock-with-transaction-fee/)
**🟢 Status:** 🔄 Need Review

## 🔹 Quick Breakdown

* **Difficulty Level:** Medium
* **Main Approach:** **Two-state DP.** After each day you either hold one share or hold none. `cash` = best profit holding nothing, `hold` = best profit holding a share. Each day: `cash = max(cash, hold + price − fee)` (sell), `hold = max(hold, cash − price)` (buy). Answer `cash`.
* **Core Concept:** model the trading rules as a tiny state machine and keep the best profit per state
* **When to Use This Pattern?** Stock problems with extra rules — fee (714), cooldown (309), at most `k` transactions (188) — and any "each step you are in one of a few modes" optimisation.
* **Mistakes to Avoid:**
  * Charging the fee on both buy and sell — it is once per transaction (charging it on the sell is the convention used here).
  * Greedy "sum every positive daily difference" (problem 122) — with a fee, many small trades lose money.
  * Recursion without memo over (day, holding) — exponential.

## 🔹 Optimization Path

* **Brute Force:** recursion choosing buy/sell/wait each day — O(2ⁿ).
* **Optimized Solution:** two rolling states — O(n) time, O(1) space.
* **Further Improvements Possible?** No; every price must be read.

## 🔹 Solution Breakdown

* **Optimal Approach:** `cash, hold = 0, -prices[0]`; for each price update both states; return `cash`.
* **Why This Works?** At the end of any day the only thing that matters for the future is whether you own a share, so keeping the best profit for each of the two states loses nothing. Using the already-updated `cash` when computing `hold` only allows a same-day sell-then-buy, which costs a fee and is never better than doing nothing, so it is harmless.
* **Edge Cases Considered:**
  * One day → 0.
  * Prices only falling, or rises never above `fee` → 0 (no trade).

## 🔹 Tricks & Patterns Used

* **States = what you hold, not what you did:** keeps the transition table tiny.
* **Rolling variables** because day `d` depends only on day `d − 1`.

## 🔹 Alternative Data Structures

* `dp[d][0/1]` table — same logic, O(n) space.
* Greedy view: keep a running "effective buy price" `min(buy, price)` and sell whenever `price > buy + fee`, then set `buy = price − fee` (lets you extend a trade without paying again).

## 🔹 Code Snippet (Brute Force)

```python
from typing import List


class Solution:
    def maxProfit(self, prices: List[int], fee: int) -> int:
        def best(day: int, holding: bool) -> int:
            if day == len(prices):
                return 0
            wait = best(day + 1, holding)
            if holding:
                return max(wait, prices[day] - fee + best(day + 1, False))
            return max(wait, -prices[day] + best(day + 1, True))

        return best(0, False)
```

## 🔹 Code Snippet (Optimized)

```python
from typing import List


class Solution:
    def maxProfit(self, prices: List[int], fee: int) -> int:
        cash, hold = 0, -prices[0]
        for price in prices[1:]:
            cash = max(cash, hold + price - fee)
            # using today's cash only enables sell-then-rebuy today, which never beats waiting
            hold = max(hold, cash - price)
        return cash
```
