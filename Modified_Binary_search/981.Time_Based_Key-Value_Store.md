# 🔹 Problem Name: 981. Time Based Key-Value Store (Binary Search, Medium)

**🔗 Link:** [LeetCode 981](https://leetcode.com/problems/time-based-key-value-store/)
**🟢 Status:** 🔄 Need Review

## 🔹 Quick Breakdown

* **Difficulty Level:** Medium
* **Main Approach:** **Per-key sorted history + `bisect`.** LeetCode guarantees `set` timestamps are strictly increasing, so appending keeps each key's timestamp list sorted for free. `get(key, t)` is "last timestamp `≤ t`": `bisect_right(times, t) − 1`.
* **Core Concept:** floor search (predecessor query) on an append-only sorted list
* **When to Use This Pattern?** Versioned / snapshot data: "value as of time `t`" — snapshot arrays, stock price history, configuration versions.
* **Mistakes to Avoid:**
  * `bisect_left` returns the first timestamp `≥ t`; an exact match would then be skipped by the `− 1`. Use `bisect_right`.
  * Returning `None` instead of `""` when no timestamp `≤ t` exists or the key was never set.
  * Sorting on every `set` — unnecessary, the input is already increasing.

## 🔹 Optimization Path

* **Brute Force:** store `(timestamp, value)` pairs and scan all of them on every `get` — O(entries) per query.
* **Optimized Solution:** binary search on the key's timestamp list — O(log k) per `get`, O(1) per `set`.
* **Further Improvements Possible?** If timestamps could arrive out of order, use a sorted container (or insert with `insort`, O(k)) per key.

## 🔹 Solution Breakdown

* **Optimal Approach:** `dict[key] → (times list, values list)`. `set` appends to both. `get` finds `i = bisect_right(times, t)`; return `values[i − 1]` if `i > 0`, else `""`.
* **Why This Works?** `bisect_right(times, t)` counts timestamps `≤ t`; the last of them is at index `count − 1`, and it is the largest `timestamp_prev ≤ t`.
* **Edge Cases Considered:**
  * Unknown key → `""`.
  * Query earlier than the first `set` for that key → `""`.
  * Exact timestamp match → that value.

## 🔹 Tricks & Patterns Used

* **Parallel lists instead of a list of tuples:** `bisect` on a plain `int` list avoids comparing tuples (and the `key=` argument needs Python 3.10+).
* **Floor = `bisect_right − 1`.**

## 🔹 Alternative Data Structures

* A balanced BST / `TreeMap.floorEntry` (Java) per key.
* `sortedcontainers.SortedDict` — not standard library, so not used here.

## 🔹 Complexity Analysis

* **Time Complexity:** `set` O(1), `get` O(log k) where `k` = number of sets for that key
* **Space Complexity:** O(total sets)

## 🔹 Code Snippet (Brute Force)

```python
class TimeMap:

    def __init__(self):
        self.entries = {}

    def set(self, key: str, value: str, timestamp: int) -> None:
        self.entries.setdefault(key, []).append((timestamp, value))

    def get(self, key: str, timestamp: int) -> str:
        best_time, best_value = 0, ""
        for time, value in self.entries.get(key, []):
            if best_time < time <= timestamp:
                best_time, best_value = time, value
        return best_value
```

## 🔹 Code Snippet (Optimized)

```python
from bisect import bisect_right


class TimeMap:

    def __init__(self):
        self.times = {}
        self.values = {}

    def set(self, key: str, value: str, timestamp: int) -> None:
        # timestamps per key arrive strictly increasing, so appending keeps them sorted
        self.times.setdefault(key, []).append(timestamp)
        self.values.setdefault(key, []).append(value)

    def get(self, key: str, timestamp: int) -> str:
        times = self.times.get(key)
        if not times:
            return ""
        i = bisect_right(times, timestamp)
        return self.values[key][i - 1] if i else ""
```
