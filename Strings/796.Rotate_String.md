# 796. Rotate String

**🔗 Link:** [LeetCode 796](https://leetcode.com/problems/rotate-string/)
**🟢 Status:** 🔄 Need Review


## 🔹 Problem Statement

A shift moves the leftmost character of `s` to the right end. Return `true` exactly when some number of shifts turns `s` into `goal`.

* **Example:** `s = "abcde", goal = "cdeab"` → `true`
* **Constraints:** `1 ≤ s.length, goal.length ≤ 100`; lowercase letters only

## 🔹 Quick Breakdown

* **Difficulty Level:** Easy
* **Main Approach:** **Doubling trick.** Every rotation of `s` is a length-`n` window of `s + s`. So `goal` is a rotation of `s` iff `len(goal) == len(s)` and `goal` occurs in `s + s`.
* **Core Concept:** turn "any cyclic shift" into "a substring of the string concatenated with itself"
* **When to Use This Pattern?** Cyclic/circular strings or arrays: rotation checks, repeated substring pattern (459), circular subarray problems.
* **Mistakes to Avoid:**
  * Forgetting the length check: `"a"` is a substring of `"abab"`, yet `"a"` is not a rotation of `"ab"`.
  * Building all `n` rotations as new strings when one search suffices.

## 🔹 Optimization Path

* **Brute Force:** compare `goal` with `s[k:] + s[:k]` for every shift `k` — O(n²).
* **Optimized Solution:** `goal in s + s` — one substring search; KMP or Z-function guarantee O(n).
* **Further Improvements Possible?** Linear time is optimal; with `n ≤ 100` the built-in search is the practical choice.

## 🔹 Solution Breakdown

* **Optimal Approach:** return `len(s) == len(goal) and goal in s + s`.
* **Why This Works?** `(s + s)[k : k + n] == s[k:] + s[:k]` for every `0 ≤ k < n`, so the length-`n` windows of `s + s` are exactly the rotations; equal lengths rule out shorter matches.
* **Edge Cases Considered:**
  * `s == goal` (shift 0) → true.
  * Different lengths → false.
  * Strings with repeated structure (`"abab"`) — several shifts match, still true.

## 🔹 Tricks & Patterns Used

* **`s + s` contains every rotation** — the standard way to linearise a cycle.
* Pair the doubling with KMP/Z when worst-case linear time matters.

## 🔹 Alternative Data Structures

* KMP failure table of `goal`, then scan `s + s`: guaranteed O(n).
* Rolling hash of each window of `s + s` (Rabin–Karp), verifying on hash hits.

## 🔹 Complexity Analysis

* **Time Complexity:** O(n) expected with the built-in search (O(n) worst case with KMP), `n ≤ 100`
* **Space Complexity:** O(n) for `s + s`

## 🔹 Code Snippet (Brute Force)

```python
class Solution:
    def rotateString(self, s: str, goal: str) -> bool:
        if len(s) != len(goal):
            return False
        return any(s[k:] + s[:k] == goal for k in range(len(s)))
```

## 🔹 Code Snippet (Optimized)
