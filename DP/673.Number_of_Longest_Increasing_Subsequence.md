# 🔹 Problem Name: 673. Number of Longest Increasing Subsequence (LIS DP, Medium)

**🔗 Link:** [LeetCode 673](https://leetcode.com/problems/number-of-longest-increasing-subsequence/)
**🟢 Status:** 🔄 Need Review

## 🔹 Problem Statement

Given an integer array, count how many strictly increasing subsequences have the maximum possible length. You return the count, not the length, and subsequences at different index positions count separately even if their values are equal.

* **Example:** `nums = [1,3,5,4,7]` → `2`
* **Constraints:** `1 ≤ nums.length ≤ 2000`, `-10^6 ≤ nums[i] ≤ 10^6`, the answer fits in a 32-bit integer

## 🔹 Quick Breakdown

* **Difficulty Level:** Medium
* **Main Approach:** **LIS DP carrying a count.** For each `i`: `length[i]` = longest strictly increasing subsequence ending at `i`, `count[i]` = how many of them. For every `j < i` with `nums[j] < nums[i]`: a longer `length[j] + 1` resets `count[i] = count[j]`; an equal one adds `count[i] += count[j]`. Answer = sum of `count[i]` over all `i` with the global maximum length.
* **Core Concept:** "best value + number of ways to reach it" in one DP — on a tie, add; on an improvement, replace
* **When to Use This Pattern?** "How many optimal solutions are there?" for any DP with a max/min — number of shortest paths (1976), number of LIS, counting optimal partitions.
* **Mistakes to Avoid:**
  * Answering with `count` of only the last index or of the single best index — every index achieving the maximum length contributes.
  * Using `<=` — the subsequence must be **strictly** increasing, so equal values never extend each other.
  * Resetting `count[i]` to `1` on a longer length instead of copying `count[j]`.

## 🔹 Optimization Path

* **Brute Force:** enumerate all index subsets, keep strictly increasing ones, count those of maximum length — O(2ⁿ · n).
* **Optimized Solution:** O(n²) length + count DP — `n ≤ 2000` gives 2·10⁶ pairs.
* **Further Improvements Possible?** O(n log n) with a Fenwick / segment tree over compressed values storing `(best length, count)` per prefix, merged by "max, add counts on ties".

## 🔹 Solution Breakdown

* **Optimal Approach:** initialise `length = [1]*n`, `count = [1]*n`; double loop as above; `best = max(length)`; return `sum(c for l, c in zip(length, count) if l == best)`.
* **Why This Works?** Each longest-ending-at-`i` subsequence has a unique second-to-last index `j`, so the LIS-ending-at-`i` set is the disjoint union of (LIS ending at `j`) + `nums[i]` over the `j`s achieving the max — exactly what the replace/add rule sums. Different end indices give different subsequences, so the final sum doesn't double count.
* **Edge Cases Considered:**
  * All equal → LIS length 1, answer `n`.
  * Strictly decreasing → answer `n`.
  * `n = 1` → 1.

## 🔹 Code Snippet (Brute Force)

```python
from typing import List


class Solution:
    def findNumberOfLIS(self, nums: List[int]) -> int:
        n = len(nums)
        best_len, ways = 0, 0
        for mask in range(1, 1 << n):
            chosen = [nums[i] for i in range(n) if mask >> i & 1]
            if all(a < b for a, b in zip(chosen, chosen[1:])):
                if len(chosen) > best_len:
                    best_len, ways = len(chosen), 1
                elif len(chosen) == best_len:
                    ways += 1
        return ways
```

## 🔹 Code Snippet (Optimized)

```python
from typing import List


class Solution:
    def findNumberOfLIS(self, nums: List[int]) -> int:
        n = len(nums)
        length, count = [1] * n, [1] * n
        for i in range(n):
            for j in range(i):
                if nums[j] < nums[i]:
                    if length[j] + 1 > length[i]:
                        length[i], count[i] = length[j] + 1, count[j]
                    elif length[j] + 1 == length[i]:
                        count[i] += count[j]
        best = max(length)
        # LIS can end at several indices; each end gives distinct subsequences
        return sum(c for l, c in zip(length, count) if l == best)
```
