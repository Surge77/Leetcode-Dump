# 🔹 Problem Name: 2462. Total Cost to Hire K Workers (Two Heaps, Medium)

**🔗 Link:** [LeetCode 2462](https://leetcode.com/problems/total-cost-to-hire-k-workers/)
**🟢 Status:** 🔄 Need Review

## 🔹 Problem Statement

You must hire exactly `k` workers, one per session. In each session you may only consider the first `candidates` and the last `candidates` workers still unhired, and you take the cheapest of them (ties go to the smaller index). Return the total cost of the `k` hires.

* **Example:** `costs = [17,12,10,2,7,2,11,20,8], k = 3, candidates = 4` → `11`
* **Constraints:** `1 ≤ costs.length ≤ 10⁵`, `1 ≤ costs[i] ≤ 10⁵`, `1 ≤ k, candidates ≤ costs.length`

## 🔹 Quick Breakdown

* **Difficulty Level:** Medium
* **Main Approach:** **Two min-heaps over the two ends.** One heap holds up to `candidates` workers from the front, the other up to `candidates` from the back. Each session hires the cheaper of the two tops (the front heap wins ties — its workers have smaller indices) and refills the heap it took from with the next unseen worker from that end.
* **Core Concept:** a sliding "eligible pool" at both ends, with a min-heap per end
* **When to Use This Pattern?** Repeatedly pick the minimum from a pool that is re-defined after each pick — job scheduling with limited windows, two-ended candidate pools.
* **Mistakes to Avoid:**
  * Letting the two pools overlap: one worker must never sit in both heaps. Loading stops when the pointers meet.
  * Forgetting that the tie-break is the smaller **index**, which equals "front heap first" for equal costs.
  * Removing from a Python list in the middle every session (O(n) each).

## 🔹 Optimization Path

* **Brute Force:** each session, take the first and last `candidates` of the remaining list, pick the min by `(cost, index)` and `pop` it — O(k · n) because of the list removal.
* **Optimized Solution:** two heaps and two pointers — O((candidates + k) log candidates).
* **Further Improvements Possible?** No; every worker is pushed at most once and every hire pops once.

## 🔹 Solution Breakdown

* **Optimal Approach:** `i = 0`, `j = n − 1`. Before each hire, top up the front heap from `i` and the back heap from `j` until each holds `candidates` entries or `i > j`. Compare the tops, pop the smaller, add it to the total.
* **Why This Works?** The eligible workers are always the first `candidates` and last `candidates` of the remaining ones. The heaps contain exactly those, and refilling after a pop pulls in the next worker from the same end, which is the one that just became eligible. When the pointers cross, all remaining workers are already inside the heaps.
* **Edge Cases Considered:**
  * `2 · candidates ≥ n`: every worker is eligible from the start, the pointers meet during the first top-up.
  * One heap emptying while the other still has workers.
  * `costs` with duplicates — only values are compared, equal values are interchangeable.

## 🔹 Tricks & Patterns Used

* **`i <= j` guard while loading:** it is what guarantees the two pools never share a worker.
* **Store only costs in the heaps:** the index is implied by which heap the worker is in.

## 🔹 Alternative Data Structures

* Heap of `(cost, index)` over a single pool of the eligible indices — same complexity, slightly more bookkeeping.
* A sorted container of eligible workers — works, but two heaps are simpler.

## 🔹 Complexity Analysis

* **Time Complexity:** O((c + k) log c) with `c = candidates`
* **Space Complexity:** O(c)

## 🔹 Code Snippet (Brute Force)

```python
from typing import List


class Solution:
    def totalCost(self, costs: List[int], k: int, candidates: int) -> int:
        rest = list(costs)
        total = 0
        for _ in range(k):
            size = len(rest)
            if size <= 2 * candidates:
                eligible = range(size)
            else:
                eligible = list(range(candidates)) + list(range(size - candidates, size))
            pick = min(eligible, key=lambda idx: (rest[idx], idx))
            total += rest.pop(pick)
        return total
```

## 🔹 Code Snippet (Optimized)

```python
import heapq
from typing import List


class Solution:
    def totalCost(self, costs: List[int], k: int, candidates: int) -> int:
        front, back = [], []
        i, j = 0, len(costs) - 1
        total = 0
        for _ in range(k):
            while len(front) < candidates and i <= j:
                heapq.heappush(front, costs[i])
                i += 1
            while len(back) < candidates and i <= j:
                heapq.heappush(back, costs[j])
                j -= 1
            # Equal costs: the front worker has the smaller index.
            if not back or (front and front[0] <= back[0]):
                total += heapq.heappop(front)
            else:
                total += heapq.heappop(back)
        return total
```
