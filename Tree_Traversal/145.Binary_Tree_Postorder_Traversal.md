# 🔹 Problem Name: 145. Binary Tree Postorder Traversal (Tree DFS, Easy)

**🔗 Link:** [LeetCode 145](https://leetcode.com/problems/binary-tree-postorder-traversal/)
**🟢 Status:** 🔄 Need Review

## 🔹 Problem Statement

Given the root of a binary tree, return the node values in postorder: the left subtree, then the right subtree, then the node itself. The follow-up asks for an iterative solution, since the recursive one is trivial.

* **Example:** `root = [1,null,2,3]` → `[3,2,1]`
* **Constraints:** `0 ≤ nodes ≤ 100`, `-100 ≤ Node.val ≤ 100`

## 🔹 Quick Breakdown

* **Difficulty Level:** Easy
* **Main Approach:** **Stack entries with a "children done" flag.** Postorder is left → right → node, so a node may only be emitted after both subtrees. The first time a node is popped (`done = False`), push it back as `(node, True)` and then its right and left children; the second time (`done = True`) both subtrees are finished, so emit it.
* **Core Concept:** the flag records which half of the recursive call you are in — before the child calls or after them
* **When to Use This Pattern?** Iterative postorder, and any bottom-up tree computation (heights, subtree sums, DP on trees) on a tree too deep for recursion.
* **Mistakes to Avoid:**
  * Emitting a node on its first pop — that is preorder.
  * Wrong push order: the stack is LIFO, so push `(node, True)`, `right`, `left` to pop them as left, right, node.
  * `f(left) + f(right) + [val]` looks linear but copies lists at every level: O(n·h).

## 🔹 Optimization Path

* **Brute Force:** recursion that returns lists and concatenates them — O(n·h) time (O(n²) on a path).
* **Optimized Solution:** flagged stack writing into one output list — O(n) time, O(h) space.
* **Further Improvements Possible?** Morris postorder reaches O(1) extra space (it emits reversed right edges of left subtrees) but is fiddly; not worth it in an interview.

## 🔹 Solution Breakdown

* **Optimal Approach:** stack of `(node, done)` starting with `(root, False)`; skip `None`; if `done`, append the value; else push `(node, True)`, `(node.right, False)`, `(node.left, False)`.
* **Why This Works?** A node's `(node, True)` entry sits **below** its children's entries, so it resurfaces only after both subtrees have been completely popped — left first, because `left` was pushed last.
* **Edge Cases Considered:**
  * Empty tree → `[]` (the single `(None, False)` entry is skipped).
  * Single node; right-only chains (example 1: `[1, null, 2, 3]` → `[3, 2, 1]`).

## 🔹 Tricks & Patterns Used

* **Two-phase stack entries `(node, done)`:** turn any recursion that does work *after* its calls into a loop. Pushing `right`, `(node, True)`, `left` gives iterative inorder the same way.
* **Mirror trick:** record node → right → left with a preorder-style stack, then reverse the list. Correct output, but nodes are *visited* parent-first, so for bottom-up DP you would iterate the recorded order backwards.

## 🔹 Alternative Data Structures

* Two stacks (the mirror trick) — simplest to remember.
* One stack plus a `prev` pointer: descend left; go right only if `node.right` is not the node emitted just before.

## 🔹 Complexity Analysis

* **Time Complexity:** O(n)
* **Space Complexity:** O(h) — per level of the current path, one `(node, True)` entry and one pending right child

## 🔹 Code Snippet (Brute Force)

```python
from typing import List, Optional


class Solution:
    def postorderTraversal(self, root: Optional[TreeNode]) -> List[int]:
        if not root:
            return []
        return self.postorderTraversal(root.left) + self.postorderTraversal(root.right) + [root.val]
```

## 🔹 Code Snippet (Optimized)

```python
from typing import List, Optional


class Solution:
    def postorderTraversal(self, root: Optional[TreeNode]) -> List[int]:
        order = []
        stack = [(root, False)]
        while stack:
            node, children_done = stack.pop()
            if not node:
                continue
            if children_done:
                order.append(node.val)
            else:
                # LIFO: push in reverse of the wanted order left, right, node
                stack.append((node, True))
                stack.append((node.right, False))
                stack.append((node.left, False))
        return order
```
