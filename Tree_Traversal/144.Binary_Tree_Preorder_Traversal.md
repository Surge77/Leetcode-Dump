# 🔹 Problem Name: 144. Binary Tree Preorder Traversal (Tree DFS, Easy)

**🔗 Link:** [LeetCode 144](https://leetcode.com/problems/binary-tree-preorder-traversal/)
**🟢 Status:** 🔄 Need Review

## 🔹 Problem Statement

Given the root of a binary tree, return the node values in preorder: a node first, then its left subtree, then its right subtree. The follow-up asks for an iterative solution, since the recursive one is trivial.

* **Example:** `root = [1,null,2,3]` → `[1,2,3]`
* **Constraints:** `0 ≤ nodes ≤ 100`, `-100 ≤ Node.val ≤ 100`

## 🔹 Quick Breakdown

* **Difficulty Level:** Easy
* **Main Approach:** **Explicit stack.** Preorder is node → left subtree → right subtree. Pop a node, record it, then push `right` **before** `left` so `left` is popped (and its whole subtree finished) first. The stack replays exactly what the call stack of the recursive version would do.
* **Core Concept:** any recursion can be simulated with your own stack; a LIFO stack emits in reverse of push order
* **When to Use This Pattern?** The follow-up "do it iteratively", trees too deep for Python's recursion limit (10⁴–10⁵ nodes), or a traversal that must pause and resume (iterators).
* **Mistakes to Avoid:**
  * Pushing `left` before `right` → node, right, left.
  * Pushing `None` children and then reading `.val` on them — skip `None` on push (or on pop).
  * `[root.val] + f(left) + f(right)` looks linear but copies lists at every level: O(n·h).

## 🔹 Optimization Path

* **Brute Force:** recursion that returns lists and concatenates them — O(n·h) time (O(n²) on a path) because every level copies its subtree's list.
* **Optimized Solution:** iterative stack writing into one output list — O(n) time, O(h) space.
* **Further Improvements Possible?** Morris traversal: O(1) extra space by temporarily pointing each in-order predecessor's empty `right` back at the current node, then restoring it.

## 🔹 Solution Breakdown

* **Optimal Approach:** `stack = [root]`; pop, append `node.val`, push `node.right` then `node.left` (non-null only).
* **Why This Works?** When a node is popped its left child lands on top, so the whole left subtree is popped and finished before the right child waiting below it — the recursive order node → left → right.
* **Edge Cases Considered:**
  * Empty tree → `[]`.
  * Single node; right-only chains (example 1: `[1, null, 2, 3]` → `[1, 2, 3]`).

## 🔹 Tricks & Patterns Used

* **Reverse push order:** to pop `a` then `b`, push `b` then `a`.
* **Mirror trick:** the same loop pushing `left` before `right` records node → right → left; reversed, that is postorder (145).

## 🔹 Alternative Data Structures

* Recursive helper appending to one shared list — O(n) and clean, but bounded by the recursion limit on huge trees.
* Morris traversal — O(1) extra space; mutates pointers temporarily.

## 🔹 Complexity Analysis

* **Time Complexity:** O(n)
* **Space Complexity:** O(h) — the stack holds at most one pending right child per level

## 🔹 Code Snippet (Brute Force)

```python
from typing import List, Optional


class Solution:
    def preorderTraversal(self, root: Optional[TreeNode]) -> List[int]:
        if not root:
            return []
        return [root.val] + self.preorderTraversal(root.left) + self.preorderTraversal(root.right)
```

## 🔹 Code Snippet (Optimized)

```python
from typing import List, Optional


class Solution:
    def preorderTraversal(self, root: Optional[TreeNode]) -> List[int]:
        order = []
        stack = [root] if root else []
        while stack:
            node = stack.pop()
            order.append(node.val)
            if node.right:  # pushed first so the left subtree is popped and finished first
                stack.append(node.right)
            if node.left:
                stack.append(node.left)
        return order
```
