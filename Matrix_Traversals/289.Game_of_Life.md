# 🔹 Problem Name: 289. Game of Life (In-place State Encoding, Medium)

**🔗 Link:** [LeetCode 289](https://leetcode.com/problems/game-of-life/)
**🟢 Status:** 🔄 Need Review

## 🔹 Quick Breakdown

* **Difficulty Level:** Medium
* **Main Approach:** **Two states in one cell.** All cells update simultaneously, so a cell's neighbours must still see its *old* state after it has decided its *new* one. Store the old state in bit 0 and the new state in bit 1: neighbours read `cell & 1`, and a final pass does `cell >>= 1`.
* **Core Concept:** encode "before" and "after" in the same storage so an in-place update never reads its own output
* **When to Use This Pattern?** In-place simulation or transformation where every cell's update depends on unchanged neighbours — Game of Life, set-matrix-zeroes markers, marking visited values inside the input array.
* **Mistakes to Avoid:**
  * Writing the new value directly: later neighbours then count an already-updated cell.
  * Counting the cell itself among its 8 neighbours.
  * Forgetting the bounds at the edges and corners.

## 🔹 Optimization Path

* **Brute Force:** copy the board, compute the next state from the copy — O(mn) time, O(mn) extra space.
* **Optimized Solution:** bit encoding in place — O(mn) time, O(1) extra space.
* **Further Improvements Possible?** For an infinite or very sparse board, store only the set of live cells and count neighbours with a `Counter` over their 8 offsets — O(live cells) per round.

## 🔹 Solution Breakdown

* **Optimal Approach:** for each cell, `live = Σ (neighbour & 1)`. The four rules collapse to: live next round iff `live == 3`, or `live == 2` and it is live now — then `cell |= 2`. Finally shift every cell right by one.
* **Why This Works?** Setting bit 1 never changes bit 0, so every neighbour count during the first pass sees the original board; the shift then discards the old state and keeps the new one.
* **Edge Cases Considered:**
  * `1 × 1` board → the cell has no neighbours and always ends dead.
  * Single row or column → neighbour windows clipped to the grid.
  * Board edges are dead beyond the border (no wrap-around).

## 🔹 Tricks & Patterns Used

* **Spare bits as a second buffer:** values are 0/1, so bit 1 is free to hold the next generation.
* **Clipped window:** `range(max(0, i − 1), min(m, i + 2))` handles every border without special cases.

## 🔹 Alternative Data Structures

* Extra state codes (`2` = live → dead, `3` = dead → live) — the same idea with named states instead of bits.
* Set of live coordinates — the right model for an unbounded board.

## 🔹 Complexity Analysis

* **Time Complexity:** O(mn) — 9 reads per cell
* **Space Complexity:** O(1) extra

## 🔹 Code Snippet (Brute Force)

```python
from typing import List


class Solution:
    def gameOfLife(self, board: List[List[int]]) -> None:
        old = [row[:] for row in board]
        m, n = len(old), len(old[0])
        for i in range(m):
            for j in range(n):
                live = sum(old[r][c] for r in range(max(0, i - 1), min(m, i + 2))
                           for c in range(max(0, j - 1), min(n, j + 2))) - old[i][j]
                board[i][j] = int(live == 3 or (live == 2 and old[i][j] == 1))
```

## 🔹 Code Snippet (Optimized)

```python
from typing import List


class Solution:
    def gameOfLife(self, board: List[List[int]]) -> None:
        m, n = len(board), len(board[0])
        for i in range(m):
            for j in range(n):
                # bit 0 = this round (neighbours still read it), bit 1 = next round
                live = sum(board[r][c] & 1 for r in range(max(0, i - 1), min(m, i + 2))
                           for c in range(max(0, j - 1), min(n, j + 2))) - board[i][j]
                if live == 3 or (live == 2 and board[i][j]):
                    board[i][j] |= 2
        for i in range(m):
            for j in range(n):
                board[i][j] >>= 1
```
