## 🔹 Problem Statement

Design a counter with `hit(timestamp)`, which records one hit at the given second, and `getHits(timestamp)`, which returns how many hits landed in the past 300 seconds up to and including that timestamp. Calls arrive in chronological order, and several hits may share the same second. *(premium — paraphrased from memory, not checked against the official page)*

* **Example:** `hit(1), hit(2), hit(3), getHits(4), hit(300), getHits(300), getHits(301)` → `3, 4, 3` for the three `getHits` calls
* **Constraints:** `1 ≤ timestamp ≤ 2 * 10^9`, timestamps non-decreasing, at most `300` calls

## 🔹 Quick Breakdown

* **Difficulty Level:** Medium
* **Main Approach:** **Queue of `[timestamp, count]` buckets.** `hit(t)` bumps the last bucket if it has the same timestamp, otherwise appends a new one. `getHits(t)` evicts buckets with `timestamp ≤ t − 300`, then returns the running total.
* **Core Concept:** timestamps arrive in non-decreasing order, so old hits are always at the front; keep a running sum instead of re-adding
* **When to Use This Pattern?** "How many events in the last `K` seconds" with ordered timestamps.
* **Mistakes to Avoid:**
  * Window off-by-one: the last 300 seconds are `(t − 300, t]`, so a hit at `t − 300` has expired (`getHits(301)` after hits at 1, 2, 3, 300 is `3`).
  * Storing one entry per hit: many hits in the same second waste memory; merge them into a bucket.

## 🔹 Optimization Path

* **Brute Force:** keep a list of every hit and count those within the window on each `getHits` — O(total hits) per query.
* **Optimized Solution:** deque of buckets with eager eviction and a running total — O(1) amortised.
* **Further Improvements Possible?** A fixed circular array of 300 `(time, count)` slots gives O(300) memory regardless of traffic (useful if hits vastly outnumber seconds).

## 🔹 Solution Breakdown

* **Optimal Approach:** `hit`: merge into the last bucket or append; `total += 1`. `getHits`: while `front.time ≤ t − 300`, subtract its count and pop; return `total`.
* **Why This Works?** Bucket timestamps are non-decreasing, so expired buckets form a prefix. The `total` always equals the sum of live bucket counts because we adjust it on every add and every pop.
* **Edge Cases Considered:**
  * Many hits at the same second → one bucket.
  * Query when nothing is in the window → `0`.

## 🔹 Tricks & Patterns Used

* **Running total next to the queue:** answers in O(1) without summing.
* **Bucket by timestamp:** compresses bursts.

## 🔹 Alternative Data Structures

* Two arrays `times[300]` / `hits[300]` indexed by `t % 300` — evicts lazily by overwriting stale slots.
* Sorted list of hit times + `bisect` — O(log n) per query, memory grows with every hit.

## 🔹 Complexity Analysis

* **Time Complexity:** `hit` O(1); `getHits` O(1) amortised (each bucket pops at most once)
* **Space Complexity:** O(300) — at most one bucket per second in the window

## 🔹 Code Snippet (Brute Force)

```python
from typing import List


class HitCounter:
    def __init__(self):
        self.hits: List[int] = []

    def hit(self, timestamp: int) -> None:
        self.hits.append(timestamp)

    def getHits(self, timestamp: int) -> int:
        return sum(1 for t in self.hits if t > timestamp - 300)
```

## 🔹 Code Snippet (Optimized)

```python
from collections import deque


class HitCounter:
    def __init__(self):
        self.buckets = deque()  # [timestamp, hits in that second], oldest first
        self.total = 0

    def hit(self, timestamp: int) -> None:
        if self.buckets and self.buckets[-1][0] == timestamp:
            self.buckets[-1][1] += 1
        else:
            self.buckets.append([timestamp, 1])
        self.total += 1

    def getHits(self, timestamp: int) -> int:
        while self.buckets and self.buckets[0][0] <= timestamp - 300:  # window is (t - 300, t]
            self.total -= self.buckets.popleft()[1]
        return self.total
```
