# 24. Swap Nodes in Pairs

**🔗 Link:** [LeetCode 24](https://leetcode.com/problems/swap-nodes-in-pairs/)
**🟢 Status:** 🔄 Need Review


## 🔹 Problem Statement

Swap every two adjacent nodes of a linked list and return the new head. Only the nodes may be rearranged; changing the stored values is not allowed. A leftover last node (odd length) stays where it is.

* **Example:** `head = [1,2,3,4]` → `[2,1,4,3]`
* **Constraints:** `0 ≤ n ≤ 100`; `0 ≤ Node.val ≤ 100`.

## 🔹 Quick Breakdown

* **Difficulty Level:** Medium
* **Main Approach:** **Dummy head + three pointer re-links per pair.** Keep `prev` at the node before the current pair; with `first = prev.next` and `second = first.next` rewire `prev → second → first → rest`, then move `prev` to `first` (now the tail of the swapped pair).
* **Core Concept:** swap the *nodes*, never the values, and use a dummy node so the head needs no special case
* **When to Use This Pattern?** In-place rearrangement of a list in fixed-size groups — pairs here, `k` in 25, reversing a sub-list in 92.
* **Mistakes to Avoid:**
  * Re-linking in the wrong order and losing `second.next` — save it (or assign `first.next` first).
  * Swapping `val` fields: the problem forbids it.
  * Not stopping when one node is left over (odd length) — it stays in place.

## 🔹 Optimization Path

* **Brute Force:** copy the values to an array, swap neighbours, build a brand-new list — O(n) time but O(n) extra space and fresh nodes.
* **Optimized Solution:** re-link the existing nodes in one pass — O(n) time, O(1) space.
* **Further Improvements Possible?** No; every node has to be visited once.

## 🔹 Solution Breakdown

* **Optimal Approach:** `dummy → head`. While `prev.next` and `prev.next.next` exist: `first.next = second.next; second.next = first; prev.next = second; prev = first`.
* **Why This Works?** After the three assignments the pair is reversed and still connected on both sides: `prev` points to `second`, `first` points to what followed the pair. Moving `prev` to `first` re-establishes the same invariant for the next pair.
* **Edge Cases Considered:**
  * Empty list or single node → returned as is.
  * Odd length → the last node is untouched.
  * The head changes, which is why the dummy node exists.

## 🔹 Tricks & Patterns Used

* **Dummy node:** removes the "what if the head moves" branch.
* **Loop guard `prev.next and prev.next.next`:** covers both even and odd lengths.

## 🔹 Alternative Data Structures

* Recursion: swap the first two, recurse on `second.next` — O(n) stack, at most 50 pair-calls deep here (`n ≤ 100`).

## 🔹 Complexity Analysis

* **Time Complexity:** O(n)
* **Space Complexity:** O(1)

## 🔹 Code Snippet (Brute Force)

```python
from typing import Optional


class Solution:
    def swapPairs(self, head: Optional[ListNode]) -> Optional[ListNode]:
        values = []
        node = head
        while node:
            values.append(node.val)
            node = node.next
        for i in range(0, len(values) - 1, 2):
            values[i], values[i + 1] = values[i + 1], values[i]
        dummy = tail = ListNode(0)
        for value in values:
            tail.next = ListNode(value)
            tail = tail.next
        return dummy.next
```

## 🔹 Code Snippet (Optimized)

```python
from typing import Optional


class Solution:
    def swapPairs(self, head: Optional[ListNode]) -> Optional[ListNode]:
        dummy = ListNode(0, head)
        prev = dummy
        while prev.next and prev.next.next:
            first, second = prev.next, prev.next.next
            first.next = second.next  # must happen before second.next is overwritten
            second.next = first
            prev.next = second
            prev = first
        return dummy.next
```
