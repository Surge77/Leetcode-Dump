# 🔹 Problem Name: 721. Accounts Merge (Union Find, Medium)

**🔗 Link:** [LeetCode 721](https://leetcode.com/problems/accounts-merge/)
**🟢 Status:** 🔄 Need Review

## 🔹 Quick Breakdown

* **Difficulty Level:** Medium
* **Main Approach:** **Union-Find over accounts.** Map every email to the first account that listed it. When a later account lists the same email, union the two accounts. Finally group each email under its account's root and emit `[name] + sorted(emails)` per root.
* **Core Concept:** "shares an email" is an equivalence relation once closed transitively — its classes are connected components
* **When to Use This Pattern?** Records that must be merged when they share **any** key — duplicate users, synonyms (1061, 1258), "same row or column" (947), equality constraints (990).
* **Mistakes to Avoid:**
  * Merging by **name**: two different people can be called "John". Only a shared email links accounts.
  * Merging only pairs that share an email directly — A–B and B–C share emails, A–C do not, but all three are one person.
  * Forgetting to de-duplicate emails or to sort them.

## 🔹 Optimization Path

* **Brute Force:** keep a list of (name, email-set) groups; repeatedly find any two groups whose sets intersect and merge them, restarting after each merge — up to `n − 1` merges, each preceded by a scan over O(n²) pairs of sets: at least cubic.
* **Optimized Solution:** Union-Find keyed by account index with an `email → owner` map — O(N log N) for `N` total emails (the final sort dominates).
* **Further Improvements Possible?** Not asymptotically — the output must be sorted.

## 🔹 Solution Breakdown

* **Optimal Approach:** `owner[email] = i` on first sight, otherwise `union(i, owner[email])`. Then `groups[find(owner[email])].append(email)` for every email, sort each group, prefix the name of the root account.
* **Why This Works?** Each union records one direct link (a shared email). Union-Find maintains the transitive closure, so two accounts end with the same root exactly when a chain of shared emails connects them. All accounts in a class carry the same name (guaranteed), so any member's name is correct.
* **Edge Cases Considered:**
  * An account with one email that appears nowhere else → its own group.
  * Same name, disjoint emails → stays separate.
  * The same email listed twice → the `owner` map keeps it once.

## 🔹 Tricks & Patterns Used

* **Union the owners, not the emails:** account indices are small integers, so `parent` is a plain list.
* **Path halving** (`parent[x] = parent[parent[x]]`) keeps `find` iterative and the trees shallow.

## 🔹 Alternative Data Structures

* Graph + DFS: connect every email of an account to its first email, then each connected component of emails is one person — same complexity, needs an adjacency map.
* Union-Find keyed directly by email strings (`dict` parent) — works, slightly heavier hashing.

## 🔹 Complexity Analysis

* **Time Complexity:** O(N log N), `N` = total emails (≤ 1 000 accounts × 9 emails); each find is amortized O(log n) with path halving alone (near-constant with union by size added), and sorting the groups is O(N log N)
* **Space Complexity:** O(N)

## 🔹 Code Snippet (Brute Force)

```python
from typing import List


class Solution:
    def accountsMerge(self, accounts: List[List[str]]) -> List[List[str]]:
        groups = [(acc[0], set(acc[1:])) for acc in accounts]
        while True:
            pair = next(((i, j) for i in range(len(groups)) for j in range(i + 1, len(groups))
                         if groups[i][1] & groups[j][1]), None)
            if pair is None:
                break
            i, j = pair
            groups[i][1].update(groups.pop(j)[1])  # a merge can create new overlaps, so search again
        return [[name] + sorted(emails) for name, emails in groups]
```

## 🔹 Code Snippet (Optimized)

```python
from collections import defaultdict
from typing import List


class Solution:
    def accountsMerge(self, accounts: List[List[str]]) -> List[List[str]]:
        parent = list(range(len(accounts)))

        def find(x: int) -> int:
            while parent[x] != x:
                parent[x] = parent[parent[x]]  # path halving keeps trees shallow without recursion
                x = parent[x]
            return x

        owner = {}
        for i, (_, *emails) in enumerate(accounts):
            for email in emails:
                if email in owner:
                    parent[find(i)] = find(owner[email])
                else:
                    owner[email] = i

        merged = defaultdict(list)
        for email, i in owner.items():
            merged[find(i)].append(email)
        return [[accounts[root][0]] + sorted(emails) for root, emails in merged.items()]
```
