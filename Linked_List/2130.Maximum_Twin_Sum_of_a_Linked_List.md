# 🔹 Problem Name: 2130. Maximum Twin Sum of a Linked List (Fast & Slow Pointers, Medium)

**🔗 Link:** [LeetCode 2130](https://leetcode.com/problems/maximum-twin-sum-of-a-linked-list/)
**🟢 Status:** 🔄 Need Review

## 🔹 Problem Statement

The list has even length `n`; node `i` and node `n - 1 - i` are twins (for `i < n / 2`), and a twin sum is the sum of their values. Return the largest twin sum in the list.

* **Example:** `head = [5,4,2,1]` → `6`
* **Constraints:** `n` is even, `2 ≤ n ≤ 10^5`; `1 ≤ Node.val ≤ 10^5`.

## 🔹 Quick Breakdown

* **Difficulty Level:** Medium
* **Main Approach:** **Find the middle, reverse the second half, walk both halves together.** Node `i` and node `n - 1 - i` are twins; after reversing the back half, the twins line up at the same offset from each half's start.
* **Core Concept:** a singly linked list cannot be indexed from the back, so bring the back half forward by reversing it
* **When to Use This Pattern?** Anything that compares the front with the mirrored back of a linked list — palindrome check (234), reorder list (143), twin sums.
* **Mistakes to Avoid:**
  * Stopping the fast/slow loop one step too early or late: with even length (guaranteed here) `slow` must end on the **first node of the second half**.
  * Forgetting that reversing mutates the list — acceptable here, but restore it if the caller needs it.

## 🔹 Optimization Path

* **Brute Force:** copy the values to an array and pair `a[i]` with `a[n - 1 - i]` — O(n) time, O(n) space.
* **Optimized Solution:** slow/fast pointers plus in-place reversal — O(n) time, O(1) space.
* **Further Improvements Possible?** Time is already linear; the array version is simpler and is perfectly fine when O(n) memory is allowed.

## 🔹 Solution Breakdown

* **Optimal Approach:** advance `slow` by 1 and `fast` by 2 until `fast` runs off the end; `slow` is the first node of the second half. Reverse from `slow`. Then step `head` and the reversed head together, taking the max of `a.val + b.val`.
* **Why This Works?** With length `n = 2m`, `slow` stops after `m` moves, at index `m`. The reversed second half starts with node `n - 1`, whose twin is node `0` — the head. Each simultaneous step keeps the pair `(i, n - 1 - i)`.
* **Edge Cases Considered:**
  * `n = 2` → one pair, the answer is the sum of both values.
  * All values equal → every twin sum is the same.
  * The first half's last node still points into the reversed half; iterating `m` steps via the reversed pointer never reads it.

## 🔹 Tricks & Patterns Used

* **Tortoise and hare** to locate the midpoint in one pass.
* **In-place reversal** with `prev` / `next` pointers.

## 🔹 Alternative Data Structures

* Stack: push the first half's values while `slow` moves, then pop while walking the second half — O(n) space, no mutation.
* Array of values with two indices.

## 🔹 Complexity Analysis

* **Time Complexity:** O(n)
* **Space Complexity:** O(1)

## 🔹 Code Snippet (Brute Force)

```python
from typing import Optional


class Solution:
    def pairSum(self, head: Optional[ListNode]) -> int:
        values = []
        while head:
            values.append(head.val)
            head = head.next
        n = len(values)
        return max(values[i] + values[n - 1 - i] for i in range(n // 2))
```

## 🔹 Code Snippet (Optimized)

```python
from typing import Optional


class Solution:
    def pairSum(self, head: Optional[ListNode]) -> int:
        slow = fast = head
        while fast and fast.next:
            slow = slow.next
            fast = fast.next.next
        prev = None
        while slow:
            nxt = slow.next
            slow.next = prev
            prev, slow = slow, nxt
        best = 0
        front, back = head, prev
        while back:
            best = max(best, front.val + back.val)
            front, back = front.next, back.next
        return best
```
