# 🔹 Problem Name: 132. Palindrome Partitioning II (Partition DP, Hard)

**🔗 Link:** [LeetCode 132](https://leetcode.com/problems/palindrome-partitioning-ii/)
**🟢 Status:** 🔄 Need Review

## 🔹 Quick Breakdown

* **Difficulty Level:** Hard
* **Main Approach:** **Prefix DP + expand around centers.** `cuts[k]` = minimum cuts for the prefix `s[:k]`, with `cuts[0] = -1` so a prefix that is itself a palindrome costs `-1 + 1 = 0`. For every center, expand outwards; each palindrome `s[l..r]` found gives `cuts[r+1] = min(cuts[r+1], cuts[l] + 1)`.
* **Core Concept:** front partition — "the last piece is a palindrome `s[l..r]`, the rest is an optimal partition of `s[:l]`"
* **When to Use This Pattern?** "Split a sequence into pieces that each satisfy a property, minimise the number of pieces" — palindrome pieces, word break (139), array partitioning (1043).
* **Mistakes to Avoid:**
  * Checking `isPalindrome(l, r)` by slicing inside the O(n²) loop → O(n³) = 8·10⁹ for `n = 2000`.
  * Returning the number of **pieces** instead of cuts (off by one).
  * Recursion over cut positions without memo — exponential.

## 🔹 Optimization Path

* **Brute Force:** try every first palindromic piece recursively — exponential.
* **Better:** `pal[l][r]` table (O(n²) memory) plus `cuts[r] = min over l` — O(n²) time and space.
* **Optimized Solution:** expand around each of the `2n − 1` centers and update `cuts` on the fly — O(n²) time, O(n) space.
* **Further Improvements Possible?** Not asymptotically for this formulation; O(n²) in the worst case (`"aaaa…"` has Θ(n²) palindromic substrings).

## 🔹 Solution Breakdown

* **Optimal Approach:** `cuts = [k - 1 for k in range(n + 1)]` (the worst: every char its own piece). For each center `c`, run odd (`l = r = c`) and even (`l = c, r = c + 1`) expansions while `s[l] == s[r]`, relaxing `cuts[r + 1]`.
* **Why This Works?** When we relax `cuts[r + 1]`, the value `cuts[l]` with `l ≤ c` is already final: every palindrome ending before position `l` has its center left of `c`, so it was processed earlier. Every palindromic last piece of every prefix is enumerated exactly once by its center.
* **Edge Cases Considered:**
  * Whole string is a palindrome → 0.
  * All distinct letters → `n − 1`.
  * `n = 1` → 0.

## 🔹 Tricks & Patterns Used

* **Sentinel `cuts[0] = -1`:** removes the special case "no cut needed when the prefix is a palindrome".
* **Expand around center:** enumerates every palindrome in O(n + count) without a table.

## 🔹 Alternative Data Structures

* Boolean table `pal[l][r] = s[l] == s[r] and pal[l+1][r-1]` — 4·10⁶ cells; clearer but heavier in memory.
* Manacher's algorithm finds radii in O(n), but the DP still needs O(n²) relaxations in the worst case.

## 🔹 Complexity Analysis

* **Time Complexity:** O(n²)
* **Space Complexity:** O(n)

## 🔹 Code Snippet (Brute Force)

```python
class Solution:
    def minCut(self, s: str) -> int:
        def pieces(start: int) -> int:
            if start == len(s):
                return 0
            best = len(s)
            for end in range(start + 1, len(s) + 1):
                piece = s[start:end]
                if piece == piece[::-1]:
                    best = min(best, 1 + pieces(end))
            return best

        return pieces(0) - 1
```

## 🔹 Code Snippet (Optimized)

```python
class Solution:
    def minCut(self, s: str) -> int:
        n = len(s)
        cuts = [k - 1 for k in range(n + 1)]  # cuts[0] = -1 so a palindromic prefix costs 0
        for center in range(n):
            for l, r in ((center, center), (center, center + 1)):
                while l >= 0 and r < n and s[l] == s[r]:
                    # cuts[l] is final: palindromes ending before l are centred left of `center`
                    if cuts[l] + 1 < cuts[r + 1]:
                        cuts[r + 1] = cuts[l] + 1
                    l -= 1
                    r += 1
        return cuts[n]
```
