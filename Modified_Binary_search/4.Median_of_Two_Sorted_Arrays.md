# 🔹 Problem Name: 4. Median of Two Sorted Arrays (Binary Search on Partition, Hard)

**🔗 Link:** [LeetCode 4](https://leetcode.com/problems/median-of-two-sorted-arrays/)
**🟢 Status:** 🔄 Need Review

## 🔹 Problem Statement

Given two sorted arrays `nums1` and `nums2`, return the median of all their elements combined, as a float (the mean of the two middle values when the total count is even). The intended running time is O(log(m + n)).

* **Example:** `nums1 = [1,3], nums2 = [2]` → `2.00000`
* **Constraints:** `0 ≤ m, n ≤ 1000`; `1 ≤ m + n ≤ 2000`; `-10^6 ≤ nums1[i], nums2[i] ≤ 10^6`.

## 🔹 Quick Breakdown

* **Difficulty Level:** Hard
* **Main Approach:** **Binary search on the cut of the shorter array.** Cut `A` after `i` elements and `B` after `j = half − i` elements, with `half = (m + n + 1) // 2`. The cut is correct when `A[i−1] ≤ B[j]` and `B[j−1] ≤ A[i]` — then the left side holds exactly the `half` smallest values. Too far right (`A[i−1] > B[j]`) → move left; otherwise move right.
* **Core Concept:** the median is defined by a split into two halves, and the split has one degree of freedom (`i`) that is monotone
* **When to Use This Pattern?** "k-th smallest / median of two sorted arrays" in better than O(m + n); any search where a feasible split point is monotone in one index.
* **Mistakes to Avoid:**
  * Binary-searching the longer array: `j = half − i` can go negative or past `n`.
  * Forgetting the sentinels: an empty side uses `−∞` (left) or `+∞` (right).
  * Odd total: the median is the max of the left side, which is why `half` rounds up.

## 🔹 Optimization Path

* **Brute Force:** merge both arrays (or `sorted(A + B)`) and read the middle — O((m + n) log(m + n)) with sort, O(m + n) with a merge.
* **Optimized Solution:** binary search the cut in the shorter array — O(log min(m, n)).
* **Further Improvements Possible?** No; the required bound is O(log(m + n)) and this is already better.

## 🔹 Solution Breakdown

* **Optimal Approach:** ensure `len(A) ≤ len(B)`; `lo, hi = 0, m`; loop: `i = (lo + hi) // 2`, `j = half − i`; read the four border values with sentinels; check the two cross conditions.
* **Why This Works?** Each side is sorted, so the left half is valid iff its largest elements (`A[i−1]`, `B[j−1]`) are ≤ the right half's smallest (`B[j]`, `A[i]`). If `A[i−1] > B[j]`, every larger `i` keeps an even bigger `A[i−1]` against a smaller `B[j]`, so the answer lies left of `i` — monotone, hence binary-searchable. A valid cut always exists because some `i` in `[0, m]` produces the true sorted split.
* **Edge Cases Considered:**
  * One array empty (`A = []`) → `i = 0`, the median comes from `B` alone.
  * All of `A` smaller (or larger) than all of `B` → cut at `i = m` (or `0`), sentinels make the checks pass.
  * Duplicates across arrays — the `≤` comparisons allow ties.

## 🔹 Tricks & Patterns Used

* **Search the shorter array:** guarantees `0 ≤ j ≤ n` for every `i` and gives O(log min).
* **`±∞` sentinels** remove four special cases at the array borders.

## 🔹 Alternative Data Structures

* Recursive "k-th smallest of two arrays": discard `k/2` elements from one array per step — O(log(m + n)).
* Two-pointer merge stopping at the middle — O(m + n), O(1) space.

## 🔹 Complexity Analysis

* **Time Complexity:** O(log min(m, n))
* **Space Complexity:** O(1)

## 🔹 Code Snippet (Brute Force)

```python
from typing import List


class Solution:
    def findMedianSortedArrays(self, nums1: List[int], nums2: List[int]) -> float:
        merged = sorted(nums1 + nums2)
        mid = len(merged) // 2
        if len(merged) % 2:
            return float(merged[mid])
        return (merged[mid - 1] + merged[mid]) / 2
```

## 🔹 Code Snippet (Optimized)

```python
from typing import List


class Solution:
    def findMedianSortedArrays(self, nums1: List[int], nums2: List[int]) -> float:
        a, b = nums1, nums2
        if len(a) > len(b):
            a, b = b, a  # keeps j = half - i inside [0, len(b)]
        m, n = len(a), len(b)
        half = (m + n + 1) // 2  # left half takes the extra element when the total is odd
        lo, hi = 0, m
        while True:
            i = (lo + hi) // 2
            j = half - i
            a_left = a[i - 1] if i > 0 else float("-inf")
            a_right = a[i] if i < m else float("inf")
            b_left = b[j - 1] if j > 0 else float("-inf")
            b_right = b[j] if j < n else float("inf")
            if a_left > b_right:
                hi = i - 1
            elif b_left > a_right:
                lo = i + 1
            else:
                left_max = max(a_left, b_left)
                if (m + n) % 2:
                    return float(left_max)
                return (left_max + min(a_right, b_right)) / 2
```
