# 315. Count of Smaller Numbers After Self

**🔗 Link:** [LeetCode 315](https://leetcode.com/problems/count-of-smaller-numbers-after-self/)
**🟢 Status:** 🔄 Need Review


## 🔹 Problem Statement

For every position `i` of an integer array, count how many elements to its right are strictly smaller than `nums[i]`, and return these counts as an array of the same length.

* **Example:** `nums = [5,2,6,1]` → `[2,1,1,0]`
* **Constraints:** `1 ≤ nums.length ≤ 10^5`, `-10^4 ≤ nums[i] ≤ 10^4`

## 🔹 Quick Breakdown

* **Difficulty Level:** Hard
* **Main Approach:** Walk from right to left. A Fenwick tree over compressed value ranks counts how many already-seen (i.e., to-the-right) values are smaller than the current one.
* **Core Concept:** Fenwick tree (Binary Indexed Tree) + coordinate compression
* **When to Use This Pattern?** Counting inversions, "how many earlier/later elements are smaller/greater", rank queries while elements are inserted.
* **Mistakes to Avoid:**
  * Querying `rank(x)` instead of `rank(x) - 1` — that counts equal values as smaller.
  * Fenwick arrays are 1-indexed; forgetting the `+1` shift loops forever at index 0.

## 🔹 Optimization Path

* **Brute Force:** O(n²) — compare every pair.
* **Optimized Solution:** O(n log n) — Fenwick or merge sort.
* **Further Improvements Possible?** No.

## 🔹 Solution Breakdown

* **Optimal Approach:** `rank[x]` = 1-based position of `x` among sorted unique values. Right to left: `answer[i] = prefix(rank[x] - 1)`, then `add(rank[x], 1)`.
* **Why This Works?** At step `i` the tree contains exactly the elements to the right of `i`; a prefix count over smaller ranks counts the smaller ones.
* **Edge Cases Considered:**
  * Duplicates (`[-1, -1]` → `[0, 0]`).
  * Negative values (compression handles them).

## 🔹 Tricks & Patterns Used

* **`i & -i`** = lowest set bit; climbing by it gives O(log n) update/prefix.
* **Coordinate compression** keeps the tree size `n`, whatever the value range.

## 🔹 Alternative Data Structures

* **Merge sort:** count how many right-half elements are placed before each left-half element.
* **Segment tree** over ranks — same complexity, more code.

## 🔹 Complexity Analysis

* **Time Complexity:** O(n log n)
* **Space Complexity:** O(n)

## 🔹 Code Snippet (Brute Force)

```python
from typing import List


class Solution:
    def countSmaller(self, nums: List[int]) -> List[int]:
        n = len(nums)
        result = [0] * n
        for i in range(n):
            for j in range(i + 1, n):
                if nums[j] < nums[i]:
                    result[i] += 1
        return result
```

## 🔹 Code Snippet (Optimized)

```python
from typing import List


class Fenwick:
    def __init__(self, n: int):
        self.tree = [0] * (n + 1)  # 1-indexed

    def add(self, i: int, delta: int) -> None:
        while i < len(self.tree):
            self.tree[i] += delta
            i += i & -i

    def prefix(self, i: int) -> int:  # sum of positions 1..i
        total = 0
        while i > 0:
            total += self.tree[i]
            i -= i & -i
        return total


class Solution:
    def countSmaller(self, nums: List[int]) -> List[int]:
        rank = {v: i + 1 for i, v in enumerate(sorted(set(nums)))}
        bit = Fenwick(len(rank))
        result = [0] * len(nums)
        for i in range(len(nums) - 1, -1, -1):
            r = rank[nums[i]]
            result[i] = bit.prefix(r - 1)  # strictly smaller values seen to the right
            bit.add(r, 1)
        return result
```
