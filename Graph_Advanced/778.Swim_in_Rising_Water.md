# 🔹 Problem Name: 778. Swim in Rising Water (Dijkstra, Hard)

**🔗 Link:** [LeetCode 778](https://leetcode.com/problems/swim-in-rising-water/)
**🟢 Status:** 🔄 Need Review

## 🔹 Quick Breakdown

* **Difficulty Level:** Hard
* **Main Approach:** **Minimax Dijkstra.** The time to reach a cell along a path is the **maximum** elevation on that path; we want the path minimising that maximum. Pop cells from a min-heap keyed by "best max so far"; moving into a neighbour costs `max(cur, grid[nr][nc])`. The first time `(n−1, n−1)` is popped, its key is the answer.
* **Core Concept:** Dijkstra works for any path cost that never decreases when a path is extended — `max` qualifies just like `+`
* **When to Use This Pattern?** "Minimise the worst edge/cell on a path" — bottleneck paths, minimum effort (1631), maximum-minimum score path (1102), safest path (2812).
* **Mistakes to Avoid:**
  * Summing elevations — the cost is a maximum, not a sum.
  * Forgetting the start cell: the answer is at least `grid[0][0]` (and at least `grid[n−1][n−1]`).
  * Never marking cells as visited — the heap then re-pushes the same cell from every neighbour.

## 🔹 Optimization Path

* **Brute Force:** for `t = 0, 1, 2, …`, BFS over cells with elevation ≤ `t`; the first `t` that connects the corners — O(n⁴).
* **Better:** binary search on `t` with the same BFS — O(n² log n²).
* **Optimized Solution:** minimax Dijkstra — O(n² log n).
* **Alternative:** union-find, adding cells in increasing elevation until the corners connect — O(n² α) after an O(n²) bucket order (elevations are a permutation of `0..n²−1`).

## 🔹 Solution Breakdown

* **Optimal Approach:** heap `[(grid[0][0], 0, 0)]`, `seen = {(0,0)}`. Pop `(t, r, c)`; if it is the target, return `t`. For each unseen neighbour, mark it and push `(max(t, grid[nr][nc]), nr, nc)`.
* **Why This Works?** Keys are popped in non-decreasing order. When a neighbour is first discovered from a cell with key `t`, every other way to reach it goes through a cell with key ≥ `t`, so its cost `max(t, h)` is already optimal — marking on push is safe for the `max` cost.
* **Edge Cases Considered:**
  * `n = 1` → `grid[0][0]`.
  * High-elevation start or end cell — included via the `max`.

## 🔹 Tricks & Patterns Used

* **Path cost = max along path** still satisfies Dijkstra's monotonicity requirement.
* **Grid as implicit graph** with 4-directional moves.

## 🔹 Alternative Data Structures

* Union-find over cells sorted by elevation (Kruskal-style bottleneck).
* Binary search on the answer + BFS/DFS reachability.

## 🔹 Complexity Analysis

* **Time Complexity:** O(n² log n)
* **Space Complexity:** O(n²)

## 🔹 Code Snippet (Brute Force)

```python
from collections import deque
from typing import List


class Solution:
    def swimInWater(self, grid: List[List[int]]) -> int:
        n = len(grid)
        t = max(grid[0][0], grid[n - 1][n - 1])
        while True:
            seen = {(0, 0)}
            queue = deque([(0, 0)])
            while queue:
                r, c = queue.popleft()
                if (r, c) == (n - 1, n - 1):
                    return t
                for nr, nc in ((r + 1, c), (r - 1, c), (r, c + 1), (r, c - 1)):
                    if 0 <= nr < n and 0 <= nc < n and (nr, nc) not in seen and grid[nr][nc] <= t:
                        seen.add((nr, nc))
                        queue.append((nr, nc))
            t += 1
```

## 🔹 Code Snippet (Optimized)

```python
import heapq
from typing import List


class Solution:
    def swimInWater(self, grid: List[List[int]]) -> int:
        n = len(grid)
        heap = [(grid[0][0], 0, 0)]
        seen = {(0, 0)}
        while heap:
            t, r, c = heapq.heappop(heap)
            if (r, c) == (n - 1, n - 1):
                return t
            for nr, nc in ((r + 1, c), (r - 1, c), (r, c + 1), (r, c - 1)):
                if 0 <= nr < n and 0 <= nc < n and (nr, nc) not in seen:
                    seen.add((nr, nc))  # first discovery is already optimal for max-cost paths
                    heapq.heappush(heap, (max(t, grid[nr][nc]), nr, nc))
        return -1
```
