# 🔹 Problem Name: 52. N-Queens II (Bitmask Backtracking, Hard)

**🔗 Link:** [LeetCode 52](https://leetcode.com/problems/n-queens-ii/)
**🟢 Status:** 🔄 Need Review

## 🔹 Problem Statement

Same puzzle as N-Queens: put `n` mutually non-attacking queens on an `n x n` board. This time return only how many distinct solutions exist, not the boards themselves.

* **Example:** `n = 4` → `2`
* **Constraints:** `1 ≤ n ≤ 9`

## 🔹 Quick Breakdown

* **Difficulty Level:** Hard
* **Main Approach:** **Row-by-row backtracking with three bitmasks.** Place one queen per row. `cols` marks taken columns, `d1` and `d2` mark squares attacked along the two diagonals **in the current row**. Free squares are `full & ~(cols | d1 | d2)`; after placing `bit`, shift `d1 | bit` left and `d2 | bit` right to move the diagonal attacks down one row.
* **Core Concept:** only the count is needed, so no board is built — the whole state is three integers
* **When to Use This Pattern?** Placement / assignment under "no two attack each other" constraints with small `n` — N-Queens, Sudoku, exact cover.
* **Mistakes to Avoid:**
  * Building and copying a board for every placement — only the count is asked for.
  * Dropping `& full` after the left shift: `free` stays correct (it is masked anyway), but `d1` keeps growing as a big integer.
  * Re-checking every previous queen per placement: O(n) extra per step.

## 🔹 Optimization Path

* **Brute Force:** every permutation of columns (one queen per row and per column), keep those with distinct `r + c` and distinct `r − c` — O(n! · n).
* **Optimized Solution:** bitmask backtracking — prunes a partial placement as soon as a row has no free square.
* **Further Improvements Possible?** Count only placements whose first-row queen is in the left half and double (handling the middle column for odd `n`) — a 2× symmetry saving. With `n ≤ 9` a lookup table also works.

## 🔹 Solution Breakdown

* **Optimal Approach:** `place(cols, d1, d2)`: if `cols == full` return 1; otherwise iterate free bits with `bit = free & −free` and sum `place(cols | bit, ((d1 | bit) << 1) & full, (d2 | bit) >> 1)`.
* **Why This Works?** A queen at column `c` attacks column `c ± k` in the row `k` below. Shifting the diagonal masks by one per row reproduces exactly that, so `free` contains precisely the safe squares. Every complete placement corresponds to one root-to-leaf path, so the count is exact.
* **Edge Cases Considered:**
  * `n = 1` → 1; `n = 2` and `n = 3` → 0.
  * `n = 9` (max) → 352.

## 🔹 Tricks & Patterns Used

* **Diagonal masks that shift per row** instead of `r + c` / `r − c` sets.
* **Lowest set bit iteration:** `bit = free & −free; free ^= bit`.

## 🔹 Alternative Data Structures

* Three boolean arrays `col[n]`, `diag[2n−1]` (`r + c`), `anti[2n−1]` (`r − c + n − 1`) — the classic version, same complexity, more bookkeeping.

## 🔹 Complexity Analysis

* **Time Complexity:** O(n!) upper bound (row `r` has at most `n − r` free columns); for `n ≤ 9` this is a few thousand calls.
* **Space Complexity:** O(n) recursion depth.

## 🔹 Code Snippet (Brute Force)

```python
from itertools import permutations


class Solution:
    def totalNQueens(self, n: int) -> int:
        return sum(
            len({r + c for r, c in enumerate(perm)}) == n and len({r - c for r, c in enumerate(perm)}) == n
            for perm in permutations(range(n))
        )
```

## 🔹 Code Snippet (Optimized)

```python
class Solution:
    def totalNQueens(self, n: int) -> int:
        full = (1 << n) - 1

        def place(cols: int, d1: int, d2: int) -> int:
            if cols == full:
                return 1
            count = 0
            free = full & ~(cols | d1 | d2)
            while free:
                bit = free & -free
                free ^= bit
                # diagonal attacks move one column outward per row
                count += place(cols | bit, ((d1 | bit) << 1) & full, (d2 | bit) >> 1)
            return count

        return place(0, 0, 0)
```
