# 🔹 Problem Name: 80. Remove Duplicates from Sorted Array II (Two Pointers, Medium)

**🔗 Link:** [LeetCode 80](https://leetcode.com/problems/remove-duplicates-from-sorted-array-ii/)
**🟢 Status:** 🔄 Need Review

## 🔹 Problem Statement

Given an integer array sorted in non-decreasing order, remove duplicates in place so that each value appears at most twice, keeping the relative order. Return `k`, the length of the result; the first `k` slots must hold it and anything after them is ignored.

* **Example:** `nums = [1,1,1,2,2,3]` → `5, nums = [1,1,2,2,3,_]`
* **Constraints:** `1 ≤ nums.length ≤ 3·10⁴`, `-10⁴ ≤ nums[i] ≤ 10⁴`, `nums` is sorted; O(1) extra memory

## 🔹 Quick Breakdown

* **Difficulty Level:** Medium
* **Main Approach:** **Write pointer compared two slots back.** Read every `x`; keep it (write to `nums[k]`, `k += 1`) when `k < 2` or `nums[k − 2] != x`. Return `k`.
* **Core Concept:** in a sorted array, `x` would be a third copy exactly when the element two places back **in the kept prefix** equals `x`
* **When to Use This Pattern?** "Keep at most `m` copies of each value of a sorted array, in place" — compare with `nums[k − m]`. `m = 1` is problem 26.
* **Mistakes to Avoid:**
  * Comparing with the **original** `nums[i − 2]` (read index): that slot may already be overwritten by the compaction; the kept prefix `nums[k − 2]` is what matters.
  * Counting run lengths with extra variables and resetting them wrongly — the `k − 2` check needs no counter.
  * `del nums[i]` for each extra copy — O(n²).

## 🔹 Optimization Path

* **Brute Force:** whenever `nums[i] == nums[i − 2]`, shift the tail left by one — O(n²), about 4.5·10⁸ moves when `n = 3·10⁴` and almost everything is a duplicate.
* **Optimized Solution:** read/write pointers — O(n), O(1) space.
* **Further Improvements Possible?** No; every element must be read once.

## 🔹 Solution Breakdown

* **Optimal Approach:** `k = 0; for x in nums: if k < 2 or nums[k - 2] != x: nums[k] = x; k += 1`.
* **Why This Works?** Invariant: `nums[:k]` is the valid answer for the elements read so far, sorted. If `nums[k − 2] == x`, then by sortedness `nums[k − 2] == nums[k − 1] == x` — two copies are already kept, so `x` is dropped. Otherwise at most one copy of `x` is kept and `x` may stay.
* **Edge Cases Considered:**
  * `n ≤ 2` → everything is kept.
  * Long runs (`[1, 1, 1, 1, 1]` → `k = 2`).
  * Negative values — only equality is used.

## 🔹 Tricks & Patterns Used

* **Lookback `m` slots in the output:** generalises "at most `m` duplicates" with one comparison.
* **Writes trail reads:** `k ≤` read index, so the read pointer never sees an overwritten value.

## 🔹 Alternative Data Structures

* `itertools.groupby` + `min(len(group), 2)` into a new list, then `nums[:k] = ...` — O(n) extra space.

* **Time Complexity:** O(n)
* **Space Complexity:** O(1)

## 🔹 Code Snippet (Brute Force)

```python
from typing import List


class Solution:
    def removeDuplicates(self, nums: List[int]) -> int:
        k, i = len(nums), 2
        while i < k:
            if nums[i] == nums[i - 2]:  # sorted: a third copy of the same value
                for j in range(i + 1, k):
                    nums[j - 1] = nums[j]
                k -= 1
            else:
                i += 1
        return k
```

## 🔹 Code Snippet (Optimized)

```python
from typing import List


class Solution:
    def removeDuplicates(self, nums: List[int]) -> int:
        k = 0
        for x in nums:
            if k < 2 or nums[k - 2] != x:
                nums[k] = x
                k += 1
        return k
```
