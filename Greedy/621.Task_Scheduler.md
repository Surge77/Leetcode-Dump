# 🔹 Problem Name: 621. Task Scheduler (Greedy / Counting, Medium)

**🔗 Link:** [LeetCode 621](https://leetcode.com/problems/task-scheduler/)
**🟢 Status:** 🔄 Need Review

## 🔹 Problem Statement

Tasks are labelled `A`–`Z`; each takes one CPU interval and the CPU may also idle. Two runs of the same label must have at least `n` intervals between them. Return the minimum number of intervals needed to finish all tasks, in any order.

* **Example:** `tasks = ["A","A","A","B","B","B"], n = 2` → `8`
* **Constraints:** `1 ≤ tasks.length ≤ 10^4`, `tasks[i]` is an uppercase letter, `0 ≤ n ≤ 100`.

## 🔹 Quick Breakdown

* **Difficulty Level:** Medium
* **Main Approach:** The most frequent task decides the frame: `(maxFreq - 1)` blocks of length `n + 1`, plus one slot per task that ties for `maxFreq`. If there are more tasks than that frame, no idle time is needed → `len(tasks)`.
* **Core Concept:** Greedy counting formula
* **When to Use This Pattern?** Cooldown / spacing constraints between equal items (reorganise string, rearrange with distance k).
* **Mistakes to Avoid:**
  * Forgetting the `max(..., len(tasks))` — many distinct tasks can fill every gap.
  * Counting only one task with the maximum frequency.

## 🔹 Optimization Path

* **Brute Force / Simulation:** tick by tick, run the ready task with the most copies left (the code below scans the ≤ 26 labels each tick; a max-heap + cooldown queue is the faster variant) — O(total time · 26).
* **Optimized Solution:** O(len(tasks)) counting formula (here `n` is the cooldown, not the task count).
* **Further Improvements Possible?** No.

## 🔹 Solution Breakdown

* **Optimal Approach:** `frame = (maxFreq - 1) · (n + 1) + countOfMax`; answer `max(frame, len(tasks))`.
* **Why This Works?** Copies of the most frequent task must be `n + 1` apart, forcing at least `frame` slots; every other task fits into the gaps (or, if the gaps overflow, the schedule simply has no idle slots).
* **Edge Cases Considered:**
  * `n = 0` → `len(tasks)`.
  * Several tasks tied at the maximum.

* **Frame argument:** the bottleneck element dictates the lower bound; show it is achievable.

## 🔹 Alternative Data Structures

* Max-heap of counts + queue of `(count, ready_time)` — the simulation also produces the actual schedule.

## 🔹 Complexity Analysis

* **Time Complexity:** O(len(tasks))
* **Space Complexity:** O(1) (26 letters)

## 🔹 Code Snippet (Brute Force)

```python
from collections import Counter
from typing import List


class Solution:
    def leastInterval(self, tasks: List[str], n: int) -> int:
        remaining = Counter(tasks)
        ready_at = {t: 1 for t in remaining}  # earliest slot each task may run again
        time = 0
        while remaining:
            time += 1
            ready = [t for t in remaining if ready_at[t] <= time]
            if not ready:
                continue  # idle slot
            task = max(ready, key=lambda t: remaining[t])
            remaining[task] -= 1
            ready_at[task] = time + n + 1
            if remaining[task] == 0:
                del remaining[task]
        return time
```

## 🔹 Code Snippet (Optimized)

```python
from collections import Counter
from typing import List


class Solution:
    def leastInterval(self, tasks: List[str], n: int) -> int:
        freq = Counter(tasks).values()
        max_freq = max(freq)
        tied = sum(1 for f in freq if f == max_freq)
        frame = (max_freq - 1) * (n + 1) + tied  # forced by the most frequent tasks
        return max(frame, len(tasks))
```
