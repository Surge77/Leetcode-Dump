# 🔹 Problem Name: 502. IPO (Greedy + Two Heaps, Hard)

**🔗 Link:** [LeetCode 502](https://leetcode.com/problems/ipo/)
**🟢 Status:** 🔄 Need Review

## 🔹 Problem Statement

You start with `w` capital and may complete at most `k` distinct projects. Project `i` needs at least `capital[i]` to start and adds `profits[i]` to your capital when finished. Return the maximum capital you can hold after finishing at most `k` projects.

* **Example:** `k = 2, w = 0, profits = [1,2,3], capital = [0,1,1]` → `4`
* **Constraints:** `1 ≤ k ≤ 10^5`, `0 ≤ w ≤ 10^9`, `1 ≤ n ≤ 10^5`, `0 ≤ profits[i] ≤ 10^4`, `0 ≤ capital[i] ≤ 10^9`.

## 🔹 Quick Breakdown

* **Difficulty Level:** Hard
* **Main Approach:** Sort projects by required capital. Each round, move every project you can now afford into a max-heap of profits, then take the most profitable one.
* **Core Concept:** Greedy with a heap ("unlock, then pick the best available")
* **When to Use This Pattern?** Items become available as a resource grows (capital, time, level); each step pick the best available item.
* **Mistakes to Avoid:**
  * Re-scanning all projects every round — O(k · n).
  * Stopping too late: if the heap is empty, nothing is affordable — break.

## 🔹 Optimization Path

* **Brute Force:** Try all sequences of up to `k` projects — exponential.
* **Optimized Solution:** O(n log n + k log n).
* **Further Improvements Possible?** No.

## 🔹 Solution Breakdown

* **Optimal Approach:** `projects = sorted(zip(capital, profits))`; pointer `i`; each round push `-profit` for all projects with `capital <= w`, pop the max, add to `w`.
* **Why This Works?** Profits are non-negative, so capital only grows and affordable projects stay affordable. Taking the largest available profit now unlocks at least as much as any other choice (exchange argument).
* **Edge Cases Considered:**
  * No project affordable at the start → `w`.
  * `k` larger than the number of projects.

## 🔹 Tricks & Patterns Used

* **Max-heap via negation** in `heapq`.
* **Sorted list + pointer** feeds the heap lazily.

## 🔹 Alternative Data Structures

* Two heaps (min-heap by capital, max-heap by profit) — same idea without the initial sort.

## 🔹 Complexity Analysis

* **Time Complexity:** O(n log n + k log n)
* **Space Complexity:** O(n)

## 🔹 Code Snippet (Brute Force)

```python
from typing import List


class Solution:
    def findMaximizedCapital(self, k: int, w: int, profits: List[int], capital: List[int]) -> int:
        n = len(profits)

        def best(left: int, cash: int, used: int) -> int:
            result = cash  # stopping early is always allowed
            if left == 0:
                return result
            for i in range(n):  # try every affordable unused project next
                if not used >> i & 1 and capital[i] <= cash:
                    result = max(result, best(left - 1, cash + profits[i], used | 1 << i))
            return result

        return best(k, w, 0)
```

## 🔹 Code Snippet (Optimized)

```python
import heapq
from typing import List


class Solution:
    def findMaximizedCapital(self, k: int, w: int, profits: List[int], capital: List[int]) -> int:
        projects = sorted(zip(capital, profits))
        available = []  # max-heap of profits (stored negated)
        i = 0
        for _ in range(k):
            while i < len(projects) and projects[i][0] <= w:
                heapq.heappush(available, -projects[i][1])
                i += 1
            if not available:
                break  # nothing affordable
            w -= heapq.heappop(available)
        return w
```
