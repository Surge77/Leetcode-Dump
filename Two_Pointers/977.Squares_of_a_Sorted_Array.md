# 🔹 Problem Name: 977. Squares of a Sorted Array (Two Pointers, Easy)

**🔗 Link:** [LeetCode 977](https://leetcode.com/problems/squares-of-a-sorted-array/)
**🟢 Status:** 🔄 Need Review

## 🔹 Problem Statement

You get an integer array already sorted in non-decreasing order, possibly containing negatives. Return a new array holding the square of every element, also sorted in non-decreasing order. The follow-up asks for an O(n) solution instead of square-then-sort.

* **Example:** `nums = [-4,-1,0,3,10]` → `[0,1,9,16,100]`
* **Constraints:** `1 ≤ nums.length ≤ 10^4`; `-10^4 ≤ nums[i] ≤ 10^4`; `nums` is sorted in non-decreasing order.

## 🔹 Quick Breakdown

* **Difficulty Level:** Easy
* **Main Approach:** **Two pointers from both ends, fill the result from the back.** The largest square is at one of the two ends (the most negative or the most positive number). Compare `nums[lo]²` and `nums[hi]²`, place the larger at the end of the result, and move that pointer inward.
* **Core Concept:** squaring turns a sorted array into a "valley" — big values at both ends, small in the middle
* **When to Use This Pattern?** A sequence that decreases then increases (or the reverse) must be sorted — merge two sorted halves, transform a sorted array by a function with a single minimum.
* **Mistakes to Avoid:**
  * Squaring and sorting without noticing the structure: O(n log n) instead of O(n).
  * Filling the result from the front with the larger square — it must be filled from the back.
  * Comparing `abs` incorrectly: compare the squares (or absolute values), not the raw numbers.

## 🔹 Optimization Path

* **Brute Force:** square every element and sort — O(n log n).
* **Optimized Solution:** two pointers — O(n).
* **Further Improvements Possible?** No; O(n) is a lower bound for producing `n` values.

## 🔹 Solution Breakdown

* **Optimal Approach:** `lo = 0`, `hi = n − 1`; for `pos` from `n − 1` down to `0`: `left, right = nums[lo]², nums[hi]²`; if `left > right` store `left` and `lo += 1`, else store `right` and `hi −= 1`.
* **Why This Works?** In a sorted array the element with the largest absolute value is always `nums[lo]` or `nums[hi]`. After placing the largest square at the last position, the same argument applies to the remaining slice.
* **Edge Cases Considered:**
  * All non-negative or all negative arrays — one pointer does all the work.
  * Equal squares from opposite signs (`[-3, 3]`) — either order is the same value.
  * A single element.

## 🔹 Tricks & Patterns Used

* **Fill from the back:** the largest remaining value is known, the smallest is not.
* **Preallocate the result:** `[0] * n` avoids reversing at the end.

## 🔹 Alternative Data Structures

* Find the split point between negatives and non-negatives (binary search), then merge the two sorted runs of squares outward from it — same O(n).
* `sorted(x * x for x in nums)` — shortest, O(n log n).

## 🔹 Complexity Analysis

* **Time Complexity:** O(n)
* **Space Complexity:** O(n) for the output, O(1) extra

## 🔹 Code Snippet (Brute Force)

```python
from typing import List


class Solution:
    def sortedSquares(self, nums: List[int]) -> List[int]:
        return sorted(x * x for x in nums)
```

## 🔹 Code Snippet (Optimized)

```python
from typing import List


class Solution:
    def sortedSquares(self, nums: List[int]) -> List[int]:
        result = [0] * len(nums)
        lo, hi = 0, len(nums) - 1
        for pos in range(len(nums) - 1, -1, -1):
            left, right = nums[lo] * nums[lo], nums[hi] * nums[hi]
            if left > right:
                result[pos] = left
                lo += 1
            else:
                result[pos] = right
                hi -= 1
        return result
```
