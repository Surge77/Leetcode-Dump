# 🔹 Problem Name: 1448. Count Good Nodes in Binary Tree (Tree DFS, Medium)

**🔗 Link:** [LeetCode 1448](https://leetcode.com/problems/count-good-nodes-in-binary-tree/)
**🟢 Status:** 🔄 Need Review

## 🔹 Problem Statement

A node X is "good" when no node on the path from the root down to X has a larger value than X. Return how many nodes in the tree are good; the root always counts.

* **Example:** `root = [3,1,4,3,null,1,5]` → `4`
* **Constraints:** `1 ≤ nodes ≤ 10^5`, `-10^4 ≤ Node.val ≤ 10^4`

## 🔹 Quick Breakdown

* **Difficulty Level:** Medium
* **Main Approach:** **Carry the path maximum down.** A node is good when no node on its root path is greater than it, i.e. `node.val ≥ max(values above it)`. Push each child with the maximum of the path so far (including its parent); the check is then O(1) per node.
* **Core Concept:** top-down DFS state — pass an accumulator from parent to child instead of looking back up
* **When to Use This Pattern?** A node's property depends on its ancestors — path max/min, bounds (validate BST), path sums, max ancestor difference.
* **Mistakes to Avoid:**
  * Using `>` instead of `≥`: equal values do not disqualify a node (the root is always good).
  * Recursion on a 10⁵-node path: far beyond Python's default limit of 1000 — use an explicit stack.
  * Resetting the maximum per subtree instead of carrying it from the root.

## 🔹 Optimization Path

* **Brute Force:** for each node, climb parent pointers to the root looking for a bigger value — O(n·h), O(n²) on a path.
* **Optimized Solution:** one DFS carrying the path maximum — O(n).
* **Further Improvements Possible?** No; every node must be checked.

## 🔹 Solution Breakdown

* **Optimal Approach:** stack of `(node, path_max)` starting with `(root, root.val)`; count the node if `node.val ≥ path_max`; push children with `max(path_max, node.val)`.
* **Why This Works?** By induction `path_max` is the maximum over all strict ancestors (plus the root's own value for the root, which keeps it good); the stack only changes traversal order, and each node's state depends only on its own path.
* **Edge Cases Considered:**
  * Single node → 1.
  * All values equal → every node is good.
  * Strictly decreasing path → only the root is good.

## 🔹 Tricks & Patterns Used

* **State in the stack entry:** `(node, path_max)` makes iterative DFS behave like recursion with a parameter.

## 🔹 Alternative Data Structures

* BFS with the same `(node, path_max)` pairs — order does not matter, same O(n).
* Recursive DFS with a parameter — clean but needs `sys.setrecursionlimit` for deep trees.

## 🔹 Complexity Analysis

* **Time Complexity:** O(n)
* **Space Complexity:** O(h) for the stack, O(n) on a skewed tree

## 🔹 Code Snippet (Brute Force)

```python
class Solution:
    def goodNodes(self, root: TreeNode) -> int:
        parent, stack = {root: None}, [root]
        while stack:
            node = stack.pop()
            for child in (node.left, node.right):
                if child:
                    parent[child] = node
                    stack.append(child)
        good = 0
        for node in parent:
            ancestor = parent[node]
            while ancestor and ancestor.val <= node.val:
                ancestor = parent[ancestor]
            good += ancestor is None  # climbed past the root without meeting a bigger value
        return good
```

## 🔹 Code Snippet (Optimized)

```python
class Solution:
    def goodNodes(self, root: TreeNode) -> int:
        good, stack = 0, [(root, root.val)]
        while stack:
            node, path_max = stack.pop()
            if node.val >= path_max:
                good += 1
            path_max = max(path_max, node.val)
            for child in (node.left, node.right):
                if child:
                    stack.append((child, path_max))
        return good
```
