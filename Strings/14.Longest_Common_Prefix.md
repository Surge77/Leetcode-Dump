# 14. Longest Common Prefix

**🔗 Link:** [LeetCode 14](https://leetcode.com/problems/longest-common-prefix/)
**🟢 Status:** 🔄 Need Review


## 🔹 Problem Statement

Given a list of strings, return the longest string that is a prefix of every one of them. If they share no prefix at all, return the empty string.

* **Example:** `strs = ["flower","flow","flight"]` → `"fl"`
* **Constraints:** `1 ≤ strs.length ≤ 200`, `0 ≤ strs[i].length ≤ 200`, lowercase English letters only

## 🔹 Quick Breakdown

* **Difficulty Level:** Easy
* **Main Approach:** **Vertical scan.** Walk the columns of the first string; at column `i` check every string. Stop at the first string that is too short or has a different character there, and return `first[:i]`.
* **Core Concept:** the answer is a prefix of **every** string, so it is a prefix of `strs[0]` — only its length is unknown, and the first bad column fixes it
* **When to Use This Pattern?** Agreement across many sequences position by position — common prefix, column-wise checks (944, 955), "how far do all of these match".
* **Mistakes to Avoid:**
  * Forgetting the length check: a shorter string ends the prefix even if every compared character matched (`["ab", "a"]` → `"a"`).
  * Empty strings in the list (`0 ≤ strs[i].length`) — the answer is `""`.

## 🔹 Optimization Path

* **Brute Force:** try every prefix of `strs[0]` from longest to shortest and test `startswith` on all strings — O(m² · k) for `k` strings with `len(strs[0]) = m`.
* **Optimized Solution:** vertical scan — O(k · (p + 1)) where `p` is the answer length, at most O(S) for `S` total characters.
* **Further Improvements Possible?** Not asymptotically: in the worst case (all strings equal) every character must be read. A trie (208) pays off only when many queries hit the same list.

## 🔹 Solution Breakdown

* **Optimal Approach:** `for i, ch in enumerate(first): for word in strs: if i == len(word) or word[i] != ch: return first[:i]`; if the loop finishes, `first` itself is common.
* **Why This Works?** Columns are checked in increasing order and column `i` is only reached when every string matched columns `0..i−1`, so the first failing column is exactly the prefix length.
* **Edge Cases Considered:**
  * A single string → that string.
  * `strs[0] == ""` → the loop never runs, returns `""`.
  * One string is a prefix of the others → stops at its length.

## 🔹 Tricks & Patterns Used

* **Lexicographic min/max:** the common prefix of all strings equals the common prefix of `min(strs)` and `max(strs)` — every other string sorts between them, so it shares whatever they share.
* **Early exit:** stop at the first mismatching column; no need to finish the scan.

## 🔹 Alternative Data Structures

* Sort, then compare only the first and last strings — O(S log k) for the sort.
* Trie of all strings, walk down while the node has exactly one child and is not the end of a word.

## 🔹 Complexity Analysis

* **Time Complexity:** O(S) worst case, `S = sum of lengths ≤ 200 · 200`
* **Space Complexity:** O(1) besides the returned slice

## 🔹 Code Snippet (Brute Force)

```python
from typing import List


class Solution:
    def longestCommonPrefix(self, strs: List[str]) -> str:
        first = strs[0]
        for length in range(len(first), -1, -1):
            if all(word.startswith(first[:length]) for word in strs):
                return first[:length]
        return ""
```

## 🔹 Code Snippet (Optimized)

```python
from typing import List


class Solution:
    def longestCommonPrefix(self, strs: List[str]) -> str:
        first = strs[0]
        for i, ch in enumerate(first):
            for word in strs:
                if i == len(word) or word[i] != ch:
                    return first[:i]
        return first
```
