# 🔹 Problem Name: 25. Reverse Nodes in k-Group (In-place Linked List Reversal, Hard)

**🔗 Link:** [LeetCode 25](https://leetcode.com/problems/reverse-nodes-in-k-group/)
**🟢 Status:** 🔄 Need Review

## 🔹 Quick Breakdown

* **Difficulty Level:** Hard
* **Main Approach:** **Reverse one k-block at a time, then stitch.** Keep `group_prev`, the node just before the current block (a dummy at first). Walk `k` steps to find the block's last node `kth`; if the list ends first, the leftover tail stays as is. Reverse the block with the usual three-pointer loop, but start `prev` at `kth.next` so the reversed block already points to what follows. Then `group_prev.next = kth` and the block's old first node becomes the next `group_prev`.
* **Core Concept:** reverse a bounded segment in place and reconnect both of its ends
* **When to Use This Pattern?** "Reverse / reorder the list in chunks", "swap pairs", "reverse between positions" — any in-place relinking of a sub-range.
* **Mistakes to Avoid:**
  * Reversing the last, shorter group — it must stay in order. Check that `k` nodes exist **before** touching any pointer.
  * Losing the block's old first node: it becomes the block's tail and the next `group_prev`, so save it before relinking.
  * Changing node values instead of nodes — the problem forbids it.

## 🔹 Optimization Path

* **Brute Force:** copy the node references into an array, reverse every full `k`-slice of the array, relink — O(n) time, O(n) extra space.
* **Optimized Solution:** in-place block reversal with a dummy head — O(n) time, O(1) extra space (the follow-up).
* **Further Improvements Possible?** No; each node is visited a constant number of times (once to count, once to reverse).

## 🔹 Solution Breakdown

* **Optimal Approach:** `dummy → head`; loop: find `kth` (return if `None`); `group_next = kth.next`; reverse `group_prev.next … kth` with `prev = group_next`; `first = group_prev.next`; `group_prev.next = kth`; `group_prev = first`.
* **Why This Works?** Initialising `prev` with `group_next` means the first node of the block, once reversed, points straight to the rest of the list; the only other link that changes is `group_prev.next`, which must now point to the old last node `kth`.
* **Edge Cases Considered:**
  * `k = 1` → list unchanged.
  * `k = n` → the whole list reversed.
  * `n % k ≠ 0` → the leftover tail untouched.

## 🔹 Tricks & Patterns Used

* **Dummy head:** the first block's new head needs no special case.
* **Seed `prev` with the successor:** the reversed block is already connected to the remainder.

## 🔹 Alternative Data Structures

* A stack of `k` nodes per block — easy to reason about, but O(k) extra space.
* Recursion (reverse the first block, recurse on the rest) — O(n / k) stack depth, fine here but not O(1) space.

## 🔹 Complexity Analysis

* **Time Complexity:** O(n)
* **Space Complexity:** O(1)

## 🔹 Code Snippet (Brute Force)

```python
from typing import Optional


class Solution:
    def reverseKGroup(self, head: Optional[ListNode], k: int) -> Optional[ListNode]:
        nodes = []
        while head:
            nodes.append(head)
            head = head.next
        full = len(nodes) - len(nodes) % k  # the short tail keeps its order
        for start in range(0, full, k):
            nodes[start:start + k] = nodes[start:start + k][::-1]
        for a, b in zip(nodes, nodes[1:]):
            a.next = b
        nodes[-1].next = None
        return nodes[0]
```

## 🔹 Code Snippet (Optimized)

```python
from typing import Optional


class Solution:
    def reverseKGroup(self, head: Optional[ListNode], k: int) -> Optional[ListNode]:
        dummy = ListNode(0, head)
        group_prev = dummy
        while True:
            kth = group_prev
            for _ in range(k):
                kth = kth.next
                if kth is None:  # fewer than k nodes left: they stay in order
                    return dummy.next
            group_next = kth.next

            prev, curr = group_next, group_prev.next  # reversed block lands on what follows
            while curr is not group_next:
                nxt = curr.next
                curr.next = prev
                prev = curr
                curr = nxt

            first = group_prev.next  # now the block's tail
            group_prev.next = kth
            group_prev = first
```
