# 437. Path Sum III

**🔗 Link:** [LeetCode 437](https://leetcode.com/problems/path-sum-iii/)
**🟢 Status:** 🔄 Need Review


## 🔹 Problem Statement

Given a binary tree and an integer `targetSum`, count the downward paths (parent to child steps only) whose node values add up to `targetSum`. A path may start and end at any node; it does not have to touch the root or a leaf.

* **Example:** `root = [10,5,-3,3,2,null,11,3,-2,null,1], targetSum = 8` → `3`
* **Constraints:** `0 ≤ nodes ≤ 1000`, `-10^9 ≤ Node.val ≤ 10^9`, `-1000 ≤ targetSum ≤ 1000`

## 🔹 Quick Breakdown

* **Difficulty Level:** Medium
* **Main Approach:** **Prefix sums on a root-to-node path.** Let `cur` be the sum from the root down to a node. A downward path ending here sums to `targetSum` exactly when some ancestor (or the empty prefix) has prefix `cur − targetSum`. Keep a hash map of prefix-sum counts for the current root path, add `seen[cur − targetSum]` to the answer, and remove the node's prefix on the way back.
* **Core Concept:** "subarray sum equals K" applied to every root-to-node path
* **When to Use This Pattern?** Count paths or segments with a given sum when values can be negative, so a sliding window or pruning does not work.
* **Mistakes to Avoid:**
  * Forgetting the empty prefix `{0: 1}`: paths that start at the root would be missed.
  * Not undoing the count when leaving a node — prefixes of other branches would leak in.
  * Requiring the path to start at the root or end at a leaf; it can start and end anywhere as long as it goes downward.
  * Recursing on a 1000-deep chain: Python's default limit is 1000, so this uses an explicit stack.
  * Using 32-bit-style thinking: sums reach `10⁹ · 1000`, Python ints are fine.

## 🔹 Optimization Path

* **Brute Force:** treat every node as a start and DFS down from it counting paths — O(n²) on a skewed tree.
* **Optimized Solution:** one DFS with a prefix-sum counter — O(n).
* **Further Improvements Possible?** No; every node is visited once.

## 🔹 Solution Breakdown

* **Optimal Approach:** `seen = {0: 1}`. Entering a node: `cur = parent_prefix + val`; `count += seen.get(cur − targetSum, 0)`; `seen[cur] += 1`; visit children. Leaving: `seen[cur] −= 1`.
* **Why This Works?** The path from ancestor `a` (exclusive) to node `v` sums to `prefix(v) − prefix(a)`. Counting ancestors with `prefix(a) = prefix(v) − targetSum` counts all valid starts for end `v`. The map only holds prefixes of the current root path, so only real ancestors are counted.
* **Edge Cases Considered:**
  * Empty tree → 0.
  * Negative values and targets (`Node.val` is in `−10⁹ … 10⁹`, `targetSum` in `−1000 … 1000`), zero-sum paths of several nodes.
  * A single node equal to the target counts once.

## 🔹 Tricks & Patterns Used

* **Counter with undo:** increment on entry, decrement on exit, so the map always describes exactly the current root path.
* **Enter/exit markers on a stack:** replaces recursion for deep trees.

## 🔹 Alternative Data Structures

* Recursive version of the same idea — about eight lines, needs `sys.setrecursionlimit` for skewed trees.
* Per-node list of ancestor sums (O(n · h)) — simpler but slower than the hash map.

## 🔹 Complexity Analysis

* **Time Complexity:** O(n)
* **Space Complexity:** O(h) for the map and the stack, up to O(n) on a skewed tree

## 🔹 Code Snippet (Brute Force)

```python
from typing import Optional


class Solution:
    def pathSum(self, root: Optional[TreeNode], targetSum: int) -> int:
        total = 0
        starts = [root] if root else []
        while starts:
            start = starts.pop()
            for child in (start.left, start.right):
                if child:
                    starts.append(child)
            walk = [(start, 0)]
            while walk:
                node, above = walk.pop()
                running = above + node.val
                if running == targetSum:
                    total += 1
                for child in (node.left, node.right):
                    if child:
                        walk.append((child, running))
        return total
```

## 🔹 Code Snippet (Optimized)

```python
from typing import Optional


class Solution:
    def pathSum(self, root: Optional[TreeNode], targetSum: int) -> int:
        count = 0
        seen = {0: 1}  # the empty prefix lets paths that begin at the root match
        stack = [(root, 0, False)] if root else []
        while stack:
            node, parent_prefix, leaving = stack.pop()
            prefix = parent_prefix + node.val
            if leaving:
                seen[prefix] -= 1
                continue
            count += seen.get(prefix - targetSum, 0)
            seen[prefix] = seen.get(prefix, 0) + 1
            stack.append((node, parent_prefix, True))
            for child in (node.right, node.left):
                if child:
                    stack.append((child, prefix, False))
        return count
```
