# 🔹 Problem Name: 1679. Max Number of K-Sum Pairs (Hash Map, Medium)

**🔗 Link:** [LeetCode 1679](https://leetcode.com/problems/max-number-of-k-sum-pairs/)
**🟢 Status:** 🔄 Need Review

## 🔹 Quick Breakdown

* **Difficulty Level:** Medium
* **Main Approach:** **One pass with a counter of unmatched values.** For each `x`, if an unmatched `k − x` is waiting, consume it and count one operation; otherwise remember `x` as unmatched.
* **Core Concept:** greedy pairing — any number can only pair with the single value `k − x`, so matching it whenever possible never hurts
* **When to Use This Pattern?** Maximum number of disjoint pairs with a fixed sum (or difference) — two-sum counting, matching complements.
* **Mistakes to Avoid:**
  * Pairing an element with itself when `x = k / 2`: the counter is updated only after the lookup, so a lone `3` is not matched with itself for `k = 6`.
  * Counting each pair twice by iterating over the counter keys without halving.
  * Sorting and removing from the middle of a list — O(n²).

## 🔹 Optimization Path

* **Brute Force:** for each element, scan the rest for an unused partner with sum `k` and mark both as used — O(n²).
* **Optimized Solution:** hash map in one pass — O(n). (Sort + two pointers is the O(n log n) alternative.)
* **Further Improvements Possible?** No; every element must be read.

## 🔹 Solution Breakdown

* **Optimal Approach:** `waiting = {}`. For `x` in `nums`: if `waiting.get(k − x, 0) > 0`: decrement it and `pairs += 1`; else `waiting[x] += 1`.
* **Why This Works?** Values `a` and `k − a` form a complete bipartite matching between their copies, so any maximal matching is a maximum one: `min(count(a), count(k − a))` pairs (and `count(k / 2) // 2` when `a = k − a`). The single pass builds such a maximal matching because an element only stays unmatched when no partner is currently waiting.
* **Edge Cases Considered:**
  * `k` even with the half value appearing an odd number of times — one copy stays unpaired.
  * No pair at all → 0.
  * Values larger than `k` simply never find a partner (all values are positive).

## 🔹 Tricks & Patterns Used

* **Look up before inserting:** keeps an element from pairing with itself.
* **Counter of "waiting" values:** the state of the greedy matching is just how many of each value are still free.

## 🔹 Alternative Data Structures

* **Sort + two pointers:** `lo`, `hi` towards each other; sum `< k` → `lo += 1`, `> k` → `hi −= 1`, equal → count and move both. O(n log n), O(1) extra space.
* `Counter` of the whole array, then `min(c[a], c[k − a])` per value — two passes.

## 🔹 Code Snippet (Brute Force)

```python
from typing import List


class Solution:
    def maxOperations(self, nums: List[int], k: int) -> int:
        used = [False] * len(nums)
        pairs = 0
        for i in range(len(nums)):
            if used[i]:
                continue
            for j in range(i + 1, len(nums)):
                if not used[j] and nums[i] + nums[j] == k:
                    used[i] = used[j] = True
                    pairs += 1
                    break
        return pairs
```

## 🔹 Code Snippet (Optimized)

```python
from typing import List


class Solution:
    def maxOperations(self, nums: List[int], k: int) -> int:
        waiting = {}
        pairs = 0
        for x in nums:
            if waiting.get(k - x, 0) > 0:
                waiting[k - x] -= 1
                pairs += 1
            else:
                waiting[x] = waiting.get(x, 0) + 1
        return pairs
```
