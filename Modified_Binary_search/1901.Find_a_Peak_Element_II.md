# 🔹 Problem Name: 1901. Find a Peak Element II (Binary Search on Rows, Medium)

**🔗 Link:** [LeetCode 1901](https://leetcode.com/problems/find-a-peak-element-ii/)
**🟢 Status:** 🔄 Need Review

## 🔹 Quick Breakdown

* **Difficulty Level:** Medium
* **Main Approach:** **Binary search over rows.** Take the middle row and its maximum, at column `j`. It already beats its left/right neighbours (it is the row max, and adjacent cells are never equal). If it also beats the cells above and below, it is a peak. Otherwise move toward the larger vertical neighbour — that half must contain a peak.
* **Core Concept:** 1D peak finding (162) lifted to 2D: reduce each row to its max, then binary search on the "slope" between rows
* **When to Use This Pattern?** "Find **any** local maximum" in O(less than the whole input) — a climb toward a larger neighbour cannot go on forever, so a half of the search space must hold a peak.
* **Mistakes to Avoid:**
  * Picking any cell in the middle row (not the row max) — it may lose to a horizontal neighbour, and the "climb" argument breaks.
  * Running a greedy hill climb from a corner: it is correct but can walk O(m·n) cells (a snake path).
  * Forgetting the border is `-1`: a cell on the edge only needs to beat its existing neighbours.

## 🔹 Optimization Path

* **Brute Force:** check every cell against its four neighbours — O(m·n).
* **Optimized Solution:** binary search on rows, O(n) per row to find the max — O(n log m).
* **Further Improvements Possible?** Search on columns instead (O(m log n)) and pick whichever dimension is smaller to binary search on.

## 🔹 Solution Breakdown

* **Optimal Approach:** `lo, hi = 0, m − 1`; `mid` row, `j = argmax(mat[mid])`; `up`/`down` = neighbours (or `-1` off-grid). Peak → return `[mid, j]`; `up > mat[mid][j]` → `hi = mid − 1`; else `lo = mid + 1`.
* **Why This Works?** Invariant: the row just outside each boundary of `[lo, hi]` (if any) has its max smaller than some cell inside. Say `up = mat[mid−1][j] > mat[mid][j]`. Then the global max of rows `lo..mid−1` is `≥ up > mat[mid][j] = max(row mid)`, so it beats everything in row `mid`, and (by the invariant) everything in row `lo − 1`, and everything inside its block. That block maximum is therefore a peak, so the upper half holds one; symmetric for going down.
* **Edge Cases Considered:**
  * One row → its max is a peak.
  * One column → classic 1D peak finding.

## 🔹 Tricks & Patterns Used

* **Row max collapses a row to one number** whose horizontal comparisons are already won.
* **`-1` sentinel** for missing neighbours (all values are `≥ 1`).

## 🔹 Alternative Data Structures

* Divide-and-conquer on the middle row **and** column ("window" algorithm) — O(m + n), but much fiddlier to get right.

## 🔹 Complexity Analysis

* **Time Complexity:** O(n log m)
* **Space Complexity:** O(1)

## 🔹 Code Snippet (Brute Force)

```python
from typing import List


class Solution:
    def findPeakGrid(self, mat: List[List[int]]) -> List[int]:
        rows, cols = len(mat), len(mat[0])
        for i in range(rows):
            for j in range(cols):
                neighbours = [mat[r][c] for r, c in ((i - 1, j), (i + 1, j), (i, j - 1), (i, j + 1))
                              if 0 <= r < rows and 0 <= c < cols]
                if all(mat[i][j] > v for v in neighbours):
                    return [i, j]
        return [-1, -1]
```

## 🔹 Code Snippet (Optimized)

```python
from typing import List


class Solution:
    def findPeakGrid(self, mat: List[List[int]]) -> List[int]:
        lo, hi = 0, len(mat) - 1
        while lo <= hi:
            mid = (lo + hi) // 2
            row = mat[mid]
            j = row.index(max(row))  # row max: already beats left and right
            up = mat[mid - 1][j] if mid > 0 else -1
            down = mat[mid + 1][j] if mid + 1 < len(mat) else -1
            if row[j] > up and row[j] > down:
                return [mid, j]
            if up > row[j]:
                hi = mid - 1
            else:
                lo = mid + 1
        return [-1, -1]
```
