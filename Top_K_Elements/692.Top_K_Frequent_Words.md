# 692. Top K Frequent Words

**🔗 Link:** [LeetCode 692](https://leetcode.com/problems/top-k-frequent-words/)
**🟢 Status:** 🔄 Need Review


## 🔹 Problem Statement

Given a list of words and an integer `k`, return the `k` most frequent words. Order the result by frequency from highest to lowest, and break frequency ties by alphabetical (lexicographical) order.

* **Example:** `words = ["i","love","leetcode","i","love","coding"], k = 2` → `["i","love"]`
* **Constraints:** `1 ≤ words.length ≤ 500`; `1 ≤ words[i].length ≤ 10`; lowercase English letters only; `k` is in `[1, number of unique words]`.

## 🔹 Quick Breakdown

* **Difficulty Level:** Medium
* **Main Approach:** **Count, then heapify with a composite key.** Count words with a `Counter`, build a min-heap of `(-count, word)` — highest count first, alphabetical among ties — and pop `k` times.
* **Core Concept:** encode the whole ordering rule (frequency desc, then lexicographic asc) into the heap key
* **When to Use This Pattern?** "Top K by some score with a deterministic tie-break" — frequent elements, closest points, K-th largest.
* **Mistakes to Avoid:**
  * Sorting by count only: ties must come out in lexicographical order.
  * Negating the word instead of the count — strings cannot be negated; negate the number and keep the word as the tie-break.
  * Returning the words in heap-array order instead of popping them.

## 🔹 Optimization Path

* **Brute Force:** `k` times scan the counted words for the best remaining one — O(k · d), `d` = distinct words.
* **Optimized Solution:** `heapify` the `d` entries in O(d), then `k` pops of O(log d) — O(d + k log d).
* **Further Improvements Possible?** A size-`k` heap with a reversed key gives O(d log k), better when `k` is tiny; with `d ≤ 500` the difference does not matter.

## 🔹 Solution Breakdown

* **Optimal Approach:** `heap = [(-c, w) for w, c in Counter(words).items()]`, `heapify`, then `[heappop(heap)[1] for _ in range(k)]`.
* **Why This Works?** Python compares tuples element by element: smaller `-count` (= larger count) first, and for equal counts the smaller word first — exactly the required order, so the `k` smallest tuples are the answer in the right sequence.
* **Edge Cases Considered:**
  * `k` equals the number of distinct words → every word is returned, fully sorted.
  * Many words with the same count → alphabetical order decides.

## 🔹 Tricks & Patterns Used

* **Negated count in the key:** turns Python's min-heap into "most frequent first" while the word stays naturally ascending.
* **`heapify` over repeated `heappush`:** builds the heap in O(d).

## 🔹 Alternative Data Structures

* Sort the `(−count, word)` list — O(d log d), the shortest code.
* Bucket by frequency (`count → sorted words`) and walk from the highest count — O(n + d log d).
* Trie with counts for lexicographic order — overkill for this size.

## 🔹 Complexity Analysis

* **Time Complexity:** O(n + d + k log d), `n` = number of words, `d` = distinct words
* **Space Complexity:** O(d)

## 🔹 Code Snippet (Brute Force)

```python
from collections import Counter
from typing import List


class Solution:
    def topKFrequent(self, words: List[str], k: int) -> List[str]:
        counts = Counter(words)
        result = []
        for _ in range(k):
            best = min(counts, key=lambda w: (-counts[w], w))
            result.append(best)
            del counts[best]
        return result
```

## 🔹 Code Snippet (Optimized)

```python
import heapq
from collections import Counter
from typing import List


class Solution:
    def topKFrequent(self, words: List[str], k: int) -> List[str]:
        heap = [(-count, word) for word, count in Counter(words).items()]
        heapq.heapify(heap)  # -count first, so ties fall back to the word in ascending order
        return [heapq.heappop(heap)[1] for _ in range(k)]
```
