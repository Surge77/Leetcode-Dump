# 🔹 Problem Name: 234. Palindrome Linked List (Fast and Slow Pointers, Easy)

**🔗 Link:** [LeetCode 234](https://leetcode.com/problems/palindrome-linked-list/)
**🟢 Status:** 🔄 Need Review

## 🔹 Quick Breakdown

* **Difficulty Level:** Easy
* **Main Approach:** **Middle + reverse the second half.** Fast/slow pointers find the middle, the second half is reversed in place, and the two halves are compared node by node. Reversing the second half again restores the input.
* **Core Concept:** a singly linked list can't be read backwards, so turn its back half around
* **When to Use This Pattern?** Anything that pairs the `i`-th node with the `i`-th from the end in O(1) space — 2130 Maximum Twin Sum, 143 Reorder List.
* **Mistakes to Avoid:**
  * Copying values into an array and calling it O(1) space.
  * Off-by-one on odd lengths: the middle node pairs with itself, so it may sit in either half.
  * Leaving the list reversed — callers usually expect their input untouched.

## 🔹 Optimization Path

* **Brute Force:** copy the values into a list, compare with its reverse — O(n) time, O(n) space.
* **Optimized Solution:** find the middle, reverse, compare, restore — O(n) time, O(1) space (the follow-up).
* **Further Improvements Possible?** No; every value must be read.

## 🔹 Solution Breakdown

* **Optimal Approach:** `while fast and fast.next` leaves `slow` at node `n // 2` (the middle for odd `n`, the first node of the second half for even `n`). Reverse from `slow`; walk `left = head` and `right = tail` while `right` exists.
* **Why This Works?** After reversal, `right` visits nodes `n−1, n−2, …, n//2` and `left` visits `0, 1, …` — exactly the mirror pairs. The node before `slow` still points to `slow` (now the tail of the reversed half), so the left walk never runs off the end before `right` does.
* **Edge Cases Considered:**
  * One node → palindrome.
  * Two nodes, equal or different.
  * Odd length — middle compared with itself.

## 🔹 Tricks & Patterns Used

* **Middle by speed ratio:** `fast` moves twice as fast, so it reaches the end when `slow` is halfway.
* **Reverse twice to restore:** reversal is its own inverse.

## 🔹 Alternative Data Structures

* Array of values / stack of the first half — easiest, O(n) memory.
* Recursion with a front pointer — elegant, but O(n) stack and overflows Python's recursion limit at `n = 10⁵`.

## 🔹 Complexity Analysis

* **Time Complexity:** O(n)
* **Space Complexity:** O(1)

## 🔹 Code Snippet (Brute Force)

```python
from typing import Optional


class Solution:
    def isPalindrome(self, head: Optional[ListNode]) -> bool:
        vals = []
        while head:
            vals.append(head.val)
            head = head.next
        return vals == vals[::-1]
```

## 🔹 Code Snippet (Optimized)

```python
from typing import Optional


class Solution:
    def isPalindrome(self, head: Optional[ListNode]) -> bool:
        def reverse(node: Optional[ListNode]) -> Optional[ListNode]:
            prev = None
            while node:
                node.next, prev, node = prev, node, node.next
            return prev

        slow = fast = head
        while fast and fast.next:
            slow, fast = slow.next, fast.next.next

        tail = reverse(slow)
        left, right, is_pal = head, tail, True
        while right:
            if left.val != right.val:
                is_pal = False
                break
            left, right = left.next, right.next
        reverse(tail)  # the node before `slow` still points to it, so this re-links the list
        return is_pal
```
