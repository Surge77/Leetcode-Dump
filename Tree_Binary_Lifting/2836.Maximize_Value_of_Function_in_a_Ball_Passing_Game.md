# 🔹 Problem Name: 2836. Maximize Value of Function in a Ball Passing Game (Binary Lifting, Hard)

**🔗 Link:** [LeetCode 2836](https://leetcode.com/problems/maximize-value-of-function-in-a-ball-passing-game/)
**🟢 Status:** 🔄 Need Review

## 🔹 Quick Breakdown

* **Difficulty Level:** Hard
* **Main Approach:** Every player passes to one fixed `receiver`, so the passes form a **functional graph**. `f(x) = x + (ids of the k receivers)`, with `k` up to 10¹⁰. Binary lifting: `up_j[v]` = holder after `2ʲ` passes from `v`, `gain_j[v]` = sum of the ids that received those passes. Decompose `k` into powers of two and jump from every start at once.
* **Core Concept:** binary lifting (doubling) on a functional graph — answer "after `k` steps" in O(log k)
* **When to Use This Pattern?** Each node has exactly one successor and you need the position / an aggregate after a huge number of steps: k-th ancestor (1483), "after k moves", cycle-heavy simulations.
* **Mistakes to Avoid:**
  * Simulating `k` passes — 10¹⁰ steps.
  * Storing all `log k` levels of both tables: 35 × 10⁵ Python ints each is hundreds of MB. Process the bits of `k` from low to high and keep only the current level.

## 🔹 Optimization Path

* **Brute Force:** simulate `k` passes for each start — O(n · k).
* **Optimized Solution:** O(n log k) time, O(n) memory.
* **Further Improvements Possible?** Cycle detection + prefix sums on each cycle gives O(n) but is much harder to get right in an exam.

## 🔹 Solution Breakdown

* **Optimal Approach:** keep `pos[x]` and `total[x]` (starting at `x`). For each bit of `k` (low to high): if set, `total[x] += gain[pos[x]]` and `pos[x] = up[pos[x]]`; then square the jump: `gain = gain + gain∘up`, `up = up∘up`.
* **Why This Works?** The walk of `k` passes from `x` is the same sequence whatever order you cut it into chunks; with chunks of sizes `2ʲ` for the set bits of `k`, the collected ids add up to exactly the `k` receivers. Doubling: `2ʲ⁺¹` passes = `2ʲ` passes, then `2ʲ` more from where you landed.
* **Edge Cases Considered:**
  * Self-passes (`receiver[i] == i`) — just a cycle of length 1.
  * `k = 1` → `max(x + receiver[x])`.

## 🔹 Tricks & Patterns Used

* **Level-by-level doubling** with list comprehensions: `up = [up[u] for u in up]`.
* **Low-to-high bit processing** so each level is used once and discarded.

## 🔹 Alternative Data Structures

* Full tables `up[j][v]` (needed when queries come one at a time with different `k`) — fine in C++/Java, heavy in Python.

* **Time Complexity:** O(n log k)
* **Space Complexity:** O(n)

## 🔹 Code Snippet (Brute Force)

```python
from typing import List


class Solution:
    def getMaxFunctionValue(self, receiver: List[int], k: int) -> int:
        best = 0
        for start in range(len(receiver)):
            total, holder = start, start
            for _ in range(k):
                holder = receiver[holder]
                total += holder
            best = max(best, total)
        return best
```

## 🔹 Code Snippet (Optimized)

```python
from typing import List


class Solution:
    def getMaxFunctionValue(self, receiver: List[int], k: int) -> int:
        n = len(receiver)
        up = receiver[:]      # holder after 2^j passes (j = current level)
        gain = receiver[:]    # ids that received those 2^j passes
        pos = list(range(n))
        total = list(range(n))  # f(x) counts the starting id x itself
        while k:
            if k & 1:
                total = [t + gain[p] for t, p in zip(total, pos)]
                pos = [up[p] for p in pos]
            k >>= 1
            if k:  # double: 2^(j+1) passes = 2^j passes, then 2^j more
                gain = [g + gain[u] for g, u in zip(gain, up)]
                up = [up[u] for u in up]
        return max(total)
```
