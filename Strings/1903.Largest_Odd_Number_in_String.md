# 🔹 Problem Name: 1903. Largest Odd Number in String (Greedy, Easy)

**🔗 Link:** [LeetCode 1903](https://leetcode.com/problems/largest-odd-number-in-string/)
**🟢 Status:** 🔄 Need Review

## 🔹 Problem Statement

`num` is a string of digits representing a huge integer. Return, as a string, the largest odd number that is a non-empty contiguous substring of `num`, or `""` if no substring is odd.

* **Example:** `num = "52"` → `"5"`
* **Constraints:** `1 ≤ num.length ≤ 10⁵`; digits only, with no leading zeros

## 🔹 Quick Breakdown

* **Difficulty Level:** Easy
* **Main Approach:** **Greedy from the right.** A number is odd iff its last digit is odd. The largest odd substring is the longest one, i.e. the prefix `num[:j + 1]` ending at the rightmost odd digit `j`. No odd digit → `""`.
* **Core Concept:** among numbers without leading zeros, more digits means larger — so maximise length
* **When to Use This Pattern?** "Largest number obtainable from a digit string" problems where a property (parity, divisibility by 5/2/10) depends only on the last digit.
* **Mistakes to Avoid:**
  * Converting `num` to `int`: up to 10⁵ digits — slow, and Python 3.11+ refuses `int()` on strings longer than 4300 digits by default.
  * Scanning from the left for the first odd digit — that gives the *shortest* odd prefix.

## 🔹 Optimization Path

* **Brute Force:** enumerate all O(n²) substrings, keep the largest odd value — O(n³) with the conversions.
* **Optimized Solution:** find the rightmost odd digit — O(n), and usually stops early.
* **Further Improvements Possible?** No; in the worst case (no odd digit) every digit is read.

## 🔹 Solution Breakdown

* **Optimal Approach:** for `j` from `n − 1` down to 0: if `int(num[j])` is odd, return `num[:j + 1]`. Return `""` after the loop.
* **Why This Works?** Any odd substring ends at some odd digit `j`. Among substrings ending at or before the rightmost odd digit, the prefix `num[:j + 1]` is the longest; it has no leading zero (the input has none), so it is also the numerically largest — any shorter number is smaller.
* **Edge Cases Considered:**
  * All digits even (`"4206"`) → `""`.
  * Last digit already odd → the whole string.
  * Single digit.

## 🔹 Tricks & Patterns Used

* **Parity lives in the last digit** — the decision reduces to choosing where the number ends.
* **Compare digit strings by length first**, never via `int()` on huge inputs.

## 🔹 Alternative Data Structures

* `num.rstrip("02468")` — strips trailing even digits in one call and returns exactly the answer.

## 🔹 Complexity Analysis

* **Time Complexity:** O(n), `n ≤ 10⁵`
* **Space Complexity:** O(n) for the returned slice (O(1) extra)

## 🔹 Code Snippet (Brute Force)

```python
class Solution:
    def largestOddNumber(self, num: str) -> str:
        best = -1
        for i in range(len(num)):
            for j in range(i, len(num)):
                if int(num[j]) % 2 == 1:
                    best = max(best, int(num[i:j + 1]))
        return "" if best == -1 else str(best)
```

## 🔹 Code Snippet (Optimized)

```python
class Solution:
    def largestOddNumber(self, num: str) -> str:
        for j in range(len(num) - 1, -1, -1):
            if int(num[j]) % 2 == 1:
                return num[:j + 1]
        return ""
```
