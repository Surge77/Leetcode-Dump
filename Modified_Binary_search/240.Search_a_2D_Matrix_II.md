# 🔹 Problem Name: 240. Search a 2D Matrix II (Staircase Search, Medium)

**🔗 Link:** [LeetCode 240](https://leetcode.com/problems/search-a-2d-matrix-ii/)
**🟢 Status:** 🔄 Need Review

## 🔹 Quick Breakdown

* **Difficulty Level:** Medium
* **Main Approach:** **Staircase walk from the top-right corner.** At `(r, c)`: equal → found; `matrix[r][c] > target` → the whole column below is even bigger, so `c −= 1`; smaller → the whole row to the left is even smaller, so `r += 1`. Each step discards a full row or column.
* **Core Concept:** start at a corner where one direction increases and the other decreases, so every comparison has exactly one useful move
* **When to Use This Pattern?** Matrices sorted along rows and columns (but not globally): search, count of elements `≤ x` (378), count negatives (1351).
* **Mistakes to Avoid:**
  * Treating it like 74 and binary-searching the flattened matrix — rows are not chained here.
  * Starting at the top-left or bottom-right: both moves increase (or decrease), so a comparison doesn't tell you where to go.

## 🔹 Optimization Path

* **Brute Force:** check every cell — O(m·n).
* **Better:** binary search each row — O(m log n).
* **Optimized Solution:** staircase walk — O(m + n).
* **Further Improvements Possible?** Only for very unbalanced shapes: when `m ≪ n`, binary searching each short row (O(m log n)) beats O(m + n). For LeetCode's `m, n ≤ 300` the walk is the standard answer.

## 🔹 Solution Breakdown

* **Optimal Approach:** `r, c = 0, n − 1`; while `r < m and c ≥ 0`: compare and move as above; return `False` when you walk off the grid.
* **Why This Works?** Invariant: if `target` exists, it lies in rows `≥ r` and columns `≤ c`. `matrix[r][c] > target` → every `matrix[i][c]` with `i ≥ r` is ≥ it, so column `c` is out. `matrix[r][c] < target` → every `matrix[r][j]` with `j ≤ c` is ≤ it, so row `r` is out. At most `m + n` moves.
* **Edge Cases Considered:**
  * `1 × 1` matrix; single row or column.
  * `target` smaller than `matrix[0][0]` or larger than `matrix[m−1][n−1]` → walks off quickly.
  * Duplicates — fine, equality returns immediately.

## 🔹 Tricks & Patterns Used

* **Corner with opposite monotonicity:** top-right (or bottom-left) turns a 2D search into a 1D walk.
* **Eliminate a whole line per comparison** — the same idea as two pointers on a sorted pair.

## 🔹 Alternative Data Structures

* Per-row `bisect` — O(m log n), simpler to reason about when `n ≫ m`.

## 🔹 Complexity Analysis

* **Time Complexity:** O(m + n)
* **Space Complexity:** O(1)

## 🔹 Code Snippet (Brute Force)

```python
from typing import List


class Solution:
    def searchMatrix(self, matrix: List[List[int]], target: int) -> bool:
        return any(target == value for row in matrix for value in row)
```

## 🔹 Code Snippet (Optimized)

```python
from typing import List


class Solution:
    def searchMatrix(self, matrix: List[List[int]], target: int) -> bool:
        rows, cols = len(matrix), len(matrix[0])
        r, c = 0, cols - 1  # top-right: left decreases, down increases
        while r < rows and c >= 0:
            value = matrix[r][c]
            if value == target:
                return True
            if value > target:
                c -= 1
            else:
                r += 1
        return False
```
