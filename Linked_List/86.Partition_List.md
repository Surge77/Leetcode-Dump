# 86. Partition List

**🔗 Link:** [LeetCode 86](https://leetcode.com/problems/partition-list/)
**🟢 Status:** 🔄 Need Review


## 🔹 Problem Statement

Given a linked list and a value `x`, rearrange it so every node with value less than `x` comes before every node with value greater than or equal to `x`. Within each of the two groups the original relative order must be preserved.

* **Example:** `head = [1,4,3,2,5,2], x = 3` → `[1,2,2,4,3,5]`
* **Constraints:** `0 ≤ n ≤ 200`; `-100 ≤ Node.val ≤ 100`; `-200 ≤ x ≤ 200`.

## 🔹 Quick Breakdown

* **Difficulty Level:** Medium
* **Main Approach:** **Two dummy-headed chains.** Walk the list once, appending each node to the `before` chain if `val < x`, else to the `after` chain. Then terminate `after` with `None` and hang it off the end of `before`.
* **Core Concept:** stable partition of a linked list by relinking nodes into two queues
* **When to Use This Pattern?** Split a list by a predicate while keeping relative order — odd/even positions, less/greater than a pivot, a partition step of quicksort on lists.
* **Mistakes to Avoid:**
  * Not setting `after_tail.next = None`: the last `after` node may still point into `before`, creating a cycle.
  * Swapping values like the array partition — that is not stable, and the problem asks to preserve order within each part.

## 🔹 Optimization Path

* **Brute Force:** copy node references into an array, build the stable order `[v for v < x] + [v for v ≥ x]`, relink — O(n) time but O(n) extra space.
* **Optimized Solution:** two chains, relinked in place — O(n) time, O(1) extra space.
* **Further Improvements Possible?** No; every node must be classified.

## 🔹 Solution Breakdown

* **Optimal Approach:** `before = before_tail = ListNode()`, same for `after`; for each node append to the right tail; `after_tail.next = None`; `before_tail.next = after.next`; return `before.next`.
* **Why This Works?** Each chain receives its nodes in the original visiting order, so both parts are stable; concatenating them puts every `< x` node first.
* **Edge Cases Considered:**
  * Empty list → `None`.
  * All nodes `< x` or all `≥ x` — one chain is empty and the dummy makes it a no-op.
  * Nodes equal to `x` go to the second part.

## 🔹 Tricks & Patterns Used

* **One dummy per output chain:** no empty-chain special cases.
* **Terminate before joining:** always cut the last chain's `next`.

## 🔹 Alternative Data Structures

* Two Python lists of values and a rebuilt list — simplest, but allocates new nodes.

* **Space Complexity:** O(1)

## 🔹 Code Snippet (Brute Force)

```python
from typing import Optional


class Solution:
    def partition(self, head: Optional[ListNode], x: int) -> Optional[ListNode]:
        nodes = []
        while head:
            nodes.append(head)
            head = head.next
        order = [n for n in nodes if n.val < x] + [n for n in nodes if n.val >= x]
        dummy = tail = ListNode()
        for node in order:
            tail.next = node
            tail = node
        tail.next = None
        return dummy.next
```

## 🔹 Code Snippet (Optimized)

```python
from typing import Optional


class Solution:
    def partition(self, head: Optional[ListNode], x: int) -> Optional[ListNode]:
        before = before_tail = ListNode()
        after = after_tail = ListNode()
        while head:
            if head.val < x:
                before_tail.next = head
                before_tail = head
            else:
                after_tail.next = head
                after_tail = head
            head = head.next
        after_tail.next = None  # it may still point at a `before` node: would form a cycle
        before_tail.next = after.next
        return before.next
```
