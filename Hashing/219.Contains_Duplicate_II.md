# 🔹 Problem Name: 219. Contains Duplicate II (Hash Map, Easy)

**🔗 Link:** [LeetCode 219](https://leetcode.com/problems/contains-duplicate-ii/)
**🟢 Status:** 🔄 Need Review

## 🔹 Problem Statement

Given an integer array and a number `k`, return whether there are two different indices `i` and `j` holding the same value whose distance `abs(i - j)` is at most `k`.

* **Example:** `nums = [1,2,3,1], k = 3` → `true`
* **Constraints:** `1 ≤ nums.length ≤ 10^5`; `-10^9 ≤ nums[i] ≤ 10^9`; `0 ≤ k ≤ 10^5`

## 🔹 Quick Breakdown

* **Difficulty Level:** Easy
* **Main Approach:** **Last-seen index map.** Scan left to right; for each value check whether it was seen before at index `j` with `i − j ≤ k`, then store `i` as its latest index.
* **Core Concept:** for a duplicate within distance `k`, only the **most recent** previous occurrence matters — it is the closest one
* **When to Use This Pattern?** "Two equal elements at most `k` apart", "nearest previous occurrence", duplicates inside a fixed-size window.
* **Mistakes to Avoid:**
  * Storing the **first** index of a value instead of updating to the latest — `[1, 0, 1, 1], k = 1` must return `True` (indices 2 and 3).
  * Off-by-one on the distance: the condition is `i − j ≤ k`, inclusive.
  * `k = 0` → always `False` (indices must be distinct).

## 🔹 Optimization Path

* **Brute Force:** compare each `i` with the next `k` positions — O(n · min(n, k)), up to ~5·10⁹ steps for `n = k = 10⁵`.
* **Optimized Solution:** last-index dictionary — O(n) time, O(n) space.
* **Further Improvements Possible?** Sliding-window set of the last `k` values — O(n) time but only O(min(n, k)) space.

## 🔹 Solution Breakdown

* **Optimal Approach:** `last = {}`; for `i, x`: if `x in last and i − last[x] ≤ k` → `True`; `last[x] = i`. Return `False` at the end.
* **Why This Works?** If a valid pair `(j, i)` exists, then at step `i` the stored index for `x` is the largest `j' < i` with `nums[j'] == x`, so `i − j' ≤ i − j ≤ k` and it is detected.
* **Edge Cases Considered:**
  * Single element → `False`.
  * Repeated value far apart then close (`[1, 2, 3, 1, 2, 3], k = 2` → `False`).

## 🔹 Tricks & Patterns Used

* **Keep the latest index:** overwriting the dict entry keeps the closest candidate.
* **Window set alternative:** add `nums[i]`, and once the window exceeds `k` elements remove `nums[i − k]`; a hit on insert is the answer.

## 🔹 Alternative Data Structures

* Sliding-window `set` of size ≤ `k` — less memory when `k ≪ n`.
* Sorting `(value, index)` pairs and checking neighbours — O(n log n).

## 🔹 Complexity Analysis

* **Time Complexity:** O(n)
* **Space Complexity:** O(n) (O(min(n, k)) with the window set)

## 🔹 Code Snippet (Brute Force)

```python
from typing import List


class Solution:
    def containsNearbyDuplicate(self, nums: List[int], k: int) -> bool:
        n = len(nums)
        for i in range(n):
            for j in range(i + 1, min(n, i + k + 1)):
                if nums[i] == nums[j]:
                    return True
        return False
```

## 🔹 Code Snippet (Optimized)

```python
from typing import List


class Solution:
    def containsNearbyDuplicate(self, nums: List[int], k: int) -> bool:
        last = {}
        for i, x in enumerate(nums):
            if x in last and i - last[x] <= k:
                return True
            last[x] = i  # the newest occurrence is the closest for every later i
        return False
```
