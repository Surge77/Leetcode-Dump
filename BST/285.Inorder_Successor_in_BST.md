## 🔹 Problem Statement

Given the root of a BST and a node `p` inside it, return the node holding the smallest value greater than `p.val` (its inorder successor), or `None` if `p` is the largest. *(premium — paraphrased from memory, not checked against the official page)*

* **Example:** `root = [2,1,3], p = 1` → `2`
* **Constraints:** `1 ≤ nodes ≤ 10^4`, `-10^5 ≤ Node.val ≤ 10^5`, all values unique

## 🔹 Quick Breakdown

* **Difficulty Level:** Medium
* **Main Approach:** **Walk down from the root once.** The successor of `p` is the smallest node with value `> p.val`. At each node: if `node.val > p.val` it is a candidate — remember it and go left (maybe a smaller candidate); otherwise go right.
* **Core Concept:** use the BST ordering to discard half the tree at every step
* **When to Use This Pattern?** "Next greater / previous smaller element in a BST" — successor, predecessor, ceiling, floor.
* **Mistakes to Avoid:**
  * Comparing `node.val >= p.val`: `p` itself is not its own successor.
  * Traversing the whole tree (O(n)) and ignoring the BST property.
  * Recursive inorder on a degenerate (linked-list-shaped) tree: depth up to 10⁴ risks the recursion limit. Walk iteratively.

## 🔹 Optimization Path

* **Brute Force:** build the inorder list, find `p`, return the next node — O(n) time and space.
* **Optimized Solution:** one root-to-leaf descent — O(h) time, O(1) space.
* **Further Improvements Possible?** If `p` has a parent pointer (problem 510), the successor is found without the root, still O(h).

## 🔹 Solution Breakdown

* **Optimal Approach:** `successor = None`; while `root`: if `root.val > p.val` → `successor = root; root = root.left`, else `root = root.right`. Return `successor`.
* **Why This Works?** The successor is the minimum over nodes strictly greater than `p.val`. Every time we step left from a node bigger than `p`, that node is the best candidate so far, and any better one must lie in its left subtree; nodes `≤ p.val` and their left subtrees can never qualify.
* **Edge Cases Considered:**
  * `p` is the maximum → `None`.
  * `p` has a right subtree → its leftmost node is found by the same loop.
  * `p` is a leaf → the lowest ancestor for which `p` is in the left subtree.

## 🔹 Tricks & Patterns Used

* **"Remember last left turn":** the candidate is the last node where the search went left.
* **Iterative descent** avoids the call stack entirely.

## 🔹 Alternative Data Structures

* Explicit stack inorder traversal that stops right after meeting `p` — O(h) space, O(n) worst-case time.
* Parent pointers plus the classic "rightmost-then-climb" rule.

## 🔹 Complexity Analysis

* **Time Complexity:** O(h) — O(log n) balanced, O(n) for a skewed tree
* **Space Complexity:** O(1)

## 🔹 Code Snippet (Brute Force)

```python
from typing import Optional


class Solution:
    def inorderSuccessor(self, root: 'TreeNode', p: 'TreeNode') -> 'Optional[TreeNode]':
        order, stack, node = [], [], root
        while stack or node:  # iterative inorder: avoids deep recursion on skewed trees
            while node:
                stack.append(node)
                node = node.left
            node = stack.pop()
            order.append(node)
            node = node.right
        index = order.index(p)
        return order[index + 1] if index + 1 < len(order) else None
```

## 🔹 Code Snippet (Optimized)

```python
from typing import Optional


class Solution:
    def inorderSuccessor(self, root: 'TreeNode', p: 'TreeNode') -> 'Optional[TreeNode]':
        successor = None
        while root:
            if root.val > p.val:
                successor = root  # a candidate; a closer one can only be on the left
                root = root.left
            else:
                root = root.right
        return successor
```
