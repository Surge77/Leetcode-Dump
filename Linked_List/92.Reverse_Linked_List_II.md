# 🔹 Problem Name: 92. Reverse Linked List II (In-place Linked List Reversal, Medium)

**🔗 Link:** [LeetCode 92](https://leetcode.com/problems/reverse-linked-list-ii/)
**🟢 Status:** 🔄 Need Review

## 🔹 Problem Statement

Given the head of a singly linked list and 1-based positions `left ≤ right`, reverse the nodes from position `left` through position `right` and return the head of the modified list. The follow-up asks for a single pass.

* **Example:** `head = [1,2,3,4,5], left = 2, right = 4` → `[1,4,3,2,5]`
* **Constraints:** `1 ≤ n ≤ 500`; `-500 ≤ Node.val ≤ 500`; `1 ≤ left ≤ right ≤ n`.

## 🔹 Quick Breakdown

* **Difficulty Level:** Medium
* **Main Approach:** **Head insertion in one pass.** Walk a pointer `prev` to the node just before position `left` (a dummy head covers `left = 1`). `curr = prev.next` is the first node of the segment and ends up as its tail. Repeat `right − left` times: unlink the node after `curr` and insert it right after `prev`. Each move pushes one more node to the front of the segment.
* **Core Concept:** reverse a sub-range by repeatedly moving the next node to the segment's front
* **When to Use This Pattern?** Reverse positions `left..right`, reverse in groups (25), any "reverse part of a list in one pass" follow-up.
* **Mistakes to Avoid:**
  * Treating `left = 1` separately — the dummy head handles it.
  * Using 0-based indices: positions are 1-based, so `prev` takes `left − 1` steps from the dummy.
  * Swapping values instead of relinking — accepted, but not the intended in-place node reversal.

## 🔹 Optimization Path

* **Brute Force:** copy the values to an array, reverse the slice `[left − 1 : right]`, write the values back — O(n) time, O(n) extra space, two passes.
* **Optimized Solution:** one pass, head insertion — O(n) time, O(1) extra space (the follow-up).
* **Further Improvements Possible?** No; reaching position `right` already takes `right` steps.

## 🔹 Solution Breakdown

* **Optimal Approach:** `prev` = node `left − 1`; `curr = prev.next`; `right − left` times: `moved = curr.next; curr.next = moved.next; moved.next = prev.next; prev.next = moved`.
* **Why This Works?** Invariant after `i` moves: `prev` is followed by the first `i + 1` segment nodes in reverse order, ending at `curr`, and `curr.next` is the first unprocessed node — so the list is never disconnected. After `right − left` moves the whole segment is reversed and `curr.next` is node `right + 1`.
* **Edge Cases Considered:**
  * `left == right` → zero moves, list unchanged.
  * `left = 1` and/or `right = n` → the dummy and `curr.next = None` handle the ends.
  * Single node `[5]`.

## 🔹 Tricks & Patterns Used

* **Dummy head** for a possibly-changing head.
* **Head insertion:** reversal without a separate reconnection step — the segment stays attached to both sides at every moment.

## 🔹 Alternative Data Structures

* Classic three-pointer reversal of the segment, then reconnect the two boundary nodes — same complexity, a little more bookkeeping.
* A stack of the segment's nodes — O(right − left) extra space.

## 🔹 Complexity Analysis

* **Time Complexity:** O(n)
* **Space Complexity:** O(1)

## 🔹 Code Snippet (Brute Force)

```python
from typing import Optional


class Solution:
    def reverseBetween(self, head: Optional[ListNode], left: int, right: int) -> Optional[ListNode]:
        values, node = [], head
        while node:
            values.append(node.val)
            node = node.next
        values[left - 1:right] = values[left - 1:right][::-1]  # positions are 1-based
        node = head
        for value in values:
            node.val = value
            node = node.next
        return head
```

## 🔹 Code Snippet (Optimized)

```python
from typing import Optional


class Solution:
    def reverseBetween(self, head: Optional[ListNode], left: int, right: int) -> Optional[ListNode]:
        dummy = ListNode(0, head)
        prev = dummy
        for _ in range(left - 1):
            prev = prev.next
        curr = prev.next  # stays put and ends up as the segment's tail
        for _ in range(right - left):
            moved = curr.next
            curr.next = moved.next
            moved.next = prev.next
            prev.next = moved
        return dummy.next
```
