# 🔹 Problem Name: 112. Path Sum (Tree DFS, Easy)

**🔗 Link:** [LeetCode 112](https://leetcode.com/problems/path-sum/)
**🟢 Status:** 🔄 Need Review

## 🔹 Quick Breakdown

* **Difficulty Level:** Easy
* **Main Approach:** **DFS carrying the remaining sum.** Store `(node, still needed)` on a stack; subtract each node's value on the way down. A root-to-leaf path works iff the remainder is exactly 0 **at a leaf**. Return `True` on the first hit.
* **Core Concept:** pass running state down the tree instead of storing whole paths
* **When to Use This Pattern?** Root-to-leaf questions — does some path hit a sum, list all such paths (113), sum the numbers the paths spell (129), best value along a path.
* **Mistakes to Avoid:**
  * Testing the sum when reaching a `None` child instead of at a leaf: a node with one child would count its empty side as a path end (`[1,2]` with target 1 must be `False`).
  * Pruning once the running sum passes the target — values can be negative.
  * Empty tree with `targetSum = 0` → `False`: there is no root-to-leaf path at all.

## 🔹 Optimization Path

* **Brute Force:** enumerate every root-to-leaf path as a list (copying the path at each step) and sum each one — O(n·h) time and memory.
* **Optimized Solution:** iterative DFS on `(node, remaining)` pairs — O(n) time, O(h) space, stops at the first valid leaf.
* **Further Improvements Possible?** No — when no path matches, every node must be visited.

## 🔹 Solution Breakdown

* **Optimal Approach:** `stack = [(root, targetSum)]`; pop `(node, rest)`, `rest -= node.val`; at a leaf with `rest == 0` return `True`; otherwise push the non-null children with `rest`.
* **Why This Works?** `rest` after subtracting is `targetSum` minus the sum of the path from the root to this node — exactly what the path still has to collect. One integer per stack entry replaces the copied path.
* **Edge Cases Considered:**
  * Empty tree → `False`.
  * A single node equal to the target → `True`.
  * Negative values and negative targets — nothing is pruned, so they need no special handling.

## 🔹 Pattern Recognition

* **Belongs To:** Tree DFS — root-to-leaf state passing

## 🔹 Tricks & Patterns Used

* **Subtract instead of add:** carry `targetSum − path sum`, so the leaf test is just `rest == 0`.
* **Leaf test:** `not node.left and not node.right` — the only place a path may end.

## 🔹 Alternative Data Structures

* Recursion `hasPathSum(child, targetSum - root.val)` — shortest code, but a 5000-node chain needs a raised recursion limit.
* BFS queue of `(node, rest)` — same O(n), O(w) memory instead of O(h).

## 🔹 Complexity Analysis

* **Time Complexity:** O(n)
* **Space Complexity:** O(h) — each pop pushes at most two children, so one waiting sibling per level

## 🔹 Code Snippet (Brute Force)

```python
from typing import List, Optional


class Solution:
    def hasPathSum(self, root: Optional[TreeNode], targetSum: int) -> bool:
        paths: List[List[int]] = []
        stack = [(root, [root.val])] if root else []
        while stack:
            node, path = stack.pop()
            if not node.left and not node.right:
                paths.append(path)
            for child in (node.left, node.right):
                if child:
                    stack.append((child, path + [child.val]))
        return any(sum(path) == targetSum for path in paths)
```

## 🔹 Code Snippet (Optimized)

```python
from typing import Optional


class Solution:
    def hasPathSum(self, root: Optional[TreeNode], targetSum: int) -> bool:
        stack = [(root, targetSum)] if root else []
        while stack:
            node, rest = stack.pop()
            rest -= node.val
            if not node.left and not node.right and rest == 0:  # only a leaf may end the path
                return True
            for child in (node.left, node.right):
                if child:
                    stack.append((child, rest))
        return False
```
