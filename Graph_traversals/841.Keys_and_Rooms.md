# 🔹 Problem Name: 841. Keys and Rooms (Graph DFS, Medium)

**🔗 Link:** [LeetCode 841](https://leetcode.com/problems/keys-and-rooms/)
**🟢 Status:** 🔄 Need Review

## 🔹 Problem Statement

There are `n` rooms numbered `0` to `n − 1`, all locked except room 0. Each room contains a set of keys, and each key opens one specific room. Starting in room 0 and collecting every key you find, return `true` if you can eventually visit all rooms, and `false` otherwise.

* **Example:** `rooms = [[1],[2],[3],[]]` → `true`
* **Constraints:** `2 ≤ n ≤ 1000`, `0 ≤ rooms[i].length ≤ 1000`, `1 ≤ sum(rooms[i].length) ≤ 3000`, keys within one room are distinct

## 🔹 Quick Breakdown

* **Difficulty Level:** Medium
* **Main Approach:** **Reachability from room 0.** Rooms are nodes and each key `rooms[i][j]` is a directed edge `i → rooms[i][j]`. DFS (or BFS) from room 0 and check that all `n` rooms were visited.
* **Core Concept:** "can I open everything" is "is every node reachable from the start"
* **When to Use This Pattern?** Connectivity / reachability on a directed graph given as adjacency lists.
* **Mistakes to Avoid:**
  * Not marking a room visited when it is **pushed**, which re-pushes the same room once for every key to it found along the way.
  * Counting keys instead of reachable rooms: having a key to a room is not the same as being able to reach the room holding it.

## 🔹 Optimization Path

* **Brute Force:** repeat full passes over all rooms, opening any room whose key you now hold, until a pass changes nothing — O(n · (n + K)) worst case (K = total keys).
* **Optimized Solution:** one DFS with a stack — O(n + K).
* **Further Improvements Possible?** No; every key may have to be read once.

## 🔹 Solution Breakdown

* **Optimal Approach:** `seen = {0}`, `stack = [0]`; pop a room, for each key not yet seen mark it and push it. Return `len(seen) == len(rooms)`.
* **Why This Works?** A room can be entered iff some already-opened room holds its key, i.e. it is reachable by a path of keys from room 0; the stack explores exactly that set.
* **Edge Cases Considered:**
  * Smallest input `n = 2`, `[[1], []]` → `True` (a single room cannot occur: `n ≥ 2`).
  * Room 0 has no keys → `False`.
  * The same key found in several rooms, and keys to room 0 itself — absorbed by `seen`.

## 🔹 Tricks & Patterns Used

* **Iterative DFS:** a chain of 1000 rooms would be 1000 recursive calls; a stack avoids any recursion-limit worry.
* **Mark on push:** each room enters the stack at most once.

## 🔹 Alternative Data Structures

* BFS with a `deque` — identical complexity.
* Union-find does not fit: edges are directed.

## 🔹 Complexity Analysis

* **Time Complexity:** O(n + K) where K = Σ len(rooms[i]) ≤ 3000
* **Space Complexity:** O(n)

## 🔹 Code Snippet (Brute Force)

```python
from typing import List


class Solution:
    def canVisitAllRooms(self, rooms: List[List[int]]) -> bool:
        opened = {0}
        changed = True
        while changed:  # rescan every room until no new key opens anything
            changed = False
            for room in list(opened):
                for key in rooms[room]:
                    if key not in opened:
                        opened.add(key)
                        changed = True
        return len(opened) == len(rooms)
```

## 🔹 Code Snippet (Optimized)

```python
from typing import List


class Solution:
    def canVisitAllRooms(self, rooms: List[List[int]]) -> bool:
        seen = {0}
        stack = [0]
        while stack:
            for key in rooms[stack.pop()]:
                if key not in seen:
                    seen.add(key)  # mark on push so a room is queued only once
                    stack.append(key)
        return len(seen) == len(rooms)
```
