# 933. Number of Recent Calls

**🔗 Link:** [LeetCode 933](https://leetcode.com/problems/number-of-recent-calls/)
**🟢 Status:** 🔄 Need Review


## 🔹 Problem Statement

Design a counter whose `ping(t)` records a new request at time `t` (in milliseconds) and returns how many requests, including this one, happened in the last 3000 ms, i.e. with times in `[t - 3000, t]`. Every call uses a strictly larger `t` than the one before.

* **Example:** `["RecentCounter","ping","ping","ping","ping"]` with args `[[],[1],[100],[3001],[3002]]` → `[null,1,2,3,3]`
* **Constraints:** `1 ≤ t ≤ 10^9`, `t` strictly increasing, at most `10^4` calls to `ping`

## 🔹 Quick Breakdown

* **Difficulty Level:** Easy
* **Main Approach:** **Sliding window over a queue.** Append each ping time; pop from the front while `front < t − 3000`; the queue length is the answer (pings in `[t − 3000, t]`).
* **Core Concept:** pings arrive in strictly increasing time, so expired ones are always at the front
* **When to Use This Pattern?** "Count events in the last `K` time units" with monotonically increasing timestamps (rate limiters, hit counters, moving averages).
* **Mistakes to Avoid:**
  * Off-by-one: the window is **inclusive** at both ends, `[t − 3000, t]`; drop only values `< t − 3000`.
  * Keeping all pings and re-counting: O(n) per call.

## 🔹 Optimization Path

* **Brute Force:** store every ping in a list and count those `≥ t − 3000` on each call — O(n) per call.
* **Optimized Solution:** `deque` with eager eviction — O(1) amortised per call.
* **Further Improvements Possible?** No; each ping is added and removed once.

## 🔹 Solution Breakdown

* **Optimal Approach:** `ping(t)`: `queue.append(t)`; `while queue[0] < t − 3000: queue.popleft()`; return `len(queue)`.
* **Why This Works?** Timestamps are strictly increasing, so the queue stays sorted; once the front is inside the window, everything behind it is too. The newest ping `t` is never evicted, so `queue[0]` always exists.
* **Edge Cases Considered:**
  * First call → `1`.
  * A ping exactly 3000 before `t` is still counted.

## 🔹 Tricks & Patterns Used

* **Evict on write:** do the cleanup inside `ping` instead of a separate timer; amortised O(1).

## 🔹 Alternative Data Structures

* Plain list + binary search (`bisect_left` on `t − 3000`) — O(log n) per call, no deletion needed, O(n) memory.

## 🔹 Complexity Analysis

* **Time Complexity:** O(1) amortised per `ping`
* **Space Complexity:** O(W) where `W ≤ 3001` is the number of pings in the window (distinct integer times)

## 🔹 Code Snippet (Brute Force)

```python
from typing import List


class RecentCounter:
    def __init__(self):
        self.pings: List[int] = []

    def ping(self, t: int) -> int:
        self.pings.append(t)
        return sum(1 for old in self.pings if old >= t - 3000)
```

## 🔹 Code Snippet (Optimized)

```python
from collections import deque


class RecentCounter:
    def __init__(self):
        self.window = deque()

    def ping(self, t: int) -> int:
        self.window.append(t)
        while self.window[0] < t - 3000:  # window is [t - 3000, t], both ends inclusive
            self.window.popleft()
        return len(self.window)
```
