# 🔹 Problem Name: 2095. Delete the Middle Node of a Linked List (Fast and Slow Pointers, Medium)

**🔗 Link:** [LeetCode 2095](https://leetcode.com/problems/delete-the-middle-node-of-a-linked-list/)
**🟢 Status:** 🔄 Need Review

## 🔹 Quick Breakdown

* **Difficulty Level:** Medium
* **Main Approach:** **Fast and slow pointers with `fast` one step ahead.** To delete node `n // 2` you need the node **before** it. Start `slow = head` and `fast = head.next.next`; when `fast` runs out, `slow` is at index `n // 2 − 1`, so `slow.next = slow.next.next`.
* **Core Concept:** offset the fast pointer's start so the slow pointer stops one node early
* **When to Use This Pattern?** Any deletion/split at the middle of a singly linked list, where you need the predecessor rather than the node itself.
* **Mistakes to Avoid:**
  * `n = 1`: the only node is the middle — return `None`, there is no predecessor.
  * Using 876's loop and then trying to delete `slow` — a singly linked node can't unlink itself.
  * Using a `prev` variable but forgetting `n = 2` (delete index 1, keep the head).

## 🔹 Optimization Path

* **Brute Force:** count the length, walk to index `n // 2 − 1`, unlink — O(n) time, two passes.
* **Optimized Solution:** one pass with offset fast/slow pointers — O(n) time, O(1) space.
* **Further Improvements Possible?** No; reaching the middle needs ~`n` pointer moves either way.

## 🔹 Solution Breakdown

* **Optimal Approach:** handle `n = 1`; then `slow, fast = head, head.next.next`; `while fast and fast.next` advance; unlink `slow.next`.
* **Why This Works?** Starting `fast` two nodes ahead is the same as running 876's loop on a list with the head's slot "pre-paid": after `k` iterations `slow` is at `k` and `fast` at `2k + 2`, and the loop stops at `k = n // 2 − 1`. Checked: `n = 2 → k = 0`, `n = 3 → 0`, `n = 4 → 1`, `n = 7 → 2`.
* **Edge Cases Considered:**
  * `n = 1` → `None`.
  * `n = 2` → delete the second node.
  * Even vs odd length — the middle is index `n // 2` in both (0-based).

## 🔹 Tricks & Patterns Used

* **Head start for `fast`:** shifts where `slow` stops by one node without a `prev` variable.
* **Dummy node alternative:** `slow = dummy, fast = head` gives the same predecessor and also covers `n = 1`.

## 🔹 Alternative Data Structures

* Array of nodes — index `n // 2 − 1` directly, O(n) memory.

* **Time Complexity:** O(n)
* **Space Complexity:** O(1)

## 🔹 Code Snippet (Brute Force)

```python
from typing import Optional


class Solution:
    def deleteMiddle(self, head: Optional[ListNode]) -> Optional[ListNode]:
        n, node = 0, head
        while node:
            n, node = n + 1, node.next
        if n == 1:
            return None
        before = head
        for _ in range(n // 2 - 1):
            before = before.next
        before.next = before.next.next
        return head
```

## 🔹 Code Snippet (Optimized)

```python
from typing import Optional


class Solution:
    def deleteMiddle(self, head: Optional[ListNode]) -> Optional[ListNode]:
        if not head.next:
            return None
        # fast starts two ahead so slow stops on the node *before* the middle
        slow, fast = head, head.next.next
        while fast and fast.next:
            slow, fast = slow.next, fast.next.next
        slow.next = slow.next.next
        return head
```
