# 🔹 Problem Name: 1312. Minimum Insertion Steps to Make a String Palindrome (Interval DP, Hard)

**🔗 Link:** [LeetCode 1312](https://leetcode.com/problems/minimum-insertion-steps-to-make-a-string-palindrome/)
**🟢 Status:** 🔄 Need Review

## 🔹 Problem Statement

You may insert any character at any position of string `s` in one step. Return the fewest insertions that turn `s` into a palindrome (a string that reads the same forwards and backwards).

* **Example:** `s = "zzazz"` → `0`
* **Constraints:** `1 ≤ s.length ≤ 500`, lowercase English letters

## 🔹 Quick Breakdown

* **Difficulty Level:** Hard
* **Main Approach:** **Interval DP (= `n − LPS`).** `f(i, j)` = insertions to make `s[i..j]` a palindrome. If `s[i] == s[j]`, both ends match: `f(i + 1, j − 1)`. Otherwise insert a mirror of one end: `1 + min(f(i + 1, j), f(i, j − 1))`. Equivalently, the characters you keep form the longest palindromic subsequence, and every other character needs one inserted partner: answer = `n − LPS(s)`.
* **Core Concept:** interval DP on `(i, j)`, filled by increasing length (or `i` descending)
* **When to Use This Pattern?** Palindrome cost problems on a substring where the two ends interact — LPS (516), min deletions, palindrome removal.
* **Mistakes to Avoid:**
  * Plain recursion without memo: up to 2ⁿ branches.
  * Filling `dp[i][j]` with `i` ascending — `dp[i + 1][...]` is not ready yet.

## 🔹 Optimization Path

* **Brute Force:** the recursion above without memo — exponential.
* **Optimized Solution:** bottom-up interval DP — O(n²) = 2.5·10⁵ for `n = 500`, with O(n) memory (two rows).
* **Further Improvements Possible?** Not asymptotically in general; O(n²) is the standard bound.

## 🔹 Solution Breakdown

* **Optimal Approach:** iterate `i` from `n − 1` down to 0 keeping `prev = dp[i + 1][*]` and building `cur = dp[i][*]` for `j > i`.
* **Why This Works?** In an optimal result, the outermost characters must match. If `s[i] == s[j]`, pairing them costs nothing and is never worse. Otherwise one of them gets a newly inserted partner on the other side, and the rest is the smaller interval.
* **Edge Cases Considered:**
  * Already a palindrome → 0.
  * All characters distinct → `n − 1`.

## 🔹 Pattern Recognition

* **Belongs To:** DP — interval / palindromic subsequence
* **Common Problems Using This:**
  * 516. Longest Palindromic Subsequence (in this repo)
  * 1143. Longest Common Subsequence (in this repo, `LPS(s) = LCS(s, reverse(s))`)
  * 583. Delete Operation for Two Strings

## 🔹 Tricks & Patterns Used

* **Insertions = deletions:** the minimum insertions equals the minimum deletions to reach a palindrome, both `n − LPS`.
* **Two-row interval DP:** `dp[i]` only reads `dp[i + 1]` and itself.

## 🔹 Alternative Data Structures

* `n − LCS(s, s[::-1])` with the standard 2-row LCS — same complexity.

## 🔹 Complexity Analysis

* **Time Complexity:** O(n²)
* **Space Complexity:** O(n)

## 🔹 Code Snippet (Brute Force)

```python
class Solution:
    def minInsertions(self, s: str) -> int:
        def cost(i: int, j: int) -> int:
            if i >= j:
                return 0
            if s[i] == s[j]:
                return cost(i + 1, j - 1)
            return 1 + min(cost(i + 1, j), cost(i, j - 1))

        return cost(0, len(s) - 1)
```

## 🔹 Code Snippet (Optimized)

```python
class Solution:
    def minInsertions(self, s: str) -> int:
        n = len(s)
        prev = [0] * n  # prev[j] = cost of s[i+1..j]
        for i in range(n - 1, -1, -1):
            cur = [0] * n
            for j in range(i + 1, n):
                if s[i] == s[j]:
                    cur[j] = prev[j - 1]
                else:
                    cur[j] = 1 + min(prev[j], cur[j - 1])
            prev = cur
        return prev[n - 1]
```
