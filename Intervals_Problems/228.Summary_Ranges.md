# 🔹 Problem Name: 228. Summary Ranges (Linear Scan, Easy)

**🔗 Link:** [LeetCode 228](https://leetcode.com/problems/summary-ranges/)
**🟢 Status:** 🔄 Need Review

## 🔹 Quick Breakdown

* **Difficulty Level:** Easy
* **Main Approach:** **Group consecutive runs in one pass.** `nums` is sorted and unique, so a run continues exactly while `nums[i] == nums[i − 1] + 1`. Remember where the current run started; when it breaks (or the array ends), emit `"start"` or `"start->end"`.
* **Core Concept:** sorted + unique means runs are contiguous blocks of the array — just find the block boundaries
* **When to Use This Pattern?** Compressing a sorted list into ranges: missing ranges (163), data stream as disjoint intervals (352), formatting page lists ("1-3, 5").
* **Mistakes to Avoid:**
  * Forgetting to flush the last run after the loop.
  * Printing `"a->a"` for a single number — it must be `"a"`.
  * Empty input → `[]`.

## 🔹 Optimization Path

* **Brute Force:** from each run start, re-check every element of the run against the start (`nums[j] == nums[i] + (j − i)`) — still fine for `n ≤ 20`, but rescans.
* **Optimized Solution:** single pass with a run-start pointer — O(n).
* **Further Improvements Possible?** No; every element must be read.

## 🔹 Solution Breakdown

* **Optimal Approach:** `start = nums[0]`; for `i` in `1..n`: if `i == n` or `nums[i] != nums[i − 1] + 1`, emit the range `start..nums[i − 1]` and set `start = nums[i]` (when `i < n`).
* **Why This Works?** With distinct sorted integers, a break `nums[i] > nums[i − 1] + 1` means the value `nums[i − 1] + 1` is missing, so the run truly ends; otherwise it continues. Each run is emitted once at its break.
* **Edge Cases Considered:**
  * `[]` → `[]`; one element → `["x"]`.
  * Values at the 32-bit limits (`-2³¹`, `2³¹ − 1`) — Python ints don't overflow (in Java/C++ use `long` for `nums[i − 1] + 1`).

## 🔹 Pattern Recognition

* **Belongs To:** Intervals — run-length grouping of a sorted array
* **Common Problems Using This:**
  * 128. Longest Consecutive Sequence (in this repo, unsorted version)
  * 163. Missing Ranges
  * 352. Data Stream as Disjoint Intervals
  * 56. Merge Intervals (in this repo)

## 🔹 Tricks & Patterns Used

* **Sentinel boundary:** treat `i == n` as a break so the final run is flushed inside the loop.
* **Two pointers:** `i` marks the run start, `j` advances while consecutive — the same scan written another way.

## 🔹 Alternative Data Structures

* `itertools.groupby(enumerate(nums), key=lambda p: p[1] - p[0])`: within a run, `value − index` is constant.

## 🔹 Complexity Analysis

* **Time Complexity:** O(n)
* **Space Complexity:** O(1) besides the output

## 🔹 Code Snippet (Brute Force)

```python
from typing import List


class Solution:
    def summaryRanges(self, nums: List[int]) -> List[str]:
        ranges = []
        i = 0
        while i < len(nums):
            end = i
            # re-verify the whole run against its start on every extension
            while end + 1 < len(nums) and all(nums[j] == nums[i] + (j - i) for j in range(i, end + 2)):
                end += 1
            ranges.append(str(nums[i]) if end == i else f"{nums[i]}->{nums[end]}")
            i = end + 1
        return ranges
```

## 🔹 Code Snippet (Optimized)

```python
from typing import List


class Solution:
    def summaryRanges(self, nums: List[int]) -> List[str]:
        ranges = []
        if not nums:
            return ranges
        start = nums[0]
        for i in range(1, len(nums) + 1):
            if i < len(nums) and nums[i] == nums[i - 1] + 1:
                continue
            end = nums[i - 1]
            ranges.append(str(start) if start == end else f"{start}->{end}")
            if i < len(nums):
                start = nums[i]
        return ranges
```
