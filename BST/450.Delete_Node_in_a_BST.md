# 🔹 Problem Name: 450. Delete Node in a BST (BST Deletion, Medium)

**🔗 Link:** [LeetCode 450](https://leetcode.com/problems/delete-node-in-a-bst/)
**🟢 Status:** 🔄 Need Review

## 🔹 Problem Statement

Given the root of a BST and a `key`, remove the node holding that key (if any) and return the root of the resulting valid BST. The root may change. More than one valid result can exist, and any is accepted.

* **Example:** `root = [5,3,6,2,4,null,7], key = 3` → `[5,4,6,2,null,null,7]`
* **Constraints:** `0 ≤ nodes ≤ 10^4`, `-10^5 ≤ Node.val, key ≤ 10^5`, unique values; follow-up: `O(height)` time

## 🔹 Quick Breakdown

* **Difficulty Level:** Medium
* **Main Approach:** **Search, then splice.** Walk down from the root (keeping the parent) to the node with `key`. If it has at most one child, link that child to the parent in its place. If it has two children, copy the value of its inorder successor (leftmost node of the right subtree) into it, then splice the successor out — the successor has no left child, so that is the easy case again.
* **Core Concept:** the three deletion cases of a BST — leaf, one child, two children (replace with successor)
* **When to Use This Pattern?** Any in-place BST edit: delete, trim a range (669), or remove nodes while keeping the order invariant.
* **Mistakes to Avoid:**
  * Forgetting the root itself can be the deleted node — return the new root, not the old one.
  * When the successor is the right child itself, its parent is the deleted node: attach `succ.right` to `node.right`, not to `parent.left`.
  * Recursive deletion on a 10⁴-node degenerate tree: depth 10⁴ blows Python's recursion limit.
  * Key not present — return the tree unchanged.

## 🔹 Optimization Path

* **Brute Force:** collect every value except `key`, rebuild a balanced BST from the sorted list — O(n) time and space (inorder is already sorted), but it ignores the height bound the follow-up asks for.
* **Optimized Solution:** iterative search + splice — O(h) time, O(1) space.
* **Further Improvements Possible?** O(h) is optimal for a plain BST; a self-balancing tree keeps `h = O(log n)`.

## 🔹 Solution Breakdown

* **Optimal Approach:** find `node` and `parent`. Two children → find `succ` (leftmost of `node.right`) and its parent, set `node.val = succ.val`, then splice `succ` (replace it by `succ.right`). Otherwise `child = node.left or node.right` replaces `node` under `parent` (or becomes the new root).
* **Why This Works?** The successor is the smallest value larger than `node.val`, so it is larger than everything in the left subtree and no larger than anything left in the right subtree — putting it at `node` keeps the BST property. Splicing a node with ≤ 1 child moves a whole subtree up one level, and every value in it already sat on the correct side of all its ancestors.
* **Edge Cases Considered:**
  * Empty tree (`n = 0`) → `None`.
  * `key` missing → unchanged tree.
  * Deleting the root with one child → that child is the new root.
  * Successor is `node.right` itself.

## 🔹 Tricks & Patterns Used

* **Copy successor value:** turns the hard two-children case into deleting a node with at most one child.
* **Parent pointer while descending:** lets an iterative solution relink without recursion.

## 🔹 Alternative Data Structures

* Recursive `root.left = deleteNode(root.left, key)` — the shortest code, fine when the tree is balanced.
* Predecessor (rightmost of the left subtree) works symmetrically.

## 🔹 Complexity Analysis

* **Time Complexity:** O(h) — one root-to-leaf walk for the node plus one for the successor; O(n) for a degenerate tree
* **Space Complexity:** O(1)

## 🔹 Code Snippet (Brute Force)

```python
from typing import List, Optional


class Solution:
    def deleteNode(self, root: Optional[TreeNode], key: int) -> Optional[TreeNode]:
        vals: List[int] = []
        stack, cur = [], root
        while stack or cur:
            while cur:
                stack.append(cur)
                cur = cur.left
            cur = stack.pop()
            if cur.val != key:
                vals.append(cur.val)  # inorder keeps vals sorted
            cur = cur.right

        def build(lo: int, hi: int) -> Optional[TreeNode]:
            if lo > hi:
                return None
            mid = (lo + hi) // 2
            return TreeNode(vals[mid], build(lo, mid - 1), build(mid + 1, hi))

        return build(0, len(vals) - 1)  # balanced, so recursion depth is only log n
```

## 🔹 Code Snippet (Optimized)

```python
from typing import Optional


class Solution:
    def deleteNode(self, root: Optional[TreeNode], key: int) -> Optional[TreeNode]:
        parent, node = None, root
        while node and node.val != key:
            parent, node = node, (node.left if key < node.val else node.right)
        if node is None:
            return root

        if node.left and node.right:
            succ_parent, succ = node, node.right
            while succ.left:
                succ_parent, succ = succ, succ.left
            node.val = succ.val
            # succ has no left child, so it is removed by lifting its right subtree
            if succ_parent is node:
                succ_parent.right = succ.right
            else:
                succ_parent.left = succ.right
            return root

        child = node.left or node.right
        if parent is None:
            return child
        if parent.left is node:
            parent.left = child
        else:
            parent.right = child
        return root
```
