# 336. Palindrome Pairs

**🔗 Link:** [LeetCode 336](https://leetcode.com/problems/palindrome-pairs/)
**🟢 Status:** 🔄 Need Review


## 🔹 Problem Statement

You get a list of distinct lowercase words (some may be empty). Return every ordered pair of different indices `(i, j)` for which `words[i] + words[j]` reads the same forwards and backwards. The problem asks for a solution linear in the total length of all words.

* **Example:** `words = ["abcd","dcba","lls","s","sssll"]` → `[[0,1],[1,0],[3,2],[2,4]]`
* **Constraints:** `1 ≤ words.length ≤ 5000`; `0 ≤ words[i].length ≤ 300`; lowercase letters; words are unique

## 🔹 Quick Breakdown

* **Difficulty Level:** Hard
* **Main Approach:** **Split every word and look up the reverse of one half.** `a + b` is a palindrome when, after cutting `a` into `pre + suf`, one part is a palindrome and the other is the reverse of `b`. For each word and each split point, if `pre` is a palindrome look for `reverse(suf)` as a word to put in **front**; if `suf` is a palindrome look for `reverse(pre)` as a word to put **behind**.
* **Core Concept:** a palindrome concatenation = a mirrored part + a self-palindromic middle
* **When to Use This Pattern?** Pair or complete strings so that the combination has a symmetric property — palindrome pairs, shortest palindrome, building palindromes from words.
* **Mistakes to Avoid:**
  * Testing all `n²` ordered pairs: `5000² · 300` is far too slow.
  * Missing the empty word: it pairs with every palindromic word, in both orders. The split loop must include the cut positions `0` and `len(word)`.
  * Counting a pair twice: at the full-length cut only the "palindromic prefix" case may fire, otherwise `(i, j)` and `(j, i)` style duplicates appear.
  * Pairing a word with itself (`idx[rev] == i`).

## 🔹 Optimization Path

* **Brute Force:** build `words[i] + words[j]` for all ordered pairs `i ≠ j` and test it — O(n² · L).
* **Optimized Solution:** hash map from word to index, `L + 1` splits per word with a palindrome test on each part — O(n · L²).
* **Further Improvements Possible?** A trie of reversed words with "remaining part is a palindrome" flags avoids re-slicing and re-testing at every cut; combined with Manacher to precompute each word's palindromic prefixes/suffixes in O(L), it reaches the O(sum of lengths) the problem asks for. The hash map version is far simpler to write.

## 🔹 Solution Breakdown

* **Optimal Approach:** `index = {w: i}`. For each word `w` and each `j` from `0` to `len(w)`: `pre, suf = w[:j], w[j:]`. If `pre` is a palindrome and `suf[::-1]` is a word `k ≠ i`, then `words[k] + w` is a palindrome → `[k, i]`. If `j < len(w)`, `suf` is a palindrome and `pre[::-1]` is a word `k ≠ i`, then `w + words[k]` is a palindrome → `[i, k]`.
* **Why This Works?** If `A + B` is a palindrome and `|A| ≥ |B|`, then `A = X + P` with `X = reverse(B)` and `P` a palindrome (the part of `A` that has no mirror partner in `B`); if `|A| < |B|`, then `B = Q + Y` with `Q` a palindrome and `Y = reverse(A)`. Enumerating every cut of every word covers both cases, and the `j < len(w)` rule makes each pair appear exactly once.
* **Edge Cases Considered:**
  * `["a", ""]` → `[[0, 1], [1, 0]]`.
  * A palindromic word with its reverse equal to itself — skipped via `k ≠ i`.
  * Words are unique, so the dictionary has no collisions.

## 🔹 Tricks & Patterns Used

* **Cut at every position, palindrome on one side, mirror on the other:** the central insight of the problem.
* **`j < len(w)` guard:** removes the duplicate that the two symmetric cases would otherwise produce.

## 🔹 Alternative Data Structures

* **Trie of reversed words:** walk each word down the trie; at every node where a word ends and the rest of the walking word is a palindrome, record a pair; at the end of the word, every stored word whose remaining suffix is a palindrome also pairs. Good when the palindrome checks must be O(1).
* Manacher's algorithm to precompute all palindromic prefixes and suffixes of each word in O(L).

## 🔹 Complexity Analysis

* **Time Complexity:** O(n · L²) — `L + 1` cuts, each with an O(L) slice, reverse and palindrome test
* **Space Complexity:** O(n · L) for the dictionary

## 🔹 Code Snippet (Brute Force)

```python
from typing import List


class Solution:
    def palindromePairs(self, words: List[str]) -> List[List[int]]:
        pairs = []
        for i, first in enumerate(words):
            for j, second in enumerate(words):
                if i != j:
                    joined = first + second
                    if joined == joined[::-1]:
                        pairs.append([i, j])
        return pairs
```

## 🔹 Code Snippet (Optimized)

```python
from typing import List


class Solution:
    def palindromePairs(self, words: List[str]) -> List[List[int]]:
        index = {word: i for i, word in enumerate(words)}
        pairs = []
        for i, word in enumerate(words):
            for cut in range(len(word) + 1):
                prefix, suffix = word[:cut], word[cut:]
                if prefix == prefix[::-1]:
                    other = index.get(suffix[::-1])
                    if other is not None and other != i:
                        pairs.append([other, i])
                # cut == len(word) would repeat the pair the prefix case just found
                if cut < len(word) and suffix == suffix[::-1]:
                    other = index.get(prefix[::-1])
                    if other is not None and other != i:
                        pairs.append([i, other])
        return pairs
```
