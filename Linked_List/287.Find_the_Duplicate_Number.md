# 🔹 Problem Name: 287. Find the Duplicate Number (Fast and Slow Pointers, Medium)

**🔗 Link:** [LeetCode 287](https://leetcode.com/problems/find-the-duplicate-number/)
**🟢 Status:** 🔄 Need Review

## 🔹 Quick Breakdown

* **Difficulty Level:** Medium
* **Main Approach:** **Treat the array as a linked list `i → nums[i]` and run Floyd's cycle detection.** Values lie in `[1, n]` and there are `n + 1` indices, so following `nums` from index 0 never leaves the array and must loop. The duplicate value is the node with two incoming edges — the cycle's entry.
* **Core Concept:** an array whose values are valid indices is a functional graph; a repeated value = two arrows into the same node = a cycle entrance
* **When to Use This Pattern?** "Values in `[1, n]` (or `[0, n−1]`), find the repeat / missing one, O(1) extra space, don't modify the array" — Floyd here; if modification were allowed, cyclic sort / sign marking (442, 448, 41).
* **Mistakes to Avoid:**
  * Sorting or marking `nums` — the problem forbids modifying the array.
  * A `set` — violates the O(1) extra space requirement.
  * Starting at index `n` or at `nums[0]` inconsistently in the two phases; index 0 is safe because no value points to 0, so 0 is never inside the cycle.
  * Assuming the duplicate appears exactly twice — `[3,3,3,3,3]` is valid.

## 🔹 Optimization Path

* **Brute Force:** sort a copy and return the first equal neighbours — O(n log n) time, O(n) space.
* **Optimized Solution:** Floyd's tortoise and hare on `i → nums[i]` — O(n) time, O(1) space, array untouched.
* **Further Improvements Possible?** Binary search on the value `m` (count of `nums ≤ m` exceeds `m` ⇒ duplicate ≤ m) is also O(1) space but O(n log n).

## 🔹 Solution Breakdown

* **Optimal Approach:** phase 1: `slow = nums[slow]`, `fast = nums[nums[fast]]` until equal. Phase 2: `slow = 0`, step both once at a time until equal; that index is the duplicate.
* **Why This Works?** Every index has exactly one outgoing edge, so the walk from 0 is a "rho" shape: a tail then a cycle. The cycle's entry is the first index reached twice, i.e. one with two predecessors `i ≠ j` where `nums[i] == nums[j]` — that index is the duplicate value. Phase 2 lands on the entry by the same `a = k·c − b` argument as 142.
* **Edge Cases Considered:**
  * `n = 1` → `[1, 1]`.
  * Duplicate repeated many times.
  * Duplicate at index 0's first hop (`nums[0]` is the duplicate) — tail length 1.

## 🔹 Tricks & Patterns Used

* **Array as implicit linked list:** `next(i) = nums[i]`, no nodes allocated.
* **Pigeonhole:** `n + 1` values in `[1, n]` guarantees a repeat and guarantees index 0 has no predecessor.

## 🔹 Alternative Data Structures

* Hash set — O(n) space.
* Binary search on value range with counting — O(n log n), O(1).
* Bit counting per bit position — O(n log n), O(1).

## 🔹 Code Snippet (Brute Force)

```python
from typing import List


class Solution:
    def findDuplicate(self, nums: List[int]) -> int:
        ordered = sorted(nums)
        for i in range(1, len(ordered)):
            if ordered[i] == ordered[i - 1]:
                return ordered[i]
        return -1
```

## 🔹 Code Snippet (Optimized)

```python
from typing import List


class Solution:
    def findDuplicate(self, nums: List[int]) -> int:
        slow = fast = 0
        while True:
            slow = nums[slow]
            fast = nums[nums[fast]]
            if slow == fast:
                break
        # no value equals 0, so index 0 sits on the tail and phase 2 meets at the entry
        slow = 0
        while slow != fast:
            slow = nums[slow]
            fast = nums[fast]
        return slow
```
