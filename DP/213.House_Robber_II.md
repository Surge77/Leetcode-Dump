# 213. House Robber II

**🔗 Link:** [LeetCode 213](https://leetcode.com/problems/house-robber-ii/)
**🟢 Status:** 🔄 Need Review


## 🔹 Problem Statement

Houses along a street hold given amounts of money, but the street is a circle, so the first and last houses are neighbours. Robbing two adjacent houses triggers the alarm. Return the maximum amount you can take without robbing any two adjacent houses.

* **Example:** `nums = [2,3,2]` → `3`
* **Constraints:** `1 ≤ nums.length ≤ 100`, `0 ≤ nums[i] ≤ 1000`

## 🔹 Quick Breakdown

* **Difficulty Level:** Medium
* **Main Approach:** **Break the circle.** The first and last houses are neighbours, so at least one of them is skipped. Run the linear House Robber (198) on `nums[1:]` and on `nums[:-1]` and take the larger result. One house alone is a special case (both slices would be empty).
* **Core Concept:** reduce a circular constraint to two linear instances by fixing which endpoint is excluded
* **When to Use This Pattern?** Circular arrays where the wrap-around edge adds one extra constraint — circular robbing, max circular subarray (918), circular arrangement DPs.
* **Mistakes to Avoid:**
  * `n = 1` → answer is `nums[0]`, but both slices are empty and would give 0.
  * Excluding **both** endpoints at once loses answers that use one of them.

## 🔹 Optimization Path

* **Brute Force:** try every subset of houses, keep those with no two circularly adjacent — O(2ⁿ · n).
* **Optimized Solution:** linear robber twice with two rolling variables — O(n) time, O(1) space.
* **Further Improvements Possible?** No; every value must be read.

## 🔹 Solution Breakdown

* **Optimal Approach:** `rob_line(houses)`: `take, skip = 0, 0`; for each `x`: `take, skip = skip + x, max(take, skip)`; answer `max(take, skip)`. Return `max(rob_line(nums[1:]), rob_line(nums[:-1]))` for `n > 1`.
* **Why This Works?** Every valid circular choice skips house 0 or skips house `n−1` (or both), so it is a valid choice in one of the two lines. Conversely, any choice in either line never uses both endpoints, so it is valid on the circle.
* **Edge Cases Considered:**
  * `n = 1` → `nums[0]`; `n = 2` → the larger of the two.
  * Zeros — `0 ≤ nums[i]`, so robbing nothing is never better than 0.

## 🔹 Tricks & Patterns Used

* **Case split on the wrap-around edge:** "first excluded" or "last excluded".
* **Take / skip pair:** `take` = best ending by robbing the current house, `skip` = best without it.

## 🔹 Alternative Data Structures

* Pass index bounds instead of slices to avoid the O(n) copies (constant-factor only).

## 🔹 Code Snippet (Brute Force)

```python
from typing import List


class Solution:
    def rob(self, nums: List[int]) -> int:
        n = len(nums)
        best = 0
        for mask in range(1 << n):
            if n > 1 and any(mask >> i & 1 and mask >> ((i + 1) % n) & 1 for i in range(n)):
                continue
            best = max(best, sum(nums[i] for i in range(n) if mask >> i & 1))
        return best
```

## 🔹 Code Snippet (Optimized)

```python
from typing import List


class Solution:
    def rob(self, nums: List[int]) -> int:
        if len(nums) == 1:
            return nums[0]  # both slices below would be empty

        def rob_line(houses: List[int]) -> int:
            take = skip = 0
            for x in houses:
                take, skip = skip + x, max(take, skip)
            return max(take, skip)

        return max(rob_line(nums[1:]), rob_line(nums[:-1]))
```
