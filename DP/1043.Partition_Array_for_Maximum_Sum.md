# 🔹 Problem Name: 1043. Partition Array for Maximum Sum (Partition DP, Medium)

**🔗 Link:** [LeetCode 1043](https://leetcode.com/problems/partition-array-for-maximum-sum/)
**🟢 Status:** 🔄 Need Review

## 🔹 Quick Breakdown

* **Difficulty Level:** Medium
* **Main Approach:** **Prefix partition DP.** `dp[i]` = best sum for the first `i` elements. The last block ends at `i − 1` and has length `L ∈ [1, k]`; it contributes `L × max(arr[i−L..i−1])`. So `dp[i] = max over L of dp[i − L] + L × blockMax`, growing `blockMax` as `L` increases.
* **Core Concept:** "cut the array into pieces" → DP over where the last piece starts
* **When to Use This Pattern?** Split an array/string into contiguous segments of bounded length with a per-segment score — palindrome partitioning (132), word break (139), job/segment scoring.
* **Mistakes to Avoid:**
  * Recomputing `max(arr[i−L:i])` from scratch for every `L`: O(n·k²). Extend the block leftwards and update the max incrementally.
  * Letting `L` exceed `i` at the start of the array.

## 🔹 Optimization Path

* **Brute Force:** recursion over the first block's length, no memo — exponential (every composition of `n` into parts ≤ `k`).
* **Optimized Solution:** bottom-up DP — O(n·k) = 2.5·10⁵ for `n = k = 500`.
* **Further Improvements Possible?** O(k) memory with a circular buffer of the last `k` dp values; time stays O(n·k).

## 🔹 Solution Breakdown

* **Optimal Approach:** `dp[0] = 0`; for `i = 1..n`, walk `L = 1..min(k, i)`, `block_max = max(block_max, arr[i − L])`, `dp[i] = max(dp[i], dp[i − L] + L * block_max)`.
* **Why This Works?** Every valid partition of the first `i` elements has a last block of some length `L ≤ k`; the rest is a partition of the first `i − L` elements, whose best value is `dp[i − L]` independently of the last block.
* **Edge Cases Considered:**
  * `k = 1` → sum of the array.
  * `k ≥ n` → `n × max(arr)`.

## 🔹 Pattern Recognition

* **Belongs To:** DP — partition / "last segment" DP (front partition)
* **Common Problems Using This:**
  * 132. Palindrome Partitioning II
  * 139. Word Break
  * 1335. Minimum Difficulty of a Job Schedule

## 🔹 Tricks & Patterns Used

* **Running max while extending a segment backwards** — turns O(k²) per index into O(k).
* **`dp[0] = 0` sentinel** for the empty prefix.

## 🔹 Alternative Data Structures

* Top-down `f(start)` with `lru_cache` — same O(n·k); recursion depth up to 500 is fine.

## 🔹 Complexity Analysis

* **Time Complexity:** O(n·k)
* **Space Complexity:** O(n)

## 🔹 Code Snippet (Brute Force)

```python
from typing import List


class Solution:
    def maxSumAfterPartitioning(self, arr: List[int], k: int) -> int:
        n = len(arr)

        def best(start: int) -> int:
            if start == n:
                return 0
            result = block_max = 0
            for end in range(start, min(start + k, n)):
                block_max = max(block_max, arr[end])
                result = max(result, block_max * (end - start + 1) + best(end + 1))
            return result

        return best(0)
```

## 🔹 Code Snippet (Optimized)

```python
from typing import List


class Solution:
    def maxSumAfterPartitioning(self, arr: List[int], k: int) -> int:
        n = len(arr)
        dp = [0] * (n + 1)
        for i in range(1, n + 1):
            block_max = 0
            for length in range(1, min(k, i) + 1):
                block_max = max(block_max, arr[i - length])
                dp[i] = max(dp[i], dp[i - length] + length * block_max)
        return dp[n]
```
