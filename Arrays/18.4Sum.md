# 🔹 Problem Name: 18. 4Sum (Two Pointers, Medium)

**🔗 Link:** [LeetCode 18](https://leetcode.com/problems/4sum/)
**🟢 Status:** 🔄 Need Review

## 🔹 Quick Breakdown

* **Difficulty Level:** Medium
* **Main Approach:** **Sort + two fixed indices + two pointers.** Fix `i < j`, then find all pairs in `nums[j+1:]` summing to `target − nums[i] − nums[j]` with `lo`/`hi` pointers moving inwards. Skip equal values at every level so each quadruplet appears once.
* **Core Concept:** k-Sum reduces to (k−1)-Sum by fixing one element; on a sorted array the base case 2-Sum is a linear two-pointer sweep
* **When to Use This Pattern?** "Find all unique tuples summing to a target" — 2Sum II, 3Sum, 3Sum Closest, 4Sum, triangle counts. Sorting buys both the two-pointer sweep and easy duplicate skipping.
* **Mistakes to Avoid:**
  * Duplicate skipping on the first visit of a value: skip `nums[j] == nums[j − 1]` only when `j > i + 1` (and `i > 0` for `i`), or `[2, 2, 2, 2]` is lost.
  * Breaking on `nums[i] > target` alone — wrong with negative numbers (`[-3, -2, -1, -1]`, target `-7`: `-3 > -7`, yet all four sum to `-7`).
  * In Java/C++ the sum of four values up to 10⁹ overflows 32 bits; Python ints do not.

## 🔹 Optimization Path

* **Brute Force:** every 4-combination of the sorted array, collected in a set — O(n⁴), C(200, 4) ≈ 6.5·10⁷ combinations for `n = 200`.
* **Optimized Solution:** sort + two loops + two pointers — O(n³) ≈ 1.3·10⁶ inner steps for `n = 200`.
* **Further Improvements Possible?** Pair-sum hashing (store all `nums[a] + nums[b]`) gives O(n²) expected for "does one exist", but producing every unique quadruplet without duplicates is messy and the output itself can be Θ(n³). For counting with independent arrays see 4Sum II (454).

## 🔹 Solution Breakdown

* **Optimal Approach:** sort; for `i`, for `j > i`: `lo, hi = j + 1, n − 1`; if the sum is small `lo += 1`, large `hi -= 1`, equal → record, move `lo` past its duplicates and step `hi`.
* **Why This Works?** With `i`, `j` fixed, the sorted suffix makes the pair search monotone: a too-small sum can only grow by moving `lo` right, a too-large one only shrink by moving `hi` left, so no valid pair is skipped. Skipping repeated values at each of the four positions means each value combination is generated from its first occurrence only.
* **Edge Cases Considered:**
  * Fewer than 4 numbers → `[]`.
  * All equal (`[2, 2, 2, 2, 2]`, target 8) → one quadruplet.
  * **Pruning:** if the 4 smallest sums from `i` already exceed `target`, nothing later can work → `break`; if `nums[i]` plus the 3 largest is still below, this `i` is hopeless → `continue`. Same at the `j` level. Valid with negatives because the array is sorted.

## 🔹 Tricks & Patterns Used

* **Fix k − 2 indices, two-pointer the rest:** O(n^(k−1)) for k-Sum.
* **Skip duplicates by comparing with the previous element at the same level.**
* **Min/max pruning** on a sorted array.

## 🔹 Alternative Data Structures

* Recursive k-Sum (`kSum(nums, target, k)` reducing to 2-Sum) — generalises to any `k`.
* Hash set inside the third loop instead of two pointers — also O(n³), needs extra duplicate handling.

## 🔹 Complexity Analysis

* **Time Complexity:** O(n³) (plus O(n log n) for the sort)
* **Space Complexity:** O(1) besides the output and the sorted copy

## 🔹 Code Snippet (Brute Force)

```python
from itertools import combinations
from typing import List


class Solution:
    def fourSum(self, nums: List[int], target: int) -> List[List[int]]:
        found = {quad for quad in combinations(sorted(nums), 4) if sum(quad) == target}
        return [list(quad) for quad in found]
```

## 🔹 Code Snippet (Optimized)

```python
from typing import List


class Solution:
    def fourSum(self, nums: List[int], target: int) -> List[List[int]]:
        nums = sorted(nums)
        n = len(nums)
        quads = []
        for i in range(n - 3):
            if i > 0 and nums[i] == nums[i - 1]:
                continue
            if nums[i] + nums[i + 1] + nums[i + 2] + nums[i + 3] > target:
                break
            if nums[i] + nums[n - 3] + nums[n - 2] + nums[n - 1] < target:
                continue
            for j in range(i + 1, n - 2):
                if j > i + 1 and nums[j] == nums[j - 1]:
                    continue
                if nums[i] + nums[j] + nums[j + 1] + nums[j + 2] > target:
                    break
                if nums[i] + nums[j] + nums[n - 2] + nums[n - 1] < target:
                    continue
                lo, hi = j + 1, n - 1
                while lo < hi:
                    total = nums[i] + nums[j] + nums[lo] + nums[hi]
                    if total < target:
                        lo += 1
                    elif total > target:
                        hi -= 1
                    else:
                        quads.append([nums[i], nums[j], nums[lo], nums[hi]])
                        lo += 1
                        while lo < hi and nums[lo] == nums[lo - 1]:
                            lo += 1  # a new lo value forces a new hi value, so no duplicate pair
                        hi -= 1
        return quads
```
