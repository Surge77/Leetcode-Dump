# 1493. Longest Subarray of 1's After Deleting One Element

**🔗 Link:** [LeetCode 1493](https://leetcode.com/problems/longest-subarray-of-1s-after-deleting-one-element/)
**🟢 Status:** 🔄 Need Review


## 🔹 Problem Statement

Given a binary array `nums`, you must delete exactly one element. Return the length of the longest non-empty subarray made only of `1`s in the resulting array, or `0` if there is none.

* **Example:** `nums = [1,1,0,1]` → `3`
* **Constraints:** `1 ≤ nums.length ≤ 10^5`, `nums[i]` is `0` or `1`

## 🔹 Quick Breakdown

* **Difficulty Level:** Medium
* **Main Approach:** **Longest window with at most one zero, minus one.** Deleting one element means the chosen window may contain one `0` (the deleted one) or none. Grow `right`, count zeros, and move `left` forward while the window has more than one zero. The answer is the largest `right - left` (window length minus the deleted element).
* **Core Concept:** "delete at most one" ≡ "allow at most one violation in the window"
* **When to Use This Pattern?** Longest subarray/substring with at most `k` bad elements (1004, 424, 3-style) where `k` is the number of deletions or flips allowed.
* **Mistakes to Avoid:**
  * Forgetting that one element **must** be deleted: with all ones, the answer is `n - 1`, not `n` — subtracting `1` from the window length handles it.
  * Shrinking with `if` instead of `while` once the zero count exceeds one.
  * Returning `0` for `n = 1`: deleting the only element leaves nothing, so `0` is right, and the formula gives it.

## 🔹 Optimization Path

* **Brute Force:** try deleting each index and scan the remaining array for its longest run of ones — O(n²).
* **Optimized Solution:** one pass with two pointers — O(n).
* **Further Improvements Possible?** Equivalent O(n) DP / run-length versions exist (`prev_run + current_run` around each zero) but do not beat the window.

## 🔹 Solution Breakdown

* **Optimal Approach:** for each `right`: `zeros += nums[right] == 0`. While `zeros > 1`: `zeros -= nums[left] == 0`; `left += 1`. Then `best = max(best, right - left)`.
* **Why This Works?** The window `[left, right]` holds at most one zero. After deleting that zero (or any one element if there is none), `right - left + 1 - 1` consecutive ones remain on one side or both of it, which is the largest block achievable ending at `right`.
* **Edge Cases Considered:**
  * `[1, 1, 1]` → `2`.
  * `[0, 0, 0]` → `0`.
  * `[1]` → `0`.
  * A zero in the middle of long runs joins the two runs into one.

## 🔹 Tricks & Patterns Used

* **Violation counter:** track `zeros` and shrink while it exceeds the budget.
* **`right - left` instead of `right - left + 1`** accounts for the mandatory deletion.

## 🔹 Alternative Data Structures

* Run-length encoding of the ones, taking `run[i] + run[i + 1]` across each single zero.
* DP with two states per index: ones ending here with and without a deletion used.

## 🔹 Complexity Analysis

* **Time Complexity:** O(n)
* **Space Complexity:** O(1)

## 🔹 Code Snippet (Brute Force)

```python
from typing import List


class Solution:
    def longestSubarray(self, nums: List[int]) -> int:
        best = 0
        for removed in range(len(nums)):
            run = 0
            for i, value in enumerate(nums):
                if i == removed:
                    continue
                run = run + 1 if value == 1 else 0
                best = max(best, run)
        return best
```

## 🔹 Code Snippet (Optimized)

```python
from typing import List


class Solution:
    def longestSubarray(self, nums: List[int]) -> int:
        left = zeros = best = 0
        for right, value in enumerate(nums):
            zeros += value == 0
            while zeros > 1:
                zeros -= nums[left] == 0
                left += 1
            best = max(best, right - left)  # one element of the window is deleted
        return best
```
