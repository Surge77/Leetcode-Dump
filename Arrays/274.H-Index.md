# 🔹 Problem Name: 274. H-Index (Counting Sort, Medium)

**🔗 Link:** [LeetCode 274](https://leetcode.com/problems/h-index/)
**🟢 Status:** 🔄 Need Review

## 🔹 Quick Breakdown

* **Difficulty Level:** Medium
* **Main Approach:** **Buckets capped at `n`.** The h-index can never exceed `n` (you need `h` papers), so a paper with more than `n` citations counts the same as one with exactly `n`. Count papers per bucket `0..n`, then walk `h` from `n` down, adding bucket `h` to a running total of papers with at least `h` citations; the first `h` where that total reaches `h` is the answer.
* **Core Concept:** the answer is bounded by `n`, so larger values collapse into one bucket and counting sort becomes O(n)
* **When to Use This Pattern?** Answers of the form "at least `x` items have value ≥ `x`" (h-index, special array); counting how many values pass a threshold for every threshold at once; values bounded by the array length.
* **Mistakes to Avoid:**
  * Sizing buckets by `max(citations)` instead of `n + 1` — the cap is what makes it linear.
  * Off-by-one in the sorted version: after sorting descending the test is `citations[i] ≥ i + 1` (paper `i` is the `(i + 1)`-th best).

## 🔹 Optimization Path

* **Brute Force:** try every `h` from `n` down and count papers with at least `h` citations — O(n²).
* **Optimized Solution:** capped counting buckets with a running suffix sum — O(n) time, O(n) space.
* **Further Improvements Possible?** No in time (every citation must be read); sorting in place trades this for O(n log n) time and O(1) extra space.

## 🔹 Solution Breakdown

* **Optimal Approach:** `buckets[min(c, n)] += 1`; for `h = n..1`: `papers += buckets[h]`, return `h` once `papers ≥ h`; return 0 if none.
* **Why This Works?** After adding bucket `h`, `papers` is the number of papers with at least `h` citations (bucket `n` holds everything ≥ `n`). As `h` decreases, `papers` can only grow while `h` shrinks, so the first `h` from the top that satisfies `papers ≥ h` is the largest one.
* **Edge Cases Considered:**
  * All zeros → 0.
  * One paper → 1 if it has any citation, else 0.
  * Citations far above `n` (`[1000, 1000]` → 2).

## 🔹 Tricks & Patterns Used

* **Cap values at the largest possible answer** so the bucket array has size `n + 1`.
* **Suffix sum over buckets** answers "how many are ≥ `h`" for every `h` in one sweep.

## 🔹 Alternative Data Structures

* Sort descending, count the leading `i` with `citations[i] ≥ i + 1` — O(n log n), O(1) extra.
* Binary search on `h` with an O(n) counting check — O(n log n).

## 🔹 Code Snippet (Brute Force)

```python
from typing import List


class Solution:
    def hIndex(self, citations: List[int]) -> int:
        for h in range(len(citations), 0, -1):
            if sum(c >= h for c in citations) >= h:
                return h
        return 0
```

## 🔹 Code Snippet (Optimized)

```python
from typing import List


class Solution:
    def hIndex(self, citations: List[int]) -> int:
        n = len(citations)
        buckets = [0] * (n + 1)
        for c in citations:
            buckets[min(c, n)] += 1  # h never exceeds n, so more than n citations counts the same as n
        papers = 0
        for h in range(n, 0, -1):
            papers += buckets[h]
            if papers >= h:
                return h
        return 0
```
