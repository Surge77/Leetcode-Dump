# 🔹 Problem Name: 901. Online Stock Span (Monotonic Stack, Medium)

**🔗 Link:** [LeetCode 901](https://leetcode.com/problems/online-stock-span/)
**🟢 Status:** 🔄 Need Review

## 🔹 Problem Statement

Design a `StockSpanner` class whose `next(price)` receives each day's price in order and returns that day's span: the number of consecutive days, counting today and going backward, whose price was less than or equal to today's price.

* **Example:** `next(100), next(80), next(60), next(70), next(60), next(75), next(85)` → `[1, 1, 1, 2, 1, 4, 6]`
* **Constraints:** `1 ≤ price ≤ 10⁵`; at most `10⁴` calls to `next`

## 🔹 Quick Breakdown

* **Difficulty Level:** Medium
* **Main Approach:** **Stack of `(price, span)` with decreasing prices.** For a new price, pop every entry with price ≤ the new one and add its span to the current span (those days, and everything they already covered, are now covered by today). Push `(price, span)`.
* **Core Concept:** previous greater element, computed online — a popped day can never be the blocker for a future day, because today is at least as high and more recent
* **When to Use This Pattern?** Streaming "how far back until something bigger/smaller", previous greater element, stock span, histogram boundaries.
* **Mistakes to Avoid:**
  * Popping on `<` instead of `≤` — the span counts days with price **less than or equal** to today.
  * Storing only prices — you then have to rescan, losing the compression of spans.

## 🔹 Optimization Path

* **Brute Force:** store every price and scan backwards on each call — O(n) per call, O(n²) total (strictly increasing prices).
* **Optimized Solution:** monotonic stack with accumulated spans — amortized O(1) per call.
* **Further Improvements Possible?** No; each price is pushed and popped at most once.

## 🔹 Solution Breakdown

* **Optimal Approach:** `span = 1; while stack and stack[-1][0] <= price: span += stack.pop()[1]; stack.append((price, span)); return span`.
* **Why This Works?** Each stack entry represents a block of consecutive days ending at that day, all with price ≤ its own price. Merging blocks whose top price is ≤ today walks back exactly until the first strictly higher price — the definition of the span.
* **Edge Cases Considered:**
  * First call → 1.
  * Strictly increasing prices — span grows by one each call, each call pops one entry.
  * Equal prices — merged (≤).

## 🔹 Tricks & Patterns Used

* **Carry the span on the stack** so popped blocks are absorbed in O(1).
* **Amortized analysis:** n pushes bound the total pops.

## 🔹 Alternative Data Structures

* Store prices with their day index and compute `day − index_of_top` after popping — same idea, index instead of span.

## 🔹 Complexity Analysis

* **Time Complexity:** amortized O(1) per `next`, O(n) total for `n ≤ 10⁴` calls
* **Space Complexity:** O(n)

## 🔹 Code Snippet (Brute Force)

```python
class StockSpanner:

    def __init__(self):
        self.prices = []

    def next(self, price: int) -> int:
        self.prices.append(price)
        span, j = 1, len(self.prices) - 2
        while j >= 0 and self.prices[j] <= price:
            span += 1
            j -= 1
        return span
```

## 🔹 Code Snippet (Optimized)

```python
class StockSpanner:

    def __init__(self):
        self.stack = []  # (price, span) with strictly decreasing prices

    def next(self, price: int) -> int:
        span = 1
        while self.stack and self.stack[-1][0] <= price:
            span += self.stack.pop()[1]  # today covers that whole block
        self.stack.append((price, span))
        return span
```
