# 🔹 Problem Name: 931. Minimum Falling Path Sum (Grid DP, Medium)

**🔗 Link:** [LeetCode 931](https://leetcode.com/problems/minimum-falling-path-sum/)
**🟢 Status:** 🔄 Need Review

## 🔹 Quick Breakdown

* **Difficulty Level:** Medium
* **Main Approach:** **Row-by-row DP.** `best[c]` = cheapest falling path ending at column `c` of the current row. For the next row: `new[c] = matrix[r][c] + min(best[c−1], best[c], best[c+1])` (ignoring out-of-range neighbours). Answer = `min(best)` after the last row.
* **Core Concept:** each cell only depends on three cells of the previous row → keep one row
* **When to Use This Pattern?** Paths that move one row down at a time with a fixed set of column moves — triangle (120), falling paths, cherry-pickup-style grids.
* **Mistakes to Avoid:**
  * Plain recursion from every top cell: 3ⁿ paths.
  * Updating `best` in place while still reading it for the neighbouring column — build a new row.

## 🔹 Optimization Path

* **Brute Force:** recurse from each top cell into the three cells below, no memo — O(n · 3ⁿ).
* **Optimized Solution:** tabulation, one row at a time — O(n²) time, O(n) extra space.
* **Further Improvements Possible?** O(1) extra space by writing into `matrix` itself (mutates input). O(n²) time is optimal — every cell must be read.

## 🔹 Solution Breakdown

* **Optimal Approach:** start with `best = matrix[0]`; for every next row, compute `new` from the three neighbours above.
* **Why This Works?** The cheapest path to `(r, c)` must pass through one of `(r−1, c−1)`, `(r−1, c)`, `(r−1, c+1)`; its prefix up to there must itself be cheapest (optimal substructure), so taking the min of those three is exact.
* **Edge Cases Considered:**
  * `n = 1` → the single value.
  * Negative values — DP with `min` handles them; no "start from 0" shortcut.
  * First / last column have only two parents.

## 🔹 Tricks & Patterns Used

* **Rolling row:** a 2-D DP whose transitions only look one row back needs O(n) memory.
* **Slice the neighbour window:** `min(best[max(c − 1, 0):c + 2])` handles the borders without branches.

## 🔹 Alternative Data Structures

* Top-down memoised recursion `f(r, c)` — same O(n²), but needs `lru_cache` and up to `n = 100` depth (fine here).

## 🔹 Complexity Analysis

* **Time Complexity:** O(n²)
* **Space Complexity:** O(n)

## 🔹 Code Snippet (Brute Force)

```python
from typing import List


class Solution:
    def minFallingPathSum(self, matrix: List[List[int]]) -> int:
        n = len(matrix)

        def fall(r: int, c: int) -> int:
            if r == n - 1:
                return matrix[r][c]
            return matrix[r][c] + min(fall(r + 1, nc) for nc in (c - 1, c, c + 1) if 0 <= nc < n)

        return min(fall(0, c) for c in range(n))
```

## 🔹 Code Snippet (Optimized)

```python
from typing import List


class Solution:
    def minFallingPathSum(self, matrix: List[List[int]]) -> int:
        best = list(matrix[0])
        for row in matrix[1:]:
            best = [value + min(best[max(c - 1, 0):c + 2]) for c, value in enumerate(row)]
        return min(best)
```
