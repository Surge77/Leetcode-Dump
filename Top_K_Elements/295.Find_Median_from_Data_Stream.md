# 🔹 Problem Name: 295. Find Median from Data Stream (Two Heaps, Hard)

**🔗 Link:** [LeetCode 295](https://leetcode.com/problems/find-median-from-data-stream/)
**🟢 Status:** 🔄 Need Review

## 🔹 Problem Statement

Design a structure that receives integers one at a time and can report the median of everything received so far. The median is the middle value of the sorted data, or the mean of the two middle values when the count is even. Implement `addNum(num)` and `findMedian()`; answers within 10⁻⁵ of the true median are accepted.

* **Example:** `["MedianFinder","addNum","addNum","findMedian","addNum","findMedian"]`, `[[],[1],[2],[],[3],[]]` → `[null,null,null,1.5,null,2.0]`
* **Constraints:** `-10⁵ ≤ num ≤ 10⁵`; at most `5·10⁴` calls to `addNum` and `findMedian`; `findMedian` is only called when at least one number has been added.

## 🔹 Quick Breakdown

* **Difficulty Level:** Hard
* **Main Approach:** **Two heaps.** `low` is a max-heap (stored negated) holding the smaller half, `high` is a min-heap holding the larger half. Keep `len(low) == len(high)` or `len(low) == len(high) + 1`. The median is `-low[0]` (odd count) or the average of the two tops (even count).
* **Core Concept:** the median only depends on the two middle elements, so keep the halves partially ordered and expose just their boundary tops
* **When to Use This Pattern?** A running median, or any "k-th smallest where k moves with the size" over a stream — sliding window median, IPO-style "best affordable item", balancing two groups.
* **Mistakes to Avoid:**
  * Pushing into `low` without routing through `high`: a large number can end up in the small half and break the ordering invariant.
  * Forgetting the negation when reading `low[0]`.
  * Integer division for the even case — the median of `[1, 2]` is `1.5`.

## 🔹 Optimization Path

* **Brute Force:** append to a list and sort on every `findMedian` — O(n log n) per query.
* **Better:** keep a sorted list with `bisect.insort` — O(log n) search but O(n) shifting per insert.
* **Optimized Solution:** two heaps — O(log n) `addNum`, O(1) `findMedian`.
* **Further Improvements Possible?** If all values lie in a small range (follow-up: `[0, 100]`), a 101-slot counting array gives O(1) insert and O(100) median.

## 🔹 Solution Breakdown

* **Optimal Approach:** `addNum(x)`: push `x` into `low`, move `low`'s max into `high`, and if `high` became larger, move `high`'s min back into `low`.
* **Why This Works?** Routing every new number through `low` and then `high` guarantees every element of `low` ≤ every element of `high`; the final rebalance restores the size rule. With both invariants, the middle element(s) are exactly the heap tops.
* **Edge Cases Considered:**
  * One element — `high` is empty, the median is `-low[0]`.
  * Duplicates and negatives (values in `[-10⁵, 10⁵]`) — heaps handle them unchanged.

## 🔹 Tricks & Patterns Used

* **Max-heap in Python:** `heapq` is min-only, so push `-x` and negate on read.
* **Push-pop routing:** always pass a new value through the other heap so the boundary stays correct without comparisons.

## 🔹 Alternative Data Structures

* Balanced BST / `SortedList` with an index lookup — O(log n) both operations.
* Counting array for bounded values (the follow-ups).

## 🔹 Complexity Analysis

* **Time Complexity:** O(log n) per `addNum`, O(1) per `findMedian`
* **Space Complexity:** O(n)

## 🔹 Code Snippet (Brute Force)

```python
class MedianFinder:

    def __init__(self):
        self.nums = []

    def addNum(self, num: int) -> None:
        self.nums.append(num)

    def findMedian(self) -> float:
        ordered = sorted(self.nums)
        mid = len(ordered) // 2
        if len(ordered) % 2:
            return float(ordered[mid])
        return (ordered[mid - 1] + ordered[mid]) / 2
```

## 🔹 Code Snippet (Optimized)

```python
import heapq


class MedianFinder:

    def __init__(self):
        self.low = []   # max-heap via negation: the smaller half
        self.high = []  # min-heap: the larger half

    def addNum(self, num: int) -> None:
        # routing through both heaps keeps every low value <= every high value
        heapq.heappush(self.high, -heapq.heappushpop(self.low, -num))
        if len(self.high) > len(self.low):
            heapq.heappush(self.low, -heapq.heappop(self.high))

    def findMedian(self) -> float:
        if len(self.low) > len(self.high):
            return float(-self.low[0])
        return (-self.low[0] + self.high[0]) / 2
```
