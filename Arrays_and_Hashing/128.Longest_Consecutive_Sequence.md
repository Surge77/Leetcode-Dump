# 128. Longest Consecutive Sequence

**🔗 Link:** [LeetCode 128](https://leetcode.com/problems/longest-consecutive-sequence/)
**🟢 Status:** 🔄 Need Review


## 🔹 Problem Statement

Given an unsorted integer array, return the length of the longest run of values that are consecutive integers (like 4, 5, 6, 7), regardless of where they sit in the array. The algorithm must run in O(n) time.

* **Example:** `nums = [100,4,200,1,3,2]` → `4`
* **Constraints:** `0 ≤ nums.length ≤ 10^5`, `-10^9 ≤ nums[i] ≤ 10^9`.

## 🔹 Quick Breakdown

* **Difficulty Level:** Medium
* **Main Approach:** **Hash set + count only from run starts.** Put every number in a set. A number `x` starts a run iff `x − 1` is not in the set; from each start walk `x, x+1, x+2, …` while present and record the length.
* **Core Concept:** O(1) membership turns "is the next value present?" into a constant-time step; starting only at run heads makes every element visited at most twice
* **When to Use This Pattern?** "Longest run of consecutive values" in an **unsorted** array with an O(n) requirement — the order in the array doesn't matter, only which values exist.
* **Mistakes to Avoid:**
  * Walking from **every** number (no `x − 1` check): a single run of length `n` costs `n + (n−1) + … ` = O(n²).
  * Iterating over `nums` instead of the set: with many duplicates of a run head, the same run is walked again for each copy.
  * Forgetting the empty array → `0`.

## 🔹 Optimization Path

* **Brute Force:** for every value, extend upward through the set — O(n²) for one long run.
* **Better:** sort and scan, skipping duplicates — O(n log n).
* **Optimized Solution:** extend only from run heads — O(n).
* **Further Improvements Possible?** No; every value must be read once.

## 🔹 Solution Breakdown

* **Optimal Approach:** `present = set(nums)`; for each `x` in `present` with `x − 1 ∉ present`, count `length` while `x + length ∈ present`; keep the max.
* **Why This Works?** Every maximal run has exactly one head (its smallest value), so each run is measured exactly once, and the inner `while` steps over each set element only inside its own run — total inner steps ≤ n.
* **Edge Cases Considered:**
  * `nums = []` → `0`.
  * Duplicates (`[1, 2, 0, 1]` → 3) — the set removes them.
  * Negative values and gaps such as `[-1, 1]` → 1.

## 🔹 Tricks & Patterns Used

* **"Start only at the head":** the `x − 1 not in set` check is the standard way to avoid re-walking a run from its middle.
* **Amortised counting:** argue the cost by "each element is touched by at most one inner loop", not by nesting depth.

## 🔹 Alternative Data Structures

* Union–Find over values, uniting `x` with `x ± 1` when present — O(n·α(n)) but heavier to write.
* Sorting — O(n log n), O(1) extra if sorting in place; acceptable in practice, but not what the problem asks.

## 🔹 Complexity Analysis

* **Time Complexity:** O(n)
* **Space Complexity:** O(n) for the set

## 🔹 Code Snippet (Brute Force)

```python
from typing import List


class Solution:
    def longestConsecutive(self, nums: List[int]) -> int:
        present = set(nums)
        best = 0
        for x in present:
            length = 1
            while x + length in present:
                length += 1
            best = max(best, length)
        return best
```

## 🔹 Code Snippet (Optimized)

```python
from typing import List


class Solution:
    def longestConsecutive(self, nums: List[int]) -> int:
        present = set(nums)
        best = 0
        for x in present:
            if x - 1 in present:
                continue  # x is inside a run that its head will measure
            length = 1
            while x + length in present:
                length += 1
            best = max(best, length)
        return best
```
