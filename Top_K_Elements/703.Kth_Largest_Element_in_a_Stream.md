# 🔹 Problem Name: 703. Kth Largest Element in a Stream (Min Heap of Size K, Easy)

**🔗 Link:** [LeetCode 703](https://leetcode.com/problems/kth-largest-element-in-a-stream/)
**🟢 Status:** 🔄 Need Review

## 🔹 Problem Statement

Maintain a stream of scores for a fixed `k`. The constructor receives `k` and the initial scores; each `add(val)` inserts a new score and returns the k-th largest score among all scores so far (k-th in sorted order, duplicates counted).

* **Example:** `["KthLargest","add","add","add","add","add"]`, `[[3,[4,5,8,2]],[3],[5],[10],[9],[4]]` → `[null,4,5,5,8,8]`
* **Constraints:** `0 ≤ nums.length ≤ 10⁴`; `1 ≤ k ≤ nums.length + 1`; `-10⁴ ≤ nums[i], val ≤ 10⁴`; at most `10⁴` calls to `add`.

## 🔹 Quick Breakdown

* **Difficulty Level:** Easy
* **Main Approach:** **Min-heap capped at `k`.** Keep only the `k` largest values seen so far in a min-heap; its root is the k-th largest. On `add`, push the value and pop the root if the heap grew past `k`.
* **Core Concept:** to track the k-th largest you never need anything smaller than it — throw it away
* **When to Use This Pattern?** "k-th largest / top k" over a stream or an array too large to sort repeatedly — top k frequent, k closest points, kth largest in an array.
* **Mistakes to Avoid:**
  * Using a max-heap of everything: the k-th largest is then `k` pops away on every query.
  * Assuming `nums` has at least `k` elements at construction — it may have `k − 1` (the first `add` then fills it).

## 🔹 Optimization Path

* **Brute Force:** keep a sorted list (`bisect.insort`) and read index `-k` — O(n) per `add` because of shifting.
* **Optimized Solution:** size-k min-heap — O(log k) per `add`.
* **Further Improvements Possible?** No in the comparison model; O(log k) per update is the heap bound.

## 🔹 Solution Breakdown

* **Optimal Approach:** heapify `nums`, pop until size ≤ `k`; `add(val)`: `heappush`, then `heappop` if size > `k`; return `heap[0]`.
* **Why This Works?** The heap holds exactly the `k` largest values; the smallest of those is, by definition, the k-th largest overall.
* **Edge Cases Considered:**
  * Empty `nums` with `k = 1` — the first `add` returns its own value.
  * Duplicates — `[5, 5]` with `k = 2` has k-th largest `5`.

## 🔹 Tricks & Patterns Used

* **Opposite heap for "top k":** k largest → min-heap (evict the smallest); k smallest → max-heap.
* **`heappushpop` once full:** push-then-pop in one sift when the heap already has `k` items.

## 🔹 Alternative Data Structures

* `SortedList` / balanced BST — O(log n) insert but keeps everything.
* Counting array over the value range (`[-10⁴, 10⁴]`) — O(range) per query.

## 🔹 Complexity Analysis

* **Time Complexity:** O(n log n) construction (heapify + pops), O(log k) per `add`
* **Space Complexity:** O(k)

## 🔹 Code Snippet (Brute Force)

```python
import bisect
from typing import List


class KthLargest:

    def __init__(self, k: int, nums: List[int]):
        self.k = k
        self.ordered = sorted(nums)

    def add(self, val: int) -> int:
        bisect.insort(self.ordered, val)
        return self.ordered[-self.k]
```

## 🔹 Code Snippet (Optimized)

```python
import heapq
from typing import List


class KthLargest:

    def __init__(self, k: int, nums: List[int]):
        self.k = k
        self.heap = list(nums)
        heapq.heapify(self.heap)
        while len(self.heap) > k:
            heapq.heappop(self.heap)

    def add(self, val: int) -> int:
        if len(self.heap) < self.k:
            heapq.heappush(self.heap, val)
        else:
            heapq.heappushpop(self.heap, val)
        return self.heap[0]
```
