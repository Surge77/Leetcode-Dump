# 355. Design Twitter

**🔗 Link:** [LeetCode 355](https://leetcode.com/problems/design-twitter/)
**🟢 Status:** 🔄 Need Review


## 🔹 Problem Statement

Build a tiny Twitter: users post tweets, follow and unfollow each other, and ask for a news feed. The feed holds the 10 most recent tweet IDs written by the user or by anyone they follow, newest first. Each tweet ID is unique.

* **Example:** `["Twitter","postTweet","getNewsFeed","follow","postTweet","getNewsFeed","unfollow","getNewsFeed"]`, `[[],[1,5],[1],[1,2],[2,6],[1],[1,2],[1]]` → `[null,null,[5],null,null,[6,5],null,[5]]`
* **Constraints:** `1 ≤ userId, followerId, followeeId ≤ 500`; `0 ≤ tweetId ≤ 10⁴`; at most `3·10⁴` calls in total; a user never follows themself.

## 🔹 Quick Breakdown

* **Difficulty Level:** Medium
* **Main Approach:** **Per-user tweet lists + k-way merge.** Every tweet gets a global increasing timestamp and is appended to its author's list, so each list is already sorted by time. `getNewsFeed(u)` merges the lists of `u` and everyone `u` follows with a max-heap seeded with each list's newest tweet, popping at most 10 times.
* **Core Concept:** merge several sorted streams, but stop after the first 10 results — only the heads matter
* **When to Use This Pattern?** "Top/most recent k across many sorted sources" — merge k sorted lists, k smallest pairs, timelines, log merging.
* **Mistakes to Avoid:**
  * Forgetting the user's own tweets (the user is not in their own follow set).
  * `unfollow` of someone not followed — use `set.discard`, not `remove`.
  * Using `tweetId` as the time order: ids are arbitrary, recency is posting order.

## 🔹 Optimization Path

* **Brute Force:** one global list of `(user, tweet)`; scan it from newest to oldest keeping tweets from relevant users until 10 — O(total tweets) per feed.
* **Optimized Solution:** heap merge over the followees' lists — O(f + 10 log f) per feed, where `f` = number of followees.
* **Further Improvements Possible?** Each user's list only needs its last 10 tweets for the feed, so a capped deque bounds memory; fan-out-on-write (pushing into followers' feeds) trades write cost for O(1) reads.

## 🔹 Solution Breakdown

* **Optimal Approach:** `tweets[u] = [(time, id), ...]`, `following[u] = set()`. For the feed, push `(-time, id, user, index)` for each source's last tweet; pop, record, push that source's previous tweet.
* **Why This Works?** Each list is sorted by time, so the globally newest remaining tweet is always among the current heads; the heap returns it in O(log f).
* **Edge Cases Considered:**
  * A user with no tweets and no followees → `[]`.
  * Fewer than 10 tweets in total → return all, newest first.
  * Unfollow after follow removes those tweets from the feed immediately.

## 🔹 Tricks & Patterns Used

* **Global clock:** a single counter gives a total order of posts across users.
* **Lazy heads:** push only one element per source and advance it on pop — never materialize the merged list.

## 🔹 Alternative Data Structures

* `defaultdict(deque)` with `maxlen=10` per user — enough for a 10-item feed.
* Sorting all candidate tweets (up to 10 per source) — O(10f log(10f)), simpler and still fast at these limits.

## 🔹 Complexity Analysis

* **Time Complexity:** `postTweet`, `follow`, `unfollow` O(1); `getNewsFeed` O(f + 10 log f)
* **Space Complexity:** O(users + tweets + follow edges)

## 🔹 Code Snippet (Brute Force)

```python
from collections import defaultdict
from typing import List


class Twitter:

    def __init__(self):
        self.timeline = []
        self.following = defaultdict(set)

    def postTweet(self, userId: int, tweetId: int) -> None:
        self.timeline.append((userId, tweetId))

    def getNewsFeed(self, userId: int) -> List[int]:
        sources = self.following[userId] | {userId}
        feed = []
        for author, tweet in reversed(self.timeline):
            if author in sources:
                feed.append(tweet)
                if len(feed) == 10:
                    break
        return feed

    def follow(self, followerId: int, followeeId: int) -> None:
        self.following[followerId].add(followeeId)

    def unfollow(self, followerId: int, followeeId: int) -> None:
        self.following[followerId].discard(followeeId)
```

## 🔹 Code Snippet (Optimized)

```python
import heapq
from collections import defaultdict
from typing import List

FEED_SIZE = 10


class Twitter:

    def __init__(self):
        self.clock = 0
        self.tweets = defaultdict(list)  # user -> [(time, tweetId)], oldest first
        self.following = defaultdict(set)

    def postTweet(self, userId: int, tweetId: int) -> None:
        self.tweets[userId].append((self.clock, tweetId))
        self.clock += 1

    def getNewsFeed(self, userId: int) -> List[int]:
        heap = []
        for user in self.following[userId] | {userId}:
            posts = self.tweets.get(user)
            if posts:
                last = len(posts) - 1
                heap.append((-posts[last][0], posts[last][1], user, last))
        heapq.heapify(heap)
        feed = []
        while heap and len(feed) < FEED_SIZE:
            _, tweet, user, idx = heapq.heappop(heap)
            feed.append(tweet)
            if idx > 0:
                time, prev = self.tweets[user][idx - 1]
                heapq.heappush(heap, (-time, prev, user, idx - 1))
        return feed

    def follow(self, followerId: int, followeeId: int) -> None:
        self.following[followerId].add(followeeId)

    def unfollow(self, followerId: int, followeeId: int) -> None:
        self.following[followerId].discard(followeeId)
```
