# 292. Nim Game

**🔗 Link:** [LeetCode 292](https://leetcode.com/problems/nim-game/)
**🟢 Status:** 🔄 Need Review


## 🔹 Problem Statement

A heap of `n` stones; you and a friend alternate removing 1 to 3 stones, you go first, and whoever takes the last stone wins. Assuming optimal play from both, return whether you win.

* **Example:** `n = 4` → `false`
* **Constraints:** `1 ≤ n ≤ 2^31 - 1`

## 🔹 Quick Breakdown

* **Difficulty Level:** Easy
* **Main Approach:** You lose exactly when `n` is a multiple of 4: whatever you take (1–3), the opponent takes the rest of that 4.
* **Core Concept:** Winning / losing positions
* **When to Use This Pattern?** Two-player games with perfect information and no draws: find which positions are losing and prove the pattern.
* **Mistakes to Avoid:**
  * Simulating every game tree — `n` goes up to 2³¹ − 1.
  * Guessing a pattern without checking small cases by DP first.

## 🔹 Optimization Path

* **Brute Force:** `win[n] = any(not win[n - k])` for `k = 1..3` — O(n).
* **Optimized Solution:** O(1): `n % 4 != 0`.
* **Further Improvements Possible?** No.

## 🔹 Solution Breakdown

* **Optimal Approach:** Return `n % 4 != 0`.
* **Why This Works?** From a multiple of 4 every move leaves a non-multiple; from a non-multiple you can always move to a multiple of 4. The player facing 0 stones has lost, and 0 is a multiple of 4.
* **Edge Cases Considered:**
  * `n = 1, 2, 3` → win; `n = 4` → lose.

## 🔹 Code Snippet (Brute Force)

```python
class Solution:
    def canWinNim(self, n: int) -> bool:
        win = [False] * (n + 1)  # win[0] = False: no stones left, the mover has lost
        for i in range(1, n + 1):
            win[i] = any(not win[i - k] for k in (1, 2, 3) if i - k >= 0)
        return win[n]
```

## 🔹 Code Snippet (Optimized)

```python
class Solution:
    def canWinNim(self, n: int) -> bool:
        return n % 4 != 0  # multiples of 4 are the losing positions
```
