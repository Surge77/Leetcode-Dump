# 🔹 Problem Name: 1004. Max Consecutive Ones III (Sliding Window, Medium)

**🔗 Link:** [LeetCode 1004](https://leetcode.com/problems/max-consecutive-ones-iii/)
**🟢 Status:** 🔄 Need Review

## 🔹 Quick Breakdown

* **Difficulty Level:** Medium
* **Main Approach:** **Variable-size sliding window.** Rephrase "flip at most `k` zeros" as "longest subarray containing at most `k` zeros". Grow the right edge; when the window holds more than `k` zeros, move the left edge until it holds `k` again.
* **Core Concept:** longest window satisfying a condition that stays true when the window shrinks
* **When to Use This Pattern?** "Longest subarray/substring with at most K bad elements / K replacements / K distinct".
* **Mistakes to Avoid:**
  * Actually flipping values — only the zero count inside the window matters.
  * `k = 0`: the answer is the longest run of ones, which may be 0.

## 🔹 Optimization Path

* **Brute Force:** every start, extend while the zero count stays ≤ k — O(n²), 10¹⁰ steps at `n = 10⁵`.
* **Optimized Solution:** sliding window — O(n), O(1) space.
* **Further Improvements Possible?** The "never-shrinking window" variant moves `left` by at most one per step and returns `n − left`; same O(n).

## 🔹 Solution Breakdown

* **Optimal Approach:** `zeros += nums[right] == 0`; while `zeros > k`, `zeros -= nums[left] == 0` and `left += 1`; `best = max(best, right − left + 1)`.
* **Why This Works?** If `[l, r]` has ≤ k zeros, so does every sub-window, so for each `right` the smallest valid `left` never moves backwards. Checking the longest valid window ending at every `right` covers the optimum.
* **Edge Cases Considered:**
  * All zeros with `k ≥ n`: the whole array, answer `n`.
  * All ones: answer `n` for any `k`.

## 🔹 Tricks & Patterns Used

* **Count the "budget" inside the window:** zeros in the window = flips needed.
* **Booleans as ints:** `zeros += nums[right] == 0` adds 1 or 0.

## 🔹 Alternative Data Structures

* Queue of zero positions: when it exceeds `k`, jump `left` to one past the oldest zero.
* Prefix count of zeros + binary search for each `right`: O(n log n).

## 🔹 Complexity Analysis

* **Time Complexity:** O(n)
* **Space Complexity:** O(1)

## 🔹 Code Snippet (Brute Force)

```python
from typing import List


class Solution:
    def longestOnes(self, nums: List[int], k: int) -> int:
        best = 0
        for start in range(len(nums)):
            zeros = 0
            for end in range(start, len(nums)):
                zeros += nums[end] == 0
                if zeros > k:
                    break
                best = max(best, end - start + 1)
        return best
```

## 🔹 Code Snippet (Optimized)

```python
from typing import List


class Solution:
    def longestOnes(self, nums: List[int], k: int) -> int:
        left = zeros = best = 0
        for right, value in enumerate(nums):
            zeros += value == 0
            while zeros > k:
                zeros -= nums[left] == 0
                left += 1
            best = max(best, right - left + 1)
        return best
```
