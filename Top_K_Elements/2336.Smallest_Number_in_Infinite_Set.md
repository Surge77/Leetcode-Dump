# 2336. Smallest Number in Infinite Set

**🔗 Link:** [LeetCode 2336](https://leetcode.com/problems/smallest-number-in-infinite-set/)
**🟢 Status:** 🔄 Need Review


## 🔹 Problem Statement

Design a `SmallestInfiniteSet` that starts out holding every positive integer. `popSmallest()` removes and returns the smallest number currently in the set, and `addBack(num)` puts `num` back into the set unless it is already there.

* **Example:** `addBack(2), popSmallest(), popSmallest(), popSmallest(), addBack(1), popSmallest(), popSmallest(), popSmallest()` → `[null, 1, 2, 3, null, 1, 4, 5]` (the first `addBack(2)` changes nothing)
* **Constraints:** `1 ≤ num ≤ 1000`; at most `1000` calls in total to `popSmallest` and `addBack`

## 🔹 Quick Breakdown

* **Difficulty Level:** Medium
* **Main Approach:** **Counter + min-heap of returned numbers.** Every number `≥ next` is still untouched, so the set is "all integers from `next` upward plus whatever was added back". Keep `next` (smallest never-popped number) and a min-heap (with a membership set) for numbers below `next` that were added back.
* **Core Concept:** represent an infinite set by its finite exceptions
* **When to Use This Pattern?** "Smallest available id / slot / number" with release operations — id allocators, number containers, seat reservation.
* **Mistakes to Avoid:**
  * Pre-filling a list with all numbers up to 1000 and rescanning it: fine for the limits, but it does not model an infinite set and costs O(n) per pop.
  * Adding back a number that is still in the set (`num ≥ next`, or already in the heap) — the set must not get duplicates.

## 🔹 Optimization Path

* **Brute Force:** keep the set of removed numbers; `popSmallest` scans `1, 2, 3, …` for the first one not removed, `addBack` deletes from the removed set — O(n) per pop.
* **Optimized Solution:** `next` counter + heap + set — O(log n) per operation.
* **Further Improvements Possible?** With `num ≤ 1000` a sorted structure is unnecessary; O(log n) is already tiny.

## 🔹 Solution Breakdown

* **Optimal Approach:** `popSmallest`: if the heap is non-empty pop it (it is smaller than `next` by construction), otherwise return `next` and increment. `addBack(num)`: only if `num < next` and `num` is not already in the heap, push it.
* **Why This Works?** Numbers `≥ next` were never removed, so they are already in the set and need no storage. Numbers `< next` were popped at some point; they are present again exactly when they sit in the heap. The heap minimum is therefore the smallest returned number, which beats `next`.
* **Edge Cases Considered:**
  * `addBack` of a number that was never popped — ignored.
  * `addBack` of the same number twice before a pop — the set guard prevents duplicates.
  * Popping after the heap empties continues with `next`.

## 🔹 Tricks & Patterns Used

* **Frontier pointer:** one integer stands for infinitely many untouched elements.
* **Heap + set:** the heap gives the minimum, the set gives O(1) duplicate checks.

## 🔹 Alternative Data Structures

* A sorted set (`SortedList` / TreeSet) of returned numbers — `pop(0)` and `add` in O(log n); the heap + set pair is the standard-library version.
* A boolean array of size 1001 with a scan pointer reset on `addBack` — enough for the stated limits.

## 🔹 Complexity Analysis

* **Time Complexity:** `popSmallest` O(log n), `addBack` O(log n), with `n` the number of returned numbers (at most 1000)
* **Space Complexity:** O(n)

## 🔹 Code Snippet (Brute Force)

```python
class SmallestInfiniteSet:
    def __init__(self):
        self.removed = set()

    def popSmallest(self) -> int:
        n = 1
        while n in self.removed:
            n += 1
        self.removed.add(n)
        return n

    def addBack(self, num: int) -> None:
        self.removed.discard(num)
```

## 🔹 Code Snippet (Optimized)

```python
import heapq


class SmallestInfiniteSet:
    def __init__(self):
        self.next_untouched = 1
        self.returned = []
        self.in_returned = set()

    def popSmallest(self) -> int:
        if self.returned:
            num = heapq.heappop(self.returned)
            self.in_returned.discard(num)
            return num
        num = self.next_untouched
        self.next_untouched += 1
        return num

    def addBack(self, num: int) -> None:
        # Numbers >= next_untouched were never removed, so they are still in the set.
        if num < self.next_untouched and num not in self.in_returned:
            heapq.heappush(self.returned, num)
            self.in_returned.add(num)
```
