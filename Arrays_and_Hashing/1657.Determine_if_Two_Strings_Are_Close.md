# 1657. Determine if Two Strings Are Close

**🔗 Link:** [LeetCode 1657](https://leetcode.com/problems/determine-if-two-strings-are-close/)
**🟢 Status:** 🔄 Need Review


## 🔹 Problem Statement

Two strings are "close" if one can be turned into the other with two moves: swap any two characters, or relabel two existing letters so every occurrence of each becomes the other. Both moves can be used any number of times on either string. Return whether `word1` and `word2` are close.

* **Example:** `word1 = "abc", word2 = "bca"` → `true`
* **Constraints:** `1 ≤ word1.length, word2.length ≤ 10^5`; both strings contain only lowercase English letters

## 🔹 Quick Breakdown

* **Difficulty Level:** Medium
* **Main Approach:** **Reduce the two operations to invariants.** Swapping any two characters means order is irrelevant. Swapping the *identities* of two letters (all `a` ↔ all `b`) means only the multiset of frequencies matters, but the **set of letters** used must stay the same. So the strings are close iff they use the same set of letters and the same sorted list of counts.
* **Core Concept:** turn an operation-reachability question into two checkable invariants
* **When to Use This Pattern?** "Can A be transformed into B using these moves" where the moves generate a group — find what the moves can *not* change, then test just that.
* **Mistakes to Avoid:**
  * Comparing sorted counts only: `"aab"` vs `"bbc"` has counts `[1, 2]` on both sides, but `c` never appears in the first, and no move can create a new letter.
  * Forgetting the length check — it is implied by equal count multisets, but cheap to test first.

## 🔹 Optimization Path

* **Brute Force:** BFS over every string reachable from `word1` with the two operations, check whether `word2` appears. The state space is factorial-sized.
* **Optimized Solution:** compare the letter sets and the sorted frequency lists — O(n + σ log σ).
* **Further Improvements Possible?** No; the alphabet is 26 letters, so the sort is constant time.

## 🔹 Solution Breakdown

* **Optimal Approach:** `Counter` each word; require `set(c1) == set(c2)` and `sorted(c1.values()) == sorted(c2.values())`.
* **Why This Works?** Operation 1 permutes positions arbitrarily (any permutation is a product of swaps). Operation 2 permutes counts among the letters that already exist. So reachable words are exactly those with the same letter set and a permutation of the same counts, and operation 2 can realise any such permutation.
* **Edge Cases Considered:**
  * Different lengths → `False` (the optimized code gets this for free: the count multisets cannot match).
  * Same counts, different letters (`"abc"` vs `"abd"`) → `False`.
  * Identical strings → `True`.

## 🔹 Tricks & Patterns Used

* **Invariant thinking:** list what each operation preserves (positions are free, counts move between existing letters) and compare only those.

## 🔹 Alternative Data Structures

* Two arrays of 26 counters: check that `(c1[i] > 0) == (c2[i] > 0)` for every letter, then compare the sorted arrays.

## 🔹 Complexity Analysis

* **Time Complexity:** O(n) to count, plus O(σ log σ) to sort, σ = 26
* **Space Complexity:** O(σ) = O(1)

## 🔹 Code Snippet (Brute Force)

```python
from collections import deque


class Solution:
    def closeStrings(self, word1: str, word2: str) -> bool:
        if len(word1) != len(word2):
            return False
        seen = {word1}
        queue = deque([word1])
        while queue:
            word = queue.popleft()
            if word == word2:
                return True
            chars = sorted(set(word))
            neighbours = []
            for i in range(len(word)):
                for j in range(i + 1, len(word)):
                    swapped = list(word)
                    swapped[i], swapped[j] = swapped[j], swapped[i]
                    neighbours.append("".join(swapped))
            for a in chars:
                for b in chars:
                    if a < b:
                        table = {a: b, b: a}
                        neighbours.append("".join(table.get(c, c) for c in word))
            for nxt in neighbours:
                if nxt not in seen:
                    seen.add(nxt)
                    queue.append(nxt)
        return False
```

## 🔹 Code Snippet (Optimized)

```python
from collections import Counter


class Solution:
    def closeStrings(self, word1: str, word2: str) -> bool:
        c1, c2 = Counter(word1), Counter(word2)
        # operation 2 only reshuffles counts among letters that already exist
        return set(c1) == set(c2) and sorted(c1.values()) == sorted(c2.values())
```
