# 🔹 Problem Name: 1334. Find the City With the Smallest Number of Neighbors at a Threshold Distance (Floyd-Warshall, Medium)

**🔗 Link:** [LeetCode 1334](https://leetcode.com/problems/find-the-city-with-the-smallest-number-of-neighbors-at-a-threshold-distance/)
**🟢 Status:** 🔄 Need Review

## 🔹 Problem Statement

Cities `0..n-1` are joined by weighted bidirectional roads. For each city count how many other cities are reachable with a total path weight of at most `distanceThreshold`. Return the city with the fewest such neighbours, choosing the largest index if several tie.

* **Example:** `n = 4, edges = [[0,1,3],[1,2,1],[1,3,4],[2,3,1]], distanceThreshold = 4` → `3`
* **Constraints:** `2 ≤ n ≤ 100`, `1 ≤ weight, distanceThreshold ≤ 10^4`, all `(from, to)` pairs distinct

## 🔹 Quick Breakdown

* **Difficulty Level:** Medium
* **Main Approach:** All-pairs shortest paths with Floyd-Warshall (n ≤ 100), then count reachable cities within the threshold for each city; ties go to the larger index.
* **Core Concept:** Floyd-Warshall (all-pairs shortest paths)
* **When to Use This Pattern?** Small `n` (≤ 400) and you need distances between **every** pair; also transitive closure ("can i reach j?").
* **Mistakes to Avoid:**
  * Wrong loop order — the intermediate node `k` **must** be the outer loop.
  * Tie-break: return the **largest** index among cities with the minimum count.

## 🔹 Optimization Path

* **Brute Force:** BFS/DFS enumerating paths — wrong for weighted graphs or exponential.
* **Optimized Solution:** Floyd-Warshall O(n³).
* **Further Improvements Possible?** Dijkstra from every node — O(n · E log n), better for sparse graphs.

## 🔹 Solution Breakdown

* **Optimal Approach:** `d[i][j] = min(d[i][j], d[i][k] + d[k][j])` for `k`, then `i`, then `j`.
* **Why This Works?** After processing `k`, `d[i][j]` is the shortest path using only nodes `0..k` as intermediates (induction on `k`).
* **Edge Cases Considered:**
  * Disconnected cities (stay at infinity).
  * Several cities with the same count.

## 🔹 Tricks & Patterns Used

* **Hoist `d[i][k]`** out of the inner loop — big speed-up in Python.
* **Iterate cities in increasing order with `<=`** to make the last minimum (largest index) win.

## 🔹 Alternative Data Structures

* Dijkstra per source with a heap.

## 🔹 Complexity Analysis

* **Time Complexity:** O(n³)
* **Space Complexity:** O(n²)

## 🔹 Code Snippet (Brute Force)

```python
from typing import List


class Solution:
    def findTheCity(self, n: int, edges: List[List[int]], distanceThreshold: int) -> int:
        adj = [[] for _ in range(n)]
        for u, v, w in edges:
            adj[u].append((v, w))
            adj[v].append((u, w))

        def reachable(src):
            # enumerate every simple path from src that stays within the threshold
            seen = {src}
            on_path = [False] * n
            on_path[src] = True

            def dfs(u, dist):
                for v, w in adj[u]:
                    if not on_path[v] and dist + w <= distanceThreshold:
                        seen.add(v)
                        on_path[v] = True
                        dfs(v, dist + w)
                        on_path[v] = False

            dfs(src, 0)
            return len(seen) - 1

        best_city, best_count = -1, float("inf")
        for i in range(n):
            count = reachable(i)
            if count <= best_count:  # '<=' => larger index wins ties
                best_city, best_count = i, count
        return best_city
```

## 🔹 Code Snippet (Optimized)

```python
from typing import List


class Solution:
    def findTheCity(self, n: int, edges: List[List[int]], distanceThreshold: int) -> int:
        INF = float("inf")
        d = [[0 if i == j else INF for j in range(n)] for i in range(n)]
        for u, v, w in edges:
            d[u][v] = d[v][u] = min(d[u][v], w)

        for k in range(n):  # k MUST be the outer loop
            dk = d[k]
            for i in range(n):
                dik = d[i][k]
                if dik == INF:
                    continue
                di = d[i]
                for j in range(n):
                    if dik + dk[j] < di[j]:
                        di[j] = dik + dk[j]

        best_city, best_count = -1, INF
        for i in range(n):
            count = sum(1 for j in range(n) if j != i and d[i][j] <= distanceThreshold)
            if count <= best_count:  # '<=' => larger index wins ties
                best_city, best_count = i, count
        return best_city
```
