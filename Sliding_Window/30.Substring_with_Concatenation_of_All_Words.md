# 30. Substring with Concatenation of All Words

**🔗 Link:** [LeetCode 30](https://leetcode.com/problems/substring-with-concatenation-of-all-words/)
**🟢 Status:** 🔄 Need Review


## 🔹 Problem Statement

You get a string `s` and a list `words` whose strings all have the same length. A substring of `s` counts if it is some ordering of all the words in `words` (duplicates included) joined together with nothing in between. Return every starting index of such a substring, in any order.

* **Example:** `s = "barfoothefoobarman"`, `words = ["foo","bar"]` → `[0,9]`
* **Constraints:** `1 ≤ s.length ≤ 10^4`, `1 ≤ words.length ≤ 5000`, `1 ≤ words[i].length ≤ 30`, lowercase letters only

## 🔹 Quick Breakdown

* **Difficulty Level:** Hard
* **Main Approach:** **Word-level sliding window, once per offset.** All words have the same length `w`, so a valid start `i` cuts `s` into words at `i, i + w, i + 2w, …`. Split the starts by `i % w`: for each of the `w` offsets, slide a window **of whole words** over that chain, keeping a counter of words in the window. Shrink from the left while some word is over-used; reset when a word is not in `words` at all; record `left` whenever the window holds exactly `k = len(words)` words.
* **Core Concept:** reduce a string problem to a sliding window over tokens, with `w` independent token streams
* **When to Use This Pattern?** Fixed-length tokens and "a window that is a permutation / multiset of a given bag" — 438/567 with words instead of characters.
* **Mistakes to Avoid:**
  * `words` can contain duplicates — compare counts, not sets.
  * Restarting the window from scratch at every start: O(n · k · w).
  * Forgetting the reset when a word is not in `words`: no window can span it.

## 🔹 Optimization Path

* **Brute Force:** for every start, cut `k` words and compare with the needed counter — O(n · k · w).
* **Optimized Solution:** `w` word-level sliding windows — every word position enters and leaves a window at most once: O(n · w) (the `w` is the cost of slicing/hashing one word).
* **Further Improvements Possible?** Rolling hashes can make each word lookup O(1), giving O(n) expected, but the slicing version is what is expected.

## 🔹 Solution Breakdown

* **Optimal Approach:** `need = Counter(words)`. For each `offset < w`: `left = offset`, `seen = Counter()`, `count = 0`; for `right` in `offset, offset + w, …`: take `word = s[right:right + w]`. If it is not needed, clear `seen`, `count = 0`, `left = right + w`. Otherwise add it, and while `seen[word] > need[word]` drop the word at `left`. If `count == k`, record `left`.
* **Why This Works?** Within one offset chain the window is a contiguous run of words. A window with an over-used word stays invalid for every extension to the right, so dropping from the left loses nothing; once all counts are ≤ needed, `count == k` means the counts are **equal**, i.e. the window is a permutation of `words`. Every valid start belongs to exactly one offset chain.
* **Edge Cases Considered:**
  * `k · w > len(s)` → no window fits, result `[]`.
  * Duplicate words (`["word", "good", "best", "word"]`).
  * Overlapping answers (`"aaaa"`, `["a", "a"]` → `[0, 1, 2]`) — after recording, the window just keeps sliding.

## 🔹 Tricks & Patterns Used

* **Split by residue:** windows aligned to `i % w` never interact, so run `w` separate passes.
* **"Count ≤ need for every key" + "total = k" ⇒ exact match** — no need to compare whole counters.

## 🔹 Alternative Data Structures

* Map each word to an integer id first, then slide over integer arrays — avoids re-hashing strings in the inner loop.
* Rolling hash (Rabin–Karp) for the word ids at each position.

## 🔹 Complexity Analysis

* **Time Complexity:** O(n · w), n ≤ 10⁴, w ≤ 30 (plus O(k · w) to build `need`)
* **Space Complexity:** O(k · w) for the counters

## 🔹 Code Snippet (Brute Force)

```python
from collections import Counter
from typing import List


class Solution:
    def findSubstring(self, s: str, words: List[str]) -> List[int]:
        w, k = len(words[0]), len(words)
        need = Counter(words)
        return [i for i in range(len(s) - k * w + 1)
                if Counter(s[i + j * w:i + (j + 1) * w] for j in range(k)) == need]
```

## 🔹 Code Snippet (Optimized)

```python
from collections import Counter
from typing import List


class Solution:
    def findSubstring(self, s: str, words: List[str]) -> List[int]:
        w, k, n = len(words[0]), len(words), len(s)
        need = Counter(words)
        result = []
        for offset in range(w):
            left, count, seen = offset, 0, Counter()
            for right in range(offset, n - w + 1, w):
                word = s[right:right + w]
                if word not in need:  # no valid window can contain this word
                    seen.clear()
                    count, left = 0, right + w
                    continue
                seen[word] += 1
                count += 1
                while seen[word] > need[word]:
                    seen[s[left:left + w]] -= 1
                    count -= 1
                    left += w
                if count == k:
                    result.append(left)
        return result
```
