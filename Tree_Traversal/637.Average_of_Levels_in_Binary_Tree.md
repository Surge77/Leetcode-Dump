# 🔹 Problem Name: 637. Average of Levels in Binary Tree (Tree BFS, Easy)

**🔗 Link:** [LeetCode 637](https://leetcode.com/problems/average-of-levels-in-binary-tree/)
**🟢 Status:** 🔄 Need Review

## 🔹 Quick Breakdown

* **Difficulty Level:** Easy
* **Main Approach:** **Level-order BFS.** Keep the current level as a list; its average is `sum / len`; the next level is all non-null children of the current one, left to right.
* **Core Concept:** BFS processed one whole level at a time gives per-level aggregates directly
* **When to Use This Pattern?** Any "per level / per row of the tree" question — averages, maxima, right side view, zigzag order, level sums.
* **Mistakes to Avoid:**
  * Integer overflow in Java/C++: values reach `2³¹ − 1` and a level can hold ~5000 of them — sum in `long`/`double`. Python ints are unbounded.
  * Integer division (`//`, or `int / int` in Java): the answer is a float.
  * Mixing levels in one queue without remembering the level size.

## 🔹 Optimization Path

* **Brute Force:** for each depth `d`, walk the tree from the root again and collect the nodes at depth `d` — O(n·h).
* **Optimized Solution:** one BFS, each node touched once — O(n).
* **Further Improvements Possible?** No; every value is part of an average.

## 🔹 Solution Breakdown

* **Optimal Approach:** `level = [root]`; while non-empty: append `sum(values) / len(level)`, then replace `level` by its children.
* **Why This Works?** The children of all depth-`d` nodes are exactly the depth-`d + 1` nodes, so each list is one complete level.
* **Edge Cases Considered:**
  * Single node → `[root.val]`.
  * Large equal values (`2³¹ − 1` everywhere) — exact in Python, overflow elsewhere.
  * Answers within 10⁻⁵ are accepted, so float rounding is not a concern.

## 🔹 Tricks & Patterns Used

* **Level as a list:** rebuilding the list per level replaces the `for _ in range(len(queue))` idiom and keeps levels separate by construction.

## 🔹 Alternative Data Structures

* `deque` with the level-size loop — the classic form, same complexity.
* DFS with per-depth `sums[d]` and `counts[d]` arrays — O(n) too, but needs recursion or an explicit stack with depths.

## 🔹 Complexity Analysis

* **Time Complexity:** O(n)
* **Space Complexity:** O(w), the widest level (up to ~n/2)

## 🔹 Code Snippet (Brute Force)

```python
from typing import List, Optional


class Solution:
    def averageOfLevels(self, root: Optional[TreeNode]) -> List[float]:
        averages, depth = [], 0
        while True:
            values, stack = [], [(root, 0)]
            while stack:  # re-walk the top of the tree for every level
                node, d = stack.pop()
                if node is None:
                    continue
                if d == depth:
                    values.append(node.val)
                else:
                    stack += [(node.left, d + 1), (node.right, d + 1)]
            if not values:
                return averages
            averages.append(sum(values) / len(values))
            depth += 1
```

## 🔹 Code Snippet (Optimized)

```python
from typing import List, Optional


class Solution:
    def averageOfLevels(self, root: Optional[TreeNode]) -> List[float]:
        averages, level = [], [root]
        while level:
            averages.append(sum(node.val for node in level) / len(level))
            level = [child for node in level for child in (node.left, node.right) if child]
        return averages
```
