# 🔹 Problem Name: 987. Vertical Order Traversal of a Binary Tree (Tree DFS and Sorting, Hard)

**🔗 Link:** [LeetCode 987](https://leetcode.com/problems/vertical-order-traversal-of-a-binary-tree/)
**🟢 Status:** 🔄 Need Review

## 🔹 Quick Breakdown

* **Difficulty Level:** Hard
* **Main Approach:** **Tag every node with `(col, row, val)` and sort once.** The root is at `(row 0, col 0)`; a left child is at `(row + 1, col − 1)`, a right child at `(row + 1, col + 1)`. The required output order — columns left to right, then rows top to bottom, then values for nodes sharing a cell — is exactly the lexicographic order of `(col, row, val)`. Group the sorted list by column.
* **Core Concept:** encode a multi-key ordering rule as a tuple and let one sort do all the tie-breaking
* **When to Use This Pattern?** Output must be grouped/ordered by coordinates computed during a traversal — vertical order, top/bottom view, diagonal traversal.
* **Mistakes to Avoid:**
  * Sorting each column by value only: nodes must stay top-to-bottom by row; values break ties only inside the **same** `(row, col)` cell.
  * Plain BFS order without sorting (that is premium problem 314's rule): here two nodes in the same cell must be ordered by value, BFS gives them in left-to-right order.
  * Assuming columns can be skipped: they cannot, see below.

## 🔹 Optimization Path

* **Brute Force:** for every column, for every row, scan all nodes and sort the ones in that cell — O(W·H·n), ~10⁹ on a 1000-node path.
* **Optimized Solution:** one traversal + one sort — O(n log n).
* **Further Improvements Possible?** Coordinates and values are all below ~1000, so a radix/counting sort on `(col, row, val)` would be O(n + 1000) — not worth the code for `n ≤ 1000`.

## 🔹 Solution Breakdown

* **Optimal Approach:** iterative DFS collecting `(col, row, val)`; `cells.sort()`; `groupby` on `col`.
* **Why This Works?** Tuple comparison checks `col` first, then `row`, then `val`, which is the problem's rule word for word. Columns between the extremes are never empty: each step changes the column by exactly 1, so the path from the root to any node at column `c` crosses every column between 0 and `c`.
* **Edge Cases Considered:**
  * Two nodes in the same cell (e.g. a left-right and a right-left grandchild) → smaller value first.
  * Single node → `[[root.val]]`.
  * Deep path of 1000 nodes — iterative traversal, no recursion limit.

## 🔹 Tricks & Patterns Used

* **Tuple keys as a sort spec:** put the fields in priority order and no comparator is needed.
* **`itertools.groupby` on a sorted list:** groups consecutive equal keys in one pass.

## 🔹 Alternative Data Structures

* `defaultdict(list)` keyed by column, then sort each column's `(row, val)` list and iterate columns from `min` to `max`.
* A heap of `(col, row, val)` popped in order — same O(n log n), more code.

## 🔹 Complexity Analysis

* **Time Complexity:** O(n log n)
* **Space Complexity:** O(n)

## 🔹 Code Snippet (Brute Force)

```python
from typing import List, Optional


class Solution:
    def verticalTraversal(self, root: Optional[TreeNode]) -> List[List[int]]:
        cells, stack = [], [(root, 0, 0)]
        while stack:
            node, row, col = stack.pop()
            if node:
                cells.append((row, col, node.val))
                stack += [(node.left, row + 1, col - 1), (node.right, row + 1, col + 1)]
        cols = [c for _, c, _ in cells]
        deepest = max(r for r, _, _ in cells)
        report = []
        for col in range(min(cols), max(cols) + 1):
            column = []
            for row in range(deepest + 1):
                column += sorted(v for r, c, v in cells if r == row and c == col)
            report.append(column)
        return report
```

## 🔹 Code Snippet (Optimized)

```python
from itertools import groupby
from typing import List, Optional


class Solution:
    def verticalTraversal(self, root: Optional[TreeNode]) -> List[List[int]]:
        cells, stack = [], [(root, 0, 0)]
        while stack:
            node, row, col = stack.pop()
            if node:
                cells.append((col, row, node.val))
                stack += [(node.left, row + 1, col - 1), (node.right, row + 1, col + 1)]
        cells.sort()  # column, then row, then value: the problem's ordering rule as a tuple
        return [[val for _, _, val in group] for _, group in groupby(cells, key=lambda cell: cell[0])]
```
