# 🔹 Problem Name: 307. Range Sum Query - Mutable (Segment Tree, Medium)

**🔗 Link:** [LeetCode 307](https://leetcode.com/problems/range-sum-query-mutable/)
**🟢 Status:** 🔄 Need Review

## 🔹 Quick Breakdown

* **Difficulty Level:** Medium
* **Main Approach:** Iterative (bottom-up) segment tree: leaves at `tree[n + i]`, each parent `tree[i] = tree[2i] + tree[2i+1]`. Update walks up from a leaf; a query walks two pointers up from both ends.
* **Core Concept:** Segment tree — point update, range query
* **When to Use This Pattern?** Range sum/min/max/gcd queries **mixed with updates**. Prefix sums break on updates (O(n) each); a segment tree does both in O(log n). Named in Infosys SP hard-question topics.
* **Mistakes to Avoid:**
  * Using a prefix-sum array — every update becomes O(n).
  * Off-by-one between inclusive `right` and the half-open loop `[l, r)`.

## 🔹 Optimization Path

* **Brute Force:** O(1) update, O(n) query (or the reverse with prefix sums).
* **Optimized Solution:** O(log n) for both.
* **Further Improvements Possible?** Fenwick tree — same complexity, shorter code, but only for invertible operations (sum, xor), not min/max.

## 🔹 Solution Breakdown

* **Optimal Approach:**
  * build: copy `nums` to `tree[n:]`, then fill parents from `n-1` down to 1
  * update: set the leaf, recompute ancestors
  * query `[l, r)`: if `l` is a right child take it and move right; if `r` is a right boundary take `r-1`; then go up one level
* **Why This Works?** Any range splits into O(log n) disjoint tree nodes; the two-pointer climb collects exactly those nodes.
* **Edge Cases Considered:**
  * Single element.
  * Repeated updates to the same index.
  * Negative values.

## 🔹 Tricks & Patterns Used

* **Iterative segment tree in a `2n` array** — no recursion, works for any `n` (not only powers of two) for commutative operations.
* Change `+` to `max`/`min`/`gcd` and the identity `0` to `-inf`/`inf`/`0` for other range queries.

## 🔹 Alternative Data Structures

* **Fenwick (BIT):** `update(i, delta)`, `prefix(i)`; range sum = `prefix(r) - prefix(l-1)`.
* **Sqrt decomposition:** O(√n) per operation — easier to adapt to odd operations.

## 🔹 Complexity Analysis

* **Time Complexity:** O(n) build, O(log n) per update/query
* **Space Complexity:** O(n)

## 🔹 Code Snippet (Optimized)

```python
from typing import List


class NumArray:
    def __init__(self, nums: List[int]):
        self.n = n = len(nums)
        self.tree = [0] * n + list(nums)  # leaves live at tree[n .. 2n-1]
        for i in range(n - 1, 0, -1):
            self.tree[i] = self.tree[2 * i] + self.tree[2 * i + 1]

    def update(self, index: int, val: int) -> None:
        i = index + self.n
        self.tree[i] = val
        while i > 1:
            i //= 2
            self.tree[i] = self.tree[2 * i] + self.tree[2 * i + 1]

    def sumRange(self, left: int, right: int) -> int:
        total = 0
        l, r = left + self.n, right + self.n + 1  # half-open [l, r)
        while l < r:
            if l & 1:  # l is a right child: take it, step past it
                total += self.tree[l]
                l += 1
            if r & 1:  # r-1 is a left child: take it
                r -= 1
                total += self.tree[r]
            l //= 2
            r //= 2
        return total
```
