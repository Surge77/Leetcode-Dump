# 🔹 Problem Name: 1092. Shortest Common Supersequence (LCS DP, Hard)

**🔗 Link:** [LeetCode 1092](https://leetcode.com/problems/shortest-common-supersequence/)
**🟢 Status:** 🔄 Need Review

## 🔹 Quick Breakdown

* **Difficulty Level:** Hard
* **Main Approach:** **LCS table + backtrack.** The shortest common supersequence writes each LCS character once and every other character of both strings once: length `n + m − LCS`. Build the suffix LCS table `lcs[i][j]` (for `a[i:]`, `b[j:]`), then walk from `(0, 0)`: equal characters → emit once and move both; otherwise emit the character from the side whose move keeps the larger LCS. Append the leftover tail.
* **Core Concept:** reconstructing a string from a DP table by replaying the decisions
* **When to Use This Pattern?** "Return the actual string/sequence", not just its length — print LCS, print SCS, edit-distance alignment.
* **Mistakes to Avoid:**
  * Building strings inside every DP cell: O(n·m·(n+m)) memory/time — store lengths, reconstruct once.
  * Forgetting the leftover suffix of one string once the other is exhausted.
  * Recursive reconstruction at `n = m = 1000` — up to 2000 frames; use a loop.

## 🔹 Optimization Path

* **Brute Force:** recursion choosing "take from `a`" / "take from `b`" (or both when equal), no memo — exponential.
* **Optimized Solution:** LCS DP O(n·m) + O(n + m) walk.
* **Further Improvements Possible?** Hirschberg's divide and conquer reconstructs in O(n + m) memory with the same time; not needed for 10⁶ cells.

## 🔹 Solution Breakdown

* **Optimal Approach:** suffix table so the walk goes forwards and the result needs no reversal. At `(i, j)` with `a[i] != b[j]`: if `lcs[i + 1][j] >= lcs[i][j + 1]`, emit `a[i]`, else emit `b[j]`.
* **Why This Works?** `scs(i, j) = n − i + m − j − lcs(i, j)`. Emitting `a[i]` costs one character and leads to `scs(i + 1, j)`; this is optimal exactly when `lcs(i + 1, j) = lcs(i, j)`, which is what the larger-LCS choice guarantees. On equal characters, sharing one character is always optimal.
* **Edge Cases Considered:**
  * Identical strings → the string itself.
  * No common character → plain concatenation (any interleaving works).
  * Several valid answers exist — LeetCode accepts any.

## 🔹 Code Snippet (Brute Force)

```python
class Solution:
    def shortestCommonSupersequence(self, str1: str, str2: str) -> str:
        def build(i: int, j: int) -> str:
            if i == len(str1):
                return str2[j:]
            if j == len(str2):
                return str1[i:]
            if str1[i] == str2[j]:
                return str1[i] + build(i + 1, j + 1)
            take_first = str1[i] + build(i + 1, j)
            take_second = str2[j] + build(i, j + 1)
            return min(take_first, take_second, key=len)

        return build(0, 0)
```

## 🔹 Code Snippet (Optimized)

```python
class Solution:
    def shortestCommonSupersequence(self, str1: str, str2: str) -> str:
        n, m = len(str1), len(str2)
        lcs = [[0] * (m + 1) for _ in range(n + 1)]
        for i in range(n - 1, -1, -1):
            for j in range(m - 1, -1, -1):
                if str1[i] == str2[j]:
                    lcs[i][j] = lcs[i + 1][j + 1] + 1
                else:
                    lcs[i][j] = max(lcs[i + 1][j], lcs[i][j + 1])

        out = []
        i = j = 0
        while i < n and j < m:
            if str1[i] == str2[j]:
                out.append(str1[i])
                i += 1
                j += 1
            elif lcs[i + 1][j] >= lcs[i][j + 1]:  # dropping str1[i] from the LCS costs nothing
                out.append(str1[i])
                i += 1
            else:
                out.append(str2[j])
                j += 1
        return "".join(out) + str1[i:] + str2[j:]
```
