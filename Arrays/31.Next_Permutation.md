# 🔹 Problem Name: 31. Next Permutation (Suffix Scan, Medium)

**🔗 Link:** [LeetCode 31](https://leetcode.com/problems/next-permutation/)
**🟢 Status:** 🔄 Need Review

## 🔹 Quick Breakdown

* **Difficulty Level:** Medium
* **Main Approach:** **Pivot, swap, reverse.** From the right, find the first `i` with `nums[i] < nums[i + 1]` (the pivot). Swap it with the rightmost element greater than it, then reverse the suffix after `i`. If no pivot exists the array is the last permutation — reverse it all.
* **Core Concept:** the longest non-increasing suffix is already at its largest arrangement; the next permutation must bump the element just before it by the smallest possible amount and reset the suffix to its smallest arrangement
* **When to Use This Pattern?** Lexicographic successor of a sequence — next permutation, next greater number with the same digits (556), iterating permutations without recursion, k-th permutation by repeated steps.
* **Mistakes to Avoid:**
  * Strict comparisons where non-strict ones are needed, which breaks on duplicates: a pivot scan with `>` finds a "pivot" in `[1, 1]`; a partner scan with `<` swaps equal values, so `[1, 5, 1]` gives `[1, 1, 5]` instead of `[5, 1, 1]`.
  * Sorting the suffix: correct but O(n log n); it is already non-increasing, so a reverse sorts it.
  * Forgetting the wrap-around: `[3, 2, 1]` → `[1, 2, 3]`.

## 🔹 Optimization Path

* **Brute Force:** generate all distinct permutations in sorted order, find the current one, take the next (wrapping) — O(n! · n).
* **Optimized Solution:** pivot / swap / reverse — O(n) time, O(1) extra space.
* **Further Improvements Possible?** No; the suffix scan may have to read the whole array.

## 🔹 Solution Breakdown

* **Optimal Approach:** `i` = last index with `nums[i] < nums[i + 1]`; `j` = last index with `nums[j] > nums[i]`; swap; reverse `nums[i + 1:]`.
* **Why This Works?** Everything left of `i` must stay (changing it would jump further than necessary). Position `i` must grow, by the least amount: the smallest suffix value larger than `nums[i]`, which is the rightmost such value because the suffix is non-increasing. After the swap the suffix is still non-increasing, so reversing it yields its smallest order.
* **Edge Cases Considered:**
  * Single element → unchanged.
  * Fully non-increasing (`[3, 2, 1]`, `[1, 1]`) → no pivot, reverse everything.
  * Duplicates (`[1, 1, 5]` → `[1, 5, 1]`).

## 🔹 Tricks & Patterns Used

* **Reverse a sorted-descending run to sort it ascending** in O(n).
* **Rightmost greater element** in a non-increasing suffix = the smallest value greater than the pivot.

## 🔹 Alternative Data Structures

* `itertools.permutations` on the sorted values — emits permutations in lexicographic order, but needs all `n!` of them.
* Binary search for `j` in the non-increasing suffix — O(log n) for the search, but the reverse keeps it O(n) overall.

* **Time Complexity:** O(n)
* **Space Complexity:** O(1)

## 🔹 Code Snippet (Brute Force)

```python
from itertools import permutations
from typing import List


class Solution:
    def nextPermutation(self, nums: List[int]) -> None:
        orders = sorted(set(permutations(nums)))
        at = orders.index(tuple(nums))
        nums[:] = orders[(at + 1) % len(orders)]
```

## 🔹 Code Snippet (Optimized)

```python
from typing import List


class Solution:
    def nextPermutation(self, nums: List[int]) -> None:
        i = len(nums) - 2
        while i >= 0 and nums[i] >= nums[i + 1]:
            i -= 1
        if i >= 0:
            j = len(nums) - 1
            while nums[j] <= nums[i]:
                j -= 1
            nums[i], nums[j] = nums[j], nums[i]
        lo, hi = i + 1, len(nums) - 1  # i = -1 when there is no pivot: reverse everything
        while lo < hi:
            nums[lo], nums[hi] = nums[hi], nums[lo]
            lo += 1
            hi -= 1
```
