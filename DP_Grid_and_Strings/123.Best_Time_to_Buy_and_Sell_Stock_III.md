# 123. Best Time to Buy and Sell Stock III

**🔗 Link:** [LeetCode 123](https://leetcode.com/problems/best-time-to-buy-and-sell-stock-iii/)
**🟢 Status:** 🔄 Need Review


## 🔹 Problem Statement

`prices[i]` is a stock's price on day `i`. You may complete at most two buy-then-sell transactions, and you must sell before buying again (no overlapping holdings). Return the maximum total profit, which is `0` if no profitable trade exists.

* **Example:** `prices = [3,3,5,0,0,3,1,4]` → `6`
* **Constraints:** `1 ≤ prices.length ≤ 10⁵`; `0 ≤ prices[i] ≤ 10⁵`.

## 🔹 Quick Breakdown

* **Difficulty Level:** Hard
* **Main Approach:** **Four running states.** `buy1` = best cash after the first buy, `sell1` = after the first sell, `buy2` = after the second buy, `sell2` = after the second sell. For each price: `buy1 = max(buy1, −p)`, `sell1 = max(sell1, buy1 + p)`, `buy2 = max(buy2, sell1 − p)`, `sell2 = max(sell2, buy2 + p)`.
* **Core Concept:** "at most two transactions, never holding two at once" is a small state machine; each state keeps the best cash reachable in it so far.
* **When to Use This Pattern?** Stock problems with a limit on transactions, cooldowns or fees — anything where the only thing that matters about the past is "which phase am I in".
* **Mistakes to Avoid:**
  * Taking the two largest single-transaction profits — they may overlap in time.
  * Summing every positive daily gain — that is 122 (unlimited transactions).
  * Starting `buy1` / `buy2` at `0` instead of `−∞` (or `−prices[0]`): you cannot be holding before buying.

## 🔹 Optimization Path

* **Brute Force:** try every split day `k`: best single trade in `prices[:k+1]` + best single trade in `prices[k:]` — O(n²).
* **Better:** precompute the best single trade ending by day `k` (left pass) and starting from day `k` (right pass) — O(n) time, O(n) space.
* **Optimized Solution:** the four-state machine — O(n) time, O(1) space.

## 🔹 Solution Breakdown

* **Optimal Approach:** one pass, updating `buy1 → sell1 → buy2 → sell2` in that order with the current price; return `sell2`.
* **Why This Works?** Every strategy with ≤ 2 trades is a walk through the phases *none → holding #1 → sold #1 → holding #2 → sold #2*, and each phase's best value only needs the previous phase's best value. Updating in order on the same day means a state can use a transition made earlier that day — equivalent to buying and selling on the same day, which earns `0` and never beats a valid strategy, so it does not inflate the answer. `sell2 ≥ sell1 ≥ 0` because `buy2 + p` can reuse `sell1`, so "fewer than two trades" is covered.
* **Edge Cases Considered:**
  * Strictly falling prices → `0` (no trade).
  * One rising run (`[1,2,3,4,5]`) → one trade, `4`; splitting it gives the same total.
  * `n = 1` → `0`.

## 🔹 Tricks & Patterns Used

* **Cash-as-state:** store "best money in hand while in phase X", so a buy is `− p` and a sell is `+ p`.
* **Prefix / suffix split:** for "two non-overlapping things", combine the best on the left with the best on the right of each cut.

## 🔹 Alternative Data Structures

* `left[k]` / `right[k]` arrays of best single-trade profits — O(n) space, easier to explain.
* The general `buy[j]`, `sell[j]` arrays from 188 with `k = 2`.

## 🔹 Code Snippet (Brute Force)

```python
from typing import List


class Solution:
    def maxProfit(self, prices: List[int]) -> int:
        def one_trade(lo: int, hi: int) -> int:
            best, cheapest = 0, float('inf')
            for p in prices[lo:hi]:
                cheapest = min(cheapest, p)
                best = max(best, p - cheapest)
            return best

        n = len(prices)
        return max(one_trade(0, k + 1) + one_trade(k, n) for k in range(n))
```

## 🔹 Code Snippet (Optimized)

```python
from typing import List


class Solution:
    def maxProfit(self, prices: List[int]) -> int:
        buy1 = buy2 = float('-inf')  # cannot hold a share before buying one
        sell1 = sell2 = 0
        for p in prices:
            buy1 = max(buy1, -p)
            sell1 = max(sell1, buy1 + p)
            buy2 = max(buy2, sell1 - p)  # second buy is funded by the first trade's profit
            sell2 = max(sell2, buy2 + p)
        return sell2
```
