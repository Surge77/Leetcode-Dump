# 🔹 Problem Name: 528. Random Pick with Weight (Prefix Sum + Binary Search, Medium)

**🔗 Link:** [LeetCode 528](https://leetcode.com/problems/random-pick-with-weight/)
**🟢 Status:** 🔄 Need Review

## 🔹 Problem Statement

Given positive weights `w`, implement `pickIndex()` so that it returns index `i` with probability `w[i] / sum(w)`. The constructor receives `w` once; `pickIndex` is then called many times.

* **Example:** `w = [1,3]` → `pickIndex()` returns `1` about 75% of the time and `0` about 25% (any sequence of picks is a valid output)
* **Constraints:** `1 ≤ w.length ≤ 10^4`, `1 ≤ w[i] ≤ 10^5`, at most `10^4` calls to `pickIndex`

## 🔹 Quick Breakdown

* **Difficulty Level:** Medium
* **Main Approach:** **Lay the weights end to end on a number line.** Build prefix sums so index `i` owns the integer range `(prefix[i-1], prefix[i]]`. Draw a uniform integer in `[1, total]` and binary-search the first prefix that is `>=` it.
* **Core Concept:** weighted sampling = uniform sampling over a longer line cut into segments proportional to the weights
* **When to Use This Pattern?** Many random picks from a *fixed* weight table: build prefix sums once in `__init__`, answer each pick in O(log n).
* **Mistakes to Avoid:**
  * Drawing from `[0, total)` with `bisect_left` — that shifts every boundary by one; draw `[1, total]` with `bisect_left`, or `[0, total)` with `bisect_right`.
  * Recomputing `sum(w)` on every call (the brute force does).
  * Picking by `random.random()` against floating prefixes when integers suffice — avoids rounding at the segment edges.

## 🔹 Optimization Path

* **Brute Force:** per call, draw a number and subtract weights one by one until it drops to `0` or below — O(n) per pick, plus a `sum` each time.
* **Optimized Solution:** prefix sums once (O(n)), then O(log n) per pick.
* **Further Improvements Possible?** The alias method gives O(1) per pick after O(n) set-up, at the price of more code.

## 🔹 Solution Breakdown

* **Optimal Approach:** `prefix = list(accumulate(w))`; `pickIndex`: `target = randint(1, prefix[-1])`; return `bisect_left(prefix, target)`.
* **Why This Works?** Index `i` covers exactly `w[i]` integers of `[1, total]`, so a uniform integer lands in it with probability `w[i] / total`. `bisect_left` returns the first `i` with `prefix[i] >= target`, which is the segment containing `target`.
* **Edge Cases Considered:**
  * `w = [1]` → always index `0`.
  * Very skewed weights (`[1, 10⁵]`) — integer arithmetic keeps the small segment exact.
  * The total is at most `10⁵ · 10⁴ = 10⁹`, still an `int` in any language.

## 🔹 Tricks & Patterns Used

* **Cumulative distribution function** as a sorted array, searched with `bisect`.
* **Build once in `__init__`:** design problems reward moving work out of the query.

## 🔹 Alternative Data Structures

* Alias method (Walker/Vose): O(n) preprocessing, O(1) per sample.
* Fenwick tree when weights change between picks (not the case here).

## 🔹 Complexity Analysis

* **Time Complexity:** O(n) for `__init__`, O(log n) per `pickIndex`
* **Space Complexity:** O(n)

## 🔹 Code Snippet (Brute Force)

```python
import random
from typing import List


class Solution:
    def __init__(self, w: List[int]):
        self.w = w

    def pickIndex(self) -> int:
        target = random.randint(1, sum(self.w))
        for i, weight in enumerate(self.w):
            target -= weight
            if target <= 0:
                return i
        return len(self.w) - 1
```

## 🔹 Code Snippet (Optimized)

```python
import random
from bisect import bisect_left
from itertools import accumulate
from typing import List


class Solution:
    def __init__(self, w: List[int]):
        self.prefix = list(accumulate(w))

    def pickIndex(self) -> int:
        target = random.randint(1, self.prefix[-1])
        return bisect_left(self.prefix, target)
```
