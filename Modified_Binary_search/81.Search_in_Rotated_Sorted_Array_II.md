# 🔹 Problem Name: 81. Search in Rotated Sorted Array II (Rotated Binary Search, Medium)

**🔗 Link:** [LeetCode 81](https://leetcode.com/problems/search-in-rotated-sorted-array-ii/)
**🟢 Status:** 🔄 Need Review

## 🔹 Quick Breakdown

* **Difficulty Level:** Medium
* **Main Approach:** **Rotated binary search with a duplicate escape.** As in 33, one of `[lo, mid]` and `[mid, hi]` is sorted; test whether `target` lies inside the sorted half and discard the other. New twist: when `nums[lo] == nums[mid] == nums[hi]` you cannot tell which half is sorted, so shrink both ends by one (`lo += 1`, `hi −= 1`).
* **Core Concept:** binary search needs a rule that discards half the range; with duplicates that rule sometimes doesn't exist, and you fall back to discarding one element
* **When to Use This Pattern?** Rotated sorted arrays that may contain duplicates (search, minimum — 154).
* **Mistakes to Avoid:**
  * Copying 33 unchanged: `[1, 0, 1, 1, 1]` with `target = 0` has `nums[lo] == nums[mid]`, and the "left half is sorted" assumption is wrong.
  * Claiming O(log n): the worst case (almost all duplicates) is O(n).

## 🔹 Optimization Path

* **Brute Force:** `target in nums` — O(n).
* **Optimized Solution:** rotated binary search — O(log n) on average / distinct-ish data, O(n) worst case.
* **Further Improvements Possible?** No: in `[1, 1, …, 1, 0, 1, …, 1]` the `0` can be anywhere, and any algorithm must look at Ω(n) cells to find it.

## 🔹 Solution Breakdown

* **Optimal Approach:** while `lo ≤ hi`: `mid` hit → `True`; if the three ends are equal, shrink both; elif `nums[lo] ≤ nums[mid]` (left sorted): keep left iff `nums[lo] ≤ target < nums[mid]`; else (right sorted): keep right iff `nums[mid] < target ≤ nums[hi]`.
* **Why This Works?** After the triple-equal case is excluded, `nums[lo] ≤ nums[mid]` really means the left half is sorted: if the drop were inside `[lo, mid]`, then `nums[mid] ≤ nums[hi] ≤ nums[lo]`, and `nums[lo] ≤ nums[mid]` would force all three to be equal. Removing `nums[lo]` and `nums[hi]` in the equal case is safe because they equal `nums[mid]`, which was just checked against `target`.
* **Edge Cases Considered:**
  * No rotation, single element, all elements equal.
  * Duplicates straddling the rotation point (`[2, 2, 0, 2, 2]`).

```python
from typing import List


class Solution:
    def search(self, nums: List[int], target: int) -> bool:
        return any(value == target for value in nums)
```

## 🔹 Code Snippet (Optimized)

```python
from typing import List


class Solution:
    def search(self, nums: List[int], target: int) -> bool:
        lo, hi = 0, len(nums) - 1
        while lo <= hi:
            mid = (lo + hi) // 2
            if nums[mid] == target:
                return True
            if nums[lo] == nums[mid] == nums[hi]:
                lo += 1  # both ends equal nums[mid], already ruled out
                hi -= 1
            elif nums[lo] <= nums[mid]:
                if nums[lo] <= target < nums[mid]:
                    hi = mid - 1
                else:
                    lo = mid + 1
            else:
                if nums[mid] < target <= nums[hi]:
                    lo = mid + 1
                else:
                    hi = mid - 1
        return False
```
