# 🔹 Problem Name: 8. String to Integer (atoi) (String Parsing, Medium)

**🔗 Link:** [LeetCode 8](https://leetcode.com/problems/string-to-integer-atoi/)
**🟢 Status:** 🔄 Need Review

## 🔹 Quick Breakdown

* **Difficulty Level:** Medium
* **Main Approach:** **Single left-to-right scan as a tiny state machine:** skip leading spaces → read at most one `+`/`-` → read digits until the first non-digit → clamp to `[−2³¹, 2³¹ − 1]`.
* **Core Concept:** parse exactly what the spec allows and stop at the first character that breaks the grammar
* **When to Use This Pattern?** Any "parse a number / token out of messy text" problem: atoi, Valid Number (65), basic calculators, decoding strings with counts.
* **Mistakes to Avoid:**
  * Skipping whitespace *after* the sign (`"+ 1"` → 0) or accepting two signs (`"+-12"` → 0).
  * Skipping non-digits *before* the number (`"words and 987"` → 0, not 987).
  * Treating `"0-1"` as `-1`: parsing stops at `-`, the answer is 0.
  * Only `' '` counts as leading whitespace in the problem statement.

## 🔹 Optimization Path

* **Brute Force:** strip spaces, match `[+-]?\d+` with a regex, convert with `int()`, clamp — O(n), but leans on big integers and a regex engine.
* **Optimized Solution:** manual scan with an overflow check before each `result * 10 + d` — O(n), O(1) space, works in fixed-width languages.
* **Further Improvements Possible?** No; every character up to the end of the number must be read.

## 🔹 Solution Breakdown

* **Optimal Approach:** index `i` walks past spaces, records the sign, then accumulates digits. Before appending digit `d`, if `result > (LIMIT − d) // 10` the true value already exceeds the limit, so return the clamped bound immediately.
* **Why This Works?** The grammar is a fixed sequence (spaces, optional sign, digits); anything after the first non-digit is ignored, so one pass with no backtracking is enough. Using `LIMIT = 2³¹ − 1` for `+` and `2³¹` for `−` makes the overflow test exact for both signs.
* **Edge Cases Considered:**
  * Empty string / only spaces / only a sign → 0.
  * Leading zeros (`"   -042"` → −42).
  * `"-91283472332"` → −2147483648; `"2147483648"` → 2147483647.

## 🔹 Tricks & Patterns Used

* **Overflow check before multiply:** `result > (LIMIT - d) // 10` is equivalent to `result * 10 + d > LIMIT` without ever computing the overflowing value.
* **Sign as a separate variable:** accumulate the magnitude, apply the sign at the end.

## 🔹 Alternative Data Structures

* Regex `^ *([+-]?\d+)` — concise, fine in Python where integers do not overflow.
* Explicit DFA table (state × char class → state), the generalisable form for problems like Valid Number.

## 🔹 Complexity Analysis

* **Time Complexity:** O(n), `n ≤ 200`
* **Space Complexity:** O(1)

## 🔹 Code Snippet (Brute Force)

```python
import re


class Solution:
    def myAtoi(self, s: str) -> int:
        match = re.match(r"[+-]?\d+", s.lstrip(" "))
        if not match:
            return 0
        return max(-2**31, min(2**31 - 1, int(match.group())))
```

## 🔹 Code Snippet (Optimized)

```python
class Solution:
    def myAtoi(self, s: str) -> int:
        INT_MAX = 2**31 - 1
        n, i = len(s), 0
        while i < n and s[i] == " ":
            i += 1
        sign = 1
        if i < n and s[i] in "+-":
            sign = -1 if s[i] == "-" else 1
            i += 1
        limit = INT_MAX if sign == 1 else INT_MAX + 1  # |INT_MIN| is one larger than INT_MAX
        result = 0
        while i < n and s[i].isdigit():
            digit = ord(s[i]) - ord("0")
            if result > (limit - digit) // 10:
                return sign * limit
            result = result * 10 + digit
            i += 1
        return sign * result
```
