# 🔹 Problem Name: 443. String Compression (Two Pointers, Medium)

**🔗 Link:** [LeetCode 443](https://leetcode.com/problems/string-compression/)
**🟢 Status:** 🔄 Need Review

## 🔹 Quick Breakdown

* **Difficulty Level:** Medium
* **Main Approach:** **Read pointer scans groups, write pointer emits them.** For each run of equal characters write the character, then, if the run is longer than 1, write the digits of its length one character at a time. Return the write position.
* **Core Concept:** in-place compaction — the output is never longer than the input, so the write index never overtakes the read index
* **When to Use This Pattern?** Rewrite an array in place with a shorter encoding — remove duplicates, remove element, run-length encoding.
* **Mistakes to Avoid:**
  * Writing the count when it is 1.
  * Writing `"12"` as a single list entry: every entry of `chars` must be one character, so a run of 12 becomes `"1"`, `"2"`.
  * Overwriting characters of a run before its length is known — measure the run first, then write.
  * Building a new list and returning it: the compressed data has to end up inside `chars`.

## 🔹 Optimization Path

* **Brute Force:** build the encoded list with `groupby`, then copy it back over the front of `chars` — O(n) time but O(n) extra space.
* **Optimized Solution:** read/write pointers on the same array — O(n) time, O(1) extra space.
* **Further Improvements Possible?** No.

## 🔹 Solution Breakdown

* **Optimal Approach:** `read = write = 0`. While `read < n`: `start = read`; advance `read` while `chars[read] == chars[start]`; `chars[write] = chars[start]`; `write += 1`; if `read − start > 1`, for each digit in `str(read − start)` write it and advance `write`. Return `write`.
* **Why This Works?** An encoded group takes at most as many cells as the run it replaces (`1 + digits(len) ≤ len` for `len ≥ 2`, and exactly 1 for `len = 1`), so `write ≤ read` always and nothing unread gets overwritten.
* **Edge Cases Considered:**
  * Single character → length 1, no count.
  * A run of 100 or more (three digits) — the loop over `str(count)` covers it.
  * Alternating characters (`"abab"`) → unchanged, length 4.

## 🔹 Tricks & Patterns Used

* **Measure the run, then write:** the inner `while` finds the run length before any cell is modified.
* **`str(count)` iteration:** the easiest way to split a count into single-character digits.

## 🔹 Alternative Data Structures

* `itertools.groupby` for the runs — concise, but the encoded output is built in an auxiliary list.
* Process from the back — not needed, the forward write never catches the read pointer.

## 🔹 Complexity Analysis

* **Time Complexity:** O(n)
* **Space Complexity:** O(1) extra (the digit string of a count is at most 4 characters)

## 🔹 Code Snippet (Brute Force)

```python
from itertools import groupby
from typing import List


class Solution:
    def compress(self, chars: List[str]) -> int:
        encoded = []
        for ch, run in groupby(chars):
            length = len(list(run))
            encoded.append(ch)
            if length > 1:
                encoded.extend(str(length))
        chars[:len(encoded)] = encoded
        return len(encoded)
```

## 🔹 Code Snippet (Optimized)

```python
from typing import List


class Solution:
    def compress(self, chars: List[str]) -> int:
        write = read = 0
        while read < len(chars):
            start = read
            while read < len(chars) and chars[read] == chars[start]:
                read += 1
            chars[write] = chars[start]
            write += 1
            if read - start > 1:
                for digit in str(read - start):
                    chars[write] = digit  # write <= read here, so unread characters are safe
                    write += 1
        return write
```
