# 🔹 Problem Name: 947. Most Stones Removed with Same Row or Column (Union Find, Medium)

**🔗 Link:** [LeetCode 947](https://leetcode.com/problems/most-stones-removed-with-same-row-or-column/)
**🟢 Status:** 🔄 Need Review

## 🔹 Quick Breakdown

* **Difficulty Level:** Medium
* **Main Approach:** **Answer = stones − connected components.** Two stones are linked if they share a row or a column. Treat every stone as an edge between node "row r" and node "column c", union them, and count the distinct roots among the row/column nodes that appear.
* **Core Concept:** inside one component every stone but one can be removed; across components nothing helps
* **When to Use This Pattern?** "Maximum things you can remove/merge while each step needs a partner" — usually collapses to `items − components`.
* **Mistakes to Avoid:**
  * Simulating removals greedily — the order matters, the component count does not.
  * Giving row `k` and column `k` the same id: `[[0, 1], [1, 0]]` would look connected (answer 1) while the true answer is 0. Use `~c` (or `c + 10001`) for columns.
  * Building all stone pairs: O(n²) — fine for `n = 1000`, but unnecessary.

## 🔹 Optimization Path

* **Brute Force:** link every pair of stones that share a row or column, count components with DFS — O(n²).
* **Optimized Solution:** Union-Find on row and column nodes — near-linear: O(n log n) worst case with path halving alone, O(n · α(n)) with union by size added.
* **Further Improvements Possible?** No; every stone must be read.

## 🔹 Solution Breakdown

* **Optimal Approach:** for each `(r, c)`: `union(r, ~c)`. Components = `len({find(x) for x in parent})`; return `len(stones) − components`.
* **Why This Works?** Upper bound: the last stone of a component shares no row or column with any remaining stone (stones of other components never do), so it can't be removed — each component keeps ≥ 1. Achievability: take a spanning tree of the component and remove leaves first; a leaf always shares a line with its still-present parent. So exactly `size − 1` per component.
  The bipartite row/column graph has the same components as the stone graph: a stone joins its row and column, and two stones share a line exactly when they touch a common node.
* **Edge Cases Considered:**
  * One stone → 0.
  * All stones in one row → `n − 1`.
  * Row index equal to a column index on unrelated stones (`[[0, 1], [1, 0]]`) → 0.

## 🔹 Tricks & Patterns Used

* **Lines as nodes:** union the stone's row with its column instead of stones with stones — n unions instead of O(n²) pair checks.
* **`~c` to separate namespaces:** `~c = −c − 1` is negative for every `c ≥ 0`, so it can never collide with a row id.
* **Lazy `parent.setdefault`:** only lines that actually hold a stone become nodes.

## 🔹 Alternative Data Structures

* DFS over stones with `row → stones` and `col → stones` maps — O(n) and no Union-Find.
* Union-Find over stone indices, unioning each stone with the first stone seen in its row and in its column.

## 🔹 Complexity Analysis

* **Time Complexity:** O(n log n) worst case for the code below (path halving only); O(n · α(n)) with union by size
* **Space Complexity:** O(n)

## 🔹 Code Snippet (Brute Force)

```python
from typing import List


class Solution:
    def removeStones(self, stones: List[List[int]]) -> int:
        n = len(stones)
        adj = [[j for j in range(n) if j != i and (stones[i][0] == stones[j][0] or stones[i][1] == stones[j][1])]
               for i in range(n)]
        seen = [False] * n
        components = 0
        for i in range(n):
            if seen[i]:
                continue
            components += 1
            seen[i] = True
            stack = [i]
            while stack:
                v = stack.pop()
                for w in adj[v]:
                    if not seen[w]:
                        seen[w] = True
                        stack.append(w)
        return n - components  # each component can shrink to exactly one stone
```

## 🔹 Code Snippet (Optimized)

```python
from typing import List


class Solution:
    def removeStones(self, stones: List[List[int]]) -> int:
        parent = {}

        def find(x: int) -> int:
            parent.setdefault(x, x)
            while parent[x] != x:
                parent[x] = parent[parent[x]]  # path halving keeps trees shallow without recursion
                x = parent[x]
            return x

        for r, c in stones:
            parent[find(r)] = find(~c)  # ~c is negative, so column ids never collide with row ids
        components = len({find(x) for x in list(parent)})
        return len(stones) - components
```
