# 🔹 Problem Name: 122. Best Time to Buy and Sell Stock II (Greedy, Medium)

**🔗 Link:** [LeetCode 122](https://leetcode.com/problems/best-time-to-buy-and-sell-stock-ii/)
**🟢 Status:** 🔄 Need Review

## 🔹 Quick Breakdown

* **Difficulty Level:** Medium
* **Main Approach:** **Collect every upswing.** A trade bought on day `i` and sold on day `j` earns `prices[j] − prices[i]`, which equals the sum of the day-to-day changes in between. With unlimited trades (and selling and re-buying on the same day allowed) you can keep exactly the positive changes and skip the negative ones: answer = Σ max(0, `prices[t] − prices[t − 1]`).
* **Core Concept:** a long trade telescopes into one-day trades, so the profit splits into independent daily gains
* **When to Use This Pattern?** Unlimited transactions with no fee and no cooldown; in general, whenever the objective telescopes into adjacent differences and you are free to take any subset of them.
* **Mistakes to Avoid:**
  * Looking for one best buy/sell pair as in 121 — a single trade misses every later rise.
  * Reusing this greedy for 714 (fee) or 309 (cooldown): splitting a trade costs something there, so use the `cash`/`hold` state DP.

## 🔹 Optimization Path

* **Brute Force:** recursion over each day's choice (act or wait) without memo — O(2ⁿ).
* **Optimized Solution:** sum of positive day-to-day changes — O(n) time, O(1) space (the `cash`/`hold` DP gives the same complexity).
* **Further Improvements Possible?** No; every price must be read.

## 🔹 Solution Breakdown

* **Optimal Approach:** walk adjacent pairs and add `today − yesterday` whenever it is positive.
* **Why This Works?** Upper bound: any set of non-overlapping trades is a sum of daily changes over disjoint day ranges, which can never exceed the sum of all positive changes. Achievable: buy at the start of every rising stretch and sell at its end — that collects exactly the positive changes.
* **Edge Cases Considered:**
  * One day — no trade possible, answer 0.
  * Strictly falling prices — every change is negative, answer 0.
  * Flat days (`change = 0`) add nothing, whichever way you treat them.

## 🔹 Pattern Recognition

* **Belongs To:** Greedy — local gains sum to the global optimum (the unconstrained member of the stock state-machine DP family)
* **Common Problems Using This:**

## 🔹 Tricks & Patterns Used

* **Telescoping:** `p[j] − p[i] = Σ (p[t] − p[t − 1])` for `t` in `(i, j]`, so a long trade is the same as a chain of one-day trades.
* **State machine DP:** `cash = max(cash, hold + p)`, `hold = max(hold, cash − p)` — same answer here, and it extends to fee, cooldown and `k`-transaction variants.

## 🔹 Alternative Data Structures

* Peak–valley scan: find each local minimum and the next local maximum, add their difference.
* Two-state DP with variables `cash`/`hold` — O(n), O(1); the template for 309 and 714.

## 🔹 Complexity Analysis

* **Time Complexity:** O(n)
* **Space Complexity:** O(1)

## 🔹 Code Snippet (Brute Force)

```python
from typing import List


class Solution:
    def maxProfit(self, prices: List[int]) -> int:
        def best(day: int, holding: bool) -> int:
            if day == len(prices):
                return 0
            wait = best(day + 1, holding)
            if holding:
                return max(wait, prices[day] + best(day + 1, False))
            return max(wait, -prices[day] + best(day + 1, True))

        return best(0, False)
```

## 🔹 Code Snippet (Optimized)

```python
from typing import List


class Solution:
    def maxProfit(self, prices: List[int]) -> int:
        profit = 0
        for yesterday, today in zip(prices, prices[1:]):
            profit += max(0, today - yesterday)  # same-day sell-and-rebuy lets every rising day stand alone
        return profit
```
