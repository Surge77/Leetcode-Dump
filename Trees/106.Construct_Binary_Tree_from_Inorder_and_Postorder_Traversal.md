# 106. Construct Binary Tree from Inorder and Postorder Traversal

**🔗 Link:** [LeetCode 106](https://leetcode.com/problems/construct-binary-tree-from-inorder-and-postorder-traversal/)
**🟢 Status:** 🔄 Need Review


## 🔹 Problem Statement

You are given the inorder and the postorder traversal of the same binary tree whose values are all distinct. Reconstruct the tree and return its root.

* **Example:** `inorder = [9,3,15,20,7], postorder = [9,15,7,20,3]` → `[3,9,20,null,null,15,7]`
* **Constraints:** `1 ≤ inorder.length ≤ 3000`; `postorder.length == inorder.length`; `-3000 ≤ inorder[i], postorder[i] ≤ 3000`; all values are unique.

## 🔹 Quick Breakdown

* **Difficulty Level:** Medium
* **Main Approach:** **Root from postorder, split from inorder.** The last postorder value is the root; its position `mid` in inorder puts the `mid` values before it in the left subtree and the rest in the right subtree, and postorder lists those same `mid` left-subtree values first. The optimized version builds the same tree in one backward pass with a stack, never searching or slicing.
* **Core Concept:** postorder fixes the root, inorder fixes the split; values are unique, so the split point is unambiguous
* **When to Use This Pattern?** Rebuilding a tree from two traversals (pre + in, post + in, pre + post for full trees), or any recursive split where one array is consumed in order while another bounds the ranges.
* **Mistakes to Avoid:**
  * Building the left subtree first while consuming postorder from the end — read backwards, postorder gives the root, then the **right** subtree, then the left.
  * `inorder.index(root)` plus slicing in every call: O(n²) on a skewed tree.
  * Plain recursion on a 3000-node chain goes 3000 calls deep — past Python's default limit of 1000.

## 🔹 Optimization Path

* **Brute Force:** recursion with `list.index` and slices — O(n²) time on a skewed tree (O(n log n) when balanced), plus the copied slices.
* **Optimized Solution:** one backward pass over postorder with a stack — O(n) time, O(n) space.
* **Further Improvements Possible?** No — O(n) is optimal. Recursion with a `value → inorder index` map and a shared postorder pointer is also O(n); the stack version just avoids the recursion limit.

## 🔹 Solution Breakdown

* **Optimal Approach:** `root = TreeNode(postorder[-1])`, `stack = [root]`, `i = n − 1` (pointer into inorder). For each earlier postorder value, going backwards: make `node`; while `stack[-1].val == inorder[i]`, pop (remember it as `parent`) and decrement `i`; if anything was popped, `parent.left = node`, else `stack[-1].right = node`; push `node`.
* **Why This Works?** Reversed postorder is `root, right subtree, left subtree` — a preorder that visits right before left — and reversed inorder is `right, root, left`. While the stack top differs from `inorder[i]`, the top still has unfinished right-side nodes, so the next node is its right child. When the top equals `inorder[i]`, its right subtree is complete; popping every such node reaches the deepest one whose left subtree hasn't started, and the next node is that left child.
* **Edge Cases Considered:**
  * A single node.
  * Left-leaning chain: every step pops once and attaches a left child.
  * Right-leaning chain: nothing is popped, the stack grows to `n`.

## 🔹 Tricks & Patterns Used

* **Postorder read backwards = preorder of the mirrored tree:** this problem is 105 with left and right swapped.
* **Value → index map:** `pos = {v: i for i, v in enumerate(inorder)}` replaces the O(n) `index` scan (valid only because values are unique).
* **Pass index bounds, not slices:** recursing on `(lo, hi)` removes the O(n) copies.

## 🔹 Alternative Data Structures

* Recursive build with the index map and a pointer walking postorder from the end — build `right` before `left`; needs `sys.setrecursionlimit` for the 3000-deep chain.

## 🔹 Complexity Analysis

* **Time Complexity:** O(n) — every node is pushed and popped at most once
* **Space Complexity:** O(n) — the stack holds up to `n` nodes on a right-leaning chain

## 🔹 Code Snippet (Brute Force)

```python
import sys
from typing import List, Optional


class Solution:
    def buildTree(self, inorder: List[int], postorder: List[int]) -> Optional[TreeNode]:
        sys.setrecursionlimit(10_000)  # a 3000-node chain recurses 3000 levels deep
        if not postorder:
            return None
        root = TreeNode(postorder[-1])
        mid = inorder.index(root.val)
        root.left = self.buildTree(inorder[:mid], postorder[:mid])
        root.right = self.buildTree(inorder[mid + 1:], postorder[mid:-1])
        return root
```

## 🔹 Code Snippet (Optimized)

```python
from typing import List, Optional


class Solution:
    def buildTree(self, inorder: List[int], postorder: List[int]) -> Optional[TreeNode]:
        root = TreeNode(postorder[-1])
        stack, i = [root], len(inorder) - 1
        for k in range(len(postorder) - 2, -1, -1):
            node = TreeNode(postorder[k])
            parent = None
            while stack and stack[-1].val == inorder[i]:
                parent = stack.pop()  # its right subtree is complete
                i -= 1
            if parent is not None:
                parent.left = node
            else:
                stack[-1].right = node
            stack.append(node)
        return root
```
