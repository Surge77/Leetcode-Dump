# 1021. Remove Outermost Parentheses

**🔗 Link:** [LeetCode 1021](https://leetcode.com/problems/remove-outermost-parentheses/)
**🟢 Status:** 🔄 Need Review


## 🔹 Problem Statement

You get a valid parentheses string and split it into primitive pieces (non-empty valid strings that cannot be split further into two valid parts). Remove the outermost pair of parentheses of every primitive piece and return the concatenation of what is left.

* **Example:** `s = "(()())(())"` → `"()()()"`
* **Constraints:** `1 ≤ s.length ≤ 10⁵`; each character is `'('` or `')'`; `s` is a valid parentheses string

## 🔹 Quick Breakdown

* **Difficulty Level:** Easy
* **Main Approach:** **Depth counter instead of a stack.** Scan once, tracking the current depth. An `'('` seen at depth 0 opens a primitive (drop it); a `')'` that brings the depth back to 0 closes it (drop it); every other character is kept.
* **Core Concept:** for a single bracket type, a stack of `'('` is fully described by its height
* **When to Use This Pattern?** Valid-parentheses strings with one bracket type: nesting depth (1614), minimum additions (921), score of parentheses (856), splitting into primitives.
* **Mistakes to Avoid:**
  * Updating depth on the wrong side of the check: for `'('` test `depth > 0` *before* incrementing; for `')'` decrement *first*, then test `depth > 0`.
  * Collecting output with `+=` on a string in a loop — use a list and join.

## 🔹 Optimization Path

* **Brute Force:** grow a candidate primitive one character at a time and recount its `'('` and `')'` from scratch to see if it is balanced — O(n²) for one long primitive.
* **Optimized Solution:** running depth — O(n).
* **Further Improvements Possible?** No; every character must be read.

## 🔹 Solution Breakdown

* **Optimal Approach:** `depth = 0`; for `'('`: if `depth > 0` keep it, then `depth += 1`; for `')'`: `depth -= 1`, then if `depth > 0` keep it.
* **Why This Works?** In a valid string the depth returns to 0 exactly at the end of each primitive. The outermost `'('` of a primitive is the only `'('` seen at depth 0, and its matching `')'` is the only `')'` that brings depth back to 0, so exactly those two characters are skipped.
* **Edge Cases Considered:**
  * Primitives that are just `"()"` contribute nothing (`"()()"` → `""`).
  * One primitive spanning the whole string.

## 🔹 Tricks & Patterns Used

* **Counter as an implicit stack:** with one bracket type, only the stack's height matters.
* **Order of update vs check** decides whether the boundary character is included.

## 🔹 Alternative Data Structures

* Explicit stack of indices — same result, O(n) extra space.
* Record primitive boundaries `(start, end)` and join `s[start + 1 : end]` slices.

## 🔹 Complexity Analysis

* **Time Complexity:** O(n), `n ≤ 10⁵`
* **Space Complexity:** O(n) for the output (O(1) extra)

## 🔹 Code Snippet (Brute Force)

```python
class Solution:
    def removeOuterParentheses(self, s: str) -> str:
        parts = []
        start = 0
        for end in range(len(s)):
            piece = s[start:end + 1]
            if piece.count("(") == piece.count(")"):
                parts.append(piece[1:-1])
                start = end + 1
        return "".join(parts)
```

## 🔹 Code Snippet (Optimized)

```python
class Solution:
    def removeOuterParentheses(self, s: str) -> str:
        kept = []
        depth = 0
        for ch in s:
            if ch == "(":
                if depth > 0:
                    kept.append(ch)
                depth += 1
            else:
                depth -= 1
                if depth > 0:  # depth 0 here means this ')' closed the primitive
                    kept.append(ch)
        return "".join(kept)
```
