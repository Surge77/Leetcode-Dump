# 🔹 Problem Name: 1283. Find the Smallest Divisor Given a Threshold (Binary Search on Answer, Medium)

**🔗 Link:** [LeetCode 1283](https://leetcode.com/problems/find-the-smallest-divisor-given-a-threshold/)
**🟢 Status:** 🔄 Need Review

## 🔹 Quick Breakdown

* **Difficulty Level:** Medium
* **Main Approach:** **Binary search on the divisor.** `cost(d) = Σ ceil(nums[i] / d)` only goes down (or stays) as `d` grows, so "`cost(d) ≤ threshold`" is false…false, true…true over `d`. Binary search for the first true in `[1, max(nums)]`.
* **Core Concept:** binary search on the answer space with a monotone feasibility check
* **When to Use This Pattern?** "Find the minimum `x` such that some O(n)-checkable condition holds", and the condition only gets easier as `x` grows — eating speed, ship capacity, days.
* **Mistakes to Avoid:**
  * Using floor division: `7 // 3 = 2`, but each element rounds **up** (`ceil(7/3) = 3`).
  * Upper bound too small: at `d = max(nums)` every term is 1 and the sum is `n ≤ threshold` (guaranteed), so `max(nums)` is always feasible.
  * Float `math.ceil(x / d)` — fine at these sizes, but the integer form `(x + d − 1) // d` never risks rounding.

## 🔹 Optimization Path

* **Brute Force:** try `d = 1, 2, 3, …` until the sum fits — O(max(nums) · n), up to 10⁶ · 5·10⁴.
* **Optimized Solution:** binary search on `d` — O(n log max(nums)) ≈ 20 passes.
* **Further Improvements Possible?** Tighter lower bound `ceil(sum(nums) / threshold)` (since `Σ ceil(x/d) ≥ Σ x / d`) — saves a few iterations, same big-O.

## 🔹 Solution Breakdown

* **Optimal Approach:** `lo, hi = 1, max(nums)`; while `lo < hi`: `mid` feasible → `hi = mid`, else `lo = mid + 1`. Return `lo`.
* **Why This Works?** Each `ceil(x / d)` is non-increasing in `d`, so the sum is too. The feasible set is a suffix `[d*, ∞)`, and the loop keeps `d*` inside `[lo, hi]`.
* **Edge Cases Considered:**
  * `threshold == len(nums)` → answer is `max(nums)`.
  * Huge threshold → answer is 1.

## 🔹 Tricks & Patterns Used

* **Integer ceiling:** `(x + d - 1) // d` or `-(-x // d)`.
* **"First true" template:** `hi = mid` on success, `lo = mid + 1` on failure, loop `while lo < hi`.

* None needed — the check is one pass over the array.

## 🔹 Complexity Analysis

* **Time Complexity:** O(n log M), `M = max(nums) ≤ 10⁶`
* **Space Complexity:** O(1)

## 🔹 Code Snippet (Brute Force)

```python
from typing import List


class Solution:
    def smallestDivisor(self, nums: List[int], threshold: int) -> int:
        divisor = 1
        while sum((x + divisor - 1) // divisor for x in nums) > threshold:
            divisor += 1
        return divisor
```

## 🔹 Code Snippet (Optimized)

```python
from typing import List


class Solution:
    def smallestDivisor(self, nums: List[int], threshold: int) -> int:
        # at max(nums) every term is 1 and len(nums) <= threshold, so it always fits
        lo, hi = 1, max(nums)
        while lo < hi:
            mid = (lo + hi) // 2
            if sum((x + mid - 1) // mid for x in nums) <= threshold:
                hi = mid
            else:
                lo = mid + 1
        return lo
```
