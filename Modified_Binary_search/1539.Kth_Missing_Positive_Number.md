# 🔹 Problem Name: 1539. Kth Missing Positive Number (Binary Search, Easy)

**🔗 Link:** [LeetCode 1539](https://leetcode.com/problems/kth-missing-positive-number/)
**🟢 Status:** 🔄 Need Review

## 🔹 Problem Statement

You get a strictly increasing array of positive integers and a number `k`. Considering the positive integers 1, 2, 3, ... that do not appear in the array, return the `k`-th one in increasing order.

* **Example:** `arr = [2,3,4,7,11], k = 5` → `9` (the missing numbers are 1, 5, 6, 8, 9, ...)
* **Constraints:** `1 ≤ arr.length ≤ 1000`; `1 ≤ arr[i] ≤ 1000`; `1 ≤ k ≤ 1000`; `arr` is strictly increasing

## 🔹 Quick Breakdown

* **Difficulty Level:** Easy
* **Main Approach:** **Binary search on "missing so far".** With no gaps, `arr[i]` would be `i + 1`, so `missing(i) = arr[i] − (i + 1)` numbers are missing before `arr[i]`. It is non-decreasing. Find the first index `lo` with `missing(lo) ≥ k`; exactly `lo` array values lie below the answer, so the answer is `k + lo`.
* **Core Concept:** binary search on a derived monotone quantity, not on the stored values
* **When to Use This Pattern?** Strictly increasing integers with gaps, and you need the k-th gap / k-th absent value in O(log n).
* **Mistakes to Avoid:**
  * Forgetting that the answer may lie past the last element (`lo == n` → `k + n`).
  * Returning `arr[lo − 1] + (k − missing(lo − 1))` without handling `lo == 0` — the `k + lo` form covers both.

## 🔹 Optimization Path

* **Brute Force:** count up from 1, skipping values in the array, until `k` misses — O(n + k).
* **Optimized Solution:** binary search — O(log n).
* **Further Improvements Possible?** A linear one-liner also works: `for x in arr: if x <= k: k += 1` then return `k` (each array value `≤` the current candidate pushes it up by one) — O(n), no extra space.

## 🔹 Solution Breakdown

* **Optimal Approach:** `lo, hi = 0, n`; while `lo < hi`: `mid`; if `arr[mid] − mid − 1 < k`: `lo = mid + 1` else `hi = mid`. Return `lo + k`.
* **Why This Works?** Fewer than `k` numbers are missing before `arr[lo − 1]`, and at least `k` before `arr[lo]`, so the k-th missing number lies between them. Below it there are exactly `k − 1` missing numbers and `lo` present numbers, so it equals `(k − 1) + lo + 1`.
* **Edge Cases Considered:**
  * `k` smaller than `arr[0]` → `lo = 0`, answer `k`.
  * No gaps (`arr = [1..n]`) → answer `n + k`.

## 🔹 Tricks & Patterns Used

* **`value − index` as a gap counter** for strictly increasing integer arrays.
* **Lower-bound template** with `hi = n` so "past the end" is a valid result.

## 🔹 Alternative Data Structures

* A `set` of the array for the brute-force membership test.

## 🔹 Complexity Analysis

* **Time Complexity:** O(log n)
* **Space Complexity:** O(1)

## 🔹 Code Snippet (Brute Force)

```python
from typing import List


class Solution:
    def findKthPositive(self, arr: List[int], k: int) -> int:
        present = set(arr)
        candidate = 0
        while k:
            candidate += 1
            if candidate not in present:
                k -= 1
        return candidate
```

## 🔹 Code Snippet (Optimized)

```python
from typing import List


class Solution:
    def findKthPositive(self, arr: List[int], k: int) -> int:
        lo, hi = 0, len(arr)  # hi = n: the answer may lie past the last element
        while lo < hi:
            mid = (lo + hi) // 2
            if arr[mid] - mid - 1 < k:
                lo = mid + 1
            else:
                hi = mid
        return lo + k
```
