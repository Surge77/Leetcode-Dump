# 202. Happy Number

**🔗 Link:** [LeetCode 202](https://leetcode.com/problems/happy-number/)
**🟢 Status:** 🔄 Need Review


## 🔹 Problem Statement

Given a positive integer `n`, repeatedly replace it with the sum of the squares of its digits. If this process reaches `1`, the number is happy; if it instead falls into a cycle that never contains `1`, it is not. Return whether `n` is happy.

* **Example:** `n = 19` → `true` (19 → 82 → 68 → 100 → 1)
* **Constraints:** `1 ≤ n ≤ 2^31 − 1`

## 🔹 Quick Breakdown

* **Difficulty Level:** Easy
* **Main Approach:** **Cycle detection on an implicit sequence.** `n → sum of squares of digits` is a function on integers, so iterating it eventually repeats. Floyd's tortoise and hare finds the cycle in O(1) memory; `n` is happy iff the cycle is the fixed point 1.
* **Core Concept:** any iterated function on a finite set ends in a cycle — detect it
* **When to Use This Pattern?** Repeatedly applying `f` until something repeats: linked-list cycles, "next index = nums[i]" arrays, digit maps, pseudo-random sequences.
* **Mistakes to Avoid:**
  * Looping until `n == 1` with no cycle check — unhappy numbers loop forever (through 4 → 16 → 37 → 58 → 89 → 145 → 42 → 20 → 4).
  * Assuming the sequence can grow without bound: for any number with `d ≥ 4` digits, the digit-square sum is at most `81·d`, far fewer digits — values quickly drop below 243 and stay there.

## 🔹 Optimization Path

* **Brute Force:** iterate and store every value in a `set`; stop at 1 (happy) or at a repeat (unhappy) — O(k) memory for the k values seen.
* **Optimized Solution:** Floyd — `slow` moves one step, `fast` two; they meet inside the cycle. Happy iff they meet at 1 — O(1) memory.
* **Further Improvements Possible?** Hard-code the only unhappy cycle (stop when you reach 4); same speed, less general.

## 🔹 Solution Breakdown

* **Optimal Approach:** `slow = n`, `fast = f(n)`; while `fast != 1 and slow != fast`: `slow = f(slow)`, `fast = f(f(fast))`. Return `fast == 1`.
* **Why This Works?** Once both pointers are in the cycle, `fast` gains one step per iteration, so it catches `slow` within one cycle length. 1 is a fixed point (`f(1) = 1`), so if the sequence reaches 1, `fast` gets there first and stays.
* **Edge Cases Considered:**
  * `n = 1` → happy immediately.
  * `n = 2` → unhappy (enters the 4-cycle).

## 🔹 Tricks & Patterns Used

* **Implicit linked list:** treat `x → f(x)` as `node.next`; no structure needs to be built.
* **Bounded state space:** the digit-square map shrinks large inputs, guaranteeing a cycle among small values.

## 🔹 Alternative Data Structures

* `set` of seen values (the brute force) — simplest and plenty fast here.
* Brent's algorithm — fewer function evaluations than Floyd.

## 🔹 Complexity Analysis

* **Time Complexity:** O(log n) — the first step costs O(digits), after which values are below 243 and the cycle is reached within a bounded number of steps
* **Space Complexity:** O(1)

## 🔹 Code Snippet (Brute Force)

```python
class Solution:
    def isHappy(self, n: int) -> bool:
        seen = set()
        while n != 1 and n not in seen:
            seen.add(n)
            n = sum(int(ch) ** 2 for ch in str(n))
        return n == 1
```

## 🔹 Code Snippet (Optimized)

```python
class Solution:
    def isHappy(self, n: int) -> bool:
        def step(x: int) -> int:
            total = 0
            while x:
                x, digit = divmod(x, 10)
                total += digit * digit
            return total

        slow, fast = n, step(n)
        while fast != 1 and slow != fast:
            slow = step(slow)
            fast = step(step(fast))
        return fast == 1
```
