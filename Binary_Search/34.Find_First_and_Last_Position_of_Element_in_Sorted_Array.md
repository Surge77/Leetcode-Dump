# 34. Find First and Last Position of Element in Sorted Array

**🔗 Link:** [LeetCode 34](https://leetcode.com/problems/find-first-and-last-position-of-element-in-sorted-array/)
**🟢 Status:** 🔄 Need Review


## 🔹 Problem Statement

Given a non-decreasing array `nums` and a `target`, return the first and last index at which `target` occurs, as `[first, last]`. If it never occurs return `[-1, -1]`. The solution must run in O(log n).

* **Example:** `nums = [5,7,7,8,8,10], target = 8` → `[3,4]`
* **Constraints:** `0 ≤ nums.length ≤ 10^5`; `-10^9 ≤ nums[i], target ≤ 10^9`; `nums` is sorted non-decreasing (duplicates allowed).

## 🔹 Quick Breakdown

* **Difficulty Level:** Medium
* **Main Approach:** **Two lower-bound searches.** `first = lower_bound(target)` (first index with `nums[i] ≥ target`); `last = lower_bound(target + 1) − 1`. If `first` is out of range or `nums[first] != target`, answer `[-1, -1]`.
* **Core Concept:** a sorted array splits into a "`< x`" prefix and a "`≥ x`" suffix; binary search finds the boundary
* **When to Use This Pattern?** Counting occurrences, first/last index of a value, "how many elements are `< x` / `≤ x`" in a sorted array.
* **Mistakes to Avoid:**
  * Finding any `target` and then walking left and right: O(n) when the whole array equals `target`.
  * Mixing the `lo ≤ hi` / `hi = mid − 1` template with the half-open `lo < hi` / `hi = mid` one — infinite loops or off-by-one.

## 🔹 Optimization Path

* **Brute Force:** linear scan for the first and last match — O(n).
* **Optimized Solution:** two binary searches — O(log n).
* **Further Improvements Possible?** No; O(log n) is the required bound.

## 🔹 Solution Breakdown

* **Optimal Approach:** half-open search on `[0, n)`: `mid = (lo + hi) // 2`; `nums[mid] < x` → `lo = mid + 1`, else `hi = mid`. Returns the boundary `lo`.
* **Why This Works?** The predicate `nums[i] ≥ x` is false…false true…true on a sorted array; the loop keeps the invariant "everything before `lo` is false, everything from `hi` on is true" until the two meet. Values are integers, so "`≥ target + 1`" is exactly "`> target`", giving the end of the run.
* **Edge Cases Considered:**
  * Empty array → `first = 0 = n` → `[-1, -1]`.
  * `target` smaller or larger than every element → boundary lands at `0` or `n` with a mismatch.
  * Whole array equal to `target` → `[0, n − 1]`.

## 🔹 Tricks & Patterns Used

* **`upper_bound(x) = lower_bound(x + 1)`** for integers — one helper serves both ends.
* **Half-open interval `[lo, hi)`:** `hi = n` lets the answer be "past the end" without special cases.

## 🔹 Alternative Data Structures

* `bisect.bisect_left` / `bisect.bisect_right` from the standard library do exactly these two searches.

## 🔹 Code Snippet (Brute Force)

```python
from typing import List


class Solution:
    def searchRange(self, nums: List[int], target: int) -> List[int]:
        hits = [i for i, value in enumerate(nums) if value == target]
        return [hits[0], hits[-1]] if hits else [-1, -1]
```

## 🔹 Code Snippet (Optimized)

```python
from typing import List


class Solution:
    def searchRange(self, nums: List[int], target: int) -> List[int]:
        def lower_bound(x: int) -> int:
            lo, hi = 0, len(nums)
            while lo < hi:
                mid = (lo + hi) // 2
                if nums[mid] < x:
                    lo = mid + 1
                else:
                    hi = mid
            return lo

        first = lower_bound(target)
        if first == len(nums) or nums[first] != target:
            return [-1, -1]
        return [first, lower_bound(target + 1) - 1]  # integers: >= target + 1 means > target
```
