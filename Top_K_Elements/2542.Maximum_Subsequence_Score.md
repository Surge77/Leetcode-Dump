# 2542. Maximum Subsequence Score

**🔗 Link:** [LeetCode 2542](https://leetcode.com/problems/maximum-subsequence-score/)
**🟢 Status:** 🔄 Need Review


## 🔹 Problem Statement

Given two equal-length arrays `nums1` and `nums2` and a number `k`, choose `k` indices. The score of a choice is (sum of the chosen `nums1` values) × (minimum of the chosen `nums2` values). Return the maximum score over all choices.

* **Example:** `nums1 = [1,3,3,2], nums2 = [2,1,3,4], k = 3` → `12`
* **Constraints:** `1 ≤ n ≤ 10⁵`, `0 ≤ nums1[i], nums2[i] ≤ 10⁵`, `1 ≤ k ≤ n`

## 🔹 Quick Breakdown

* **Difficulty Level:** Medium
* **Main Approach:** **Fix the minimum, keep the best `k` sums.** Sort index pairs by `nums2` descending. Walking down that order, the current `nums2` is the smallest seen, so it is the minimum of any subset of the elements seen so far that includes it. Keep a min-heap of the `k` largest `nums1` values seen; whenever it holds `k` values, the score is `sum(heap) × current nums2`.
* **Core Concept:** fix one factor (the minimum), then optimise the other (the sum) greedily
* **When to Use This Pattern?** "Sum of one array times min/max of another over a chosen subset" — team performance, IPO-like selection, weighted subset problems.
* **Mistakes to Avoid:**
  * Trying every subset: `C(n, k)` explodes for `n = 10⁵`.
  * Sorting by `nums1` — the minimum is over `nums2`, so that is the order that makes the minimum known.
  * Scoring before the heap holds exactly `k` elements.

## 🔹 Optimization Path

* **Brute Force:** enumerate every subset of `k` indices and compute `sum × min` — O(C(n, k) · k).
* **Optimized Solution:** sort + size-`k` min-heap — O(n log n).
* **Further Improvements Possible?** No; sorting is the lower bound for this approach.

## 🔹 Solution Breakdown

* **Optimal Approach:** `order = sorted(zip(nums2, nums1), reverse=True)`. For each `(b, a)`: push `a`, add it to `total`; if the heap exceeds `k`, pop the smallest and subtract it; when the heap has `k` items, `best = max(best, total * b)`.
* **Why This Works?** When processing `b` every element in the heap has `nums2 ≥ b`, so the true minimum of the chosen set is at least `b`; using `b` can only under-estimate it and the optimal set is reached when `b` is its real minimum. For that `b`, the largest possible sum comes from the `k` biggest `nums1` values among the candidates — exactly what the heap keeps (it must contain the current element only if it is among the top `k`, and if it is not, the true score for this `b` is covered by an earlier, larger `b`).
* **Edge Cases Considered:**
  * `k = 1` → the answer is `max(nums1[i] · nums2[i])`.
  * `k = n` → one candidate, the sum of everything times the global minimum.
  * Zeros in `nums1` or `nums2` — the score is 0 and the formula still holds.

## 🔹 Tricks & Patterns Used

* **Sort descending to make "the minimum" a known value:** the element being processed is always the smallest `nums2` allowed so far.
* **Running sum next to the heap:** adding and removing one element keeps the sum O(1) to read.

## 🔹 Alternative Data Structures

* A sorted container / order-statistic tree of `nums1` values — gives the top-`k` sum but is heavier than a heap.

## 🔹 Complexity Analysis

* **Time Complexity:** O(n log n) for the sort plus O(n log k) for the heap
* **Space Complexity:** O(n) for the sorted pairs, O(k) for the heap

## 🔹 Code Snippet (Brute Force)

```python
from itertools import combinations
from typing import List


class Solution:
    def maxScore(self, nums1: List[int], nums2: List[int], k: int) -> int:
        return max(
            sum(nums1[i] for i in chosen) * min(nums2[i] for i in chosen)
            for chosen in combinations(range(len(nums1)), k)
        )
```

## 🔹 Code Snippet (Optimized)

```python
import heapq
from typing import List


class Solution:
    def maxScore(self, nums1: List[int], nums2: List[int], k: int) -> int:
        heap = []  # the k largest nums1 values among the pairs processed so far
        total = 0
        best = 0
        for b, a in sorted(zip(nums2, nums1), reverse=True):
            heapq.heappush(heap, a)
            total += a
            if len(heap) > k:
                total -= heapq.heappop(heap)
            if len(heap) == k:
                best = max(best, total * b)  # b is the smallest nums2 among everything in the heap
        return best
```
