# 🔹 Problem Name: 1048. Longest String Chain (LIS DP, Medium)

**🔗 Link:** [LeetCode 1048](https://leetcode.com/problems/longest-string-chain/)
**🟢 Status:** 🔄 Need Review

## 🔹 Quick Breakdown

* **Difficulty Level:** Medium
* **Main Approach:** **LIS over words sorted by length, with a hash map.** Sort words by length so every predecessor is processed before its successors. For each word `w`, try deleting each of its characters; if the result `p` is a known word, `chain[w] = max(chain[w], chain[p] + 1)`. Answer = max over `chain`.
* **Core Concept:** generate the O(L) possible predecessors instead of comparing against all O(n) earlier words
* **When to Use This Pattern?** Longest chain / sequence where "x can follow y" is a local edit — LIS on a DAG whose edges you can enumerate from the larger end.
* **Mistakes to Avoid:**
  * Sorting lexicographically instead of by length — predecessors may come later.
  * Checking "predecessor" as "same letters plus one" (multiset) — order matters; it must be a subsequence with exactly one extra character.

## 🔹 Optimization Path

* **Brute Force:** LIS-style DP comparing every pair `(earlier, later)` with a subsequence check — O(n²·L) ≈ 1.6·10⁷ for `n = 1000`, `L = 16`.
* **Optimized Solution:** delete-one-character + dict lookup — O(n·L²) (L deletions, each building an O(L) string) plus the O(n log n) sort.
* **Further Improvements Possible?** Bucket words by length instead of sorting; asymptotically the same here.

## 🔹 Solution Breakdown

* **Optimal Approach:** `for w in sorted(words, key=len): chain[w] = 1 + max(chain.get(w[:i] + w[i+1:], 0) for i in range(len(w)))`.
* **Why This Works?** `p` is a predecessor of `w` iff `p` is `w` with one character removed, so the deletions enumerate **all** predecessors. Sorting by length is a topological order of this DAG (edges go from length `ℓ` to `ℓ + 1`).
* **Edge Cases Considered:**
  * No word has a predecessor → 1.
  * Duplicate words — the dict simply keeps one entry with the same value.

## 🔹 Tricks & Patterns Used

* **Enumerate neighbours from the item itself** (delete one char) rather than scanning all candidates.
* **Sort by size = topological order** for a DAG whose edges always grow the size.

## 🔹 Alternative Data Structures

* Explicit graph + DFS with memo (longest path in a DAG) — same complexity, more code.

## 🔹 Complexity Analysis

* **Time Complexity:** O(n log n + n·L²)
* **Space Complexity:** O(n·L)

## 🔹 Code Snippet (Brute Force)

```python
from typing import List


class Solution:
    def longestStrChain(self, words: List[str]) -> int:
        def is_predecessor(short: str, long: str) -> bool:
            if len(long) != len(short) + 1:
                return False
            i = 0
            for ch in long:
                if i < len(short) and short[i] == ch:
                    i += 1
            return i == len(short)

        words = sorted(words, key=len)
        chain = [1] * len(words)
        for j in range(len(words)):
            for i in range(j):
                if is_predecessor(words[i], words[j]):
                    chain[j] = max(chain[j], chain[i] + 1)
        return max(chain)
```

## 🔹 Code Snippet (Optimized)

```python
from typing import List


class Solution:
    def longestStrChain(self, words: List[str]) -> int:
        chain = {}
        for word in sorted(words, key=len):
            chain[word] = 1 + max(chain.get(word[:i] + word[i + 1:], 0) for i in range(len(word)))
        return max(chain.values())
```
