# 🔹 Problem Name: 2352. Equal Row and Column Pairs (Hash Map of Tuples, Medium)

**🔗 Link:** [LeetCode 2352](https://leetcode.com/problems/equal-row-and-column-pairs/)
**🟢 Status:** 🔄 Need Review

## 🔹 Quick Breakdown

* **Difficulty Level:** Medium
* **Main Approach:** **Hash whole rows.** Count every row as a tuple in a `Counter`; then for each column, build its tuple and add how many rows equal it.
* **Core Concept:** a sequence made hashable (tuple) becomes an O(1) lookup key
* **When to Use This Pattern?** "Count pairs of equal sequences / lines / strings" — group the sequences by content instead of comparing every pair.
* **Mistakes to Avoid:**
  * Counting each matching *pair* once: duplicate rows must each pair with the column, hence a count, not a set.
  * Using lists as dictionary keys — they are unhashable; convert to tuples.

## 🔹 Optimization Path

* **Brute Force:** compare every row with every column element by element — O(n³).
* **Optimized Solution:** hash the rows once, look each column up — O(n²).
* **Further Improvements Possible?** Reading the `n²` cells is unavoidable, so O(n²) is optimal.

## 🔹 Solution Breakdown

* **Optimal Approach:** `rows = Counter(map(tuple, grid))`; answer `= sum(rows[col] for col in zip(*grid))`.
* **Why This Works?** `zip(*grid)` yields each column as a tuple in order. A row and a column are equal iff their tuples are, and `rows[col]` is the number of rows with that content, so each column contributes all its matching pairs at once.
* **Edge Cases Considered:**
  * `n = 1` → the single cell matches itself, answer `1`.
  * Several identical rows and one matching column → answer counts each row.
  * `Counter` returns `0` for a missing key, so no `in` check is needed.

## 🔹 Tricks & Patterns Used

* **`zip(*grid)` transposes a matrix** and yields tuples ready to hash.

## 🔹 Alternative Data Structures

* A trie over the values of each row, walked down by each column — avoids hashing long tuples but is more code.
* Polynomial rolling hash per row and column — O(1) comparisons, but risks collisions.

## 🔹 Complexity Analysis

* **Time Complexity:** O(n²) — each tuple is O(n) to build and hash, and there are 2n of them
* **Space Complexity:** O(n²) for the stored row tuples

## 🔹 Code Snippet (Brute Force)

```python
from typing import List


class Solution:
    def equalPairs(self, grid: List[List[int]]) -> int:
        n = len(grid)
        pairs = 0
        for r in range(n):
            for c in range(n):
                if all(grid[r][k] == grid[k][c] for k in range(n)):
                    pairs += 1
        return pairs
```

## 🔹 Code Snippet (Optimized)

```python
from collections import Counter
from typing import List


class Solution:
    def equalPairs(self, grid: List[List[int]]) -> int:
        rows = Counter(map(tuple, grid))
        return sum(rows[col] for col in zip(*grid))
```
