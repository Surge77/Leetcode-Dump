# 188. Best Time to Buy and Sell Stock IV

**🔗 Link:** [LeetCode 188](https://leetcode.com/problems/best-time-to-buy-and-sell-stock-iv/)
**🟢 Status:** 🔄 Need Review


## 🔹 Problem Statement

Given daily stock prices and an integer `k`, find the maximum profit from at most `k` transactions, where one transaction is one buy followed by one sell and you cannot hold more than one share at a time. Return `0` if no profit is possible.

* **Example:** `k = 2, prices = [2,4,1]` → `2`
* **Constraints:** `1 ≤ k ≤ 100`; `1 ≤ prices.length ≤ 1000`; `0 ≤ prices[i] ≤ 1000`.

## 🔹 Quick Breakdown

* **Difficulty Level:** Hard
* **Main Approach:** **`k` pairs of states.** `buy[j]` = best cash while holding the `j`-th share, `sell[j]` = best cash after completing `j` trades. For each price and each `j = 1..k`: `buy[j] = max(buy[j], sell[j-1] − p)`, `sell[j] = max(sell[j], buy[j] + p)`. Answer `sell[k]`.
* **Core Concept:** 123's four-state machine generalised to `2k` states; the only memory of the past that matters is "how many trades started, am I holding".
* **When to Use This Pattern?** "At most `k` transactions / operations" over a sequence where you alternate between two modes.
* **Mistakes to Avoid:**
  * Initialising `buy[j]` to `0` — you cannot hold a share you have not paid for; use `−∞`.
  * Ignoring the `2k ≥ n` case: then the limit never binds and the answer is the sum of all positive daily gains (122).
  * Counting a "transaction" as a buy *and* a sell separately — one trade = one buy + one sell.

## 🔹 Optimization Path

* **Brute Force:** recursion that, each day, chooses buy / sell / skip given `(day, trades left, holding)` — exponential without memo.
* **Optimized Solution:** `2k` states updated once per day — O(n · k) time, O(k) space. With `k ≤ 100`, `n ≤ 1000` that is ≤ 10⁵ updates.
* **Further Improvements Possible?** For huge `k` and `n`, the valley/peak + merge technique (or Lagrangian "Aliens trick" with a binary-searched fee) reaches O(n log n), far beyond what LeetCode needs.

## 🔹 Solution Breakdown

* **Optimal Approach:** if `2k ≥ n`, return `sum(max(0, prices[i] − prices[i-1]))`. Otherwise run the DP above, `sell[0] = 0` fixed.
* **Why This Works?** A strategy with `≤ k` trades visits *sold `j−1` → holding `j` → sold `j`* in order, so `buy[j]` only needs `sell[j-1]` and `sell[j]` only needs `buy[j]`. Each state keeps the best cash ever reachable in it, which is all future decisions need. Same-day buy-then-sell (updating `buy[j]` before `sell[j]` with the same `p`) yields `0` profit, so it never overstates the answer. With `2k ≥ n` there are at most `⌊n/2⌋` useful trades (each needs two distinct days), so the cap is irrelevant.
* **Edge Cases Considered:**
  * Falling prices → `0`.
  * `n = 1` → `0`.
  * `k` larger than needed → shortcut to the greedy sum.

## 🔹 Tricks & Patterns Used

* **Cap check:** a constraint that cannot bind (`2k ≥ n`) turns the problem into the unconstrained greedy one.
* **Cash-as-state DP** with `−∞` for impossible states.

## 🔹 Alternative Data Structures

* Full `dp[j][i]` table (`j` trades, day `i`) with the running `max(dp[j-1][t] − prices[t])` trick — same O(n · k) time, O(n · k) space.
* Memoised recursion on `(day, trades left, holding)` — O(n · k) states.

## 🔹 Complexity Analysis

* **Time Complexity:** O(n · k) (O(n) when `2k ≥ n`)
* **Space Complexity:** O(k)

## 🔹 Code Snippet (Brute Force)

```python
from typing import List


class Solution:
    def maxProfit(self, k: int, prices: List[int]) -> int:
        def go(day: int, left: int, holding: bool) -> int:
            if day == len(prices) or (left == 0 and not holding):
                return 0
            best = go(day + 1, left, holding)
            if holding:
                best = max(best, prices[day] + go(day + 1, left, False))
            else:
                best = max(best, -prices[day] + go(day + 1, left - 1, True))
            return best

        return go(0, k, False)
```

## 🔹 Code Snippet (Optimized)

```python
from typing import List


class Solution:
    def maxProfit(self, k: int, prices: List[int]) -> int:
        n = len(prices)
        if 2 * k >= n:
            # the cap can never bind, so take every rising step (problem 122)
            return sum(max(0, prices[i] - prices[i - 1]) for i in range(1, n))
        buy = [float('-inf')] * (k + 1)
        sell = [0] * (k + 1)
        for p in prices:
            for j in range(1, k + 1):
                buy[j] = max(buy[j], sell[j - 1] - p)
                sell[j] = max(sell[j], buy[j] + p)
        return sell[k]
```
