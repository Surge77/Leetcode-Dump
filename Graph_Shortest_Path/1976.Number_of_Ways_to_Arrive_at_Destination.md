# 1976. Number of Ways to Arrive at Destination

**🔗 Link:** [LeetCode 1976](https://leetcode.com/problems/number-of-ways-to-arrive-at-destination/)
**🟢 Status:** 🔄 Need Review


## 🔹 Problem Statement

A city has `n` intersections joined by bidirectional roads, each with a travel time; every intersection can be reached from every other and any two are joined by at most one road. Count how many different routes from intersection `0` to intersection `n − 1` take the minimum possible total time, and return that count modulo `10^9 + 7`.

* **Example:** `n = 7, roads = [[0,6,7],[0,1,2],[1,2,3],[1,3,3],[6,3,3],[3,5,1],[6,5,1],[2,5,1],[0,4,5],[4,6,2]]` → `4`
* **Constraints:** `1 ≤ n ≤ 200`, `n − 1 ≤ roads.length ≤ n(n − 1)/2`, `1 ≤ time_i ≤ 10^9`, the graph is connected

## 🔹 Quick Breakdown

* **Difficulty Level:** Medium
* **Main Approach:** **Dijkstra that also counts.** Alongside `dist[v]` keep `ways[v]` = number of shortest paths from 0 to `v`. Relaxing edge `u → v` with `nd = dist[u] + t`: if `nd < dist[v]`, the old paths are no longer shortest — set `dist[v] = nd`, `ways[v] = ways[u]`; if `nd == dist[v]`, these are additional shortest paths — `ways[v] += ways[u]`. Answer `ways[n − 1] mod 10⁹+7`.
* **Core Concept:** shortest-path DAG + path counting, done in Dijkstra's pop order
* **When to Use This Pattern?** "How many shortest / cheapest routes", "number of optimal ways" on a weighted graph with non-negative weights.
* **Mistakes to Avoid:**
  * Adding to `ways[v]` on strict improvement instead of **replacing** it.
  * Processing stale heap entries — skip a pop whose `d > dist[u]`, or its `ways[u]` gets pushed twice.
  * 32-bit overflow in other languages: distances reach 200 × 10⁹ — use 64-bit. Path counts grow like 2ⁿ — take the modulo while adding.
  * Floating-point distances (`float` sums) — keep integer times so equality checks are exact.

## 🔹 Optimization Path

* **Brute Force:** enumerate every simple path from 0 to `n − 1` with DFS, keep the minimum time and how many paths achieve it — exponential, fine only for tiny `n`.
* **Optimized Solution:** Dijkstra with a counting array — O((n + E) log E).
* **Further Improvements Possible?** The graph can be dense (`E ≤ n(n−1)/2 ≈ 2·10⁴`); an array-based O(n²) Dijkstra avoids the heap and is equally fast here.

## 🔹 Solution Breakdown

* **Optimal Approach:** adjacency list (undirected), `dist = [inf]·n`, `ways = [0]·n`, `dist[0] = 0`, `ways[0] = 1`; standard lazy Dijkstra with the two-case update above.
* **Why This Works?** Times are positive, so every predecessor `u` of `v` on a shortest path has `dist[u] < dist[v]` and is popped — with a **final** `ways[u]` — before `v` is popped. Every shortest path to `v` ends with exactly one such edge `u → v`, so `ways[v] = Σ ways[u]` over those edges, which is what the relaxations accumulate. Shortest paths are automatically simple with positive weights, so the brute force's "simple paths only" loses nothing.
* **Edge Cases Considered:**
  * `n = 1` → 1 (the empty path).
  * Many equal-length routes (a ladder of 2-node layers gives 2^(layers) paths) → the modulo matters.
  * A direct road that is longer than a detour → only the detours count.

## 🔹 Tricks & Patterns Used

* **Replace on `<`, accumulate on `==`:** the general recipe for counting optimal solutions during any relaxation-based algorithm.
* **Lazy deletion in the heap:** push duplicates, discard stale pops by comparing with `dist[u]`.

## 🔹 Alternative Data Structures

* Dijkstra for distances only, then sort nodes by `dist` and count paths with a DP over edges where `dist[u] + t == dist[v]`.
* Floyd-Warshall (`n ≤ 200` → 8·10⁶ steps) plus the same DP — simpler to reason about, slower.

## 🔹 Complexity Analysis

* **Time Complexity:** O((n + E) log E), `E ≤ n(n − 1)/2`
* **Space Complexity:** O(n + E)

## 🔹 Code Snippet (Brute Force)

```python
from typing import List


class Solution:
    def countPaths(self, n: int, roads: List[List[int]]) -> int:
        adj = [[] for _ in range(n)]
        for u, v, t in roads:
            adj[u].append((v, t))
            adj[v].append((u, t))
        best, ways = float("inf"), 0
        on_path = [False] * n

        def walk(v: int, time: int) -> None:
            nonlocal best, ways
            if v == n - 1:
                if time < best:
                    best, ways = time, 1
                elif time == best:
                    ways += 1
                return
            on_path[v] = True  # positive times make every shortest path simple, so skip revisits
            for w, t in adj[v]:
                if not on_path[w]:
                    walk(w, time + t)
            on_path[v] = False

        walk(0, 0)
        return ways % (10**9 + 7)
```

## 🔹 Code Snippet (Optimized)

```python
import heapq
from typing import List


class Solution:
    def countPaths(self, n: int, roads: List[List[int]]) -> int:
        MOD = 10**9 + 7
        adj = [[] for _ in range(n)]
        for u, v, t in roads:
            adj[u].append((v, t))
            adj[v].append((u, t))

        dist = [float("inf")] * n
        ways = [0] * n
        dist[0], ways[0] = 0, 1
        heap = [(0, 0)]
        while heap:
            d, u = heapq.heappop(heap)
            if d > dist[u]:
                continue  # stale entry: u was finalized earlier with a shorter time
            for v, t in adj[u]:
                nd = d + t
                if nd < dist[v]:
                    dist[v], ways[v] = nd, ways[u]  # older routes to v are no longer shortest
                    heapq.heappush(heap, (nd, v))
                elif nd == dist[v]:
                    ways[v] = (ways[v] + ways[u]) % MOD
        return ways[n - 1]
```
