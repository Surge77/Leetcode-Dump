# 🔹 Problem Name: 148. Sort List (Merge Sort, Medium)

**🔗 Link:** [LeetCode 148](https://leetcode.com/problems/sort-list/)
**🟢 Status:** 🔄 Need Review

## 🔹 Quick Breakdown

* **Difficulty Level:** Medium
* **Main Approach:** **Bottom-up merge sort on the list itself.** Merge adjacent runs of length 1, then 2, 4, 8, … : each pass cuts the list into pieces of `size` nodes, merges them pairwise and splices the result back behind a tail pointer. After ⌈log₂ n⌉ passes the list is sorted.
* **Core Concept:** merging two sorted linked lists needs no extra memory (just relink `next` pointers), so merge sort is the natural O(n log n) sort for lists
* **When to Use This Pattern?** Sorting a linked list, or any sort where random access is expensive but sequential access and relinking are cheap.
* **Mistakes to Avoid:**
  * Quicksort: no random access for pivots, and sorted input degrades it to O(n²).
  * Top-down recursive merge sort: recursion depth is only log n, but it uses O(log n) stack — the follow-up asks for O(1) extra space.
  * Forgetting to cut (`node.next = None`) the pieces before merging, which merges past the run.

## 🔹 Optimization Path

* **Brute Force:** insertion sort into a growing sorted list — O(n²) (5·10⁴ nodes → ~1.25·10⁹ steps).
* **Better:** top-down merge sort (find middle with slow/fast pointers) — O(n log n) time, O(log n) stack.
* **Optimized Solution:** bottom-up merge sort — O(n log n) time, O(1) extra space.
* **Further Improvements Possible?** No comparison sort beats O(n log n).

## 🔹 Solution Breakdown

* **Optimal Approach:** count `n`. For `size = 1, 2, 4, …` while `size < n`: walk from `dummy.next`; repeatedly `left = cur`, `right = split(left, size)`, `cur = split(right, size)`; append `merge(left, right)` after `tail` and move `tail` to the merged end.
* **Why This Works?** Invariant: before a pass with `size`, every block of `size` consecutive nodes is sorted. Merging pairs of blocks produces sorted blocks of `2·size`. Once `size ≥ n`, the single block is the whole list.
* **Edge Cases Considered:**
  * Empty list or one node → returned as is.
  * Odd tail block with no partner — merged with an empty list, i.e. appended unchanged.
  * Duplicates and negatives — `<=` in merge keeps it stable.

## 🔹 Tricks & Patterns Used

* **Dummy head + tail pointer** to splice merged runs back without special-casing the first one.
* **`split(head, k)`** cuts after `k` nodes and returns the rest — the list version of slicing.

## 🔹 Alternative Data Structures

* Copy values into a Python list, `sort()`, write them back — O(n log n) but O(n) extra space.
* Top-down merge sort with slow/fast middle finding — simplest to write, O(log n) stack.

* **Time Complexity:** O(n log n)
* **Space Complexity:** O(1) extra

## 🔹 Code Snippet (Brute Force)

```python
from typing import Optional


class Solution:
    def sortList(self, head: Optional[ListNode]) -> Optional[ListNode]:
        dummy = ListNode()
        while head:
            nxt = head.next
            prev = dummy
            while prev.next and prev.next.val <= head.val:
                prev = prev.next
            head.next = prev.next
            prev.next = head
            head = nxt
        return dummy.next
```

## 🔹 Code Snippet (Optimized)

```python
from typing import Optional


class Solution:
    def sortList(self, head: Optional[ListNode]) -> Optional[ListNode]:
        def split(node: Optional[ListNode], k: int) -> Optional[ListNode]:
            for _ in range(k - 1):
                if not node:
                    return None
                node = node.next
            if not node:
                return None
            rest, node.next = node.next, None
            return rest

        def merge(a: Optional[ListNode], b: Optional[ListNode], tail: ListNode) -> ListNode:
            while a and b:
                if a.val <= b.val:  # <= keeps equal values in original order
                    tail.next, a = a, a.next
                else:
                    tail.next, b = b, b.next
                tail = tail.next
            tail.next = a or b
            while tail.next:
                tail = tail.next
            return tail

        n, node = 0, head
        while node:
            n, node = n + 1, node.next
        dummy = ListNode(0, head)
        size = 1
        while size < n:
            cur, tail = dummy.next, dummy
            while cur:
                left = cur
                right = split(left, size)
                cur = split(right, size)
                tail = merge(left, right, tail)
            size *= 2
        return dummy.next
```
