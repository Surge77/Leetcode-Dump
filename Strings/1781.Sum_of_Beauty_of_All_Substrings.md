# 🔹 Problem Name: 1781. Sum of Beauty of All Substrings (Frequency Counting, Medium)

**🔗 Link:** [LeetCode 1781](https://leetcode.com/problems/sum-of-beauty-of-all-substrings/)
**🟢 Status:** 🔄 Need Review

## 🔹 Problem Statement

The beauty of a string is the highest letter frequency minus the lowest non-zero letter frequency in it. Return the sum of the beauties of all substrings of `s`.

* **Example:** `s = "aabcb"` → `5`
* **Constraints:** `1 ≤ s.length ≤ 500`; lowercase letters only

## 🔹 Quick Breakdown

* **Difficulty Level:** Medium
* **Main Approach:** **Fix the start, extend the end, update counts incrementally.** For each `i`, grow `j` from `i` to `n − 1`, adding `s[j]` to a 26-slot count array. The max frequency only grows, so track it in O(1); the min over non-zero counts is a 26-step scan.
* **Core Concept:** reuse the counts of `s[i..j−1]` to get the counts of `s[i..j]` instead of recounting
* **When to Use This Pattern?** "Sum / count something over all substrings" with `n` around 500–2000 and a small alphabet — enumerate `O(n²)` substrings with O(1)/O(σ) incremental work each.
* **Mistakes to Avoid:**
  * Recounting each substring from scratch: O(n³) = 1.25·10⁸ for `n = 500`.
  * Including letters with count 0 in the minimum — beauty only uses characters that appear.

## 🔹 Optimization Path

* **Brute Force:** build a `Counter` for every substring — O(n³).
* **Optimized Solution:** incremental counts per start index — O(n² · 26).
* **Further Improvements Possible?** Keeping a "how many letters have frequency f" table can make the min O(1) amortised, but at `n ≤ 500` the 26-step scan is simpler and fast enough.

## 🔹 Solution Breakdown

* **Optimal Approach:** for each `i`: reset `count = [0] * 26`, `most = 0`; for each `j ≥ i`: bump `count[s[j]]`, `most = max(most, count[s[j]])`, `least = min(c for c in count if c)`, add `most − least`.
* **Why This Works?** Extending a substring by one character changes exactly one count by +1, so the running array is always the exact frequency table of `s[i..j]`. A count never decreases while `j` grows, so the max can only rise — and only through the character just added.
* **Edge Cases Considered:**
  * Single-character substrings and substrings of one distinct letter have beauty 0.
  * `n = 1` → 0.

## 🔹 Tricks & Patterns Used

* **Monotone max under insertions:** counts only increase as `j` grows, so `most` needs no rescan.
* **Fixed alphabet array** (`ord(ch) − 97`) instead of a dict for tight inner loops.

## 🔹 Alternative Data Structures

* Prefix-count table `pre[k][c]` — any substring's counts in O(26), same total complexity, more memory.
* Frequency-of-frequency array to maintain the min in O(1).

## 🔹 Complexity Analysis

* **Time Complexity:** O(26 · n²) ≈ 6.5·10⁶ steps for `n = 500`
* **Space Complexity:** O(26)

## 🔹 Code Snippet (Brute Force)

```python
from collections import Counter


class Solution:
    def beautySum(self, s: str) -> int:
        total = 0
        for i in range(len(s)):
            for j in range(i + 1, len(s) + 1):
                freq = Counter(s[i:j]).values()
                total += max(freq) - min(freq)
        return total
```

## 🔹 Code Snippet (Optimized)

```python
class Solution:
    def beautySum(self, s: str) -> int:
        codes = [ord(ch) - ord("a") for ch in s]
        total = 0
        for i in range(len(codes)):
            count = [0] * 26
            most = 0
            for j in range(i, len(codes)):
                c = codes[j]
                count[c] += 1
                if count[c] > most:
                    most = count[c]
                total += most - min(x for x in count if x)  # zero counts are absent letters
        return total
```
