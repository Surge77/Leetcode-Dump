# 🔹 Problem Name: 421. Maximum XOR of Two Numbers in an Array (Binary Trie, Medium)

**🔗 Link:** [LeetCode 421](https://leetcode.com/problems/maximum-xor-of-two-numbers-in-an-array/)
**🟢 Status:** 🔄 Need Review

## 🔹 Quick Breakdown

* **Difficulty Level:** Medium
* **Main Approach:** Insert every number's 31 bits (high to low) into a binary trie. For each number, walk the trie greedily choosing the **opposite** bit whenever possible — that maximises XOR from the top bit down.
* **Core Concept:** Binary trie + greedy bit selection
* **When to Use This Pattern?** Maximum/minimum XOR pairs, XOR queries with limits (1707), counting pairs with XOR in a range.
* **Mistakes to Avoid:**
  * O(n²) pairs — n is 2·10⁵.
  * Processing bits low to high — a higher bit outweighs all lower bits combined, so go from the top.

## 🔹 Optimization Path

* **Brute Force:** O(n²).
* **Optimized Solution:** O(31 · n) binary trie.
* **Further Improvements Possible?** Prefix-set greedy (build the answer bit by bit using a set of prefixes) — same bound, often faster in Python.

## 🔹 Solution Breakdown

* **Optimal Approach:** Trie stored as a list of `[child0, child1]` pairs. Query: at each bit `b`, prefer child `1 - b`; if it exists, set that bit in the result.
* **Why This Works?** Getting a 1 in bit `k` is worth more than all bits below `k` together (`2^k > 2^k - 1`), so the greedy choice at every level is optimal.
* **Edge Cases Considered:**
  * Single number → 0.
  * All numbers equal → 0.

## 🔹 Pattern Recognition

* **Belongs To:** Trie / Bit Manipulation
* **Common Problems Using This:**
  * 1707. Maximum XOR With an Element From Array (offline + trie)
  * 2935. Maximum Strong Pair XOR II
  * 1803. Count Pairs With XOR in a Range

## 🔹 Tricks & Patterns Used

* **Bit Manipulation:** `(x >> b) & 1`, building the answer with `result |= 1 << b`.
* **Array-based trie** (list of pairs) is faster than dict nodes.

## 🔹 Alternative Data Structures

* **Prefix set greedy:** for each bit, check whether `candidate ^ p` exists among the prefixes `{x >> b}`.

## 🔹 Complexity Analysis

* **Time Complexity:** O(31 · n)
* **Space Complexity:** O(31 · n)

## 🔹 Code Snippet (Optimized)

```python
from typing import List

BITS = 31


class Solution:
    def findMaximumXOR(self, nums: List[int]) -> int:
        trie = [[0, 0]]  # node -> [child for bit 0, child for bit 1]; 0 = none

        def insert(x: int) -> None:
            node = 0
            for b in range(BITS - 1, -1, -1):
                bit = (x >> b) & 1
                if not trie[node][bit]:
                    trie[node][bit] = len(trie)
                    trie.append([0, 0])
                node = trie[node][bit]

        def best_with(x: int) -> int:
            node, result = 0, 0
            for b in range(BITS - 1, -1, -1):
                want = 1 - ((x >> b) & 1)  # opposite bit makes this XOR bit 1
                if trie[node][want]:
                    result |= 1 << b
                    node = trie[node][want]
                else:
                    node = trie[node][1 - want]
            return result

        for x in nums:
            insert(x)
        return max(best_with(x) for x in nums)
```
