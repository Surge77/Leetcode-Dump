# 242. Valid Anagram

**🔗 Link:** [LeetCode 242 - Valid Anagram](https://leetcode.com/problems/valid-anagram/description/)

**🟢 Status:** ✅ Solved


## 🔹 Problem Statement

Given two strings `s` and `t`, return `true` if `t` is a rearrangement of the letters of `s` (same letters with the same counts), otherwise `false`. The follow-up asks how to adapt the solution when the input may contain Unicode characters.

* **Example:** `s = "anagram", t = "nagaram"` → `true`
* **Constraints:** `1 ≤ s.length, t.length ≤ 5 * 10^4`; `s` and `t` consist of lowercase English letters

---

## 🔹 Quick Breakdown

* **Difficulty Level:** Easy
* **Main Approach:** Frequency Counting (Using an Array as a Hash Table)
* **Core Concept:** Hashing, Character Frequency
* **When to Use This Pattern?** When verifying if two words contain the **same characters with identical frequencies**.
* **Mistakes to Avoid:**
  * Failing to check the **lengths** of both strings first.
  * Overlooking **case sensitivity** and **whitespace** handling if the input were not guaranteed lowercase letters (LeetCode's constraints guarantee it, so the normalisation in the code below is optional here).
  * Using a 26-slot array when the follow-up allows Unicode — use a hash map instead.

## 🔹 Solution Breakdown

* **Optimal Approach:**
  * Use a **fixed-size integer array** of size `26` to store frequency counts of characters.
  * Increment the count for each character in `s`, decrement for each character in `t`.
  * If the array contains all **zeroes** at the end, the words are anagrams.
* **Why This Works?**
  * Instead of using a **HashMap**, a **fixed-size array** is utilized, offering faster performance.
  * Since only lowercase English letters (`a-z`) are involved, an array of size `26` is sufficient.
* **Edge Cases Considered:**
  * Different **lengths** (checked at the beginning).
  * Case sensitivity (both strings converted to **lowercase**) and whitespace (spaces removed) — not needed for the official input, which is lowercase letters only. Note the Java checks the length *before* removing spaces, so with spaces it would reject `"a b"` vs `"ab"`; the Python variant normalises first.

## 🔹 Code Snippet (Optimized)

```java

class Solution {
    public boolean isAnagram(String s, String t) {
        if (s.length() != t.length()) return false;

        // Convert to lowercase (optional based on requirements)
        s = s.toLowerCase();
        t = t.toLowerCase();

        // Remove whitespaces (if needed)
        s = s.replace(" ", "");
        t = t.replace(" ", "");

        // Character frequency array
        int[] counts = new int[26];

        // Fill the frequency array
        for (int i = 0; i < s.length(); i++) {
            counts[s.charAt(i) - 'a']++;
            counts[t.charAt(i) - 'a']--;
        }

        // Check if all counts are zero
        for (int val : counts) {
            if (val != 0) return false;
        }

        return true;
    }
}
```

## 🔹 Code Snippet (Python)

```python
class Solution:
    def isAnagram(self, s: str, t: str) -> bool:
        s, t = s.lower().replace(" ", ""), t.lower().replace(" ", "")  # same normalisation as the Java
        if len(s) != len(t):
            return False
        counts = [0] * 26
        for a, b in zip(s, t):
            counts[ord(a) - ord("a")] += 1
            counts[ord(b) - ord("a")] -= 1
        return not any(counts)
```
