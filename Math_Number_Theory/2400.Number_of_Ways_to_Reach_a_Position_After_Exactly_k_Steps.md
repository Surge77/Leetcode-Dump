# 🔹 Problem Name: 2400. Number of Ways to Reach a Position After Exactly k Steps (Combinatorics, nCr mod p, Medium)

**🔗 Link:** [LeetCode 2400](https://leetcode.com/problems/number-of-ways-to-reach-a-position-after-exactly-k-steps/)
**🟢 Status:** 🔄 Need Review

## 🔹 Problem Statement

You stand at `startPos` on an infinite integer number line and must make exactly `k` steps, each one unit left or right. Return the number of distinct step sequences that end at `endPos`, modulo `10^9 + 7`; two ways differ if their step orders differ.

* **Example:** `startPos = 1, endPos = 2, k = 3` → `3`
* **Constraints:** `1 ≤ startPos, endPos, k ≤ 1000`

## 🔹 Quick Breakdown

* **Difficulty Level:** Medium
* **Main Approach:** A walk is just a choice of **which** of the `k` steps go right. With `d = |end − start|`, you need `R − L = d` and `R + L = k`, so `R = (k + d) / 2` and the answer is `C(k, R) mod 10⁹+7`.
* **Core Concept:** counting by choosing positions → binomial coefficient; nCr mod a prime via factorials and Fermat's inverse
* **When to Use This Pattern?** "Number of ways to arrange / reach / choose …" where order is forced once you pick a subset of positions; anything that asks for a count mod a prime with `n` up to ~10⁶.
* **Mistakes to Avoid:**
  * Forgetting the two impossible cases: `d > k`, or `k − d` odd (parity never matches).
  * Dividing with `/` under a modulus — multiply by the modular inverse `pow(x, MOD − 2, MOD)` instead (MOD is prime).

## 🔹 Optimization Path

* **Brute Force:** DP over (step, position): `ways[t][p] = ways[t−1][p−1] + ways[t−1][p+1]` — O(k²).
* **Optimized Solution:** one binomial coefficient — O(k) to build factorials, O(log MOD) for one inverse.
* **Further Improvements Possible?** For many queries precompute `fact` and `inv_fact` once (see the contest template); each `C(n, r)` is then O(1).

## 🔹 Solution Breakdown

* **Optimal Approach:** check feasibility, `R = (k + d) // 2`, return `fact[k] · inverse(fact[R] · fact[k − R])`.
* **Why This Works?** Every sequence of `R` rights and `k − R` lefts ends at `start + R − (k − R) = start + d` (or `start − d` by symmetry), and different subsets of right-steps are different walks — a bijection with `R`-subsets of `k` steps.
* **Edge Cases Considered:**
  * `start == end` with even `k` → `C(k, k/2)`; with odd `k` → 0.
  * `d == k` → exactly one walk.

## 🔹 Tricks & Patterns Used

* **Fermat's little theorem:** for prime `p`, `x⁻¹ ≡ x^(p−2) (mod p)` → `pow(x, p - 2, p)`.
* **Parity check** before any counting: each step changes the position's parity.

## 🔹 Alternative Data Structures

* Pascal's triangle (`C[n][r] = C[n−1][r−1] + C[n−1][r]`) needs no inverses — fine for `n ≤ ~2000`, works for any modulus.
* `math.comb(k, R) % MOD` is correct in Python but builds a huge integer; fine here (`k ≤ 1000`), too slow inside a loop of 10⁵ queries.

* **Time Complexity:** O(k)
* **Space Complexity:** O(k)

## 🔹 Code Snippet (Brute Force DP)

```python
class Solution:
    def numberOfWays(self, startPos: int, endPos: int, k: int) -> int:
        MOD = 10**9 + 7
        ways = {startPos: 1}
        for _ in range(k):
            nxt = {}
            for pos, count in ways.items():
                for step in (-1, 1):
                    nxt[pos + step] = (nxt.get(pos + step, 0) + count) % MOD
            ways = nxt
        return ways.get(endPos, 0)
```

## 🔹 Code Snippet (Optimized)

```python
MOD = 10**9 + 7


class Solution:
    def numberOfWays(self, startPos: int, endPos: int, k: int) -> int:
        distance = abs(endPos - startPos)
        if distance > k or (k - distance) % 2:
            return 0
        rights = (k + distance) // 2
        fact = [1] * (k + 1)
        for i in range(1, k + 1):
            fact[i] = fact[i - 1] * i % MOD
        denominator = fact[rights] * fact[k - rights] % MOD
        return fact[k] * pow(denominator, MOD - 2, MOD) % MOD  # C(k, rights) mod p
```
