# 🔹 Problem Name: 40. Combination Sum II (Backtracking, Medium)

**🔗 Link:** [LeetCode 40](https://leetcode.com/problems/combination-sum-ii/)
**🟢 Status:** 🔄 Need Review

## 🔹 Quick Breakdown

* **Difficulty Level:** Medium
* **Main Approach:** **Sort, then backtrack with "skip equal siblings".** Each element is used at most once (`dfs(i + 1, …)`). Because `candidates` may contain duplicates, at one recursion level only the **first** of a run of equal values is tried: `if i > start and c[i] == c[i − 1]: continue`. Break when `c[i] > remain`.
* **Core Concept:** duplicates are removed at generation time — two equal values in the same position of the combination would produce the same subtree
* **When to Use This Pattern?** Combinations / subsets from a multiset where the output must not repeat — Subsets II, Permutations II, Combination Sum II.
* **Mistakes to Avoid:**
  * Generating everything and deduplicating with a set: with `candidates = [1] * 100` and `target = 30` there are C(100, 30) ≈ 3·10²⁵ index subsets for one answer.
  * Writing the skip as `i > 0` instead of `i > start` — that also forbids taking two equal values **at different depths**, losing `[1, 1, 6]`.

## 🔹 Optimization Path

* **Brute Force:** every subset of indices (bitmask), keep those summing to `target`, dedupe sorted tuples — O(2ⁿ · n); only feasible for tiny `n`, not `n = 100`.
* **Optimized Solution:** sorted backtracking with sibling-skip and break — explores only distinct value-multisets whose sum stays ≤ `target`.
* **Further Improvements Possible?** Group the input into `(value, count)` pairs and choose a count per value — the same search, slightly fewer calls.

## 🔹 Solution Breakdown

* **Optimal Approach:** `candidates.sort()`; `dfs(start, remain)`: on `remain == 0` record a copy; for `i ≥ start`: skip equal siblings, break on `c[i] > remain`, push, `dfs(i + 1, remain − c[i])`, pop.
* **Why This Works?** Sorting groups equal values. At a given level, choosing the first or the second `1` as the next element leads to identical sets of completions, so trying only the first loses nothing and creates no duplicates. Deeper levels start at `i + 1`, so the second `1` can still follow the first.
* **Edge Cases Considered:**
  * All values larger than `target` → `[]` (the first iteration breaks).
  * Many equal values (`[2,5,2,1,2]`, target 5) → `[[1,2,2],[5]]`, no repeats.

## 🔹 Tricks & Patterns Used

* **`i > start` sibling skip** — the canonical dedupe for sorted multisets.
* **Sort + break** on the first value that overshoots.

## 🔹 Alternative Data Structures

* `Counter` of values and recursion over distinct values with a chosen multiplicity `0..count`.

## 🔹 Complexity Analysis

* **Time Complexity:** O(2ⁿ · n) worst case (`n ≤ 100`, but `target ≤ 30` and values ≥ 1 cap the depth at 30 and the sibling skip caps the branching at 50 distinct values, so real runs are tiny).
* **Space Complexity:** O(target) recursion depth and path, excluding the output; O(n) for the sorted copy.

## 🔹 Code Snippet (Brute Force)

```python
from typing import List


class Solution:
    def combinationSum2(self, candidates: List[int], target: int) -> List[List[int]]:
        n = len(candidates)
        found = set()
        for mask in range(1 << n):
            picked = [candidates[i] for i in range(n) if mask >> i & 1]
            if sum(picked) == target:
                found.add(tuple(sorted(picked)))
        return [list(combo) for combo in found]
```

## 🔹 Code Snippet (Optimized)

```python
from typing import List


class Solution:
    def combinationSum2(self, candidates: List[int], target: int) -> List[List[int]]:
        candidates = sorted(candidates)
        result, path = [], []

        def dfs(start: int, remain: int) -> None:
            if remain == 0:
                result.append(path[:])
                return
            for i in range(start, len(candidates)):
                if i > start and candidates[i] == candidates[i - 1]:
                    continue  # an equal sibling would grow the exact same subtree
                if candidates[i] > remain:
                    break
                path.append(candidates[i])
                dfs(i + 1, remain - candidates[i])
                path.pop()

        dfs(0, target)
        return result
```
