# 🔹 Problem Name: 373. Find K Pairs with Smallest Sums (Heap K-way Merge, Medium)

**🔗 Link:** [LeetCode 373](https://leetcode.com/problems/find-k-pairs-with-smallest-sums/)
**🟢 Status:** 🔄 Need Review

## 🔹 Problem Statement

Two arrays are given, each sorted in non-decreasing order. A pair takes one element from each array; return the `k` pairs with the smallest sums. Equal values at different indices form separate pairs.

* **Example:** `nums1 = [1,7,11], nums2 = [2,4,6], k = 3` → `[[1,2],[1,4],[1,6]]`
* **Constraints:** `1 ≤ nums1.length, nums2.length ≤ 10⁵`; `-10⁹ ≤ nums1[i], nums2[i] ≤ 10⁹`; `1 ≤ k ≤ 10⁴` and `k ≤ nums1.length · nums2.length`.

## 🔹 Quick Breakdown

* **Difficulty Level:** Medium
* **Main Approach:** **K-way merge.** Since both arrays are sorted, row `i` (`nums1[i]` paired with `nums2[0], nums2[1], ...`) is a sorted list of sums. Seed a min-heap with `(nums1[i] + nums2[0], i, 0)` for the first `min(k, n1)` rows; pop the smallest, record it, push `(i, j + 1)`. Stop after `k` pops.
* **Core Concept:** an implicit sorted matrix of sums — explore it lazily from the smallest corner instead of building all `n1 · n2` pairs
* **When to Use This Pattern?** "k-th / k smallest" over pairs or a matrix whose rows and columns are sorted — 378, 719 (with binary search), 1439, merge k sorted lists.
* **Mistakes to Avoid:**
  * Generating every pair: up to 10⁵ × 10⁵ = 10¹⁰.
  * Pushing both `(i + 1, j)` and `(i, j + 1)` from each pop without a visited set — the same cell gets pushed twice.
  * Seeding all `n1` rows when `k` is small: only the first `k` rows can contribute.

## 🔹 Optimization Path

* **Brute Force:** build all pairs, sort by sum, take `k` — O(n1·n2·log(n1·n2)).
* **Optimized Solution:** heap over rows — O(k log min(k, n1)).
* **Further Improvements Possible?** Binary search on the sum value plus two-pointer counting finds the k-th sum in O((n1 + n2) log range), but listing the pairs still costs O(k).

## 🔹 Solution Breakdown

* **Optimal Approach:** heap of `(sum, i, j)`; after popping `(i, j)` push `(i, j + 1)` if it exists.
* **Why This Works?** Within row `i` the sums are non-decreasing in `j`, so the smallest unseen pair is always the current head of some row — exactly what the heap holds. Each row enters via its column-0 seed, so no cell is pushed twice.
* **Edge Cases Considered:**
  * Duplicate values (`[1, 1, 2]`) — duplicate pairs are distinct index pairs and both count.
  * `k = n1 · n2` — every pair is returned (the constraints guarantee `k ≤ n1 · n2`).
  * Negative numbers (values in `[-10⁹, 10⁹]`) — ordering by sum is unaffected.

## 🔹 Tricks & Patterns Used

* **Seed the first column, advance along rows:** each cell has exactly one predecessor, which removes the need for a visited set.
* **Cap the seeds at `k`:** row `i ≥ k` has at least `k` smaller-or-equal pairs above it.

## 🔹 Alternative Data Structures

* Heap of `(sum, i, j)` with a visited set, pushing right and down neighbours — same complexity, more bookkeeping.

## 🔹 Complexity Analysis

* **Time Complexity:** O(k log min(k, n1))
* **Space Complexity:** O(min(k, n1)) for the heap, plus O(k) output

## 🔹 Code Snippet (Brute Force)

```python
from typing import List


class Solution:
    def kSmallestPairs(self, nums1: List[int], nums2: List[int], k: int) -> List[List[int]]:
        pairs = sorted(([a, b] for a in nums1 for b in nums2), key=sum)
        return pairs[:k]
```

## 🔹 Code Snippet (Optimized)

```python
import heapq
from typing import List


class Solution:
    def kSmallestPairs(self, nums1: List[int], nums2: List[int], k: int) -> List[List[int]]:
        # rows beyond k can never be needed: k pairs from earlier rows are already no larger
        heap = [(nums1[i] + nums2[0], i, 0) for i in range(min(k, len(nums1)))]
        heapq.heapify(heap)
        result = []
        while heap and len(result) < k:
            _, i, j = heapq.heappop(heap)
            result.append([nums1[i], nums2[j]])
            if j + 1 < len(nums2):
                heapq.heappush(heap, (nums1[i] + nums2[j + 1], i, j + 1))
        return result
```
