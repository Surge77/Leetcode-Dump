# 918. Maximum Sum Circular Subarray

**🔗 Link:** [LeetCode 918](https://leetcode.com/problems/maximum-sum-circular-subarray/)
**🟢 Status:** 🔄 Need Review


## 🔹 Problem Statement

Given an array treated as circular (the last element is followed by the first), return the largest sum of a non-empty contiguous subarray. A subarray may wrap around the end but may use each element at most once.

* **Example:** `nums = [1,-2,3,-2]` → `3`
* **Constraints:** `1 ≤ n ≤ 3 * 10^4`, `-3 * 10^4 ≤ nums[i] ≤ 3 * 10^4`

## 🔹 Quick Breakdown

* **Difficulty Level:** Medium
* **Main Approach:** **Kadane twice.** A circular subarray either does not wrap (plain max subarray, Kadane) or wraps around the end — and a wrapping subarray is the whole array **minus** a contiguous middle piece. So the best wrapping sum is `total − (minimum subarray sum)`. Answer = `max(maxKadane, total − minKadane)`, except when every number is negative.
* **Core Concept:** the complement of a wrapping subarray is an ordinary subarray
* **When to Use This Pattern?** "Circular" array where the chosen piece is contiguous — maximise the piece by minimising its complement.
* **Mistakes to Avoid:**
  * All-negative input: `minKadane` is the whole array, so `total − min = 0`, which is the **empty** subarray — not allowed. Return `maxKadane` instead.
  * Concatenating the array with itself and running Kadane: it can pick a window longer than `n`.

## 🔹 Optimization Path

* **Brute Force:** every start, extend up to `n` elements around the circle — O(n²) = 9·10⁸ for `n = 3·10⁴`.
* **Optimized Solution:** one pass tracking running max, running min and total — O(n), O(1) space.
* **Further Improvements Possible?** No; every element must be read.

## 🔹 Solution Breakdown

* **Optimal Approach:** `curMax = max(x, curMax + x)`, `curMin = min(x, curMin + x)`; keep the best of each and the total.
* **Why This Works?** For a wrapping subarray `nums[j..n-1] + nums[0..i]`, the removed part `nums[i+1..j-1]` is non-empty and contiguous; maximising what is kept equals minimising what is removed. If `maxKadane < 0`, every element is negative and the best answer is the single largest element, which Kadane already found.
* **Edge Cases Considered:**
  * All negative → `maxKadane` (e.g. `[-3,-2,-3]` → `-2`).
  * Minimum subarray = whole array while some element is `≥ 0`: `total − min = 0 ≤ maxKadane`, so the empty choice never wins.
  * `n = 1`.

## 🔹 Code Snippet (Brute Force)

```python
from typing import List


class Solution:
    def maxSubarraySumCircular(self, nums: List[int]) -> int:
        n = len(nums)
        best = nums[0]
        for start in range(n):
            running = 0
            for length in range(n):
                running += nums[(start + length) % n]
                best = max(best, running)
        return best
```

## 🔹 Code Snippet (Optimized)

```python
from typing import List


class Solution:
    def maxSubarraySumCircular(self, nums: List[int]) -> int:
        cur_max = cur_min = 0
        best_max, best_min = nums[0], nums[0]
        total = 0
        for x in nums:
            cur_max = max(x, cur_max + x)
            cur_min = min(x, cur_min + x)
            best_max = max(best_max, cur_max)
            best_min = min(best_min, cur_min)
            total += x
        if best_max < 0:  # all negative: total - best_min would be the empty subarray
            return best_max
        return max(best_max, total - best_min)
```
