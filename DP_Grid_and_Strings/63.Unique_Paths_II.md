# 🔹 Problem Name: 63. Unique Paths II (Grid DP, Medium)

**🔗 Link:** [LeetCode 63](https://leetcode.com/problems/unique-paths-ii/)
**🟢 Status:** 🔄 Need Review

## 🔹 Quick Breakdown

* **Difficulty Level:** Medium
* **Main Approach:** **Row-by-row DP.** `dp[j]` = number of paths to the current cell; an obstacle sets it to `0`, otherwise `dp[j] += dp[j-1]` (above + left).
* **Core Concept:** paths into a cell = paths into the cell above + paths into the cell to the left, and an obstacle has zero paths in or out.
* **When to Use This Pattern?** Counting monotone (right/down) paths in a grid with blocked cells — 62 with obstacles.
* **Mistakes to Avoid:**
  * Initialising the whole first row / column to `1`: an obstacle in it cuts off every cell after it.
  * Forgetting that the start or the target itself can be an obstacle → answer `0`.
  * The closed form `C(m+n-2, m-1)` from 62 no longer applies.

## 🔹 Optimization Path

* **Brute Force:** recursion over every right/down path — O(2^(m+n)).
* **Optimized Solution:** each cell's count depends only on two neighbours — O(m · n) time, O(n) space with one rolling row.
* **Further Improvements Possible?** No — every cell has to be read at least once.

## 🔹 Solution Breakdown

* **Optimal Approach:** `dp = [0] * n`, `dp[0] = 1` (one way to "enter" the start). For each row, for each `j`: obstacle → `dp[j] = 0`; else if `j > 0` → `dp[j] += dp[j-1]`.
* **Why This Works?** Before the update `dp[j]` still holds the count for the cell above; `dp[j-1]` was already updated for the current row, so it is the cell to the left. Zeroing obstacles means no path is ever counted through them. Seeding `dp[0] = 1` makes the first row and column inherit `1` until the first obstacle, then `0`.
* **Edge Cases Considered:**
  * `obstacleGrid[0][0] == 1` → zeroed on the first step, answer `0`.
  * Single row or column with an obstacle anywhere → `0`.
  * LeetCode guarantees the answer fits in `2·10⁹`; Python ints would not overflow anyway.

## 🔹 Tricks & Patterns Used

* **1D rolling row:** "above" is the old `dp[j]`, "left" is the new `dp[j-1]`.
* **Seed one cell instead of a whole border** so obstacles on the border are handled by the same rule.

## 🔹 Alternative Data Structures

* Full `m × n` table — same time, O(m · n) space, easier to debug.
* Top-down memoised recursion on `(r, c)`.

## 🔹 Complexity Analysis

* **Time Complexity:** O(m · n)
* **Space Complexity:** O(n)

## 🔹 Code Snippet (Brute Force)

```python
from typing import List


class Solution:
    def uniquePathsWithObstacles(self, obstacleGrid: List[List[int]]) -> int:
        m, n = len(obstacleGrid), len(obstacleGrid[0])

        def walk(r: int, c: int) -> int:
            if r == m or c == n or obstacleGrid[r][c] == 1:
                return 0
            if r == m - 1 and c == n - 1:
                return 1
            return walk(r + 1, c) + walk(r, c + 1)

        return walk(0, 0)
```

## 🔹 Code Snippet (Optimized)

```python
from typing import List


class Solution:
    def uniquePathsWithObstacles(self, obstacleGrid: List[List[int]]) -> int:
        n = len(obstacleGrid[0])
        dp = [0] * n
        dp[0] = 1  # one way to stand on the start; zeroed below if it is blocked
        for row in obstacleGrid:
            for j in range(n):
                if row[j] == 1:
                    dp[j] = 0
                elif j > 0:
                    dp[j] += dp[j - 1]  # old dp[j] is the cell above, dp[j-1] the cell to the left
        return dp[-1]
```
