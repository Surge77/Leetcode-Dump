# 🔹 Problem Name: 124. Binary Tree Maximum Path Sum (DP on Trees, Hard)

**🔗 Link:** [LeetCode 124](https://leetcode.com/problems/binary-tree-maximum-path-sum/)
**🟢 Status:** 🔄 Need Review

## 🔹 Quick Breakdown

* **Difficulty Level:** Hard
* **Main Approach:** Post-order. Each node returns its best **downward** gain `val + max(0, left gain, right gain)` to its parent, and separately updates the global answer with the path that **bends** at it: `val + max(0, left) + max(0, right)`.
* **Core Concept:** Tree DP — "return one thing, record another"
* **When to Use This Pattern?** Paths that may start and end anywhere in a tree: diameter, longest univalue path, max path sum.
* **Mistakes to Avoid:**
  * Returning the bent path to the parent — a parent can only extend a one-sided path.
  * Initialising the answer to 0 — all-negative trees need the largest single node.
  * Not clipping negative child gains to 0.

## 🔹 Optimization Path

* **Brute Force:** Try every pair of endpoints — O(n²) paths, O(n³) naive.
* **Optimized Solution:** O(n) single post-order pass.
* **Further Improvements Possible?** No.

## 🔹 Solution Breakdown

* **Optimal Approach:** Iterative post-order (reversed pre-order) storing `gain[node]`; `best = max(best, val + l + r)` with `l, r = max(0, child gain)`.
* **Why This Works?** Every path has exactly one highest node; at that node the path is "left part + node + right part", and each part is a best downward chain — exactly what the children's gains measure.
* **Edge Cases Considered:**
  * Single node.
  * All negative values → the maximum node value.
  * Deep skewed tree (iterative traversal avoids `RecursionError`).

## 🔹 Pattern Recognition

* **Belongs To:** DP on Trees / Tree Traversal
* **Common Problems Using This:**
  * 543. Diameter of Binary Tree

## 🔹 Tricks & Patterns Used

* **Two quantities per node:** the value passed up (one branch) vs the value recorded (both branches).
* **`max(0, gain)`** = "drop a branch that only hurts".

## 🔹 Alternative Data Structures

* Recursive DFS with a `nonlocal best` — shortest to write; raise the recursion limit for deep trees.

## 🔹 Complexity Analysis

* **Time Complexity:** O(n)
* **Space Complexity:** O(n)

## 🔹 Code Snippet (Optimized)

```python
from typing import Optional

# class TreeNode:
#     def __init__(self, val=0, left=None, right=None):
#         self.val = val
#         self.left = left
#         self.right = right


class Solution:
    def maxPathSum(self, root: Optional["TreeNode"]) -> int:
        order, stack = [], [root]
        while stack:  # pre-order; reversed => children before parents
            node = stack.pop()
            order.append(node)
            if node.left:
                stack.append(node.left)
            if node.right:
                stack.append(node.right)

        gain = {None: 0}  # best downward path sum starting at node
        best = float("-inf")
        for node in reversed(order):
            left = max(0, gain[node.left])
            right = max(0, gain[node.right])
            best = max(best, node.val + left + right)  # path bending at node
            gain[node] = node.val + max(left, right)  # one branch goes up
        return best
```
