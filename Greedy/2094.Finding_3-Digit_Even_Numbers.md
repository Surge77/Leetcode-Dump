# 2094. Finding 3-Digit Even Numbers

**🔗 Link:** [LeetCode Problem 2094](https://leetcode.com/problems/finding-3-digit-even-numbers/description/?envType=daily-question&envId=2025-05-12)

**🟢 Status:** ✅ Solved


## 🔹 Problem Statement

You get an array of single digits, possibly with repeats. Form every distinct three-digit number that uses three of those digits (each digit used at most as many times as it appears), has no leading zero and is even. Return them in ascending order.

* **Example:** `digits = [2,1,3,0]` → `[102,120,130,132,210,230,302,310,312,320]`
* **Constraints:** `3 ≤ digits.length ≤ 100`, `0 ≤ digits[i] ≤ 9`.

## 🔹Quick Breakdown

* **Difficulty Level:** Easy
* **Main Approach:** Iterative construction of 3-digit even numbers using the available digits while ensuring that the ones place digit is even and the hundreds place digit is non-zero.
* **Core Concept:** Digit-frequency table + bounded enumeration (filed under Greedy, but nothing is chosen greedily — the answer space is only 9·10·5 candidates)
* **When to Use This Pattern?** When generating all valid combinations of numbers with constraints, such as even numbers or avoiding leading zeros.
* **Mistakes to Avoid:**
  * Allowing invalid 3-digit numbers (e.g., leading zeros).
  * Forgetting to check that the ones place is an even digit (0, 2, 4, 6, 8).

## 🔹 Optimization Path

* **Brute Force:** O(n³) – try every ordered triple of distinct indices (n ≤ 100), keep even numbers without a leading zero, dedupe with a set.
* **Optimized Solution:** O(n) to count the digits, then a constant 9 · 10 · 5 = 450 candidate checks (plus sorting at most 450 results) – a frequency table replaces index bookkeeping, so duplicates never arise and no set is needed.
* **Further Improvements Possible?** The approach is already optimal as we iterate through all combinations, ensuring validity at each step.

## 🔹 Solution Breakdown

* **Optimal Approach:** The algorithm uses nested loops to select digits for the hundreds, tens, and ones place, ensuring that the final number is a valid 3-digit even number.
* **Why This Works?** It generates all possible combinations of valid digits while ensuring constraints (e.g., the ones digit is even, and the hundreds digit is non-zero).
* **Edge Cases Considered:**
  * Leading zeros are avoided in the hundreds place.
  * Only even digits are used for the ones place (0, 2, 4, 6, 8).
  * Digits can repeat as long as their frequency allows.

## 🔹 Tricks & Patterns Used

* **Digit frequency array (size 10):** decrement a digit when it is placed, restore it afterwards (Java), or compare against a `Counter` of the candidate's digits (Python).
* **Search space is tiny:** the hundreds digit is 1–9, the ones digit is 0/2/4/6/8, so every candidate in `100 … 998` (step 2) can be tested directly.

## 🔹 Alternative Data Structures

* **Can this problem be optimized using a different DS?**
  * A **Set** is needed only in the brute force (permutations of indices repeat the same number); the frequency-table loops generate each number once.
  * Enumerating `range(100, 1000, 2)` in order (the Python version) yields an already sorted result, so no sort is needed.

## 🔹 Complexity Analysis

* **Time Complexity:** O(n) – one pass to count digits, then a fixed number (≤ 450) of candidate checks and a sort of at most 450 results.
* **Space Complexity:** O(1) – a 10-slot frequency array plus a result list of at most 450 numbers (output only).

## 🔹 Code Snippet (Optimized)

```java

class Solution {
    public int[] findEvenNumbers(int[] digits) {
        List<Integer> result = new ArrayList<>();
        int[] freq = new int[10]; // Frequency of digits

        // Count the frequency of each digit in the input array
        for (int num : digits) {
            freq[num]++;
        }

        // Iterate over the hundreds place (1-9)
        for (int i = 1; i <= 9; i++) {
            if (freq[i] == 0) continue; // Skip if no digit available
            freq[i]--; // Decrease frequency after choosing digit

            // Iterate over the tens place (0-9)
            for (int j = 0; j <= 9; j++) {
                if (freq[j] == 0) continue; // Skip if no digit available
                freq[j]--; // Decrease frequency after choosing digit

                // Iterate over the ones place (0, 2, 4, 6, 8)
                for (int k = 0; k <= 8; k += 2) {
                    if (freq[k] == 0) continue; // Skip if no digit available
                    freq[k]--; // Decrease frequency after choosing digit

                    // Construct the valid 3-digit number
                    int num = i * 100 + j * 10 + k;
                    result.add(num); // Add to result list

                    // Restore frequency after processing this digit
                    freq[k]++;
                }
                freq[j]++; // Restore frequency for tens place
            }
            freq[i]++; // Restore frequency for hundreds place
        }

        Collections.sort(result); // Sort the results in ascending order
        int[] resultArr = new int[result.size()];
        for (int i = 0; i < result.size(); i++) {
            resultArr[i] = result.get(i);
        }

        return resultArr;
    }
}

```

## 🔹 Code Snippet (Brute Force)

```python
from itertools import permutations
from typing import List


class Solution:
    def findEvenNumbers(self, digits: List[int]) -> List[int]:
        found = set()
        for a, b, c in permutations(digits, 3):  # every ordered triple of distinct indices
            if a != 0 and c % 2 == 0:
                found.add(a * 100 + b * 10 + c)
        return sorted(found)
```

## 🔹 Code Snippet (Python)

```python
from collections import Counter
from typing import List


class Solution:
    def findEvenNumbers(self, digits: List[int]) -> List[int]:
        have = Counter(digits)
        result = []
        for num in range(100, 1000, 2):  # 3 digits, no leading zero, even
            need = Counter(map(int, str(num)))
            if all(have[d] >= c for d, c in need.items()):
                result.append(num)
        return result
```
