# 🔹 Problem Name: 334. Increasing Triplet Subsequence (Greedy, Medium)

**🔗 Link:** [LeetCode 334](https://leetcode.com/problems/increasing-triplet-subsequence/)
**🟢 Status:** 🔄 Need Review

## 🔹 Problem Statement

Given an integer array, decide whether it contains three positions `i < j < k` whose values strictly increase: `nums[i] < nums[j] < nums[k]`. The indices need not be adjacent. The follow-up asks for O(n) time and O(1) space.

* **Example:** `nums = [1,2,3,4,5]` → `true`
* **Constraints:** `1 ≤ nums.length ≤ 5 · 10^5`, `-2^31 ≤ nums[i] ≤ 2^31 - 1`.

## 🔹 Quick Breakdown

* **Difficulty Level:** Medium
* **Main Approach:** **Track the two smallest tails.** `first` = smallest value seen, `second` = smallest value that has something smaller before it (the tail of the best length-2 increasing subsequence). Any `x > second` completes a triplet.
* **Core Concept:** the length-≤ 2 case of the LIS "patience" tails array
* **When to Use This Pattern?** "Does an increasing subsequence of length `k` exist" for small constant `k` with O(1) space.
* **Mistakes to Avoid:**
  * Treating `first` and `second` as positions: they are values, and `first` may come **after** `second` in the array — that is fine, `second` still proves some smaller value came before it.
  * Using `<` instead of `<=` when updating, which allows equal elements (`[1, 1, 1]`).
  * O(n²)/O(n³) subsequence enumeration at `n = 5·10⁵`.

## 🔹 Optimization Path

* **Brute Force:** check every triple `i < j < k` — O(n³).
* **Optimized Solution:** one pass with two variables — O(n) time, O(1) space.
* **Further Improvements Possible?** No.

## 🔹 Solution Breakdown

* **Optimal Approach:** `first = second = ∞`. For each `x`: if `x <= first` → `first = x`; elif `x <= second` → `second = x`; else return `True`.
* **Why This Works?** Invariant: a length-2 increasing pair ending in `second` exists in the processed prefix, and `first` is the smallest value of the prefix. Lowering `first` never invalidates the pair already proven (it is remembered by `second`), but gives future values a better chance of lowering `second`. If `x > second` a pair plus `x` is increasing.
* **Edge Cases Considered:**
  * Fewer than 3 elements → `False`.
  * `[2, 1, 5, 0, 4, 6]` → `True` (`first = 0` but `second = 4`, then `6`).
  * Duplicates never count.

## 🔹 Tricks & Patterns Used

* **Two sentinels at `inf`** so the first values populate them naturally.
* **Early return** the moment a third element appears.

## 🔹 Alternative Data Structures

* Prefix-min and suffix-max arrays: a middle element `j` works iff `prefMin[j−1] < nums[j] < sufMax[j+1]` — O(n) time and space.
* General LIS with a `bisect` tails array, stopping at length 3.

## 🔹 Code Snippet (Brute Force)

```python
from typing import List


class Solution:
    def increasingTriplet(self, nums: List[int]) -> bool:
        n = len(nums)
        for i in range(n):
            for j in range(i + 1, n):
                if nums[j] <= nums[i]:
                    continue
                for k in range(j + 1, n):
                    if nums[k] > nums[j]:
                        return True
        return False
```

## 🔹 Code Snippet (Optimized)

```python
from typing import List


class Solution:
    def increasingTriplet(self, nums: List[int]) -> bool:
        first = second = float("inf")
        for x in nums:
            if x <= first:
                first = x
            elif x <= second:
                second = x  # something smaller than x exists earlier, via a former `first`
            else:
                return True
        return False
```
