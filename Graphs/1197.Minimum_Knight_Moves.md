# 1197. Minimum Knight Moves

## 🔹 Problem Statement

A knight starts at `(0, 0)` on an infinite chessboard. Given a target square `(x, y)`, return the minimum number of standard knight moves needed to reach it; the target is always reachable. *(premium — paraphrased from memory, not checked against the official page)*

* **Example:** `x = 2, y = 1` → `1`
* **Constraints:** `-300 ≤ x, y ≤ 300`, `0 ≤ |x| + |y| ≤ 300`

## 🔹 Quick Breakdown

* **Difficulty Level:** Medium
* **Main Approach:** **BFS on the infinite board, folded by symmetry.** The board is symmetric under `x → −x` and `y → −y`, so replace the target by `(|x|, |y|)` and only explore cells with `x ≥ −2` and `y ≥ −2`. BFS from `(0, 0)` with the 8 knight moves; the level of the target is the answer.
* **Core Concept:** shortest path in an unweighted graph is BFS; symmetry shrinks the search space by about 4×
* **When to Use This Pattern?** Minimum number of moves for a piece on an unbounded grid.
* **Mistakes to Avoid:**
  * DFS or recursion: it finds *a* path, not the shortest.
  * Forgetting `visited`: each cell is reached from 8 neighbours and the queue explodes.
  * Restricting to `x, y ≥ 0` strictly: some targets (e.g. `(1, 1)`) need a step through a negative coordinate. Allowing down to `−2` is enough.
  * Visited stored as a 2-D list with bounds guessed too tightly — use a set.

## 🔹 Optimization Path

* **Brute Force:** BFS in all four quadrants with no bounds, only a `visited` set — correct, but explores roughly 4× more cells.
* **Optimized Solution:** BFS restricted by symmetry to `x, y ≥ −2` on the folded target.
* **Further Improvements Possible?** There is an O(1) closed form (with exceptions for `(1, 0)` and `(2, 2)`), and bidirectional BFS also halves the depth; BFS is far easier to get right in an interview.

## 🔹 Solution Breakdown

* **Optimal Approach:** `x, y = abs(x), abs(y)`; BFS level by level from `(0, 0)` until `(x, y)` is popped. Skip neighbours with a coordinate `< −2`.
* **Why This Works?** Reflecting the board across either axis maps a shortest path to a shortest path, so the answer for `(x, y)` equals that for `(|x|, |y|)`. A shortest path to a first-quadrant cell never needs to wander farther than 2 cells outside the quadrant, so the bound only prunes cells that cannot help.
* **Edge Cases Considered:**
  * `(0, 0)` → `0`.
  * `(1, 1)` → `2`, `(1, 0)` → `3`, `(2, 2)` → `4`, `(5, 5)` → `4`, `(2, 1)` → `1`.
  * `|x| + |y| ≤ 300` (the largest inputs, e.g. `(300, 0)`, still explore a ~300 × 300 window).

## 🔹 Tricks & Patterns Used

* **Symmetry folding:** `abs()` on the target.
* **Pruned search window** instead of a physical grid.
* **Level-by-level BFS** to count moves without storing distances.

## 🔹 Alternative Data Structures

* Bidirectional BFS from the origin and the target.
* Memoised recursion on the folded target, `f(x, y) = 1 + min(f(|x−1|, |y−2|), f(|x−2|, |y−1|))` with `(0,0) → 0`, `(1,1) → 2`.

## 🔹 Complexity Analysis

* **Time Complexity:** O((|x| + |y|)²) cells (the knight needs about `(|x| + |y|) / 3` moves and BFS visits every cell within that many moves, so the window is quadratic in the distance, not in `|x| · |y|`: a target like `(300, 0)` still explores ~300 × 300 cells)
* **Space Complexity:** O((|x| + |y|)²)

## 🔹 Code Snippet (Brute Force)

```python
from collections import deque


class Solution:
    def minKnightMoves(self, x: int, y: int) -> int:
        moves = [(1, 2), (2, 1), (2, -1), (1, -2), (-1, -2), (-2, -1), (-2, 1), (-1, 2)]
        queue = deque([(0, 0, 0)])
        seen = {(0, 0)}
        while queue:
            cx, cy, steps = queue.popleft()
            if (cx, cy) == (x, y):
                return steps
            for dx, dy in moves:
                nxt = (cx + dx, cy + dy)
                if nxt not in seen:
                    seen.add(nxt)
                    queue.append((nxt[0], nxt[1], steps + 1))
        return -1
```

## 🔹 Code Snippet (Optimized)

```python
from collections import deque


class Solution:
    def minKnightMoves(self, x: int, y: int) -> int:
        x, y = abs(x), abs(y)  # the board is symmetric in both axes
        moves = [(1, 2), (2, 1), (2, -1), (1, -2), (-1, -2), (-2, -1), (-2, 1), (-1, 2)]
        seen = {(0, 0)}
        frontier = [(0, 0)]
        steps = 0
        while frontier:
            next_frontier = []
            for cx, cy in frontier:
                if (cx, cy) == (x, y):
                    return steps
                for dx, dy in moves:
                    nx, ny = cx + dx, cy + dy
                    # going slightly below 0 is sometimes needed; further is never useful
                    if nx >= -2 and ny >= -2 and (nx, ny) not in seen:
                        seen.add((nx, ny))
                        next_frontier.append((nx, ny))
            frontier = next_frontier
            steps += 1
        return -1
```
