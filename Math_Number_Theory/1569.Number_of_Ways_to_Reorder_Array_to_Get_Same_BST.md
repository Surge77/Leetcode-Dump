# 🔹 Problem Name: 1569. Number of Ways to Reorder Array to Get Same BST (Combinatorics + Tree DP, Hard)

**🔗 Link:** [LeetCode 1569](https://leetcode.com/problems/number-of-ways-to-reorder-array-to-get-same-bst/)
**🟢 Status:** 🔄 Need Review

## 🔹 Problem Statement

`nums` is a permutation of `1..n`, and inserting its elements in order into an empty BST gives some tree. Count how many reorderings of `nums` build exactly the same BST (the original order itself is not counted, so answer = ways minus one), modulo `10^9 + 7`.

* **Example:** `nums = [2,1,3]` → `1`
* **Constraints:** `1 ≤ nums.length ≤ 1000`; `1 ≤ nums[i] ≤ nums.length`; all values distinct.

## 🔹 Quick Breakdown

* **Difficulty Level:** Hard
* **Main Approach:** The first element is the root. The keys smaller than it form the left subtree and the larger ones the right subtree. The relative order **inside** each side must give the same subtree, but the two sides can be **interleaved** freely: `C(L + R, L)` ways. Recurse: `ways(node) = C(L + R, L) · ways(left) · ways(right)`; answer `ways(root) − 1` (exclude the original order).
* **Core Concept:** counting interleavings with a binomial coefficient, multiplied up a tree (tree DP)
* **When to Use This Pattern?** "How many orders / insertion sequences / topological orders produce the same structure?" — merge independent sequences while keeping each one's internal order.
* **Mistakes to Avoid:**
  * Forgetting the `− 1` (the given order itself does not count).
  * Recursing on sublists: a sorted input makes the tree a path, recursion depth `n = 1000` → stack overflow in Python. Build the BST and fold it iteratively.

## 🔹 Optimization Path

* **Brute Force:** try all `n!` permutations and compare BSTs — only for `n ≤ 8`.
* **Optimized Solution:** Pascal's triangle up to `n` (O(n²)), insert into a BST (O(n²) worst case), one post-order pass.
* **Further Improvements Possible?** Factorials + inverses make each `C` O(1) with O(n) precompute; the BST build stays the bottleneck.

## 🔹 Solution Breakdown

* **Optimal Approach:** insert `nums` into a BST (child maps), then a post-order traversal computes each node's subtree `size` and `ways` with the formula above.
* **Why This Works?** Two sequences produce the same BST iff they have the same root and, restricted to each side, produce the same subtrees. Any interleaving of a valid left sequence with a valid right sequence keeps both restrictions intact — and the choices multiply.
* **Edge Cases Considered:**
  * `n = 1` or a path-shaped tree (each node has one child) → `C(m, 0) = 1` everywhere → answer 0.

## 🔹 Tricks & Patterns Used

* **Interleaving count:** merging sequences of lengths `a` and `b` without reordering either: `C(a + b, a)`.
* **Pascal's triangle mod p** avoids modular inverses entirely when `n` is small.
* **Iterative post-order** with `(node, visited)` pairs.

## 🔹 Alternative Data Structures

* Recursive divide on lists (`[x for x in rest if x < root]`) is shorter but O(n²) memory traffic and needs `sys.setrecursionlimit`.

## 🔹 Complexity Analysis

* **Time Complexity:** O(n²) (Pascal triangle and worst-case BST insertion)
* **Space Complexity:** O(n²) for the triangle

## 🔹 Code Snippet (Brute Force)

```python
from itertools import permutations
from typing import List


class Solution:
    def numOfWays(self, nums: List[int]) -> int:
        def shape(order):
            left, right = {}, {}
            for x in order[1:]:
                node = order[0]
                while True:
                    child = left if x < node else right
                    if node not in child:
                        child[node] = x
                        break
                    node = child[node]
            return left, right

        target = shape(nums)
        return sum(1 for p in permutations(nums) if shape(p) == target) - 1
```

## 🔹 Code Snippet (Optimized)

```python
from typing import List

MOD = 10**9 + 7


class Solution:
    def numOfWays(self, nums: List[int]) -> int:
        n = len(nums)
        comb = [[1] * (a + 1) for a in range(n + 1)]  # comb[a][b] = C(a, b) mod p
        for a in range(2, n + 1):
            for b in range(1, a):
                comb[a][b] = (comb[a - 1][b - 1] + comb[a - 1][b]) % MOD

        root, left, right = nums[0], {}, {}
        for x in nums[1:]:
            node = root
            while True:
                child = left if x < node else right
                if node not in child:
                    child[node] = x
                    break
                node = child[node]

        size, ways = {}, {}
        stack = [(root, False)]
        while stack:
            node, children_done = stack.pop()
            if not children_done:
                stack.append((node, True))
                stack += [(c, False) for c in (left.get(node), right.get(node)) if c is not None]
                continue
            lo, hi = left.get(node), right.get(node)
            size_lo, size_hi = size.get(lo, 0), size.get(hi, 0)
            size[node] = size_lo + size_hi + 1
            ways[node] = comb[size_lo + size_hi][size_lo] * ways.get(lo, 1) % MOD * ways.get(hi, 1) % MOD
        return (ways[root] - 1) % MOD
```
