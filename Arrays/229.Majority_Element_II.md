# 🔹 Problem Name: 229. Majority Element II (Boyer-Moore Voting, Medium)

**🔗 Link:** [LeetCode 229](https://leetcode.com/problems/majority-element-ii/)
**🟢 Status:** 🔄 Need Review

## 🔹 Problem Statement

Given an integer array of size `n`, return every value that appears strictly more than `⌊n / 3⌋` times. At most two values can qualify, and the answer may be in any order.

* **Example:** `nums = [3,2,3]` → `[3]`
* **Constraints:** `1 ≤ nums.length ≤ 5·10⁴`, `-10⁹ ≤ nums[i] ≤ 10⁹` (follow-up: linear time, O(1) space)

## 🔹 Quick Breakdown

* **Difficulty Level:** Medium
* **Main Approach:** **Boyer–Moore voting with two candidates.** At most two values can appear more than `⌊n/3⌋` times (three of them would need more than `n` elements). Keep two candidates with counters: a match increments its counter, an empty slot adopts the value, otherwise decrement both counters — three distinct values cancel. A second pass counts the two survivors and keeps those above `⌊n/3⌋`.
* **Core Concept:** cancelling groups of `k` distinct values can never wipe out a value that occurs more than `n/k` times
* **When to Use This Pattern?** "Find every element occurring more than `n/k` times" in O(1) extra space — keep `k − 1` candidates; also streaming heavy hitters (Misra–Gries).
* **Mistakes to Avoid:**
  * Skipping the verification pass — survivors are only *candidates*; `[1, 2, 3]` leaves two of them and neither qualifies.
  * Testing `count == 0` before testing for a match — one value can then take both slots. Order: match `cand1`, match `cand2`, fill an empty slot, cancel.

## 🔹 Optimization Path

* **Brute Force:** count every distinct value with a full scan — O(n · distinct) = O(n²).
* **Optimized Solution:** two-candidate voting + a verification pass — O(n) time, O(1) space (the follow-up).
* **Further Improvements Possible?** No; a hash-map count is also O(n) but needs O(n) space.

## 🔹 Solution Breakdown

* **Optimal Approach:** one voting pass to get `cand1`, `cand2`; return those whose real count exceeds `len(nums) // 3`.
* **Why This Works?** Every cancel step consumes three units — the incoming value and one unit from each counter — so there are at most `⌊n/3⌋` of them, and each costs any single value at most one unit (the incoming value differs from both candidates). A value with more than `⌊n/3⌋` copies therefore still has a positive counter at the end: it is one of the two candidates.
* **Edge Cases Considered:**
  * `n = 1` or `2` — `⌊n/3⌋ = 0`, so every distinct value qualifies (`[1, 2]` → `[1, 2]`).
  * All values equal → one answer; nothing above the threshold → `[]`.
  * The threshold is strict: exactly `⌊n/3⌋` copies is not enough.

* **Candidate + verify:** a cheap filtering pass followed by an exact counting pass.

## 🔹 Alternative Data Structures

* `Counter(nums)` and filter — O(n) time, O(n) space; the default when O(1) space is not asked for.
* Sort, then check runs: `nums[i] == nums[i + n // 3]` marks a qualifying value — O(n log n).

## 🔹 Code Snippet (Brute Force)

```python
from typing import List


class Solution:
    def majorityElement(self, nums: List[int]) -> List[int]:
        return [x for x in set(nums) if nums.count(x) > len(nums) // 3]
```

## 🔹 Code Snippet (Optimized)

```python
from typing import List


class Solution:
    def majorityElement(self, nums: List[int]) -> List[int]:
        cand1, cand2, count1, count2 = None, None, 0, 0
        for x in nums:
            if x == cand1:  # match checks come first so one value never fills both slots
                count1 += 1
            elif x == cand2:
                count2 += 1
            elif count1 == 0:
                cand1, count1 = x, 1
            elif count2 == 0:
                cand2, count2 = x, 1
            else:  # three distinct values cancel each other
                count1 -= 1
                count2 -= 1
        return [c for c in (cand1, cand2) if c is not None and nums.count(c) > len(nums) // 3]
```
