# 🔹 Problem Name: 16. 3Sum Closest (Two Pointers, Medium)

**🔗 Link:** [LeetCode 16](https://leetcode.com/problems/3sum-closest/)
**🟢 Status:** 🔄 Need Review

## 🔹 Quick Breakdown

* **Difficulty Level:** Medium
* **Main Approach:** **Sort, fix one number, two pointers for the other two.** For each `i`, move `lo` and `hi` towards each other over the rest of the sorted array; if the triple sum is below the target move `lo` up, if above move `hi` down, and track the sum closest to the target.
* **Core Concept:** sorted order lets the sum be steered towards the target one pointer at a time
* **When to Use This Pattern?** Find pairs/triples whose sum is exactly or nearly a target in an array where the order of elements is irrelevant — 3Sum, 4Sum, two-sum on sorted data.
* **Mistakes to Avoid:**
  * Three nested loops: `500³ / 6 ≈ 2·10⁷` is fine for 500, but the pattern is what generalises.
  * Returning the **difference** instead of the sum.
  * Initialising the best with `0` or `inf` as a sum — start with the first triple's sum.
  * Stopping early only when `sum == target`; otherwise keep scanning.

## 🔹 Optimization Path

* **Brute Force:** try every triple `i < j < k` — O(n³).
* **Optimized Solution:** sort + fixed `i` + two pointers — O(n²).
* **Further Improvements Possible?** Not substantially; O(n²) is the standard bound for 3Sum-type problems.

## 🔹 Solution Breakdown

* **Optimal Approach:** `nums.sort()`. For `i` in `range(n − 2)`: `lo = i + 1`, `hi = n − 1`; while `lo < hi`: `total = nums[i] + nums[lo] + nums[hi]`; update `best` if `|total − target| < |best − target|`; return `total` immediately if it equals the target; `lo += 1` if `total < target` else `hi −= 1`.
* **Why This Works?** With the array sorted, increasing `lo` can only increase the sum and decreasing `hi` can only decrease it. If the sum is too small, no triple that keeps `nums[lo]` with a smaller `nums[hi]` can do better, so `lo` can be discarded (and symmetrically for `hi`).
* **Edge Cases Considered:**
  * Exactly three numbers → one triple.
  * An exact hit → return at once.
  * Duplicates and negative numbers need no special handling, since only the closeness is tracked.

## 🔹 Tricks & Patterns Used

* **Sort first:** `O(n log n)` buys a monotone relationship between pointer moves and the sum.
* **Early return on an exact match:** distance 0 cannot be beaten.

## 🔹 Alternative Data Structures

* For each pair, binary search the third value — O(n² log n).
* Hash set of complements works for the exact 3Sum but not for "closest".

## 🔹 Complexity Analysis

* **Time Complexity:** O(n²)
* **Space Complexity:** O(1) extra (O(n) for the sort in some implementations)

## 🔹 Code Snippet (Brute Force)

```python
from itertools import combinations
from typing import List


class Solution:
    def threeSumClosest(self, nums: List[int], target: int) -> int:
        return min((sum(triple) for triple in combinations(nums, 3)), key=lambda s: abs(s - target))
```

## 🔹 Code Snippet (Optimized)

```python
from typing import List


class Solution:
    def threeSumClosest(self, nums: List[int], target: int) -> int:
        nums = sorted(nums)
        best = nums[0] + nums[1] + nums[2]
        for i in range(len(nums) - 2):
            lo, hi = i + 1, len(nums) - 1
            while lo < hi:
                total = nums[i] + nums[lo] + nums[hi]
                if abs(total - target) < abs(best - target):
                    best = total
                if total == target:
                    return total
                if total < target:
                    lo += 1
                else:
                    hi -= 1
        return best
```
