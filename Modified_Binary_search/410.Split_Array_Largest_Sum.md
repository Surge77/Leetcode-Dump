# 🔹 Problem Name: 410. Split Array Largest Sum (Binary Search on Answer, Hard)

**🔗 Link:** [LeetCode 410](https://leetcode.com/problems/split-array-largest-sum/)
**🟢 Status:** 🔄 Need Review

## 🔹 Quick Breakdown

* **Difficulty Level:** Hard
* **Main Approach:** Guess the largest allowed subarray sum `S` and check greedily whether the array splits into `≤ k` pieces with every piece `≤ S`. Binary search the smallest such `S`.
* **Core Concept:** Minimise the maximum → binary search on answer
* **When to Use This Pattern?** "Minimise the maximum" or "maximise the minimum" over contiguous splits/placements (aggressive cows, router placement, book allocation).
* **Mistakes to Avoid:**
  * Thinking you need exactly `k` pieces in the check — `≤ k` is enough, since a piece can always be split further without increasing the maximum.
  * Lower bound `0` instead of `max(nums)`.

## 🔹 Optimization Path

* **Brute Force:** Try every placement of `k-1` cuts — O(C(n, k)).
* **DP:** `dp[i][j]` = best for the first `i` numbers in `j` pieces — O(k · n²).
* **Optimized Solution:** O(n log(sum)).

## 🔹 Solution Breakdown

* **Optimal Approach:** `pieces(S)` = greedy count of pieces with sum ≤ S. Smallest `S` in `[max, sum]` with `pieces(S) <= k`.
* **Why This Works?** A bigger limit never needs more pieces, so feasibility is monotone in `S`; greedy gives the minimum number of pieces for a fixed `S`.
* **Edge Cases Considered:**
  * `k = 1` → total sum.
  * `k = n` → maximum element.
  * Zeros in the array.

## 🔹 Pattern Recognition

* **Belongs To:** Modified Binary Search — search on answer
* **Common Problems Using This:**
  * 1011. Capacity To Ship Packages Within D Days (in this repo)
  * 1231. Divide Chocolate (maximise the minimum)
  * 1552. Magnetic Force Between Two Balls

## 🔹 Tricks & Patterns Used

* **Answer-space search** over `[max(nums), sum(nums)]`.
* **"≤ k pieces" relaxation** makes the greedy check valid.

## 🔹 Alternative Data Structures

* DP with prefix sums (O(k · n²)) — good when you must also output where the cuts go.

## 🔹 Complexity Analysis

* **Time Complexity:** O(n log(sum(nums)))
* **Space Complexity:** O(1)

## 🔹 Code Snippet (Brute Force)

```python
from itertools import combinations
from typing import List


class Solution:
    def splitArray(self, nums: List[int], k: int) -> int:
        n = len(nums)
        best = sum(nums)
        for cuts in combinations(range(1, n), k - 1):  # every placement of k-1 cuts
            bounds = [0, *cuts, n]
            largest = max(sum(nums[bounds[i]:bounds[i + 1]]) for i in range(k))
            best = min(best, largest)
        return best
```

## 🔹 Code Snippet (Optimized)

```python
from typing import List


class Solution:
    def splitArray(self, nums: List[int], k: int) -> int:
        def pieces(limit: int) -> int:
            count, cur = 1, 0
            for x in nums:
                if cur + x > limit:
                    count += 1
                    cur = 0
                cur += x
            return count

        lo, hi = max(nums), sum(nums)
        while lo < hi:
            mid = (lo + hi) // 2
            if pieces(mid) <= k:
                hi = mid
            else:
                lo = mid + 1
        return lo
```
