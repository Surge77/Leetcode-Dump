# 🔹 Problem Name: 332. Reconstruct Itinerary (Eulerian Path, Hard)

**🔗 Link:** [LeetCode 332](https://leetcode.com/problems/reconstruct-itinerary/)
**🟢 Status:** 🔄 Need Review

## 🔹 Problem Statement

Given a list of flight tickets `[from, to]`, rebuild the itinerary that starts at `"JFK"` and uses every ticket exactly once. A valid itinerary is guaranteed to exist; if several do, return the one that is smallest when compared lexically airport by airport.

* **Example:** `tickets = [["MUC","LHR"],["JFK","MUC"],["SFO","SJC"],["LHR","SFO"]]` → `["JFK","MUC","LHR","SFO","SJC"]`
* **Constraints:** `1 ≤ tickets.length ≤ 300`, every airport code is 3 uppercase letters, `from != to`

## 🔹 Quick Breakdown

* **Difficulty Level:** Hard
* **Main Approach:** **Hierholzer's algorithm with lexical edge order.** Using every ticket exactly once is an Eulerian path from `"JFK"`. Keep each airport's destinations sorted; walk greedily along the smallest unused ticket, and when an airport has no tickets left, pop it onto the answer. The answer, reversed, is the lexicographically smallest itinerary.
* **Core Concept:** in Hierholzer's algorithm, a dead end can only be the **end** of the path, so airports are emitted in reverse order as they get stuck
* **When to Use This Pattern?** "Use every edge exactly once" — itineraries, De Bruijn sequences (753, Cracking the Safe), valid arrangements of pairs (2097).
* **Mistakes to Avoid:**
  * Plain greedy (always take the smallest destination, never back up): it can walk into a dead end before using all tickets, e.g. `JFK→KUL` before `JFK→NRT→JFK`.
  * Backtracking: correct but exponential in the worst case.
  * Popping from the front of a sorted list (O(n)) — sort in reverse and pop from the end.

## 🔹 Optimization Path

* **Brute Force:** DFS backtracking that tries destinations in lexical order and returns the first route using all tickets — exponential worst case.
* **Optimized Solution:** Hierholzer with an explicit stack — O(E log E) for the sort, O(E) for the walk.
* **Further Improvements Possible?** No; sorting the tickets dominates and is needed for the lexical requirement.

## 🔹 Solution Breakdown

* **Optimal Approach:** `adj[src]` = destinations sorted descending. `stack = ["JFK"]`; while the stack is non-empty: if `adj[top]` is non-empty, push `adj[top].pop()` (the smallest); otherwise pop `top` into `route`. Return `route[::-1]`.
* **Why This Works?** The walk can only get stuck at the path's end vertex (all other vertices have balanced in/out degree along the way). Each stuck vertex is the latest point of the remaining path, so emitting in pop order builds the path backwards, splicing in any detour cycles. Taking the smallest ticket first means the lexically smallest choice survives whenever it can be completed; a greedy choice that leads to a dead end is emitted **later** in the route, which is exactly where it must go.
* **Edge Cases Considered:**
  * Duplicate tickets (`JFK→ATL` twice) — kept as separate list entries.
  * A ticket that must be saved for last (the dead-end branch) — handled by the post-order emission.
  * A valid itinerary is guaranteed; `E ≤ 300`.

## 🔹 Tricks & Patterns Used

* **Reverse-sorted adjacency + `pop()`** gives smallest-first in O(1) per edge.
* **Post-order emission, then reverse** — the core of Hierholzer's algorithm.

## 🔹 Alternative Data Structures

* Min-heaps per airport instead of reverse-sorted lists — same O(E log E).
* Recursive Hierholzer (`visit(u)`: while edges, `visit(pop)`; then append `u`) — fine at `E = 300`, iterative avoids depth concerns.

## 🔹 Complexity Analysis

* **Time Complexity:** O(E log E)
* **Space Complexity:** O(E)

## 🔹 Code Snippet (Brute Force)

```python
from collections import defaultdict
from typing import List


class Solution:
    def findItinerary(self, tickets: List[List[str]]) -> List[str]:
        adj = defaultdict(list)
        for src, dst in sorted(tickets):
            adj[src].append(dst)
        used = {src: [False] * len(dsts) for src, dsts in adj.items()}
        route = ["JFK"]

        def dfs() -> bool:
            if len(route) == len(tickets) + 1:
                return True
            src = route[-1]
            for i, dst in enumerate(adj[src]):
                if not used[src][i]:
                    used[src][i] = True
                    route.append(dst)
                    if dfs():
                        return True
                    route.pop()
                    used[src][i] = False
            return False

        dfs()
        return route
```

## 🔹 Code Snippet (Optimized)

```python
from collections import defaultdict
from typing import List


class Solution:
    def findItinerary(self, tickets: List[List[str]]) -> List[str]:
        adj = defaultdict(list)
        for src, dst in sorted(tickets, reverse=True):
            adj[src].append(dst)  # reverse order so pop() yields the smallest
        stack, route = ["JFK"], []
        while stack:
            if adj[stack[-1]]:
                stack.append(adj[stack[-1]].pop())
            else:
                route.append(stack.pop())  # stuck: this airport is the end of what's left
        return route[::-1]
```
