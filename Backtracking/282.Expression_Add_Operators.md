# 282. Expression Add Operators

**🔗 Link:** [LeetCode 282](https://leetcode.com/problems/expression-add-operators/)
**🟢 Status:** 🔄 Need Review


## 🔹 Problem Statement

Given a digit string `num` and an integer `target`, insert `+`, `-` or `*` between some of the digits (or none, to glue digits into a longer number) so the expression evaluates to `target`. Return all such expressions; operands may not have leading zeros, and normal operator precedence applies.

* **Example:** `num = "123", target = 6` → `["1*2*3","1+2+3"]`
* **Constraints:** `1 ≤ num.length ≤ 10`, `num` has only digits, `-2^31 ≤ target ≤ 2^31 - 1`

## 🔹 Quick Breakdown

* **Difficulty Level:** Hard
* **Main Approach:** **Backtracking that evaluates on the fly.** At each position choose the next operand `num[pos:end]` (no leading zeros) and an operator. Carry `value` (the expression's value so far) and `last` (the last multiplicative term, signed). `+x`: `value + x`, last `x`. `−x`: `value − x`, last `−x`. `*x`: undo the last term and re-add it multiplied — `value − last + last·x`, last `last·x`.
* **Core Concept:** handling `*` precedence without a parser by remembering the last term
* **When to Use This Pattern?** "Insert operators / split digits so the expression hits a target" — anything where evaluation must respect precedence while the expression is built left to right.
* **Mistakes to Avoid:**
  * Leading zeros: `"05"` is not a valid operand, but `"0"` is — stop extending the operand once it starts with `'0'`.
  * Evaluating each finished string from scratch (or with `eval`): an extra O(n) per leaf and a security smell.
  * Putting an operator before the first operand.

## 🔹 Optimization Path

* **Brute Force:** each of the `n − 1` gaps gets one of `{"", "+", "−", "*"}` → 4ⁿ⁻¹ strings; reject leading-zero operands, evaluate each with a small precedence-aware evaluator — O(4ⁿ · n).
* **Optimized Solution:** DFS with `value`/`last` — the same 4ⁿ⁻¹ leaves, but each step is O(1) arithmetic plus the string building.
* **Further Improvements Possible?** Build the expression in a shared char list instead of string concatenation; the output can itself be exponential, so no asymptotic win is available.

## 🔹 Solution Breakdown

* **Optimal Approach:** `dfs(pos, expr, value, last)`; at `pos == n` record `expr` if `value == target`; for `end` in `pos+1..n`: break if the operand would have a leading zero; first operand starts the expression, otherwise branch on `+`, `−`, `*`.
* **Why This Works?** An expression without parentheses is a sum of signed products. `value` is the sum of all finished terms plus the current term `last`; multiplying only changes the current term, so replacing `last` by `last·x` is exactly `value − last + last·x`.
* **Edge Cases Considered:**
  * `"105"`, target 5 → `["1*0+5", "10-5"]` (`"1*05"` is rejected).
  * `"00"`, target 0 → `["0+0", "0-0", "0*0"]`.
  * Large targets: Python integers never overflow; in Java/C++ `value` needs 64 bits.

## 🔹 Tricks & Patterns Used

* **Last-term undo for `*`:** `value − last + last·x`.
* **Leading-zero break:** `if end > pos + 1 and num[pos] == "0": break`.

## 🔹 Alternative Data Structures

* A stack of terms (as in Basic Calculator II) for the brute-force evaluator.

## 🔹 Complexity Analysis

* **Time Complexity:** O(n · 4ⁿ⁻¹) for `n ≤ 10` — at most 4⁹ = 262144 leaves, each building a string of length O(n).
* **Space Complexity:** O(n) recursion depth plus the current string, excluding the output.

## 🔹 Code Snippet (Brute Force)

```python
import re
from itertools import product
from typing import List


class Solution:
    def addOperators(self, num: str, target: int) -> List[str]:
        result = []
        for ops in product(("", "+", "-", "*"), repeat=len(num) - 1):
            expr = num[0] + "".join(op + digit for op, digit in zip(ops, num[1:]))
            tokens = re.split(r"([+\-*])", expr)
            operands = tokens[::2]
            if any(len(x) > 1 and x[0] == "0" for x in operands):
                continue
            total, term = 0, int(operands[0])
            for op, x in zip(tokens[1::2], operands[1:]):
                if op == "*":
                    term *= int(x)
                else:
                    total += term
                    term = int(x) if op == "+" else -int(x)
            if total + term == target:
                result.append(expr)
        return result
```

## 🔹 Code Snippet (Optimized)

```python
from typing import List


class Solution:
    def addOperators(self, num: str, target: int) -> List[str]:
        n = len(num)
        result = []

        def dfs(pos: int, expr: str, value: int, last: int) -> None:
            if pos == n:
                if value == target:
                    result.append(expr)
                return
            for end in range(pos + 1, n + 1):
                if end > pos + 1 and num[pos] == "0":
                    break  # "0" is an operand, "05" is not
                part = num[pos:end]
                x = int(part)
                if pos == 0:
                    dfs(end, part, x, x)
                    continue
                dfs(end, expr + "+" + part, value + x, x)
                dfs(end, expr + "-" + part, value - x, -x)
                # `*` binds to the last term only: take it back out, add it multiplied
                dfs(end, expr + "*" + part, value - last + last * x, last * x)

        dfs(0, "", 0, 0)
        return result
```
