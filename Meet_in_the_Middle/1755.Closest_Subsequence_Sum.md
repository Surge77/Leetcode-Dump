# 🔹 Problem Name: 1755. Closest Subsequence Sum (Meet in the Middle, Hard)

**🔗 Link:** [LeetCode 1755](https://leetcode.com/problems/closest-subsequence-sum/)
**🟢 Status:** 🔄 Need Review

## 🔹 Quick Breakdown

* **Difficulty Level:** Hard
* **Main Approach:** `n ≤ 40` means `2⁴⁰` subsets — too many, but `2²⁰ ≈ 10⁶` is fine. Split the array in half, list all subset sums of each half, sort both, and find the pair `a + b` closest to `goal` with **two pointers** (left half ascending, right half descending).
* **Core Concept:** meet in the middle — trade one exponential search for two square-root-sized ones plus a merge
* **When to Use This Pattern?** `n` around 30–40 with a subset/choice problem, values too large for a sum-indexed DP (here `|nums[i]| ≤ 10⁷`, `|goal| ≤ 10⁹`).
* **Mistakes to Avoid:**
  * A knapsack DP over sums — the sum range is ~8·10⁸, far too big.
  * Forgetting the empty subsequence (sum 0) — it is in both halves' lists automatically.

## 🔹 Optimization Path

* **Brute Force:** all `2ⁿ` subsets — O(2ⁿ · n).
* **Optimized Solution:** O(2^(n/2) · n) to build and sort both halves, O(2^(n/2)) two-pointer merge.
* **Further Improvements Possible?** Generate each half's sums already sorted by merging (`merge(sums, sums + x)`), removing the log factor.

## 🔹 Solution Breakdown

* **Optimal Approach:** `sums(half)` by doubling (`out += [s + x for s in out]`), sort, then walk `i` up the left list and `j` down the right list: if `a + b < goal` increase `i`, if greater decrease `j`, stop early at an exact hit.
* **Why This Works?** Every subsequence is a left part plus a right part, so its sum is some `a + b`. For a fixed `i`, as `j` decreases the sum decreases monotonically; the two-pointer scan visits the closest candidate on both sides of `goal` for each `a`.
* **Edge Cases Considered:**
  * `n = 1` — one half is empty, its sum list is `[0]`.
  * `goal` reachable exactly → return 0 immediately.

## 🔹 Tricks & Patterns Used

* **Subset sums by doubling:** start from `[0]`, for each `x` append `s + x` for all current `s`.
* **Closest pair from two sorted lists** with two pointers.

## 🔹 Alternative Data Structures

* Binary search (`bisect`) in the sorted right list for each left sum: O(2^(n/2) · log) — also fine.

* **Time Complexity:** O(2^(n/2) · n)

## 🔹 Code Snippet (Brute Force)

```python
from typing import List


class Solution:
    def minAbsDifference(self, nums: List[int], goal: int) -> int:
        sums = [0]
        for x in nums:
            sums += [s + x for s in sums]
        return min(abs(s - goal) for s in sums)
```

## 🔹 Code Snippet (Optimized)

```python
from typing import List


class Solution:
    def minAbsDifference(self, nums: List[int], goal: int) -> int:
        def subset_sums(arr):
            sums = [0]
            for x in arr:
                sums += [s + x for s in sums]
            return sorted(sums)

        half = len(nums) // 2
        left, right = subset_sums(nums[:half]), subset_sums(nums[half:])
        best = abs(goal)
        i, j = 0, len(right) - 1
        while i < len(left) and j >= 0:
            total = left[i] + right[j]
            best = min(best, abs(total - goal))
            if total < goal:
                i += 1
            elif total > goal:
                j -= 1
            else:
                return 0
        return best
```
