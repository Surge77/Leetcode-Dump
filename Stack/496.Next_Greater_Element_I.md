# 🔹 Problem Name: 496. Next Greater Element I (Monotonic Stack, Easy)

**🔗 Link:** [LeetCode 496](https://leetcode.com/problems/next-greater-element-i/)
**🟢 Status:** 🔄 Need Review

## 🔹 Quick Breakdown

* **Difficulty Level:** Easy
* **Main Approach:** **Monotonic decreasing stack over `nums2`, answers in a hash map.** Scan `nums2`; while the current value is greater than the stack top, the top has found its next greater element — record `greater[top] = x` and pop. Push `x`. Values left on the stack have none. Then `nums1` is just lookups.
* **Core Concept:** each element waits on the stack until the first larger element to its right arrives
* **When to Use This Pattern?** "Next / previous greater / smaller element", "how many days until warmer", spans, histogram boundaries.
* **Mistakes to Avoid:**
  * Answering for the position of `x` in `nums1` — the "next greater" is defined in `nums2`.
  * Pushing indices of `nums2` and then forgetting to map back to values; values work directly because all values are distinct.

## 🔹 Optimization Path

* **Brute Force:** for each `x` in `nums1`, find it in `nums2` and scan right for the first larger value — O(m · n).
* **Optimized Solution:** one stack pass over `nums2` + dictionary — O(m + n). This is the follow-up the problem asks for.
* **Further Improvements Possible?** No; both arrays must be read.

## 🔹 Solution Breakdown

* **Optimal Approach:** `for x in nums2: while stack and stack[-1] < x: greater[stack.pop()] = x; stack.append(x)`; answer `[greater.get(x, -1) for x in nums1]`.
* **Why This Works?** The stack is strictly decreasing from bottom to top (everything smaller than `x` was popped before pushing `x`). An element is popped by the first later element bigger than it — exactly its next greater element.
* **Edge Cases Considered:**
  * The last element of `nums2` → −1.
  * `nums2` strictly decreasing — nothing is ever popped, everything is −1.

## 🔹 Tricks & Patterns Used

* **Distinct values ⇒ values can be dictionary keys** — no index bookkeeping.
* **Answer when popping**, not when pushing.

## 🔹 Alternative Data Structures

* Scan `nums2` right-to-left keeping a stack of candidates (pop everything ≤ `x`, the top is the answer) — same complexity.

## 🔹 Complexity Analysis

* **Time Complexity:** O(m + n), `m, n ≤ 1000`
* **Space Complexity:** O(n)

## 🔹 Code Snippet (Brute Force)

```python
from typing import List


class Solution:
    def nextGreaterElement(self, nums1: List[int], nums2: List[int]) -> List[int]:
        result = []
        for x in nums1:
            start = nums2.index(x)
            result.append(next((y for y in nums2[start + 1:] if y > x), -1))
        return result
```

## 🔹 Code Snippet (Optimized)

```python
from typing import List


class Solution:
    def nextGreaterElement(self, nums1: List[int], nums2: List[int]) -> List[int]:
        greater = {}
        stack = []  # strictly decreasing: values still waiting for something bigger
        for x in nums2:
            while stack and stack[-1] < x:
                greater[stack.pop()] = x
            stack.append(x)
        return [greater.get(x, -1) for x in nums1]
```
