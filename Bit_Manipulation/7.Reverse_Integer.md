# 🔹 Problem Name: 7. Reverse Integer (Math, Medium)

**🔗 Link:** [LeetCode 7](https://leetcode.com/problems/reverse-integer/)
**🟢 Status:** 🔄 Need Review

## 🔹 Problem Statement

Reverse the decimal digits of a signed 32-bit integer, keeping its sign. If the reversed value falls outside `[−2^31, 2^31 − 1]`, return 0. The problem assumes you cannot store 64-bit integers.

* **Example:** `x = 123` → `321`
* **Constraints:** `−2^31 ≤ x ≤ 2^31 − 1`

## 🔹 Quick Breakdown

* **Difficulty Level:** Medium
* **Main Approach:** **Pop and push digits with an overflow guard.** Repeatedly take the last digit of `|x|` (`x % 10`), drop it (`x //= 10`) and append it to `result` (`result * 10 + digit`). **Before** appending, check that `result * 10 + digit` still fits in `2³¹ − 1`; if not, return 0. Reapply the sign at the end.
* **Core Concept:** build a number digit by digit while proving each step stays inside a fixed-width range — the check has to happen before the overflowing operation, because a 32-bit machine cannot hold the overflowed value to inspect it afterwards
* **When to Use This Pattern?** Digit-by-digit reconstruction under a 32-bit limit — atoi (8), palindrome numbers (9), reversing or rotating digits.
* **Mistakes to Avoid:**
  * Checking `result > 2³¹ − 1` **after** multiplying — fine in Python, but the problem forbids storing 64-bit values, and in C++/Java the overflow has already happened.
  * Using `%` / `//` on a negative `x` in Python: `-123 % 10 == 7`. Work on `abs(x)` and restore the sign.
  * Forgetting trailing zeros vanish: `120 → 21`.

## 🔹 Optimization Path

* **Brute Force:** `int(str(abs(x))[::-1])`, then a range check — O(d), but it builds a string and relies on an unbounded int to hold the overflowed value.
* **Optimized Solution:** pop/push with a pre-check — O(d) time, O(1) space, never exceeds 32 bits.
* **Further Improvements Possible?** No; every digit must be read (`d ≤ 10`).

## 🔹 Solution Breakdown

* **Optimal Approach:** `result > (INT_MAX − digit) // 10` is exactly the condition `result * 10 + digit > INT_MAX`, rewritten so nothing in it overflows.
* **Why This Works?** One bound serves both signs: the negative limit is `2³¹`, one more than `INT_MAX`, but a reversed magnitude of exactly `2147483648` would need the input `8463847412`, which is itself out of range. So `INT_MAX` is the true bound for `|result|`.
* **Edge Cases Considered:**
  * `x = 0` → loop never runs, returns 0.
  * `1534236469` → reversed `9646324351` overflows → 0.
  * `-2147483648` → reversed overflows → 0.

* **Overflow pre-check:** to test `a * 10 + d > LIMIT` without overflowing, test `a > (LIMIT − d) // 10`.
* **Sign separation:** reverse the magnitude, multiply the sign back in.

## 🔹 Code Snippet (Brute Force)

```python
class Solution:
    def reverse(self, x: int) -> int:
        sign = -1 if x < 0 else 1
        result = sign * int(str(abs(x))[::-1])
        return result if -2**31 <= result <= 2**31 - 1 else 0
```

## 🔹 Code Snippet (Optimized)

```python
INT_MAX = 2**31 - 1


class Solution:
    def reverse(self, x: int) -> int:
        sign = -1 if x < 0 else 1
        x = abs(x)  # Python's % rounds toward -inf, so negative digits come out wrong
        result = 0
        while x:
            digit = x % 10
            x //= 10
            # result * 10 + digit > INT_MAX, rearranged so no step leaves 32 bits
            if result > (INT_MAX - digit) // 10:
                return 0
            result = result * 10 + digit
        return sign * result
```
