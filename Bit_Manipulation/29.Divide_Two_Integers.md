# 🔹 Problem Name: 29. Divide Two Integers (Bit Manipulation, Medium)

**🔗 Link:** [LeetCode 29](https://leetcode.com/problems/divide-two-integers/)
**🟢 Status:** 🔄 Need Review

## 🔹 Problem Statement

Divide `dividend` by `divisor` and return the quotient truncated toward zero, without using multiplication, division or the mod operator. Results are limited to the signed 32-bit range, so a quotient above `2^31 − 1` must be clamped to `2^31 − 1` (and below `−2^31` to `−2^31`).

* **Example:** `dividend = 10, divisor = 3` → `3`
* **Constraints:** `−2^31 ≤ dividend, divisor ≤ 2^31 − 1`, `divisor ≠ 0`

## 🔹 Quick Breakdown

* **Difficulty Level:** Medium
* **Main Approach:** **Binary long division with shifts.** Work with magnitudes `a = |dividend|`, `b = |divisor|`. For each bit position `s` from 31 down to 0, if `b << s` still fits into what is left of `a`, subtract it and set bit `s` of the quotient. Apply the sign at the end; the only overflow is `−2³¹ / −1`, which clamps to `2³¹ − 1`.
* **Core Concept:** every quotient is a sum of powers of two, so it can be built greedily from the highest bit, exactly like schoolbook long division in base 2
* **When to Use This Pattern?** Multiplication, division or exponentiation where the "obvious" repeated operation runs `value` times — replace it with doubling (`<< 1`) and read the answer bit by bit (also: 50. Pow(x, n), Russian peasant multiplication).
* **Mistakes to Avoid:**
  * Repeated subtraction: `2³¹ / 1` takes two billion iterations.
  * Forgetting the single overflow case `dividend = −2³¹, divisor = −1`.
  * Rounding toward −∞ (Python's `//`) instead of truncating toward zero: `7 / −3` must be `−2`, not `−3`.

## 🔹 Optimization Path

* **Brute Force:** subtract `b` from `a` until it no longer fits — O(|quotient|), up to 2³¹ steps.
* **Optimized Solution:** one pass over 32 bit positions — O(32) = O(log range).
* **Further Improvements Possible?** No; the quotient has up to 32 bits and each is decided in O(1).

## 🔹 Solution Breakdown

* **Optimal Approach:** `(a >> s) >= b` is equivalent to `a >= b << s` for non-negative values, and it never creates a number wider than `a`.
* **Why This Works?** At position `s`, the remaining `a` is less than `b · 2^(s+1)` (otherwise bit `s + 1` would have been taken), so bit `s` of the quotient is 1 exactly when `b · 2^s ≤ a`. This is long division where each "digit" is 0 or 1.
* **Edge Cases Considered:**
  * `−2³¹ / −1` → `2³¹ − 1`.
  * `−2³¹ / 1` → `−2³¹` (quotient bit 31 set, then negated — still in range).
  * `|dividend| < |divisor|` → 0.

## 🔹 Tricks & Patterns Used

* **Sign by XOR of signs:** `negative = (dividend < 0) != (divisor < 0)`.
* **Greedy high bit first:** decide quotient bits from 31 down to 0.

## 🔹 Alternative Data Structures

* Exponential search: double `b` until it exceeds `a`, subtract the largest fitting multiple, repeat — O(log² range).

## 🔹 Complexity Analysis

* **Time Complexity:** O(32) = O(1) for 32-bit inputs
* **Space Complexity:** O(1)

## 🔹 Code Snippet (Brute Force)

```python
class Solution:
    def divide(self, dividend: int, divisor: int) -> int:
        if dividend == -2**31 and divisor == -1:
            return 2**31 - 1
        negative = (dividend < 0) != (divisor < 0)
        remaining, step = abs(dividend), abs(divisor)
        quotient = 0
        while remaining >= step:
            remaining -= step
            quotient += 1
        return -quotient if negative else quotient
```

## 🔹 Code Snippet (Optimized)

```python
INT_MAX = 2**31 - 1
INT_MIN = -2**31
BITS = 32


class Solution:
    def divide(self, dividend: int, divisor: int) -> int:
        if dividend == INT_MIN and divisor == -1:
            return INT_MAX  # the only quotient that does not fit in 32 bits
        negative = (dividend < 0) != (divisor < 0)
        remaining, step = abs(dividend), abs(divisor)
        quotient = 0
        for shift in range(BITS - 1, -1, -1):
            # compare by shifting `remaining` down, so `step << shift` is never built too wide
            if (remaining >> shift) >= step:
                remaining -= step << shift
                quotient |= 1 << shift
        return -quotient if negative else quotient  # magnitudes truncate toward zero
```
