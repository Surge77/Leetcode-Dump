# 94. Binary Tree Inorder Traversal

**🔗 Link:** [LeetCode 94](https://leetcode.com/problems/binary-tree-inorder-traversal/)
**🟢 Status:** 🔄 Need Review


## 🔹 Problem Statement

Given the root of a binary tree, return the node values in inorder: the left subtree, then the node, then the right subtree. The follow-up asks for an iterative solution, since the recursive one is trivial.

* **Example:** `root = [1,null,2,3]` → `[1,3,2]`
* **Constraints:** `0 ≤ nodes ≤ 100`, `-100 ≤ Node.val ≤ 100`

## 🔹 Quick Breakdown

* **Difficulty Level:** Easy
* **Main Approach:** **Explicit stack.** From the current node, go left as far as possible, pushing every node on the way. When there is no left child, pop: that node's left subtree is finished, so emit it, then continue from its right child.
* **Core Concept:** the call stack of the recursive `left → node → right`, made explicit
* **When to Use This Pattern?** Anything that needs a BST's values in sorted order, or a left-to-right walk you want to pause and resume — k-th smallest, validate BST, BST iterator, two-sum in a BST.
* **Mistakes to Avoid:**
  * Emitting a node when it is **pushed** (that is preorder) instead of when it is popped.
  * Returning `left + [val] + right` from every call: each level copies its whole subtree's list — O(n²) on a path-shaped tree.

## 🔹 Optimization Path

* **Brute Force:** recursion that returns a fresh list and concatenates — O(n·h) time spent copying (O(n²) on a path, O(n log n) when balanced).
* **Optimized Solution:** iterative stack appending to one shared list — O(n) time, O(h) space.
* **Further Improvements Possible?** Morris traversal gets O(1) extra space: thread each node's inorder predecessor's empty `right` pointer back to it, follow the thread, then remove it.

## 🔹 Solution Breakdown

* **Optimal Approach:** `while node or stack`: push-and-go-left while `node`; then `node = stack.pop()`, append `node.val`, `node = node.right`.
* **Why This Works?** A node is popped only after everything pushed above it — its whole left subtree — has been popped, and its right subtree is entered only after it is emitted: exactly `left, node, right`. The stack holds the ancestors we went left from, so it never exceeds the height.
* **Edge Cases Considered:**
  * Empty tree → `[]`.
  * Right-leaning path: the stack holds one node at a time; left-leaning path: it holds all `n`.

## 🔹 Tricks & Patterns Used

* **"Go left, pop, step right":** the iterative inorder template; stopping after `k` pops gives the k-th smallest of a BST without touching the rest.
* **One output list for the whole traversal:** append to it instead of returning and joining lists — removes the O(n·h) copying.

## 🔹 Alternative Data Structures

* Recursion with a shared `result` list — O(n) time, O(h) call stack (safe here: at most 100 nodes).
* Morris threading — O(1) extra space, but it temporarily rewires the tree, which is unsafe if other code reads it concurrently.

## 🔹 Complexity Analysis

* **Time Complexity:** O(n) — every node is pushed and popped once
* **Space Complexity:** O(h) for the stack (O(n) on a left-leaning path), excluding the output

## 🔹 Code Snippet (Brute Force)

```python
from typing import List, Optional


class Solution:
    def inorderTraversal(self, root: Optional[TreeNode]) -> List[int]:
        if root is None:
            return []
        return self.inorderTraversal(root.left) + [root.val] + self.inorderTraversal(root.right)
```

## 🔹 Code Snippet (Optimized)

```python
from typing import List, Optional


class Solution:
    def inorderTraversal(self, root: Optional[TreeNode]) -> List[int]:
        result, stack, node = [], [], root
        while node or stack:
            while node:
                stack.append(node)  # its value waits until the left subtree is done
                node = node.left
            node = stack.pop()
            result.append(node.val)
            node = node.right
        return result
```
