# 540. Single Element in a Sorted Array

**🔗 Link:** [LeetCode 540](https://leetcode.com/problems/single-element-in-a-sorted-array/)
**🟢 Status:** 🔄 Need Review


## 🔹 Problem Statement

In a sorted integer array every value appears exactly twice except one value that appears once. Return that single value. The solution must use O(log n) time and O(1) extra space.

* **Example:** `nums = [1,1,2,3,3,4,4,8,8]` → `2`
* **Constraints:** `1 ≤ nums.length ≤ 10^5`; `0 ≤ nums[i] ≤ 10^5`.

## 🔹 Quick Breakdown

* **Difficulty Level:** Medium
* **Main Approach:** **Binary search on pair parity.** Before the single element, every pair starts at an **even** index (`nums[2i] == nums[2i+1]`); after it, every pair starts at an odd index. Snap `mid` to the even index of its pair: if `nums[mid] == nums[mid + 1]` the pairing is still intact, so the single is to the right (`lo = mid + 2`); otherwise it is at `mid` or to the left (`hi = mid`).
* **Core Concept:** binary search on a **monotone predicate over indices** ("is the pairing still aligned here?"), not on values
* **When to Use This Pattern?** Sorted data plus an O(log n) requirement where no target value is given — find the index where some local property flips.
* **Mistakes to Avoid:**
  * XOR of everything is O(n): correct, but the problem demands O(log n).
  * Forgetting to snap `mid` to even: comparing `nums[mid]` with `nums[mid + 1]` from an odd `mid` checks the wrong pair.
  * `lo = mid + 1` instead of `mid + 2` lands on the second half of a pair and breaks the even-index invariant.

## 🔹 Optimization Path

* **Brute Force:** walk the array two at a time; the first pair that does not match starts with the single — O(n).
* **Optimized Solution:** binary search over even indices — O(log n), O(1) space.
* **Further Improvements Possible?** No; O(log n) is optimal for searching sorted input.

## 🔹 Solution Breakdown

* **Optimal Approach:** `lo, hi = 0, n − 1`; while `lo < hi`: `mid = (lo + hi) // 2`, `mid −= mid % 2`; matched pair → `lo = mid + 2`, else `hi = mid`. Return `nums[lo]`.
* **Why This Works?** The single sits at an even index `s` (an even number of elements precede it). For even `i < s`, `nums[i] == nums[i+1]`; for even `i ≥ s`, `nums[i] != nums[i+1]`. That predicate is monotone over even indices, and `lo`/`hi` always stay even with `s` in `[lo, hi]`.
* **Edge Cases Considered:**
  * `n = 1` → loop never runs, return `nums[0]`.
  * Single at index 0 or at the last index — `hi` is even (`n` is odd), so `mid + 1 ≤ hi` always exists.

## 🔹 Tricks & Patterns Used

* **Snap `mid` to the pair start:** `mid -= mid % 2` (or compare with `nums[mid ^ 1]`, the partner index, which avoids the snap).
* **Search space stays even:** step by 2 so `lo` never lands mid-pair.

## 🔹 Alternative Data Structures

* `functools.reduce(xor, nums)` — O(n), works on unsorted input too.
* `mid ^ 1` partner trick: if `nums[mid] == nums[mid ^ 1]` go right (`lo = mid + 1`), else `hi = mid`.

## 🔹 Code Snippet (Brute Force)

```python
from typing import List


class Solution:
    def singleNonDuplicate(self, nums: List[int]) -> int:
        for i in range(0, len(nums) - 1, 2):
            if nums[i] != nums[i + 1]:
                return nums[i]
        return nums[-1]
```

## 🔹 Code Snippet (Optimized)

```python
from typing import List


class Solution:
    def singleNonDuplicate(self, nums: List[int]) -> int:
        lo, hi = 0, len(nums) - 1
        while lo < hi:
            mid = (lo + hi) // 2
            mid -= mid % 2  # pairs before the single start at even indices
            if nums[mid] == nums[mid + 1]:
                lo = mid + 2
            else:
                hi = mid
        return nums[lo]
```
