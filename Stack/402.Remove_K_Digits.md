# 🔹 Problem Name: 402. Remove K Digits (Monotonic Stack, Medium)

**🔗 Link:** [LeetCode 402](https://leetcode.com/problems/remove-k-digits/)
**🟢 Status:** 🔄 Need Review

## 🔹 Quick Breakdown

* **Difficulty Level:** Medium
* **Main Approach:** **Greedy with an increasing stack.** Scan the digits; while removals remain and the stack top is larger than the current digit, pop it (a smaller digit earlier always beats a larger one). Push the digit. If removals are left at the end, cut them from the tail (the stack is non-decreasing, so the tail holds the largest digits). Strip leading zeros; empty → `"0"`.
* **Core Concept:** the leftmost position where a digit is larger than its successor is the best single removal; the stack applies that rule k times in one pass
* **When to Use This Pattern?** "Smallest / largest number (or lexicographically smallest subsequence) after deleting / keeping k elements": 316, 1081, 321, 1673.
* **Mistakes to Avoid:**
  * Stopping when the string is already non-decreasing but `k > 0` — trim the end.
  * Leaving leading zeros (`"10200", k=1` → `"200"`, not `"0200"`).
  * Returning `""` when everything is removed — return `"0"`.

## 🔹 Optimization Path

* **Brute Force:** apply the single-removal greedy k times, rescanning from the start each time — O(n · k), up to 5·10⁹ steps at `n = 10⁵`.
* **Optimized Solution:** monotonic stack — O(n).
* **Further Improvements Possible?** No; every digit is read once and pushed/popped at most once.

## 🔹 Solution Breakdown

* **Optimal Approach:** `while k and stack and stack[-1] > d: pop, k -= 1`; push `d`; afterwards drop `k` digits from the end, `lstrip("0")`, default `"0"`.
* **Why This Works?** For equal-length results, the first differing digit decides. Keeping a larger digit before a smaller one when a deletion is still available can never be better: deleting it makes that position smaller. Popping greedily realises this choice for every position from left to right.
* **Edge Cases Considered:**
  * `k == len(num)` → `"0"`.
  * Zeros exposed at the front after removals.
  * Equal digits (`"1111"`) — not popped; removals come off the tail.

## 🔹 Pattern Recognition

* **Belongs To:** Monotonic Stack — greedy subsequence selection
* **Common Problems Using This:**
  * 316. Remove Duplicate Letters
  * 1673. Find the Most Competitive Subsequence
  * 321. Create Maximum Number

## 🔹 Tricks & Patterns Used

* **Compare digit characters directly** — `"3" > "2"` works on single chars.
* **Leftover budget trims the tail**, since the stack is non-decreasing.

## 🔹 Alternative Data Structures

* Choosing each of the `n − k` output digits as the minimum of a sliding window (deque or sparse table) — O(n) / O(n log n) but more code.

## 🔹 Complexity Analysis

* **Time Complexity:** O(n), `n ≤ 10⁵`
* **Space Complexity:** O(n)

## 🔹 Code Snippet (Brute Force)

```python
class Solution:
    def removeKdigits(self, num: str, k: int) -> str:
        digits = list(num)
        for _ in range(k):
            i = 0
            while i + 1 < len(digits) and digits[i] <= digits[i + 1]:
                i += 1
            del digits[i]  # first descent, or the last digit if none
        return "".join(digits).lstrip("0") or "0"
```

## 🔹 Code Snippet (Optimized)

```python
class Solution:
    def removeKdigits(self, num: str, k: int) -> str:
        stack = []
        for d in num:
            while k and stack and stack[-1] > d:
                stack.pop()
                k -= 1
            stack.append(d)
        if k:
            stack = stack[:-k]  # stack is non-decreasing: the largest digits sit at the end
        return "".join(stack).lstrip("0") or "0"
```
