# 1482. Minimum Number of Days to Make m Bouquets

**🔗 Link:** [LeetCode 1482](https://leetcode.com/problems/minimum-number-of-days-to-make-m-bouquets/)
**🟢 Status:** 🔄 Need Review


## 🔹 Problem Statement

Flower `i` blooms on day `bloomDay[i]` and can then go into exactly one bouquet. A bouquet needs `k` flowers that are adjacent in the garden. Return the earliest day by which `m` bouquets can be made, or `-1` if the garden never has enough flowers.

* **Example:** `bloomDay = [1,10,3,10,2], m = 3, k = 1` → `3`
* **Constraints:** `1 ≤ bloomDay.length ≤ 10^5`; `1 ≤ bloomDay[i] ≤ 10^9`; `1 ≤ m ≤ 10^6`; `1 ≤ k ≤ n`

## 🔹 Quick Breakdown

* **Difficulty Level:** Medium
* **Main Approach:** **Binary search on the day.** Once a flower blooms it stays bloomed, so if `m` bouquets can be made by day `d` they can be made by any later day. Binary search the first feasible day in `[min(bloomDay), max(bloomDay)]`; the check is one greedy left-to-right pass counting runs of `k` adjacent bloomed flowers.
* **Core Concept:** binary search on answer + greedy feasibility check
* **When to Use This Pattern?** "Minimum time/value such that we can form at least `m` groups" where the check is a linear greedy scan.
* **Mistakes to Avoid:**
  * Not returning `-1` up front when `m · k > n` — the search would return a day that is not actually feasible.
  * Not resetting the run after cutting a bouquet: the next bouquet needs `k` **fresh** adjacent flowers.
  * In fixed-width languages `m · k` overflows 32 bits (10⁶ · 10⁵); Python is fine.

## 🔹 Optimization Path

* **Brute Force:** try each distinct bloom day in increasing order and run the check — O(n²) in the worst case.
* **Optimized Solution:** binary search on the day — O(n log(max bloomDay)) ≈ 30 passes.
* **Further Improvements Possible?** Binary search over the sorted distinct days instead of the value range — O(n log n), same order in practice.

## 🔹 Solution Breakdown

* **Optimal Approach:** `can(day)`: walk the garden, `run += 1` for each bloomed flower (`bloomDay[i] ≤ day`), reset on an unbloomed one; when `run == k`, count a bouquet and reset `run = 0`. Feasible iff count `≥ m`.
* **Why This Works?** Greedy cutting a bouquet as soon as `k` adjacent flowers are ready is optimal: any solution can shift its leftmost bouquet left to the earliest complete run without hurting the rest. Feasibility is monotone in `day` because the set of bloomed flowers only grows.
* **Edge Cases Considered:**
  * `m · k > n` → `-1`.
  * `m · k == n` → every flower is needed → `max(bloomDay)`.

## 🔹 Tricks & Patterns Used

* **Feasibility pre-check** (`m · k > n`) turns "no answer" into an O(1) exit and lets the search assume the top of the range is feasible.
* **Greedy run counter** with reset after each bouquet.

## 🔹 Alternative Data Structures

* Sorted distinct days as the search space.
* Union-find over flowers in bloom order (add flowers day by day, track run lengths) — O(n log n), heavier than needed.

* **Space Complexity:** O(1)

## 🔹 Code Snippet (Brute Force)

```python
from typing import List


class Solution:
    def minDays(self, bloomDay: List[int], m: int, k: int) -> int:
        for day in sorted(set(bloomDay)):
            bouquets = run = 0
            for bloom in bloomDay:
                run = run + 1 if bloom <= day else 0
                if run == k:
                    bouquets += 1
                    run = 0
            if bouquets >= m:
                return day
        return -1
```

## 🔹 Code Snippet (Optimized)

```python
from typing import List


class Solution:
    def minDays(self, bloomDay: List[int], m: int, k: int) -> int:
        if m * k > len(bloomDay):
            return -1

        def can(day: int) -> bool:
            bouquets = run = 0
            for bloom in bloomDay:
                run = run + 1 if bloom <= day else 0
                if run == k:
                    bouquets += 1
                    run = 0  # a flower can be in only one bouquet
            return bouquets >= m

        lo, hi = min(bloomDay), max(bloomDay)
        while lo < hi:
            mid = (lo + hi) // 2
            if can(mid):
                hi = mid
            else:
                lo = mid + 1
        return lo
```
