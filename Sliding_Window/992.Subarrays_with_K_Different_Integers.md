# 🔹 Problem Name: 992. Subarrays with K Different Integers (Sliding Window, Hard)

**🔗 Link:** [LeetCode 992](https://leetcode.com/problems/subarrays-with-k-different-integers/)
**🟢 Status:** 🔄 Need Review

## 🔹 Quick Breakdown

* **Difficulty Level:** Hard
* **Main Approach:** **"At most" trick with a frequency map.** Count subarrays with at most `k` distinct values by a sliding window, do the same for `k − 1`, and subtract.
* **Core Concept:** "exactly `k` distinct" is not monotone as the window shrinks, "at most `k` distinct" is
* **When to Use This Pattern?** "Number of subarrays with exactly K <something countable that only grows as the window grows>".
* **Mistakes to Avoid:**
  * Not deleting a key when its count drops to 0 — the stale key makes `len(freq)` overcount distinct values.
  * Trying a single window for "exactly k": for a fixed `right`, the valid starts form a range in the middle, not a suffix.

## 🔹 Optimization Path

* **Brute Force:** every start, extend the end with a set of seen values — O(n²), 2·10⁸ steps at `n = 2·10⁴`: too slow in Python.
* **Optimized Solution:** `atMost(k) − atMost(k − 1)` — O(n).
* **Further Improvements Possible?** One pass with three pointers (`left_far`, `left_near`, `right`) does it in a single sweep; same O(n), less readable.

## 🔹 Solution Breakdown

* **Optimal Approach:** `atMost(k)`: add `nums[right]` to `freq`; while `len(freq) > k`, decrement `freq[nums[left]]` (delete at 0) and advance `left`. Add `right − left + 1`.
* **Why This Works?** Removing elements never increases the number of distinct values, so for each `right` the valid starts are exactly `[left, right]` and `left` never moves back. Subarrays with ≤ k distinct minus those with ≤ k − 1 distinct leave exactly those with k distinct.
* **Edge Cases Considered:**
  * `k = 1`: `atMost(0)` is 0, answer = number of subarrays made of one repeated value.
  * `k` larger than the number of distinct values in the whole array: both counts equal `n(n+1)/2`, answer 0.

## 🔹 Tricks & Patterns Used

* **`exact(K) = atMost(K) − atMost(K − 1)`.**
* **`len(freq)` as the distinct count:** O(1) as long as zero-count keys are removed.

## 🔹 Alternative Data Structures

* Values are in `[1, n]`, so a list of size `n + 1` plus a `distinct` counter replaces the dict and is faster.

## 🔹 Complexity Analysis

* **Time Complexity:** O(n) — two passes, each pointer moves at most `n` times
* **Space Complexity:** O(n) for the frequency map

## 🔹 Code Snippet (Brute Force)

```python
from typing import List


class Solution:
    def subarraysWithKDistinct(self, nums: List[int], k: int) -> int:
        count = 0
        for start in range(len(nums)):
            seen = set()
            for end in range(start, len(nums)):
                seen.add(nums[end])
                if len(seen) == k:
                    count += 1
                elif len(seen) > k:
                    break  # extending further can only add values
        return count
```

## 🔹 Code Snippet (Optimized)

```python
from collections import defaultdict
from typing import List


class Solution:
    def subarraysWithKDistinct(self, nums: List[int], k: int) -> int:
        def at_most(limit: int) -> int:
            freq = defaultdict(int)
            left = count = 0
            for right, value in enumerate(nums):
                freq[value] += 1
                while len(freq) > limit:
                    freq[nums[left]] -= 1
                    if freq[nums[left]] == 0:
                        del freq[nums[left]]  # keeps len(freq) equal to the distinct count
                    left += 1
                count += right - left + 1
            return count

        return at_most(k) - at_most(k - 1)
```
