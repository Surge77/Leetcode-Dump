# 🔹 Problem Name: 179. Largest Number (Custom Sort, Medium)

**🔗 Link:** [LeetCode 179](https://leetcode.com/problems/largest-number/)
**🟢 Status:** 🔄 Need Review

## 🔹 Problem Statement

Given non-negative integers, order them so that gluing their decimal forms together produces the biggest possible number. Because the result can be huge, return it as a string.

* **Example:** `nums = [10,2]` → `"210"`
* **Constraints:** `1 ≤ nums.length ≤ 100`, `0 ≤ nums[i] ≤ 10^9`.

## 🔹 Quick Breakdown

* **Difficulty Level:** Medium
* **Main Approach:** **Sort strings with the comparator "`a` before `b` iff `a + b > b + a`".** Convert numbers to strings, sort by that rule, concatenate. If the first piece is `"0"` the answer is `"0"`.
* **Core Concept:** greedy ordering via an exchange argument — the pairwise concatenation order is transitive, so a sort produces the globally best arrangement
* **When to Use This Pattern?** "Arrange items to form the largest/smallest string" where items have different lengths.
* **Mistakes to Avoid:**
  * Sorting lexicographically (`"9" > "34" > "30" > "3"` puts `30` before `3`, giving `"303"` < `"330"`) or by numeric value.
  * Returning `"00"` for `[0, 0]` — collapse to `"0"`.
  * Comparing by length first.

## 🔹 Optimization Path

* **Brute Force:** try every permutation of the numbers and keep the largest concatenation — O(n! · n · L), feasible only for tiny `n`.
* **Optimized Solution:** sort with the pairwise comparator — O(n log n · L).
* **Further Improvements Possible?** Key-based trick: compare `s * 10` (repeat the string, since `len ≤ 10`); it avoids `cmp_to_key` but is harder to justify.

## 🔹 Solution Breakdown

* **Optimal Approach:** `sorted(strs, key=cmp_to_key(lambda a, b: -1 if a + b > b + a else 1 if a + b < b + a else 0))`; join; handle the all-zero case.
* **Why This Works?** Suppose `a + b > b + a` but an arrangement puts `b` directly before `a`. Swapping that adjacent pair leaves every other digit in place (both orders occupy the same positions), so it strictly increases the number. An optimal arrangement therefore has no such pair, and since "`a + b ≥ b + a`" is a total preorder, sorting by it produces exactly that arrangement.
* **Edge Cases Considered:**
  * `[0, 0]` → `"0"`.
  * `[3, 30, 34, 5, 9]` → `"9534330"`.
  * Single element.

## 🔹 Tricks & Patterns Used

* **`functools.cmp_to_key`** to turn a pairwise comparator into a sort key.
* **Concatenation comparison** instead of numeric/length comparison.

## 🔹 Alternative Data Structures

* Repeat-padding key: `key=lambda s: s * 10` with `reverse=True` (valid because each number has ≤ 10 digits).

## 🔹 Complexity Analysis

* **Time Complexity:** O(n log n · L) with L ≤ 10 the digits per number
* **Space Complexity:** O(n · L)

## 🔹 Code Snippet (Brute Force)

```python
from itertools import permutations
from typing import List


class Solution:
    def largestNumber(self, nums: List[int]) -> str:
        # all permutations have equal length, so string max equals numeric max
        best = max("".join(p) for p in permutations(map(str, nums)))
        return "0" if best[0] == "0" else best
```

## 🔹 Code Snippet (Optimized)

```python
from functools import cmp_to_key
from typing import List


class Solution:
    def largestNumber(self, nums: List[int]) -> str:
        def before(a: str, b: str) -> int:
            if a + b > b + a:
                return -1
            return 1 if a + b < b + a else 0

        pieces = sorted(map(str, nums), key=cmp_to_key(before))
        return "0" if pieces[0] == "0" else "".join(pieces)  # all zeros collapse to a single "0"
```
