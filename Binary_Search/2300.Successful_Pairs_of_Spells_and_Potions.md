# 2300. Successful Pairs of Spells and Potions

**🔗 Link:** [LeetCode 2300](https://leetcode.com/problems/successful-pairs-of-spells-and-potions/)
**🟢 Status:** 🔄 Need Review


## 🔹 Problem Statement

Given arrays of spell strengths and potion strengths, a spell and a potion form a successful pair when their product is at least `success`. For each spell, in the original order, return how many potions pair successfully with it.

* **Example:** `spells = [5,1,3], potions = [1,2,3,4,5], success = 7` → `[4,0,3]`
* **Constraints:** `1 ≤ n, m ≤ 10^5`; `1 ≤ spells[i], potions[i] ≤ 10^5`; `1 ≤ success ≤ 10^10`

## 🔹 Quick Breakdown

* **Difficulty Level:** Medium
* **Main Approach:** **Sort the potions once, binary-search a threshold per spell.** A pair succeeds when `spell * potion >= success`, i.e. `potion >= ceil(success / spell)`. In sorted potions, all successful ones form a suffix, so its size is `m - bisect_left(potions, need)`.
* **Core Concept:** turn a product condition into a per-query lower bound over a sorted array
* **When to Use This Pattern?** "For each query, count elements meeting a monotone condition" — sort once, then one `bisect` per query.
* **Mistakes to Avoid:**
  * Floating-point division (`success / spell`): products reach 10¹⁰ and ceil errors creep in. Use the integer `ceil` `(success + spell - 1) // spell`.
  * Sorting the spells — the output must stay aligned with the original spell order.
  * Using `bisect_right` — the equality case `spell * potion == success` counts as success, so use `bisect_left`.

## 🔹 Optimization Path

* **Brute Force:** for each spell scan every potion — O(n · m) (up to 10¹⁰ checks).
* **Optimized Solution:** sort potions (O(m log m)), then one binary search per spell (O(n log m)).
* **Further Improvements Possible?** Sorting both and using two pointers is the same asymptotically; the answer for each spell must still be written, so O(n log m) is effectively optimal.

## 🔹 Solution Breakdown

* **Optimal Approach:** `potions.sort()`; for each spell `s`: `need = (success + s - 1) // s`; answer `m - bisect_left(potions, need)`.
* **Why This Works?** For positive integers, `s * p >= success` iff `p >= ceil(success / s)`. Sorted potions put every `p >= need` at the end, so counting them is `m - first index with p >= need`.
* **Edge Cases Considered:**
  * `need` larger than every potion → `bisect_left` returns `m`, count `0`.
  * `need` at or below the smallest potion → count is `m`.
  * Equal spells share the same threshold; each is simply computed again.

* **Integer ceiling division:** `(a + b - 1) // b`.

## 🔹 Alternative Data Structures

* Sort spells with their indices and sweep potions with a monotone pointer — O(n log n + m log m).
* Counting array over potion values (≤ 10⁵) with suffix sums: answer a spell by indexing `need` directly, O(n + m + max potion).

* **Time Complexity:** O((n + m) log m)
* **Space Complexity:** O(1) extra (O(m) if you copy the potions before sorting)

## 🔹 Code Snippet (Brute Force)

```python
from typing import List


class Solution:
    def successfulPairs(self, spells: List[int], potions: List[int], success: int) -> List[int]:
        return [sum(1 for p in potions if s * p >= success) for s in spells]
```

## 🔹 Code Snippet (Optimized)

```python
from bisect import bisect_left
from typing import List


class Solution:
    def successfulPairs(self, spells: List[int], potions: List[int], success: int) -> List[int]:
        potions.sort()
        m = len(potions)
        # integer ceil keeps the threshold exact for products up to 10^10
        return [m - bisect_left(potions, (success + s - 1) // s) for s in spells]
```
