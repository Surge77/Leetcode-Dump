# 252. Meeting Rooms

## 🔹 Problem Statement

Given a list of meeting time intervals `[start, end]`, decide whether one person could attend all of them, meaning no two meetings overlap. Meetings that only touch (one ends exactly when the next starts) do not count as overlapping. *(premium — paraphrased from memory, not checked against the official page)*

* **Example:** `intervals = [[0,30],[5,10],[15,20]]` → `false`
* **Constraints:** `0 ≤ intervals.length ≤ 10^4`; `0 ≤ start < end ≤ 10^6`

## 🔹 Quick Breakdown

* **Difficulty Level:** Easy
* **Main Approach:** **Sort by start, compare neighbours.** One person can attend all meetings iff no two overlap. After sorting by start time, an overlap exists iff some meeting starts before the previous one ends.
* **Core Concept:** after sorting by start, any overlapping pair implies an overlapping **adjacent** pair, so only `n − 1` checks are needed
* **When to Use This Pattern?** "Do any intervals overlap?" — scheduling conflicts, validating a calendar, the first step of merge-intervals problems.
* **Mistakes to Avoid:**
  * Treating touching meetings as a conflict: `[1, 5]` and `[5, 8]` are fine (one ends as the other starts), so the test is strict `start < prev_end`.
  * Comparing every pair: O(n²) for `n ≤ 10⁴`.

## 🔹 Optimization Path

* **Brute Force:** check every pair `(a, b)` for `a.start < b.end and b.start < a.end` — O(n²).
* **Optimized Solution:** sort + one adjacent scan — O(n log n).
* **Further Improvements Possible?** Not with comparisons in general (it's at least as hard as element distinctness).

## 🔹 Solution Breakdown

* **Optimal Approach:** `intervals.sort()`; return `False` if `intervals[i][0] < intervals[i − 1][1]` for any `i`; else `True`.
* **Why This Works?** Suppose `a` (earlier start) overlaps a later `c` with `b` in between in sorted order. Then `b.start ≤ c.start < a.end`, so `a` and `b` already overlap — and repeating the argument down the chain reaches an adjacent overlapping pair.
* **Edge Cases Considered:**
  * `[]` or one meeting → `True`.
  * Identical meetings `[[1, 3], [1, 3]]` → `False`.
  * Unsorted input such as `[[7, 10], [2, 4]]` → `True` once sorted.

## 🔹 Tricks & Patterns Used

* **Adjacent-pair reduction:** sorting turns a pairwise question into a linear scan.
* **Half-open intervals `[start, end)`:** touching is not overlapping — decide `<` vs `≤` from the statement.

## 🔹 Alternative Data Structures

* Sweep over 2n events (end before start at ties) checking that at most one meeting is active.
* Sorting starts and ends separately — overlap iff `starts[i] < ends[i − 1]` for some `i`.

## 🔹 Complexity Analysis

* **Time Complexity:** O(n log n)
* **Space Complexity:** O(n) for the sort (Timsort), O(1) extra otherwise

## 🔹 Code Snippet (Brute Force)

```python
from typing import List


class Solution:
    def canAttendMeetings(self, intervals: List[List[int]]) -> bool:
        n = len(intervals)
        for i in range(n):
            for j in range(i + 1, n):
                a, b = intervals[i], intervals[j]
                if a[0] < b[1] and b[0] < a[1]:
                    return False
        return True
```

## 🔹 Code Snippet (Optimized)

```python
from typing import List


class Solution:
    def canAttendMeetings(self, intervals: List[List[int]]) -> bool:
        ordered = sorted(intervals)
        for i in range(1, len(ordered)):
            if ordered[i][0] < ordered[i - 1][1]:  # equal is fine: one ends as the next starts
                return False
        return True
```
