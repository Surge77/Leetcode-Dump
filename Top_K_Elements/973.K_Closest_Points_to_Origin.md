# 🔹 Problem Name: 973. K Closest Points to Origin (Max Heap of Size K, Medium)

**🔗 Link:** [LeetCode 973](https://leetcode.com/problems/k-closest-points-to-origin/)
**🟢 Status:** 🔄 Need Review

## 🔹 Quick Breakdown

* **Difficulty Level:** Medium
* **Main Approach:** **Max-heap of size `k`** keyed by squared distance. Scan the points; push `(-dist², x, y)`, and when the heap exceeds `k`, pop the farthest. What remains are the `k` closest.
* **Core Concept:** "k smallest" → keep a max-heap of candidates so the worst one is evicted in O(log k)
* **When to Use This Pattern?** Select the k best by some score without fully sorting — top k frequent, kth largest, closest elements.
* **Mistakes to Avoid:**
  * Taking `sqrt`: unnecessary and introduces floats; squared distance has the same order.
  * Pushing `(dist, point)` into `heapq` and expecting a max-heap — negate the key.

## 🔹 Optimization Path

* **Brute Force:** sort all points by squared distance and take `k` — O(n log n).
* **Optimized Solution:** size-k max-heap — O(n log k).
* **Further Improvements Possible?** Quickselect on distances partitions the k closest in O(n) average (O(n²) worst case without a random pivot).

## 🔹 Solution Breakdown

* **Optimal Approach:** for each point push `(-(x² + y²), x, y)`; if `len(heap) > k`, `heappop` (removes the largest distance).
* **Why This Works?** After each step the heap holds the `k` closest points among those seen: a new point either beats the current farthest (which is evicted) or is evicted itself.
* **Edge Cases Considered:**
  * `k == n` — every point is returned.
  * The answer may be returned in any order; LeetCode guarantees it is unique as a set.

## 🔹 Tricks & Patterns Used

* **Compare squared distances:** monotonic transform, keeps integers.
* **`heapq.nsmallest(k, points, key=...)`:** the library version of the same size-k heap.

## 🔹 Alternative Data Structures

* Quickselect (Hoare/Lomuto partition with a random pivot) — O(n) average, in place.
* Bucket by distance is impractical here: squared distances reach 2·10⁸.

## 🔹 Complexity Analysis

* **Time Complexity:** O(n log k)
* **Space Complexity:** O(k)

## 🔹 Code Snippet (Brute Force)

```python
from typing import List


class Solution:
    def kClosest(self, points: List[List[int]], k: int) -> List[List[int]]:
        return sorted(points, key=lambda p: p[0] * p[0] + p[1] * p[1])[:k]
```

## 🔹 Code Snippet (Optimized)

```python
import heapq
from typing import List


class Solution:
    def kClosest(self, points: List[List[int]], k: int) -> List[List[int]]:
        heap = []  # max-heap via negated distance: root = farthest kept point
        for x, y in points:
            heapq.heappush(heap, (-(x * x + y * y), x, y))
            if len(heap) > k:
                heapq.heappop(heap)
        return [[x, y] for _, x, y in heap]
```
