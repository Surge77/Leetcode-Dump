# 🔹 Problem Name: 6. Zigzag Conversion (String Simulation, Medium)

**🔗 Link:** [LeetCode 6](https://leetcode.com/problems/zigzag-conversion/)
**🟢 Status:** 🔄 Need Review

## 🔹 Quick Breakdown

* **Difficulty Level:** Medium
* **Main Approach:** **Row buckets.** Walk the string once while a cursor bounces between row `0` and row `numRows − 1`; append each character to the bucket of its row, then concatenate the buckets top to bottom.
* **Core Concept:** only the **row** of a character matters for the output — its column in the drawing is irrelevant
* **When to Use This Pattern?** "Write the input in a shape, read it back in another order" — zigzag, diagonal or spiral read-outs, slanted ciphers. Find the property the read order sorts by (here: the row) and bucket by it.
* **Mistakes to Avoid:**
  * `numRows == 1`: the cursor would bounce off row 0 into row 1 and crash — return `s` directly.
  * Flipping the direction **after** moving instead of when the cursor reaches the top or bottom row: it overshoots to row `−1` or `numRows`.
  * Drawing the full 2D grid: O(numRows × n) memory for an O(n) answer.

## 🔹 Optimization Path

* **Brute Force:** draw the zigzag in a `numRows × n` grid, then read it row by row skipping blanks — O(numRows · n) time and space.
* **Optimized Solution:** row buckets — O(n) time, O(n) space.
* **Further Improvements Possible?** Index arithmetic: the pattern repeats every `cycle = 2·(numRows − 1)` characters, and row `r` holds the indices `k·cycle + r` and (for middle rows) `k·cycle + cycle − r`. That emits the answer directly without buckets — same O(n).

## 🔹 Solution Breakdown

* **Optimal Approach:** `row, step = 0, 1`; for each character: append it to `rows[row]`, reverse `step` when `row` is `0` or `numRows − 1`, then `row += step`.
* **Why This Works?** Reading the drawing row by row keeps, inside one row, the left-to-right order — which is exactly the order the characters were written. So each bucket is already in output order; only the row assignment has to be right.
* **Edge Cases Considered:**
  * `numRows == 1` → the string itself.
  * `numRows ≥ len(s)` → every character gets its own row, read top to bottom = `s`.

## 🔹 Tricks & Patterns Used

* **Bouncing cursor:** flip `step` at both walls, then move — the same loop handles the vertical stroke and the diagonal.
* **Drop the dimension the output ignores:** the grid's columns never affect the order, so a list per row replaces the grid.

## 🔹 Alternative Data Structures

* Cycle formula with direct indexing — no buckets, same complexity.
* A full 2D grid (the brute force below) — useful to visualise, wasteful to keep.

## 🔹 Complexity Analysis

* **Time Complexity:** O(n)
* **Space Complexity:** O(n) for the buckets and the output

## 🔹 Code Snippet (Brute Force)

```python
class Solution:
    def convert(self, s: str, numRows: int) -> str:
        if numRows == 1:
            return s
        grid = [[""] * len(s) for _ in range(numRows)]
        row = col = 0
        going_down = True
        for ch in s:
            grid[row][col] = ch
            if going_down and row == numRows - 1:
                going_down = False
            elif not going_down and row == 0:
                going_down = True
            if going_down:
                row += 1
            else:  # the diagonal moves up and one column right
                row -= 1
                col += 1
        return "".join(ch for line in grid for ch in line if ch)
```

## 🔹 Code Snippet (Optimized)

```python
class Solution:
    def convert(self, s: str, numRows: int) -> str:
        if numRows == 1 or numRows >= len(s):
            return s
        rows = [[] for _ in range(numRows)]
        row, step = 0, 1
        for ch in s:
            rows[row].append(ch)
            if row == 0:
                step = 1
            elif row == numRows - 1:
                step = -1
            row += step
        return "".join("".join(bucket) for bucket in rows)
```
