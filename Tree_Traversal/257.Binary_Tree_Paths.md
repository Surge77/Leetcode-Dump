# 🔹 Problem Name: 257. Binary Tree Paths (Tree Backtracking, Easy)

**🔗 Link:** [LeetCode 257](https://leetcode.com/problems/binary-tree-paths/)
**🟢 Status:** 🔄 Need Review

## 🔹 Quick Breakdown

* **Difficulty Level:** Easy
* **Main Approach:** **DFS with one shared path (backtracking).** Push the node's value on the way down, record `"->".join(path)` at a leaf, pop on the way back up. Each answer string is built exactly once, at its leaf.
* **Core Concept:** choose → explore → un-choose on a tree, emitting only at leaves
* **When to Use This Pattern?** "Return all root-to-leaf paths" or all paths with some property (113 Path Sum II), any enumeration where partial answers are prefixes of each other.
* **Mistakes to Avoid:**
  * Emitting at `None` children instead of at leaves → each leaf's path appears twice and one-child nodes produce fake paths.
  * Forgetting the `pop()` → values leak into the sibling branch's paths.
  * Building strings at every level (`prefix + "->" + val`): every path is recopied once per depth.

## 🔹 Optimization Path

* **Brute Force:** each call returns its subtree's paths and the parent prepends `"val->"` to every one — a leaf at depth `d` is copied `d` times: O(Σ d²) characters over all leaves.
* **Optimized Solution:** backtracking with a shared list, joined at leaves — O(n + L), where `L` is the total length of the answer.
* **Further Improvements Possible?** No: writing the output already costs `L`.

## 🔹 Solution Breakdown

* **Optimal Approach:** `dfs(node)`: append `str(node.val)`; at a leaf, append `"->".join(parts)` to the answer; recurse into existing children; pop.
* **Why This Works?** `parts` always holds exactly the values from the root to the current node — pushed on entry, popped on exit — so at a leaf it is that leaf's path, and every root-to-leaf path ends at exactly one leaf.
* **Edge Cases Considered:**
  * Single node → `["1"]` (at least one node is guaranteed).
  * Negative values: `str(-5)` keeps the sign, giving `"1->-5"`.
  * Repeated values can produce identical strings for different paths — both are kept.

## 🔹 Pattern Recognition

* **Belongs To:** Tree DFS — backtracking over root-to-leaf paths

## 🔹 Tricks & Patterns Used

* **Shared mutable path + `pop()`:** O(h) memory for the path instead of one copy per node.
* **Join only at the leaves:** pay for a string only when it is a finished answer.

## 🔹 Alternative Data Structures

* Iterative stack of `(node, path_string)` pairs — no recursion, but every push builds a new string, so the work is the sum of all node depths.
* BFS with the same pairs — same cost, O(w) memory.

## 🔹 Complexity Analysis

* **Time Complexity:** O(n + L), `L` = total characters in the answer (at most O(n·h))
* **Space Complexity:** O(h) for the path and the recursion, excluding the output

## 🔹 Code Snippet (Brute Force)

```python
from typing import List, Optional


class Solution:
    def binaryTreePaths(self, root: Optional[TreeNode]) -> List[str]:
        if not root.left and not root.right:
            return [str(root.val)]
        paths = []
        for child in (root.left, root.right):
            if child:
                paths += [f"{root.val}->{tail}" for tail in self.binaryTreePaths(child)]
        return paths
```

## 🔹 Code Snippet (Optimized)

```python
from typing import List, Optional


class Solution:
    def binaryTreePaths(self, root: Optional[TreeNode]) -> List[str]:
        paths, parts = [], []

        def dfs(node: TreeNode) -> None:
            parts.append(str(node.val))
            if not node.left and not node.right:
                paths.append("->".join(parts))
            for child in (node.left, node.right):
                if child:
                    dfs(child)
            parts.pop()  # undo, so the sibling branch starts from the same prefix

        dfs(root)
        return paths
```
