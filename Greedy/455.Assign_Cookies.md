# 🔹 Problem Name: 455. Assign Cookies (Greedy Two Pointers, Easy)

**🔗 Link:** [LeetCode 455](https://leetcode.com/problems/assign-cookies/)
**🟢 Status:** 🔄 Need Review

## 🔹 Quick Breakdown

* **Difficulty Level:** Easy
* **Main Approach:** **Sort both, two pointers.** Sort greed factors `g` and cookie sizes `s`. Walk the cookies from smallest to largest; whenever the current cookie satisfies the least greedy unfed child, feed that child and move to the next one. A cookie too small for the least greedy child is useless to everyone, so skip it.
* **Core Concept:** match the smallest sufficient resource to the smallest demand — never waste a big cookie on a child a smaller one could satisfy
* **When to Use This Pattern?** Maximise the number of pairs `(demand, supply)` with `supply ≥ demand`, each used once — boats (881), matching players with trainers (2410), assigning workers to jobs.
* **Mistakes to Avoid:**
  * Advancing the child pointer when the cookie is too small — the child is still hungry; it is the cookie that is useless.
  * Giving each child the largest cookie: it can starve later children that only a big cookie could feed.

## 🔹 Optimization Path

* **Brute Force:** sort children; for each child, scan all remaining cookies for the smallest one that fits and remove it — O(n · m).
* **Optimized Solution:** sort both and sweep with two pointers — O(n log n + m log m).
* **Further Improvements Possible?** Not asymptotically; the sort dominates. Counting sort is impossible since values reach 2³¹ − 1.

## 🔹 Solution Breakdown

* **Optimal Approach:** `child = 0`; for each cookie in ascending order, if `child < len(g)` and `cookie >= g[child]`, increment `child`. Answer is `child`.
* **Why This Works?** Exchange argument: in any optimal assignment, the least greedy child can be swapped to receive the smallest cookie that fits them, and fed children can be re-assigned in sorted order without breaking any match. So feeding children in sorted order with the smallest fitting cookies loses nothing.
* **Edge Cases Considered:**
  * No cookies (`s = []`) → 0.
  * Every cookie smaller than every greed factor → 0.
  * More cookies than children — stop counting once every child is fed.

## 🔹 Tricks & Patterns Used

* **Sort both sides, one pointer per side:** the pointer over the scarce side only advances on a successful match.
* **Exchange argument** to justify the greedy choice.

## 🔹 Alternative Data Structures

* A sorted multiset of cookies with binary search (`bisect`) to pull the smallest fitting cookie per child — same O(n log m) but needs deletions, so a plain sorted list costs O(m) per removal.

## 🔹 Complexity Analysis

* **Time Complexity:** O(n log n + m log m) for `n` children and `m` cookies
* **Space Complexity:** O(n + m) for the sorted copies (O(1) extra if sorting in place)

## 🔹 Code Snippet (Brute Force)

```python
from typing import List


class Solution:
    def findContentChildren(self, g: List[int], s: List[int]) -> int:
        cookies = sorted(s)
        content = 0
        for greed in sorted(g):
            for i, size in enumerate(cookies):
                if size >= greed:
                    cookies.pop(i)  # cookies is sorted, so this is the smallest one that fits
                    content += 1
                    break
        return content
```

## 🔹 Code Snippet (Optimized)

```python
from typing import List


class Solution:
    def findContentChildren(self, g: List[int], s: List[int]) -> int:
        g, s = sorted(g), sorted(s)
        child = 0
        for size in s:
            if child < len(g) and size >= g[child]:
                child += 1
            # otherwise this cookie is too small for every remaining child, so drop it
        return child
```
