# 🔹 Problem Name: 2104. Sum of Subarray Ranges (Monotonic Stack, Medium)

**🔗 Link:** [LeetCode 2104](https://leetcode.com/problems/sum-of-subarray-ranges/)
**🟢 Status:** 🔄 Need Review

## 🔹 Problem Statement

The range of a subarray is its largest element minus its smallest. Given an integer array `nums`, return the sum of the ranges of all its contiguous non-empty subarrays.

* **Example:** `nums = [1,2,3]` → `4`
* **Constraints:** `1 ≤ nums.length ≤ 1000`, `-10^9 ≤ nums[i] ≤ 10^9`

## 🔹 Quick Breakdown

* **Difficulty Level:** Medium
* **Main Approach:** **Contribution technique.** `Σ (max − min) = Σ max − Σ min` over all subarrays. Each element is the minimum of `(i − left) · (right − i)` subarrays, where `left`/`right` are the nearest smaller elements on each side — found with a monotonic stack. Sum of maxima = −(sum of minima of the negated array), so one helper does both.
* **Core Concept:** instead of enumerating subarrays, count for each element how many subarrays it is the min (or max) of
* **When to Use This Pattern?** "Sum over all subarrays of min / max / range" — 907, 2104, 1856, 2281.
* **Mistakes to Avoid:**
  * Double counting equal values: break ties asymmetrically (pop on `≥` going right, so each subarray's minimum is attributed to exactly one index).
  * Negatives: values go down to −10⁹, so the "negate to reuse the min helper" trick needs a sentinel below every value (`-inf`).
  * Taking `% 10⁹+7` — this problem wants the exact sum (Python ints are unbounded anyway).

## 🔹 Optimization Path

* **Brute Force:** for every start, extend the end while tracking running min and max — O(n²). (Accepted for `n ≤ 1000`; the follow-up asks for O(n).)
* **Optimized Solution:** two monotonic-stack passes — O(n).
* **Further Improvements Possible?** No; O(n) is optimal.

## 🔹 Solution Breakdown

* **Optimal Approach:** `sum_of_mins(a)`: scan `i = 0 … n` with `a[n] = −∞`; while the top `j` has `a[j] ≥ a[i]`, pop it and add `a[j] · (j − left) · (i − j)` with `left` = new top (or −1). Answer = `−sum_of_mins(−nums) − sum_of_mins(nums)`.
* **Why This Works?** When `j` is popped by `i`, `i` is the first index to its right with a value ≤ `a[j]`, and the new top is the last index to its left with a value < `a[j]`. Subarrays that contain `j` and stay strictly inside those bounds have `a[j]` as their minimum, and the `<` / `≤` asymmetry gives each subarray to exactly one index.
* **Edge Cases Considered:**
  * `n = 1` → 0.
  * All equal → 0.
  * Mixed signs, e.g. `[4, -2, -3, 4, 1]` → 59.

* **Max via min of negation** — one helper, two calls.
* **Sentinel `−∞` at the end** flushes the stack with no extra loop.

## 🔹 Alternative Data Structures

* Precompute `prev_less` / `next_less_or_equal` arrays in two separate passes, then sum — same complexity, easier to debug.

## 🔹 Code Snippet (Brute Force)

```python
from typing import List


class Solution:
    def subArrayRanges(self, nums: List[int]) -> int:
        total = 0
        for i in range(len(nums)):
            low = high = nums[i]
            for j in range(i, len(nums)):
                low, high = min(low, nums[j]), max(high, nums[j])
                total += high - low
        return total
```

## 🔹 Code Snippet (Optimized)

```python
from typing import List


class Solution:
    def subArrayRanges(self, nums: List[int]) -> int:
        def sum_of_mins(a: List[int]) -> int:
            total, stack = 0, []
            for i in range(len(a) + 1):
                cur = a[i] if i < len(a) else float("-inf")  # sentinel pops everything
                while stack and a[stack[-1]] >= cur:  # ">=" here, "<" on the left: no double count
                    j = stack.pop()
                    left = stack[-1] if stack else -1
                    total += a[j] * (j - left) * (i - j)
                stack.append(i)
            return total

        return -sum_of_mins([-x for x in nums]) - sum_of_mins(nums)
```
