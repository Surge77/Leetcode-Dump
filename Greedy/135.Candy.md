# 135. Candy

**🔗 Link:** [LeetCode 135](https://leetcode.com/problems/candy/)
**🟢 Status:** 🔄 Need Review


## 🔹 Problem Statement

Children stand in a line, each with a rating. Hand out candies so that every child gets at least one, and any child with a strictly higher rating than a neighbour gets more candies than that neighbour. Return the smallest total number of candies that works.

* **Example:** `ratings = [1,0,2]` → `5`
* **Constraints:** `1 ≤ n == ratings.length ≤ 5·10⁴`, `0 ≤ ratings[i] ≤ 5·10⁴`

## 🔹 Quick Breakdown

* **Difficulty Level:** Hard
* **Main Approach:** **One pass per neighbour.** Left to right: if `ratings[i] > ratings[i − 1]`, give `candies[i − 1] + 1`, otherwise 1 — every left-neighbour rule now holds with the fewest candies. Right to left: if `ratings[i] > ratings[i + 1]`, raise `candies[i]` to `candies[i + 1] + 1` when that is bigger. Taking the `max` keeps the left rule intact.
* **Core Concept:** split a two-sided constraint into two one-sided ones, solve each greedily, combine with `max`
* **When to Use This Pattern?** Each position depends on a run or condition to its left and another to its right — trapping rain water, product except self, nearest character on either side, "good days" with non-increasing/non-decreasing windows.
* **Mistakes to Avoid:**
  * Giving equal ratings equal candy — the rule only binds strictly higher ratings; `[1, 2, 2]` needs `1 + 2 + 1 = 4`.
  * Overwriting instead of taking `max` in the second pass — that breaks the left-neighbour rule fixed by pass 1.
  * A single left-to-right pass: misses falling runs like `[3, 2, 1]`.

## 🔹 Optimization Path

* **Brute Force:** start everyone at 1 and keep sweeping, raising any child who breaks a rule, until nothing changes — O(n²) (a falling run of length `n` needs `n` sweeps).
* **Optimized Solution:** two passes — O(n) time, O(n) space.
* **Further Improvements Possible?** O(1) space by counting the current up-slope and down-slope lengths (the peak gets `max(up, down) + 1`) — same O(n) time, much easier to get wrong.

## 🔹 Solution Breakdown

* **Optimal Approach:** `candies = [1] * n`; forward pass for the left rule, backward pass with `max` for the right rule; return `sum(candies)`.
* **Why This Works?** Child `i` is forced to at least `L[i]` = length of the strictly rising run ending at `i` (from the left) and at least `R[i]` (the same from the right) — each is a chain of rules ending at a child with 1. `max(L[i], R[i])` is therefore a lower bound, and it is feasible: if `ratings[i] < ratings[i + 1]` then `R[i] = 1`, so `candies[i] = L[i] < L[i + 1] ≤ candies[i + 1]` (symmetric for the other side). Feasible and minimal at every child ⇒ minimal total.
* **Edge Cases Considered:**
  * `n = 1` → 1; all ratings equal → `n`.
  * Strictly falling ratings → `n(n + 1)/2` (the backward pass does all the work).
  * A valley `[2, 1, 2]` → `2 + 1 + 2 = 5`.

## 🔹 Tricks & Patterns Used

* **Two one-sided passes + `max`:** each pass enforces one neighbour; `max` keeps both.
* **Run-length counter:** `L[i] = L[i − 1] + 1` if rising else 1 — the length of the strictly rising run ending at `i`.

## 🔹 Alternative Data Structures

* Sort children by rating and give each `1 + max(candies of lower-rated neighbours)` in that order — O(n log n); the sorted order is a topological order of the "must exceed" graph.
* Slope counters (`up`, `down`, `peak`) instead of the array — O(1) space.

## 🔹 Code Snippet (Brute Force)

```python
from typing import List


class Solution:
    def candy(self, ratings: List[int]) -> int:
        n = len(ratings)
        candies = [1] * n
        while True:
            changed = False
            for i in range(n):
                need = 1
                if i > 0 and ratings[i] > ratings[i - 1]:
                    need = candies[i - 1] + 1
                if i + 1 < n and ratings[i] > ratings[i + 1]:
                    need = max(need, candies[i + 1] + 1)
                if need > candies[i]:  # only ever raise, so the sweeps settle on the smallest valid amounts
                    candies[i], changed = need, True
            if not changed:
                return sum(candies)
```

## 🔹 Code Snippet (Optimized)

```python
from typing import List


class Solution:
    def candy(self, ratings: List[int]) -> int:
        n = len(ratings)
        candies = [1] * n
        for i in range(1, n):
            if ratings[i] > ratings[i - 1]:
                candies[i] = candies[i - 1] + 1
        for i in range(n - 2, -1, -1):
            if ratings[i] > ratings[i + 1]:
                candies[i] = max(candies[i], candies[i + 1] + 1)  # max keeps the left-neighbour rule from pass 1
        return sum(candies)
```
