# 2846. Minimum Edge Weight Equilibrium Queries in a Tree

**🔗 Link:** [LeetCode 2846](https://leetcode.com/problems/minimum-edge-weight-equilibrium-queries-in-a-tree/)
**🟢 Status:** 🔄 Need Review


## 🔹 Problem Statement

An undirected weighted tree on nodes `0..n-1` is given as an edge list `[u, v, w]`. For each query `[a, b]`, find the fewest edge-weight changes (any edge, any new value) needed so that all edges on the path from `a` to `b` have equal weight. Queries are independent: the tree resets after each one. Return one answer per query.

* **Example:** `n = 7, edges = [[0,1,1],[1,2,1],[2,3,1],[3,4,2],[4,5,2],[5,6,2]], queries = [[0,3],[3,6],[2,6],[0,6]]` → `[0,0,1,3]`
* **Constraints:** `1 ≤ n ≤ 10⁴`; `1 ≤ wᵢ ≤ 26`; `1 ≤ queries.length ≤ 2·10⁴`; the input is a valid tree.

## 🔹 Quick Breakdown

* **Difficulty Level:** Hard
* **Main Approach:** For a query `(a, b)`, make every edge on the path equal with the fewest changes: keep the most frequent weight, change the rest → `pathLength − maxCount`. Weights are only 1..26, so store `cnt[v][w]` = number of weight-`w` edges from the root to `v`. With `c = LCA(a, b)`: `pathCount[w] = cnt[a][w] + cnt[b][w] − 2·cnt[c][w]` and `pathLength = depth[a] + depth[b] − 2·depth[c]`. LCA by **binary lifting**.
* **Core Concept:** root-to-node prefix aggregates + LCA turn any path query into O(1) arithmetic (here O(26))
* **When to Use This Pattern?** Many queries about the path between two tree nodes: distance, sum, count of a value, max edge (with lifting tables for max).
* **Mistakes to Avoid:**
  * Walking the path per query — O(n) each, 10⁴ × 2·10⁴ = 2·10⁸.
  * Subtracting `cnt[c]` only once: the root→c part is in **both** `cnt[a]` and `cnt[b]`.
  * Recursive DFS on a path-shaped tree — use BFS.

## 🔹 Optimization Path

* **Brute Force:** find the path by parent pointers per query — O(q · n).
* **Optimized Solution:** O(26 n + n log n) preprocessing, O(log n + 26) per query.
* **Further Improvements Possible?** Euler tour + sparse table gives O(1) LCA per query (Tarjan's offline LCA is near-linear in total); the 26-weight scan stays.

## 🔹 Solution Breakdown

* **Optimal Approach:** BFS from 0 for `parent`, `depth`, `cnt` (copy the parent's 27-slot row, add the edge weight). Build `up[j][v] = up[j−1][up[j−1][v]]`. LCA: lift the deeper node by the depth difference (bits), then lift both while their ancestors differ.
* **Why This Works?** The path `a → b` is `a → c` plus `c → b`; root-prefix counts subtract to exactly those two segments.
* **Edge Cases Considered:**
  * `a == b` → path length 0 → answer 0.
  * `n = 1` (no edges).

## 🔹 Tricks & Patterns Used

* **Path aggregate = f(a) + f(b) − 2·f(lca)** for anything additive along root paths (an edge-based quantity; for node values add back `val[lca]` once).
* **Small alphabet trick:** 26 counters per node instead of a general data structure.

## 🔹 Alternative Data Structures

* Heavy-light decomposition + segment tree — for path **updates** as well as queries; overkill here.

* **Time Complexity:** O(n (26 + log n) + q (log n + 26))
* **Space Complexity:** O(n (26 + log n))

## 🔹 Code Snippet (Brute Force)

```python
from collections import Counter
from typing import List


class Solution:
    def minOperationsQueries(self, n: int, edges: List[List[int]], queries: List[List[int]]) -> List[int]:
        adj = [[] for _ in range(n)]
        for u, v, w in edges:
            adj[u].append((v, w))
            adj[v].append((u, w))
        parent, weight_up, depth = [-1] * n, [0] * n, [0] * n
        parent[0], order = 0, [0]
        for v in order:
            for nxt, w in adj[v]:
                if parent[nxt] == -1:
                    parent[nxt], weight_up[nxt], depth[nxt] = v, w, depth[v] + 1
                    order.append(nxt)
        answer = []
        for a, b in queries:
            weights = []
            while a != b:
                if depth[a] < depth[b]:
                    a, b = b, a
                weights.append(weight_up[a])
                a = parent[a]
            answer.append(len(weights) - max(Counter(weights).values(), default=0))
        return answer
```

## 🔹 Code Snippet (Optimized)

```python
from typing import List

WEIGHTS = 26


class Solution:
    def minOperationsQueries(self, n: int, edges: List[List[int]], queries: List[List[int]]) -> List[int]:
        adj = [[] for _ in range(n)]
        for u, v, w in edges:
            adj[u].append((v, w))
            adj[v].append((u, w))

        log = max(1, n.bit_length())
        up = [[0] * n for _ in range(log)]
        depth = [0] * n
        cnt = [[0] * (WEIGHTS + 1) for _ in range(n)]  # cnt[v][w]: weight-w edges on root -> v
        seen, order = [False] * n, [0]
        seen[0] = True
        for v in order:
            for nxt, w in adj[v]:
                if not seen[nxt]:
                    seen[nxt] = True
                    up[0][nxt], depth[nxt] = v, depth[v] + 1
                    cnt[nxt] = cnt[v][:]
                    cnt[nxt][w] += 1
                    order.append(nxt)
        for j in range(1, log):
            prev = up[j - 1]
            up[j] = [prev[prev[v]] for v in range(n)]

        def lca(a: int, b: int) -> int:
            if depth[a] < depth[b]:
                a, b = b, a
            diff, j = depth[a] - depth[b], 0
            while diff:
                if diff & 1:
                    a = up[j][a]
                diff, j = diff >> 1, j + 1
            if a == b:
                return a
            for j in range(log - 1, -1, -1):
                if up[j][a] != up[j][b]:
                    a, b = up[j][a], up[j][b]
            return up[0][a]

        answer = []
        for a, b in queries:
            c = lca(a, b)
            length = depth[a] + depth[b] - 2 * depth[c]
            most = max(cnt[a][w] + cnt[b][w] - 2 * cnt[c][w] for w in range(1, WEIGHTS + 1))
            answer.append(length - most)
        return answer
```
