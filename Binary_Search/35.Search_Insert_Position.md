# 35. Search Insert Position

**🔗 Link:** [LeetCode 35](https://leetcode.com/problems/search-insert-position/)
**🟢 Status:** 🔄 Need Review


## 🔹 Problem Statement

Given a sorted array of distinct integers and a `target`, return the index of `target` if it is present. Otherwise return the index where it would have to be inserted to keep the array sorted. The algorithm must run in O(log n).

* **Example:** `nums = [1,3,5,6], target = 5` → `2`
* **Constraints:** `1 ≤ nums.length ≤ 10^4`; `-10^4 ≤ nums[i], target ≤ 10^4`; `nums` has distinct values sorted ascending.

## 🔹 Quick Breakdown

* **Difficulty Level:** Easy
* **Main Approach:** **Lower bound.** The answer is the first index `i` with `nums[i] ≥ target` — the index of `target` if present, otherwise where it would be inserted. If no such index exists, the answer is `n`.
* **Core Concept:** one boundary search answers both "found" and "not found"
* **When to Use This Pattern?** Insertion points, "how many elements are smaller than `x`", ceiling of `x` in a sorted array.
* **Mistakes to Avoid:**
  * Returning `-1` when `target` is missing — the problem wants the insertion index.
  * Using `hi = n − 1`: then `target` larger than everything can never return `n`.

## 🔹 Optimization Path

* **Brute Force:** scan left to right for the first `nums[i] ≥ target` — O(n).
* **Optimized Solution:** binary search on `[0, n)` — O(log n), as required.
* **Further Improvements Possible?** No.

## 🔹 Solution Breakdown

* **Optimal Approach:** `lo, hi = 0, n`; while `lo < hi`: `nums[mid] < target` → `lo = mid + 1`, else `hi = mid`; return `lo`.
* **Why This Works?** Values are distinct and sorted, so `nums[i] ≥ target` is false for a prefix and true for the rest; the loop shrinks `[lo, hi)` around that switch point while keeping "before `lo` is too small, from `hi` on is big enough".
* **Edge Cases Considered:**
  * `target` smaller than `nums[0]` → `0`.
  * `target` larger than `nums[-1]` → `n`.
  * Single element.

## 🔹 Tricks & Patterns Used

* **Half-open interval `[lo, hi)`** with `hi = n` makes "past the end" a normal answer.
* **`mid = (lo + hi) // 2`** with `lo < hi` never equals `hi`, so `nums[mid]` is always in range.

## 🔹 Code Snippet (Brute Force)

```python
from typing import List


class Solution:
    def searchInsert(self, nums: List[int], target: int) -> int:
        for i, value in enumerate(nums):
            if value >= target:
                return i
        return len(nums)
```

## 🔹 Code Snippet (Optimized)

```python
from typing import List


class Solution:
    def searchInsert(self, nums: List[int], target: int) -> int:
        lo, hi = 0, len(nums)  # hi = n so "after every element" is reachable
        while lo < hi:
            mid = (lo + hi) // 2
            if nums[mid] < target:
                lo = mid + 1
            else:
                hi = mid
        return lo
```
