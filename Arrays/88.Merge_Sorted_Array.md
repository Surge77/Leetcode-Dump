# 🔹 Problem Name: 88. Merge Sorted Array (Two Pointers, Easy)

**🔗 Link:** [LeetCode 88](https://leetcode.com/problems/merge-sorted-array/)
**🟢 Status:** 🔄 Need Review

## 🔹 Problem Statement

You get two arrays sorted in non-decreasing order, `nums1` and `nums2`, with `m` and `n` real elements. `nums1` has length `m + n`: its first `m` slots hold values and the last `n` are zero-filled spare room. Merge `nums2` into `nums1` in place so that `nums1` ends up as one sorted array; nothing is returned.

* **Example:** `nums1 = [1,2,3,0,0,0], m = 3, nums2 = [2,5,6], n = 3` → `[1,2,2,3,5,6]`
* **Constraints:** `nums1.length == m + n`, `nums2.length == n`, `0 ≤ m, n ≤ 200` (`1 ≤ m + n ≤ 200`), `-10⁹ ≤ nums1[i], nums2[j] ≤ 10⁹`

## 🔹 Quick Breakdown

* **Difficulty Level:** Easy
* **Main Approach:** **Merge from the back.** The `n` free slots sit at the end of `nums1`, so fill `nums1` right to left: compare the largest unplaced values `nums1[i]` and `nums2[j]` and write the bigger one at `k = i + j + 1`. Stop as soon as `nums2` is used up — whatever is left of `nums1` is already in place.
* **Core Concept:** write into the empty end of the buffer so no unread element is ever overwritten
* **When to Use This Pattern?** Merging two sorted sequences in place when the spare room is at the end of one of them; more generally, any in-place rewrite where writing from the front would clobber data you still need — fill from the side that is free.
* **Mistakes to Avoid:**
  * Merging from the front: every `nums2` value placed early forces shifting the rest of `nums1` right — O(m·n).
  * Looping `while i >= 0 and j >= 0` and forgetting the leftover `nums2` values (e.g. `m = 0`, or all of `nums2` smaller than `nums1[0]`).

## 🔹 Optimization Path

* **Brute Force:** copy `nums2` into the tail and sort — O((m + n) log(m + n)).
* **Optimized Solution:** three pointers from the back — O(m + n) time, O(1) extra space (the follow-up).
* **Further Improvements Possible?** No; every slot of the output is written once.

## 🔹 Solution Breakdown

* **Optimal Approach:** `i = m − 1`, `j = n − 1`, `k = m + n − 1`; while `j ≥ 0`, move the larger of `nums1[i]` (only if `i ≥ 0`) and `nums2[j]` to `nums1[k]` and step that pointer and `k` left.
* **Why This Works?** `k = i + j + 1`, so while `nums2` still has values (`j ≥ 0`) the write position is strictly right of `i` — a write never lands on an unread `nums1` value. Each step places the largest remaining value, which is exactly what the right-most open slot needs.
* **Edge Cases Considered:**
  * `m = 0` — every slot comes from `nums2`; `n = 0` — nothing to do.
  * Equal values — taking `nums2[j]` on a tie is fine, the values are identical.
  * Values down to −10⁹ — no sentinel is needed because `i ≥ 0` is checked explicitly.

## 🔹 Tricks & Patterns Used

* **Backward fill:** when the free space is at the end, write from the end.
* **Loop only on the source that must move:** leftovers of `nums1` are already home, so the loop condition is just `j ≥ 0`.

## 🔹 Alternative Data Structures

* A separate output array merged from the front, then copied back — O(m + n) extra space, the same merge step merge sort uses.
* `heapq.merge` — lazily merges any number of sorted iterables.

* **Time Complexity:** O(m + n)
* **Space Complexity:** O(1)

## 🔹 Code Snippet (Brute Force)

```python
from typing import List


class Solution:
    def merge(self, nums1: List[int], m: int, nums2: List[int], n: int) -> None:
        nums1[m:] = nums2  # slice assignment keeps the same list object, so the caller sees the result
        nums1.sort()
```

## 🔹 Code Snippet (Optimized)

```python
from typing import List


class Solution:
    def merge(self, nums1: List[int], m: int, nums2: List[int], n: int) -> None:
        i, j, k = m - 1, n - 1, m + n - 1
        while j >= 0:  # leftover nums1 values are already in their final slots
            if i >= 0 and nums1[i] > nums2[j]:
                nums1[k] = nums1[i]
                i -= 1
            else:
                nums1[k] = nums2[j]
                j -= 1
            k -= 1
```
