## 🔹 Problem Statement

Given a list of meeting time intervals `[start, end]`, return the minimum number of conference rooms needed so that every meeting gets a room and no two overlapping meetings share one. A room freed at time `t` can host a meeting starting at `t`. *(premium — paraphrased from memory, not checked against the official page)*

* **Example:** `intervals = [[0,30],[5,10],[15,20]]` → `2`
* **Constraints:** `1 ≤ intervals.length ≤ 10^4`; `0 ≤ start < end ≤ 10^6`

## 🔹 Quick Breakdown

* **Difficulty Level:** Medium
* **Main Approach:** **Sort by start + min-heap of end times.** Process meetings in start order. The heap holds the end time of every room in use; if the earliest-ending room is free by the time the new meeting starts (`heap[0] ≤ start`), reuse it (pop), then push the new end. The heap's peak size is the answer.
* **Core Concept:** rooms needed = maximum number of meetings running at the same instant
* **When to Use This Pattern?** "Minimum number of resources so no two overlapping jobs share one" — rooms, platforms, CPUs, cars; also "max overlap of intervals".
* **Mistakes to Avoid:**
  * Treating `end == start` as a conflict — a room freed at 10 can host a meeting starting at 10, so pop on `≤`.
  * Popping all finished rooms is fine too, but then the answer is the **max** heap size, not the final size.
  * Sorting by end time — start order is what makes the greedy valid.

## 🔹 Optimization Path

* **Brute Force:** the maximum overlap is reached at some meeting's start, so for each start count meetings with `s ≤ start < e` — O(n²).
* **Optimized Solution:** sort + heap — O(n log n).
* **Further Improvements Possible?** Two sorted arrays (starts, ends) with two pointers — same O(n log n) but no heap; or a difference array when times are small (≤ 10⁶).

## 🔹 Solution Breakdown

* **Optimal Approach:** `for start, end in sorted(intervals)`: if heap non-empty and `heap[0] ≤ start` → `heapreplace(heap, end)` else `heappush(heap, end)`. Answer: `len(heap)`.
* **Why This Works?** We only pop when a room is free, and we pop at most one per meeting, so the heap never shrinks — its final size equals its peak. When we push without popping, every room's end is `> start`, and every room's meeting started `≤ start`, so all of them plus the new one overlap at `start`: the count is a real lower bound and is achieved.
* **Edge Cases Considered:**
  * One meeting → 1.
  * Back-to-back meetings `[[1, 5], [5, 10]]` → 1.
  * All identical → `n`.

## 🔹 Tricks & Patterns Used

* **Heap of end times:** the heap top is "the room that frees up first" — the only one worth checking.
* **Chronological ordering:** two-pointer version — `ends` pointer advances when `starts[i] ≥ ends[j]` (room freed), else allocate a room.

## 🔹 Alternative Data Structures

* Event sweep: `+1` at start, `−1` at end, sort with ends before starts at equal times, track the running max.
* Difference array over time values (≤ 10⁶) — O(n + T).

## 🔹 Code Snippet (Brute Force)

```python
from typing import List


class Solution:
    def minMeetingRooms(self, intervals: List[List[int]]) -> int:
        return max((sum(1 for s, e in intervals if s <= start < e) for start, _ in intervals), default=0)
```

## 🔹 Code Snippet (Optimized)

```python
import heapq
from typing import List


class Solution:
    def minMeetingRooms(self, intervals: List[List[int]]) -> int:
        ends = []
        for start, end in sorted(intervals):
            if ends and ends[0] <= start:
                heapq.heapreplace(ends, end)  # reuse the room that freed up first
            else:
                heapq.heappush(ends, end)
        return len(ends)
```
