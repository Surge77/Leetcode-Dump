# 🔹 Problem Name: 233. Number of Digit One (Digit DP, Hard)

**🔗 Link:** [LeetCode 233](https://leetcode.com/problems/number-of-digit-one/)
**🟢 Status:** 🔄 Need Review

## 🔹 Quick Breakdown

* **Difficulty Level:** Hard
* **Main Approach:** Build numbers `0..n` digit by digit. State = `(position, ones so far, tight)`, where `tight` means "the prefix equals n's prefix, so the next digit is capped by n's digit".
* **Core Concept:** Digit DP
* **When to Use This Pattern?** "Count numbers in `[L, R]` (R up to 10¹⁸) whose digits satisfy a property" — digit sum, no repeated digits, contains 7, divisible by k. Answer for `[L, R]` = `f(R) - f(L-1)`.
* **Mistakes to Avoid:**
  * Looping over all numbers up to n — impossible for n = 10⁹.
  * Caching states while ignoring `tight` — tight and free branches have different digit ranges.

## 🔹 Optimization Path

* **Brute Force:** O(n · log n) — count '1' in each number.
* **Optimized Solution:** O(D² · 10), D = number of digits (about D · D · 2 states `(pos, ones, tight)`, 10 transitions each) — effectively constant since D ≤ 10.
* **Further Improvements Possible?** A per-position closed formula gives O(log n), but the digit-DP template generalises to every similar question.

## 🔹 Solution Breakdown

* **Optimal Approach:** `dfs(pos, ones, tight)`: try every digit `d` up to `limit = digits[pos] if tight else 9`; recurse with `ones + (d == 1)` and `tight and d == limit`; at the end return `ones`.
* **Why This Works?** Every number `≤ n` corresponds to exactly one root-to-leaf path in this digit tree (shorter numbers = leading zeros), and states with the same `(pos, ones, tight)` have identical sub-trees, so memo removes the repetition.
* **Edge Cases Considered:**
  * `n = 0` → 0.
  * `n` made of all 1s.
  * Powers of 10.

## 🔹 Tricks & Patterns Used

* **Tight flag** = prefix still equal to the upper bound.
* **Leading zeros** are harmless here (zeros are not ones); add a `started` flag when they matter (e.g., "no repeated digits").

## 🔹 Alternative Data Structures

* Positional formula: for each power `p`, count `high · p + min(max(low - p + 1, 0), p)` where `high`, `low` come from `n`.

## 🔹 Complexity Analysis

* **Time Complexity:** O(D² · 10), D = number of digits
* **Space Complexity:** O(D²)

## 🔹 Code Snippet (Optimized)

```python
from functools import lru_cache


class Solution:
    def countDigitOne(self, n: int) -> int:
        digits = list(map(int, str(n)))

        @lru_cache(maxsize=None)
        def dfs(pos: int, ones: int, tight: bool) -> int:
            if pos == len(digits):
                return ones
            limit = digits[pos] if tight else 9
            total = 0
            for d in range(limit + 1):
                total += dfs(pos + 1, ones + (d == 1), tight and d == limit)
            return total

        return dfs(0, 0, True)
```
