# 🔹 Problem Name: 167. Two Sum II - Input Array Is Sorted (Two Pointers, Medium)

**🔗 Link:** [LeetCode 167](https://leetcode.com/problems/two-sum-ii-input-array-is-sorted/)
**🟢 Status:** 🔄 Need Review

## 🔹 Problem Statement

You get a 1-indexed array sorted in non-decreasing order and a target. Find the two different positions whose values add up to the target and return them as `[index1, index2]` with `index1 < index2`. Exactly one solution exists, and you may only use constant extra space.

* **Example:** `numbers = [2,7,11,15], target = 9` → `[1,2]`
* **Constraints:** `2 ≤ numbers.length ≤ 3 · 10^4`; `−1000 ≤ numbers[i] ≤ 1000`; sorted non-decreasing; `−1000 ≤ target ≤ 1000`; exactly one solution

## 🔹 Quick Breakdown

* **Difficulty Level:** Medium
* **Main Approach:** **Opposite-end two pointers.** Start `lo = 0`, `hi = n − 1`. If `numbers[lo] + numbers[hi]` is too small, only moving `lo` right can grow it; if too big, only moving `hi` left can shrink it. Stop when it equals `target` and return the **1-indexed** pair.
* **Core Concept:** sortedness lets every comparison discard a whole row (or column) of candidate pairs
* **When to Use This Pattern?** A sorted array (or one you may sort) and a question about a pair whose sum/difference must hit, or get close to, a target — 3Sum, container-style problems, "count pairs with sum < k".
* **Mistakes to Avoid:**
  * Returning 0-indexed positions — the answer is `[lo + 1, hi + 1]`.
  * Using a hash map: correct, but O(n) extra space, which the problem explicitly asks you to avoid.
  * Letting `lo == hi`: the same element may not be used twice.

## 🔹 Optimization Path

* **Brute Force:** try every pair `i < j` — O(n²), 4.5·10⁸ pairs at `n = 3·10⁴`.
* **Optimized Solution:** two pointers — O(n) time, O(1) space.
* **Further Improvements Possible?** No; in the worst case every element must be looked at.

## 🔹 Solution Breakdown

* **Optimal Approach:** loop while `lo < hi`; compare the sum with `target` and move exactly one pointer.
* **Why This Works?** If `numbers[lo] + numbers[hi] < target`, then `numbers[lo]` plus any element at or left of `hi` is also too small, so `lo` is in no valid pair and can be dropped (symmetrically for `hi`). Each step discards one index without ever discarding the answer, and exactly one solution is guaranteed.
* **Edge Cases Considered:**
  * Negative numbers and duplicates (`[-1, 0]`, `[3, 3]` with target 6) — the argument above never assumes positivity or distinctness.
  * `n = 2` — the loop runs once.

## 🔹 Tricks & Patterns Used

* **Elimination argument:** each comparison proves one endpoint useless, giving a linear scan over an n² search space.

## 🔹 Alternative Data Structures

* Hash map `value → index` — O(n) time but O(n) space; works without sortedness.
* Binary search for `target − numbers[i]` for every `i` — O(n log n), O(1) space.

## 🔹 Complexity Analysis

* **Time Complexity:** O(n)
* **Space Complexity:** O(1)

## 🔹 Code Snippet (Brute Force)

```python
from typing import List


class Solution:
    def twoSum(self, numbers: List[int], target: int) -> List[int]:
        n = len(numbers)
        for i in range(n):
            for j in range(i + 1, n):
                if numbers[i] + numbers[j] == target:
                    return [i + 1, j + 1]
        return []
```

## 🔹 Code Snippet (Optimized)

```python
from typing import List


class Solution:
    def twoSum(self, numbers: List[int], target: int) -> List[int]:
        lo, hi = 0, len(numbers) - 1
        while lo < hi:
            total = numbers[lo] + numbers[hi]
            if total == target:
                return [lo + 1, hi + 1]
            if total < target:
                lo += 1  # numbers[lo] is too small even with the largest partner left
            else:
                hi -= 1
        return []
```
