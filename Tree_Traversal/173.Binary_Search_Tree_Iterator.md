# 🔹 Problem Name: 173. Binary Search Tree Iterator (Iterative Inorder, Medium)

**🔗 Link:** [LeetCode 173](https://leetcode.com/problems/binary-search-tree-iterator/)
**🟢 Status:** 🔄 Need Review

## 🔹 Problem Statement

Design `BSTIterator`, built from a BST's root, that walks the tree in sorted (in-order) order one value at a time. `next()` returns the next smallest value (calls are always valid) and `hasNext()` says whether any value remains. The follow-up wants average O(1) time per call with O(h) memory.

* **Example:** `BSTIterator([7,3,15,null,null,9,20])`, then `next()` → `3`, `next()` → `7`, `hasNext()` → `true`, `next()` → `9`
* **Constraints:** `1 ≤ nodes ≤ 10^5`, `0 ≤ Node.val ≤ 10^6`, at most `10^5` calls to `hasNext` and `next`

## 🔹 Quick Breakdown

* **Difficulty Level:** Medium
* **Main Approach:** **A paused in-order traversal.** Keep a stack of the nodes still waiting to be returned, smallest on top: initially the left spine of the root. `next()` pops the top node and pushes the left spine of its right subtree (its successor and the path to it); `hasNext()` is "stack not empty".
* **Core Concept:** the explicit stack of an iterative in-order traversal *is* the suspended recursion — stop after each output and resume on the next call
* **When to Use This Pattern?** Iterate a BST in sorted order on demand: k-th smallest with early exit, merging two BSTs in sorted order, two pointers over a BST (a forward and a reverse iterator, 653).
* **Mistakes to Avoid:**
  * Flattening the whole tree in the constructor: correct, but O(n) memory where the follow-up asks for O(h).
  * Pushing only `node.right` after a pop: the successor is the **leftmost** node of the right subtree, so push its whole left spine.
  * A recursive generator (`yield from`) on a 10⁵-node skewed BST → `RecursionError`.

## 🔹 Optimization Path

* **Brute Force:** collect all values with any traversal and sort them — O(n log n) construction, O(1) `next`, O(n) memory.
* **Optimized Solution:** left-spine stack — `next()` O(1) amortized (O(h) worst case for a single call), `hasNext()` O(1), O(h) memory.
* **Further Improvements Possible?** Morris threading gets O(1) extra memory, but the tree stays modified between calls — unsafe when the caller can read the tree meanwhile.

## 🔹 Solution Breakdown

* **Optimal Approach:** `push_left(node)`: while `node`, push it and go left. Constructor: `push_left(root)`. `next()`: `node = pop()`, `push_left(node.right)`, return `node.val`.
* **Why This Works?** In-order is left subtree → node → right subtree. Every node on the stack has its left subtree either empty or already returned, so the top is the smallest value not yet returned. After it come the nodes of its right subtree (starting with that subtree's leftmost node), and only then the ancestors still on the stack.
* **Amortized cost:** over a full iteration each node is pushed once and popped once — 2n stack operations across n calls to `next()`.
* **Edge Cases Considered:**
  * Single node.
  * Left chain of 10⁵ nodes: the constructor pushes all of them — still O(h), because `h = n`.
  * Right chain: the stack never holds more than one node.

## 🔹 Tricks & Patterns Used

* **"Push the left spine" helper:** the entire iterative in-order traversal fits in it plus one pop.
* **Amortized analysis by counting per-node operations:** one push and one pop per node, however unevenly they fall across calls.

## 🔹 Alternative Data Structures

* Sorted list built up front (the brute force) — simplest; fine when memory is not a concern.
* A generator driven by the same explicit stack — elegant, but `hasNext()` then needs a one-element look-ahead buffer.

## 🔹 Complexity Analysis

* **Time Complexity:** constructor O(h); `next()` O(1) amortized; `hasNext()` O(1)
* **Space Complexity:** O(h)

## 🔹 Code Snippet (Brute Force)

```python
from typing import Optional


class BSTIterator:
    def __init__(self, root: Optional[TreeNode]):
        values, stack = [], [root]
        while stack:
            node = stack.pop()
            if node:
                values.append(node.val)
                stack.append(node.left)
                stack.append(node.right)
        self.values = sorted(values)  # a BST's in-order sequence is its sorted sequence
        self.pos = 0

    def next(self) -> int:
        self.pos += 1
        return self.values[self.pos - 1]

    def hasNext(self) -> bool:
        return self.pos < len(self.values)
```

## 🔹 Code Snippet (Optimized)

```python
from typing import Optional


class BSTIterator:
    def __init__(self, root: Optional[TreeNode]):
        self.stack = []
        self._push_left_spine(root)

    def _push_left_spine(self, node: Optional[TreeNode]) -> None:
        while node:
            self.stack.append(node)
            node = node.left

    def next(self) -> int:
        node = self.stack.pop()  # its left subtree is already returned, so it is the smallest left
        self._push_left_spine(node.right)  # successor = leftmost node of the right subtree
        return node.val

    def hasNext(self) -> bool:
        return bool(self.stack)
```
