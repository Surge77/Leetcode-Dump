# 🔹 Problem Name: 525. Contiguous Array (Prefix Sum + Hash Map, Medium)

**🔗 Link:** [LeetCode 525](https://leetcode.com/problems/contiguous-array/)
**🟢 Status:** 🔄 Need Review

## 🔹 Problem Statement

Given a binary array `nums`, return the length of the longest contiguous subarray that contains the same number of `0`s and `1`s (`0` if there is none).

* **Example:** `nums = [0,1]` → `2`
* **Constraints:** `1 ≤ nums.length ≤ 10^5`, `nums[i]` is `0` or `1`

## 🔹 Quick Breakdown

* **Difficulty Level:** Medium
* **Main Approach:** **Map `0` to `-1`, then find the longest subarray with sum `0`.** Keep a running balance and store the **first** index where each balance occurred. When a balance repeats at index `i`, the stretch between the two positions has equal zeros and ones.
* **Core Concept:** equal prefix sums at two positions mean the slice between them sums to zero
* **When to Use This Pattern?** "Longest/shortest subarray with a target sum" — particularly after recasting a *balance* condition (equal 0s and 1s, equal `(` and `)`) into a signed sum.
* **Mistakes to Avoid:**
  * Overwriting the stored index on a repeat — keep the **first** occurrence so the subarray is as long as possible.
  * Forgetting the base case `{0: -1}`: it lets a subarray starting at index `0` count.
  * Counting `0`s and `1`s separately and comparing them for each pair of indices (O(n²)).

## 🔹 Optimization Path

* **Brute Force:** for each start, extend the end while maintaining a running balance, record the length whenever it is `0` — O(n²).
* **Optimized Solution:** one pass with a hash map `balance → first index` — O(n).
* **Further Improvements Possible?** No; every element must be read.

## 🔹 Solution Breakdown

* **Optimal Approach:** `balance = 0`, `first = {0: -1}`. For each index `i`: `balance += 1 if nums[i] else -1`. If `balance` is in `first`, `best = max(best, i - first[balance])`; otherwise `first[balance] = i`.
* **Why This Works?** `balance` after index `i` equals `(#ones − #zeros)` in `nums[0..i]`. If it is identical at `j < i`, then `nums[j+1..i]` has `#ones − #zeros = 0`, which is exactly "equal numbers of 0 and 1".
* **Edge Cases Considered:**
  * Whole array balanced → matched against the `-1` sentinel gives length `n`.
  * All ones or all zeros → no balance repeats, answer `0`.
  * A single element → answer `0`.

## 🔹 Tricks & Patterns Used

* **Value remapping:** `0 → -1` converts "equal counts" into "sum is zero".
* **Sentinel `{0: -1}`** for subarrays that start at the beginning.

## 🔹 Alternative Data Structures

* An array of size `2n + 1` indexed by `balance + n` instead of a dictionary — faster constant factor, same complexity.

## 🔹 Complexity Analysis

* **Time Complexity:** O(n)
* **Space Complexity:** O(n)

## 🔹 Code Snippet (Brute Force)

```python
from typing import List


class Solution:
    def findMaxLength(self, nums: List[int]) -> int:
        best = 0
        for start in range(len(nums)):
            balance = 0
            for end in range(start, len(nums)):
                balance += 1 if nums[end] else -1
                if balance == 0:
                    best = max(best, end - start + 1)
        return best
```

## 🔹 Code Snippet (Optimized)

```python
from typing import List


class Solution:
    def findMaxLength(self, nums: List[int]) -> int:
        first_seen = {0: -1}  # empty prefix: lets a subarray start at index 0
        balance = best = 0
        for i, bit in enumerate(nums):
            balance += 1 if bit else -1
            if balance in first_seen:
                best = max(best, i - first_seen[balance])
            else:
                first_seen[balance] = i  # keep the earliest index for the longest span
        return best
```
