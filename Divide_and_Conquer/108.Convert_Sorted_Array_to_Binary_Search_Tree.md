# 108. Convert Sorted Array to Binary Search Tree

**🔗 Link:** [LeetCode 108](https://leetcode.com/problems/convert-sorted-array-to-binary-search-tree/)
**🟢 Status:** 🔄 Need Review


## 🔹 Problem Statement

Given an array sorted in strictly increasing order, build a height-balanced binary search tree (the two subtrees of every node differ in height by at most one) that contains exactly those values. Any valid balanced tree is accepted.

* **Example:** `nums = [-10,-3,0,5,9]` → `[0,-3,9,-10,null,5]` (`[0,-10,5,null,-3,null,9]` is also valid)
* **Constraints:** `1 ≤ nums.length ≤ 10^4`, `-10^4 ≤ nums[i] ≤ 10^4`, strictly increasing

## 🔹 Quick Breakdown

* **Difficulty Level:** Easy
* **Main Approach:** **Pick the middle as root, recurse on both halves.** The middle element of `nums[lo..hi]` becomes the root; the left half builds the left subtree and the right half the right subtree. Halves differ in size by at most one, so the tree is height-balanced.
* **Core Concept:** an in-order traversal of a BST is sorted, so any split point works for the BST property — the **middle** is what keeps it balanced
* **When to Use This Pattern?** Building a balanced tree from sorted data (array, linked list, or an in-order traversal), rebalancing a BST.
* **Mistakes to Avoid:**
  * Slicing `nums[:mid]` / `nums[mid + 1:]` at every level: correct, but O(n log n) time and extra copies — pass indices instead.
  * Inserting the elements one by one in sorted order: produces a linked-list-shaped tree of height n.

## 🔹 Optimization Path

* **Brute Force:** same recursion but slicing new lists at each level — O(n log n) time.
* **Optimized Solution:** recursion on index bounds — O(n) time.
* **Further Improvements Possible?** No; every element needs its own node.

## 🔹 Solution Breakdown

* **Optimal Approach:** `build(lo, hi)` returns `None` if `lo > hi`, else creates `TreeNode(nums[mid])` with `mid = (lo + hi) // 2` and children `build(lo, mid − 1)`, `build(mid + 1, hi)`.
* **Why This Works?** Everything left of `mid` is smaller and everything right is larger (strictly increasing input), so the BST property holds. By induction, subtree sizes differ by at most one at every node, which bounds height differences by one.
* **Edge Cases Considered:**
  * `n = 1` → a single node.
  * Even length — either middle works; the answer is not unique (LeetCode accepts any balanced BST).
  * Recursion depth is only ⌈log₂(10⁴ + 1)⌉ = 14, so recursion is safe here.

## 🔹 Code Snippet (Brute Force)

```python
from typing import List, Optional


class Solution:
    def sortedArrayToBST(self, nums: List[int]) -> Optional[TreeNode]:
        if not nums:
            return None
        mid = len(nums) // 2
        return TreeNode(nums[mid], self.sortedArrayToBST(nums[:mid]), self.sortedArrayToBST(nums[mid + 1:]))
```

## 🔹 Code Snippet (Optimized)

```python
from typing import List, Optional


class Solution:
    def sortedArrayToBST(self, nums: List[int]) -> Optional[TreeNode]:
        def build(lo: int, hi: int) -> Optional[TreeNode]:
            if lo > hi:
                return None
            mid = (lo + hi) // 2  # middle keeps both halves within one element of each other
            return TreeNode(nums[mid], build(lo, mid - 1), build(mid + 1, hi))

        return build(0, len(nums) - 1)
```
