# 120. Triangle

**🔗 Link:** [LeetCode 120](https://leetcode.com/problems/triangle/)
**🟢 Status:** 🔄 Need Review


## 🔹 Problem Statement

A triangle is given as a list of rows, row `i` having `i + 1` numbers. Walk from the top to the bottom row; from index `i` you may step to index `i` or `i + 1` of the next row. Return the smallest possible sum along such a walk.

* **Example:** `triangle = [[2],[3,4],[6,5,7],[4,1,8,3]]` → `11`
* **Constraints:** `1 ≤ triangle.length ≤ 200`; `−10⁴ ≤ triangle[i][j] ≤ 10⁴`.

## 🔹 Quick Breakdown

* **Difficulty Level:** Medium
* **Main Approach:** **Bottom-up DP.** Start with the last row; for each row going up, `dp[c] = triangle[r][c] + min(dp[c], dp[c+1])`. The answer ends up in `dp[0]`.
* **Core Concept:** the best path from `(r, c)` down only depends on the best paths from its two children `(r+1, c)` and `(r+1, c+1)`.
* **When to Use This Pattern?** Minimum / maximum path through a layered structure where each node has a few fixed successors (triangles, falling paths in a matrix).
* **Mistakes to Avoid:**
  * Greedy: always stepping to the smaller child — a small value now can lead into a row of huge values.
  * Going top-down, then forgetting the answer is `min` of the whole last row (bottom-up avoids that: the top has a single cell).
  * Values can be negative (`-10⁴…10⁴`), so do not seed with `0` or prune on sign.

## 🔹 Optimization Path

* **Brute Force:** recursion over every path — `2^(n-1)` paths, O(2^n).
* **Optimized Solution:** each of the `n(n+1)/2` cells is solved once — O(n²) time.
* **Further Improvements Possible?** The follow-up asks for O(n) extra space: one array the size of the last row, overwritten from left to right as we move up.

## 🔹 Solution Breakdown

* **Optimal Approach:** `dp = list(triangle[-1])`; for `r` from `n-2` down to `0`, for `c` in `0..r`: `dp[c] = triangle[r][c] + min(dp[c], dp[c+1])`.
* **Why This Works?** Any path from `(r, c)` takes `triangle[r][c]` and then continues from one of the two children, and the best continuation from a child does not depend on how we reached it. Updating left to right is safe because `dp[c]` is written only after `dp[c]` and `dp[c+1]` (still from the row below) were read, and `dp[c+1]` is not written until the next step.
* **Edge Cases Considered:**
  * One row → that single value (can be negative, e.g. `[[-10]]` → `-10`).
  * Negative numbers deep in the triangle make the greedy choice wrong.

## 🔹 Tricks & Patterns Used

* **Solve toward the side with one cell:** bottom-up ends at the apex, so no final `min` over a row.
* **Reuse the last row's length** as the rolling array — copied, so the input is not mutated.

## 🔹 Alternative Data Structures

* Top-down memoised recursion on `(r, c)` — O(n²) time and space (depth `n ≤ 200`, safe in Python).
* In-place update of `triangle` — O(1) extra space, but it mutates the caller's input.

## 🔹 Complexity Analysis

* **Time Complexity:** O(n²) — one visit per cell
* **Space Complexity:** O(n)

## 🔹 Code Snippet (Brute Force)

```python
from typing import List


class Solution:
    def minimumTotal(self, triangle: List[List[int]]) -> int:
        def best(r: int, c: int) -> int:
            if r == len(triangle) - 1:
                return triangle[r][c]
            return triangle[r][c] + min(best(r + 1, c), best(r + 1, c + 1))

        return best(0, 0)
```

## 🔹 Code Snippet (Optimized)

```python
from typing import List


class Solution:
    def minimumTotal(self, triangle: List[List[int]]) -> int:
        dp = list(triangle[-1])  # copy: best path from each cell of the last row is the cell itself
        for r in range(len(triangle) - 2, -1, -1):
            for c in range(r + 1):
                dp[c] = triangle[r][c] + min(dp[c], dp[c + 1])
        return dp[0]
```
