# 🔹 Problem Name: 99. Recover Binary Search Tree (Morris Inorder Traversal, Medium)

**🔗 Link:** [LeetCode 99](https://leetcode.com/problems/recover-binary-search-tree/)
**🟢 Status:** 🔄 Need Review

## 🔹 Quick Breakdown

* **Difficulty Level:** Medium
* **Main Approach:** **Inorder finds the inversions.** The inorder sequence of a BST is sorted; swapping two values creates either one adjacent inversion (the swapped nodes are neighbours in inorder) or two. The first bad node is the **larger** element of the first inversion, the second is the **smaller** element of the last inversion. Swap their values back. Morris traversal does the walk with O(1) extra space.
* **Core Concept:** BST ⇔ sorted inorder; a single swap in a sorted array is detectable from its descents
* **When to Use This Pattern?** Anything that needs "the previous node in sorted order" while walking a BST — validate BST, minimum difference, kth smallest, mode in BST — especially when the follow-up asks for O(1) space.
* **Mistakes to Avoid:**
  * Taking the smaller element of the *first* inversion as the second node — wrong when the swapped nodes are not adjacent (`[1,2,3,4,5] → [1,4,3,2,5]` has inversions `4>3` and `3>2`; the answer is `4` and `2`).
  * Stopping after the first inversion — adjacent swaps produce only one inversion, non-adjacent swaps produce two; always keep scanning and overwrite `second`.
  * Recursive inorder on a 1000-node path: depth 1000 hits Python's default recursion limit.
  * Breaking out of a Morris walk early — the temporary threads would stay in the tree.

## 🔹 Optimization Path

* **Brute Force:** collect inorder values, sort them, write them back in inorder — O(n log n) time, O(n) space.
* **Better:** iterative inorder with a `prev` pointer, record the two bad nodes — O(n) time, O(h) stack.
* **Optimized Solution:** the same scan with Morris traversal — O(n) time, O(1) space (the follow-up).
* **Further Improvements Possible?** No; every node must be inspected.

## 🔹 Solution Breakdown

* **Optimal Approach:** Morris inorder: if `cur` has no left child, visit it and go right. Otherwise find its inorder predecessor (rightmost node of the left subtree); if the predecessor's `right` is empty, thread it to `cur` and go left; if it already points to `cur`, cut the thread, visit `cur`, go right. "Visit" = compare with `prev`: on `prev.val > cur.val`, set `first = prev` if unset and always `second = cur`.
* **Why This Works?** Swapping `a < b` at inorder positions `i < j` makes position `i` too big and position `j` too small. If `j = i + 1` that is one descent `(b, a)`; otherwise there are two descents, `(b, x)` at `i` and `(y, a)` at `j − 1`. In both cases `first` = left element of the first descent and `second` = right element of the last one.
* **Edge Cases Considered:**
  * Two nodes only (`n = 2`) — one descent, `first` and `second` from the same pair.
  * Swapped root and a leaf — Morris still visits every node in order.
  * Values at the int range limits — only comparisons, no arithmetic.

## 🔹 Tricks & Patterns Used

* **Morris threading:** borrow the empty `right` pointer of the predecessor as a return link instead of a stack; each edge is walked at most a constant number of times.
* **Fix by value swap:** the tree's shape is already correct, so swapping two `val`s repairs it without relinking.

## 🔹 Alternative Data Structures

* Explicit stack inorder — O(h) space, simpler and harder to get wrong under pressure.
* Recursive inorder with `nonlocal prev` — fine for balanced trees, needs `sys.setrecursionlimit` for a 1000-node path.

## 🔹 Complexity Analysis

* **Time Complexity:** O(n) — each edge is traversed at most twice by the predecessor search
* **Space Complexity:** O(1) extra

## 🔹 Code Snippet (Brute Force)

```python
from typing import List, Optional


class Solution:
    def recoverTree(self, root: Optional[TreeNode]) -> None:
        nodes: List[TreeNode] = []
        stack, cur = [], root
        while stack or cur:
            while cur:
                stack.append(cur)
                cur = cur.left
            cur = stack.pop()
            nodes.append(cur)
            cur = cur.right
        # the correct BST holds the same values, just in sorted inorder
        for node, val in zip(nodes, sorted(node.val for node in nodes)):
            node.val = val
```

## 🔹 Code Snippet (Optimized)

```python
from typing import Optional


class Solution:
    def recoverTree(self, root: Optional[TreeNode]) -> None:
        first = second = prev = None
        cur = root
        while cur:
            if cur.left:
                pred = cur.left
                while pred.right and pred.right is not cur:
                    pred = pred.right
                if pred.right is None:
                    pred.right = cur  # thread back so we can return without a stack
                    cur = cur.left
                    continue
                pred.right = None  # left subtree done: restore the original shape
            if prev and prev.val > cur.val:
                if first is None:
                    first = prev
                second = cur  # keep overwriting: a non-adjacent swap has a second descent
            prev = cur
            cur = cur.right
        first.val, second.val = second.val, first.val
```
