# 503. Next Greater Element II

**🔗 Link:** [LeetCode 503](https://leetcode.com/problems/next-greater-element-ii/)
**🟢 Status:** 🔄 Need Review


## 🔹 Problem Statement

You get an array that is treated as circular, so after the last element the search for a larger value wraps around to the first. For every position, return the first value larger than it met when walking forward (with wrap-around), or `-1` if no such value exists.

* **Example:** `nums = [1,2,1]` → `[2,-1,2]`
* **Constraints:** `1 ≤ nums.length ≤ 10⁴`, `−10⁹ ≤ nums[i] ≤ 10⁹`

## 🔹 Quick Breakdown

* **Difficulty Level:** Medium
* **Main Approach:** **Monotonic stack over the array walked twice.** The array is circular, so iterate `i` from `0` to `2n − 1` and read `nums[i % n]`. Keep a stack of indices whose answer is unknown, with decreasing values; a larger value pops them and becomes their answer. Push indices only during the first lap — the second lap just resolves the leftovers.
* **Core Concept:** "circular" = unroll the array once (conceptually `nums + nums`) without copying it
* **When to Use This Pattern?** Next greater / smaller in a circular array, wrap-around windows, ring buffers.
* **Mistakes to Avoid:**
  * Pushing during the second lap too — harmless but doubles the work; answers must still go to `i % n`.
  * Using values as keys — duplicates are allowed here, so store indices.
  * Expecting the maximum to find an answer: it stays −1 (so do its duplicates).

## 🔹 Optimization Path

* **Brute Force:** for each `i`, scan `nums[(i + 1) % n], nums[(i + 2) % n], …` for up to `n − 1` steps — O(n²).
* **Optimized Solution:** two laps with a monotonic stack — O(n).
* **Further Improvements Possible?** No; O(n) is optimal.

## 🔹 Solution Breakdown

* **Optimal Approach:** `res = [-1] * n`; for `i in range(2n)`: `x = nums[i % n]`; `while stack and nums[stack[-1]] < x: res[stack.pop()] = x`; `if i < n: stack.append(i)`.
* **Why This Works?** After the first lap the stack holds the indices with no greater element to their right. Walking the array again presents, in order, the elements that come after them circularly; the first larger one pops each of them, which is exactly its circular next greater element.
* **Edge Cases Considered:**
  * `n = 1` → `[-1]`.
  * All equal → all −1 (strictly greater is required).

## 🔹 Code Snippet (Brute Force)

```python
from typing import List


class Solution:
    def nextGreaterElements(self, nums: List[int]) -> List[int]:
        n = len(nums)
        result = []
        for i in range(n):
            result.append(next((nums[(i + step) % n] for step in range(1, n)
                                if nums[(i + step) % n] > nums[i]), -1))
        return result
```

## 🔹 Code Snippet (Optimized)

```python
from typing import List


class Solution:
    def nextGreaterElements(self, nums: List[int]) -> List[int]:
        n = len(nums)
        result = [-1] * n
        stack = []  # indices still waiting, values decreasing
        for i in range(2 * n):
            x = nums[i % n]
            while stack and nums[stack[-1]] < x:
                result[stack.pop()] = x
            if i < n:  # the second lap only resolves what the first lap left
                stack.append(i)
        return result
```
