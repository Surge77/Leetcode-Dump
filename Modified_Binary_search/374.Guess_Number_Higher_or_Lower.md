# 🔹 Problem Name: 374. Guess Number Higher or Lower (Binary Search, Easy)

**🔗 Link:** [LeetCode 374](https://leetcode.com/problems/guess-number-higher-or-lower/)
**🟢 Status:** 🔄 Need Review

## 🔹 Problem Statement

A hidden number between `1` and `n` has been picked. You can call `guess(num)`, which tells you whether your guess is too high (`-1`), too low (`1`) or correct (`0`). Return the picked number.

* **Example:** `n = 10, pick = 6` → `6`
* **Constraints:** `1 ≤ n ≤ 2^31 - 1`; `1 ≤ pick ≤ n`.

## 🔹 Quick Breakdown

* **Difficulty Level:** Easy
* **Main Approach:** **Binary search driven by an oracle.** `guess(num)` returns `-1` if `num` is **higher** than the pick, `1` if it is **lower**, and `0` if correct. Probe the midpoint and discard the half the oracle rules out.
* **Core Concept:** the API's three-way answer is the comparison result of a sorted-array binary search
* **When to Use This Pattern?** Searching a known range with a comparator you cannot inspect, only call.
* **Mistakes to Avoid:**
  * Reading the sign backwards: `-1` means *your guess is too big* (the pick is lower), so move `hi = mid - 1`.
  * `(lo + hi) // 2` overflowing in fixed-width languages at `n ≈ 2³¹`.
  * Looping `while lo < hi` with `hi = mid - 1` — use `while lo <= hi` when you exclude `mid`.

## 🔹 Optimization Path

* **Brute Force:** guess `1, 2, 3, …` — up to `n` API calls.
* **Optimized Solution:** binary search — at most 31 calls for `n ≤ 2³¹ - 1`.
* **Further Improvements Possible?** No, `log n` is optimal for a comparison oracle.

## 🔹 Solution Breakdown

* **Optimal Approach:** `lo, hi = 1, n`; `mid = lo + (hi - lo) // 2`; `0` → return; `-1` → `hi = mid - 1`; `1` → `lo = mid + 1`.
* **Why This Works?** The result of `guess` is monotone in the guess, so each probe eliminates `mid` and everything on the wrong side. The pick always stays inside `[lo, hi]`, which shrinks until a probe hits it.
* **Edge Cases Considered:**
  * `n = 1` → the only guess is correct.
  * Pick equals `1` or `n` → the window collapses toward that end.
  * The pick is guaranteed to be in `[1, n]`, so the loop always returns.

## 🔹 Tricks & Patterns Used

* **Three-way comparator:** translate the oracle's sign into which bound to move.
* **Overflow-safe midpoint** `lo + (hi - lo) // 2`.

## 🔹 Alternative Data Structures

* None; the search space is just the integer range `[1, n]`, never materialised.

* **Space Complexity:** O(1)

## 🔹 Code Snippet (Brute Force)

```python
# guess(num: int) -> int is provided by LeetCode
class Solution:
    def guessNumber(self, n: int) -> int:
        for num in range(1, n + 1):
            if guess(num) == 0:
                return num
        return -1
```

## 🔹 Code Snippet (Optimized)

```python
# guess(num: int) -> int is provided by LeetCode
class Solution:
    def guessNumber(self, n: int) -> int:
        lo, hi = 1, n
        while lo <= hi:
            mid = lo + (hi - lo) // 2
            verdict = guess(mid)
            if verdict == 0:
                return mid
            if verdict == -1:  # -1 means our guess is higher than the pick
                hi = mid - 1
            else:
                lo = mid + 1
        return -1
```
