# 61. Rotate List

**🔗 Link:** [LeetCode 61](https://leetcode.com/problems/rotate-list/)
**🟢 Status:** 🔄 Need Review


## 🔹 Problem Statement

Rotate a linked list to the right by `k` places, so the last `k` nodes move to the front, and return the new head. `k` can be far larger than the list length.

* **Example:** `head = [1,2,3,4,5], k = 2` → `[4,5,1,2,3]`
* **Constraints:** `0 ≤ n ≤ 500`; `-100 ≤ Node.val ≤ 100`; `0 ≤ k ≤ 2·10^9`.

## 🔹 Quick Breakdown

* **Difficulty Level:** Medium
* **Main Approach:** **Close the ring, cut it in the right place.** One pass finds the length `n` and the tail. Rotating by `k` is the same as rotating by `k % n`; if that is 0, return `head`. Otherwise link `tail.next = head` and walk `n − k − 1` steps from `head` to the new tail; the node after it is the new head, and cutting there opens the ring.
* **Core Concept:** a rotation of a list is a cut of the circular list — only two pointers change
* **When to Use This Pattern?** Cyclic shifts of a sequence you cannot index (linked lists), "move the last `k` nodes to the front".
* **Mistakes to Avoid:**
  * Rotating one step at a time `k` times: `k` goes up to 2·10⁹.
  * Forgetting `k % n` — and dividing by zero on an empty list.
  * Leaving the ring closed when `k % n == 0` (return before linking, or cut afterwards).

## 🔹 Optimization Path

* **Brute Force:** `k % n` single-step rotations, each walking to the second-last node and moving the tail to the front — O(n · (k mod n)) = O(n²).
* **Optimized Solution:** length + ring + one cut — O(n).
* **Further Improvements Possible?** No; finding the length already takes a full pass.

## 🔹 Solution Breakdown

* **Optimal Approach:** count `n` while walking to `tail`; `k %= n`; if `k == 0` return `head`; `tail.next = head`; `new_tail` = node `n − k − 1` steps from `head`; `new_head = new_tail.next`; `new_tail.next = None`.
* **Why This Works?** After rotating right by `k`, the last `k` nodes come first, so the new head is node index `n − k` and the new tail is index `n − k − 1`; in the ring every other link stays the same.
* **Edge Cases Considered:**
  * Empty list or a single node → returned unchanged.
  * `k` a multiple of `n` → unchanged.
  * `k > n` (example: `[0,1,2]`, `k = 4` → `[2,0,1]`).

## 🔹 Tricks & Patterns Used

* **Reduce `k` modulo the period:** rotations by `n` are the identity.
* **Ring trick:** making the list circular turns "move the tail block to the front" into "cut at one place".

## 🔹 Alternative Data Structures

* Copy node references into an array and relink `arr[n−k:] + arr[:n−k]` — O(n) extra space.
* Two pointers `k` apart (after `k %= n`) to find the new tail without a second count.

## 🔹 Complexity Analysis

* **Time Complexity:** O(n)
* **Space Complexity:** O(1)

## 🔹 Code Snippet (Brute Force)

```python
from typing import Optional


class Solution:
    def rotateRight(self, head: Optional[ListNode], k: int) -> Optional[ListNode]:
        if head is None or head.next is None:
            return head
        n, node = 0, head
        while node:
            n += 1
            node = node.next
        for _ in range(k % n):  # without the modulo, k = 2·10⁹ steps
            before_tail = head
            while before_tail.next.next:
                before_tail = before_tail.next
            tail = before_tail.next
            before_tail.next = None
            tail.next = head
            head = tail
        return head
```

## 🔹 Code Snippet (Optimized)

```python
from typing import Optional


class Solution:
    def rotateRight(self, head: Optional[ListNode], k: int) -> Optional[ListNode]:
        if head is None:
            return None
        n, tail = 1, head
        while tail.next:
            n += 1
            tail = tail.next
        k %= n
        if k == 0:
            return head
        tail.next = head  # close the ring; exactly one link gets cut below
        new_tail = head
        for _ in range(n - k - 1):
            new_tail = new_tail.next
        new_head = new_tail.next
        new_tail.next = None
        return new_head
```
