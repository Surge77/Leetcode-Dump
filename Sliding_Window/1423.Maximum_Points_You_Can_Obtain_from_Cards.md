# 🔹 Problem Name: 1423. Maximum Points You Can Obtain from Cards (Sliding Window, Medium)

**🔗 Link:** [LeetCode 1423](https://leetcode.com/problems/maximum-points-you-can-obtain-from-cards/)
**🟢 Status:** 🔄 Need Review

## 🔹 Quick Breakdown

* **Difficulty Level:** Medium
* **Main Approach:** **Fixed-size window over the ends.** Any choice takes `i` cards from the left and `k − i` from the right. Start with the first `k` cards, then move one card at a time from the left end to the right end, keeping the best sum.
* **Core Concept:** taking from both ends = leaving a contiguous block of `n − k` in the middle
* **When to Use This Pattern?** "Pick from either end, K times" with no interaction between picks — the result only depends on how many came from each side.
* **Mistakes to Avoid:**
  * Greedily taking the larger end each turn — `[3, 100, 1, 1, 4]`, `k = 2`: greedy takes 4 then 3 (7), but 3 + 100 = 103.
  * Memoised recursion over (taken from left, taken from right): O(k²) states for a problem that only has `k + 1` distinct outcomes.

## 🔹 Optimization Path

* **Brute Force:** for each split `i` in `0..k`, sum `i` left cards and `k − i` right cards from scratch — O(k²), 10¹⁰ at `k = 10⁵`.
* **Optimized Solution:** slide the split, updating the sum in O(1) — O(k).
* **Further Improvements Possible?** Equivalent view: minimise the sum of a window of size `n − k` and subtract it from the total — O(n).

## 🔹 Solution Breakdown

* **Optimal Approach:** `total = sum(cardPoints[:k])`; for `i` from 1 to `k`, `total += cardPoints[-i] − cardPoints[k − i]`; keep the max.
* **Why This Works?** The `k − i + 1` cards that are not picked form one contiguous block, so every valid selection is "a prefix of length `i` plus a suffix of length `k − i`". The loop visits all `k + 1` of them, each derived from the previous one by swapping one card.
* **Edge Cases Considered:**
  * `k = n`: every card is taken; all splits give the total.
  * `k = 1`: the larger of the two ends.

## 🔹 Tricks & Patterns Used

* **Complement window:** "take from both ends" ⇔ "leave a contiguous middle".
* **Swap one card per step:** O(1) update instead of re-summing.

## 🔹 Alternative Data Structures

* Prefix sums `pre` and `suf`: answer `max(pre[i] + suf[k − i])` — same O(k), O(k) extra space.

## 🔹 Complexity Analysis

* **Time Complexity:** O(k)
* **Space Complexity:** O(1)

## 🔹 Code Snippet (Brute Force)

```python
from typing import List


class Solution:
    def maxScore(self, cardPoints: List[int], k: int) -> int:
        n = len(cardPoints)
        best = 0
        for from_left in range(k + 1):
            from_right = k - from_left
            best = max(best, sum(cardPoints[:from_left]) + sum(cardPoints[n - from_right:]))
        return best
```

## 🔹 Code Snippet (Optimized)

```python
from typing import List


class Solution:
    def maxScore(self, cardPoints: List[int], k: int) -> int:
        total = best = sum(cardPoints[:k])
        for i in range(1, k + 1):
            # give back the i-th card from the left, take the i-th card from the right
            total += cardPoints[-i] - cardPoints[k - i]
            best = max(best, total)
        return best
```
