# 🔹 Problem Name: 222. Count Complete Tree Nodes (Tree Binary Search, Medium)

**🔗 Link:** [LeetCode 222](https://leetcode.com/problems/count-complete-tree-nodes/)
**🟢 Status:** 🔄 Need Review

## 🔹 Quick Breakdown

* **Difficulty Level:** Medium
* **Main Approach:** **Use completeness to skip whole perfect subtrees.** At `node`, let `dl` and `dr` be the left-spine depths of `node.left` and `node.right` (in a complete tree the left spine is the height). If `dl == dr`, the bottom level reaches into the right subtree, so the **left** subtree is perfect: it holds `2^dl − 1` nodes; add those plus `node` (`2^dl`) and move right. Otherwise `dl == dr + 1`: the **right** subtree is perfect with height `dr`; add `2^dr` and move left. One level down per step.
* **Core Concept:** binary search for where the bottom level ends — each O(log n) height comparison settles one half of the tree by formula
* **When to Use This Pattern?** Complete or perfect binary trees (heaps), "count / find the last node in sub-linear time", any structure where comparing two heights tells you which half is full.
* **Mistakes to Avoid:**
  * A plain traversal is O(n): accepted, but it ignores the required "less than O(n)".
  * Measuring a subtree's height along its **right** spine — in a complete tree only the left spine is guaranteed to reach the bottom level.
  * Off by one: a perfect tree with `h` levels has `2^h − 1` nodes, so `1 << h` counts it **plus** its parent.

## 🔹 Optimization Path

* **Brute Force:** count every node with a DFS — O(n).
* **Optimized Solution:** height-comparison descent — O(log² n): about log n steps, each walking an O(log n) spine.
* **Further Improvements Possible?** Not in practice; the other standard method (binary search over the bottom level's positions) is also O(log² n) — about 16² = 256 steps for 5·10⁴ nodes.

## 🔹 Solution Breakdown

* **Optimal Approach:** `count = 0`, `node = root`. While `node`: compute `dl`, `dr`; if equal, `count += 1 << dl` and `node = node.right`; else `count += 1 << dr` and `node = node.left`.
* **Why This Works?** Both children of a node in a complete tree are complete. Equal spine depths mean the bottom level continues past the left subtree into the right one, so the left subtree's last level is full. A deeper left spine means the bottom level stops inside the left subtree, so the right subtree is full but one level shorter. Either way one child is counted by formula and only the other is explored.
* **Edge Cases Considered:**
  * Empty tree → 0.
  * Single node: both depths are 0, so it adds `2^0 = 1`.
  * Perfect tree: equal depths at every step; the walk goes right all the way down.

## 🔹 Tricks & Patterns Used

* **Left-spine depth = height** of a complete tree, found in O(log n) without visiting the rest.
* **Perfect-tree size:** `h` levels → `2^h − 1` nodes.
* **Heap indexing:** with 1-based index `i`, children are `2i` and `2i + 1`; the bits of `i` after the leading 1 spell the path (0 = left, 1 = right). The bottom-level binary search uses this to test "does position `i` exist?" in O(log n).

## 🔹 Alternative Data Structures

* Binary search over bottom-level positions `0 .. 2^(h−1) − 1` with an `exists(i)` walk from the root — O(log² n).
* Recursion: if the leftmost and rightmost depths match, return `2^h − 1`; else `1 + count(left) + count(right)` — also O(log² n), since at most one child per level is non-perfect.

## 🔹 Complexity Analysis

* **Time Complexity:** O(log² n)
* **Space Complexity:** O(1)

## 🔹 Code Snippet (Brute Force)

```python
from typing import Optional


class Solution:
    def countNodes(self, root: Optional[TreeNode]) -> int:
        if not root:
            return 0
        return 1 + self.countNodes(root.left) + self.countNodes(root.right)
```

## 🔹 Code Snippet (Optimized)

```python
from typing import Optional


class Solution:
    def countNodes(self, root: Optional[TreeNode]) -> int:
        def spine_depth(node: Optional[TreeNode]) -> int:
            depth = 0
            while node:  # in a complete tree the leftmost path reaches the bottom level
                depth += 1
                node = node.left
            return depth

        count, node = 0, root
        while node:
            left_depth, right_depth = spine_depth(node.left), spine_depth(node.right)
            if left_depth == right_depth:
                count += 1 << left_depth  # perfect left subtree (2^d - 1) plus `node`
                node = node.right
            else:
                count += 1 << right_depth  # perfect right subtree, one level shorter, plus `node`
                node = node.left
        return count
```
