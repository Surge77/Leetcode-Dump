# 🔹 Problem Name: 518. Coin Change II (Dynamic Programming, Medium)

**🔗 Link:** [LeetCode 518](https://leetcode.com/problems/coin-change-ii/)
**🟢 Status:** 🔄 Need Review

## 🔹 Quick Breakdown

* **Difficulty Level:** Medium
* **Main Approach:** Count combinations: loop coins on the **outside**, amounts on the inside, `dp[a] += dp[a - c]`.
* **Core Concept:** Unbounded knapsack (counting)
* **When to Use This Pattern?** "How many ways to make a total" where order does **not** matter.
* **Mistakes to Avoid:**
  * Swapping the loops — amounts outside counts **permutations** (`1+2` and `2+1` twice); that is problem 377.
  * Forgetting `dp[0] = 1` (one way to make zero: take nothing).

## 🔹 Optimization Path

* **Brute Force:** Exponential recursion over (coin index, remaining amount).
* **Optimized Solution:** O(amount · coins) time, O(amount) space.
* **Further Improvements Possible?** No.

## 🔹 Solution Breakdown

* **Optimal Approach:** After processing the first `k` coin types, `dp[a]` = ways to make `a` using only those types.
* **Why This Works?** Fixing coin order (outer loop) means every combination is built in exactly one order — non-decreasing coin index — so nothing is counted twice.
* **Edge Cases Considered:**
  * `amount = 0` → 1.
  * No coin divides the amount → 0.

## 🔹 Pattern Recognition

* **Belongs To:** DP — Unbounded Knapsack (counting)
* **Common Problems Using This:**
  * 377. Combination Sum IV (permutations — loops swapped)
  * 322. Coin Change (minimum coins)
  * 1155. Number of Dice Rolls With Target Sum

## 🔹 Tricks & Patterns Used

* **Loop order decides combinations vs permutations** — the single most tested knapsack detail.
* **Forward inner loop** (`c → amount`) lets a coin be reused; a backward loop would make it 0/1.

## 🔹 Alternative Data Structures

* 2D table `dp[i][a]` makes the "using first i coins" meaning explicit; the 1D array is that table compressed.

## 🔹 Complexity Analysis

* **Time Complexity:** O(amount · len(coins))
* **Space Complexity:** O(amount)

## 🔹 Code Snippet (Optimized)

```python
from typing import List


class Solution:
    def change(self, amount: int, coins: List[int]) -> int:
        dp = [1] + [0] * amount  # dp[a]: ways to make a with coins seen so far
        for c in coins:  # coins outside => combinations, not permutations
            for a in range(c, amount + 1):  # forward => coin c is reusable
                dp[a] += dp[a - c]
        return dp[amount]
```
