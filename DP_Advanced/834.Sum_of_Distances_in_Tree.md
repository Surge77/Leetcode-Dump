# 834. Sum of Distances in Tree

**🔗 Link:** [LeetCode 834](https://leetcode.com/problems/sum-of-distances-in-tree/)
**🟢 Status:** 🔄 Need Review


## 🔹 Problem Statement

Given a connected tree with `n` nodes (labelled `0` to `n - 1`) as an edge list, build an array whose `i`-th entry is the sum of the distances (in edges) from node `i` to every other node.

* **Example:** `n = 6, edges = [[0,1],[0,2],[2,3],[2,4],[2,5]]` → `[8,12,6,10,10,10]`
* **Constraints:** `1 ≤ n ≤ 3 * 10^4`, `edges.length == n - 1`, the edges form a valid tree

## 🔹 Quick Breakdown

* **Difficulty Level:** Hard
* **Main Approach:** **Rerooting.** Root the tree at 0. Pass 1 (bottom-up) computes `count[v]` (subtree size) and `below[v]` (sum of distances from `v` into its subtree), so `answer[0] = below[0]`. Pass 2 (top-down): moving the root from `p` to its child `v` brings the `count[v]` nodes of `v`'s subtree one step closer and pushes the other `n − count[v]` one step away: `answer[v] = answer[p] − count[v] + (n − count[v])`.
* **Core Concept:** compute an answer for **every** root in O(n) by deriving a child's answer from its parent's
* **When to Use This Pattern?** "For each node, compute <something over the whole tree> as if it were the root" — sum of distances, number of correct guesses (2581), max distance, best root.
* **Mistakes to Avoid:**
  * Running a BFS from every node: O(n²) = 9·10⁸ for `n = 3·10⁴`.
  * Recursive DFS on a path-shaped tree: depth 3·10⁴ → recursion error. Use a BFS order and loop over it backwards for the bottom-up pass.

## 🔹 Optimization Path

* **Brute Force:** BFS from every node — O(n²).
* **Optimized Solution:** two linear passes — O(n).
* **Further Improvements Possible?** No; O(n) is optimal (the output has `n` numbers).

## 🔹 Solution Breakdown

* **Optimal Approach:** BFS from 0 for `parent` and an order where parents precede children; reversed order → sizes and `below`; forward order → `answer`.
* **Why This Works?** Distances from `v` differ from distances from its parent `p` by exactly ±1: −1 for nodes in `v`'s subtree, +1 for everyone else. Summing gives the transition formula.
* **Edge Cases Considered:**
  * `n = 1` → `[0]`.
  * A path (deep tree) — handled iteratively.

## 🔹 Tricks & Patterns Used

* **BFS order as a topological order of the rooted tree:** iterate it backwards for children-before-parents, forwards for parents-before-children — no recursion needed.
* **Change of root = local correction:** only the edge `p–v` changes sides.

## 🔹 Alternative Data Structures

* Recursive DFS with `sys.setrecursionlimit` and a thread with a big stack — works, but the iterative BFS order is shorter and safer in an exam.

* **Time Complexity:** O(n)
* **Space Complexity:** O(n)

## 🔹 Code Snippet (Brute Force)

```python
from collections import deque
from typing import List


class Solution:
    def sumOfDistancesInTree(self, n: int, edges: List[List[int]]) -> List[int]:
        adj = [[] for _ in range(n)]
        for a, b in edges:
            adj[a].append(b)
            adj[b].append(a)
        answer = []
        for source in range(n):
            dist = [-1] * n
            dist[source] = 0
            queue = deque([source])
            while queue:
                v = queue.popleft()
                for w in adj[v]:
                    if dist[w] < 0:
                        dist[w] = dist[v] + 1
                        queue.append(w)
            answer.append(sum(dist))
        return answer
```

## 🔹 Code Snippet (Optimized)

```python
from typing import List


class Solution:
    def sumOfDistancesInTree(self, n: int, edges: List[List[int]]) -> List[int]:
        adj = [[] for _ in range(n)]
        for a, b in edges:
            adj[a].append(b)
            adj[b].append(a)

        parent, order = [-1] * n, [0]
        parent[0] = 0
        for v in order:  # BFS: parents appear before their children
            for w in adj[v]:
                if parent[w] == -1:
                    parent[w] = v
                    order.append(w)

        count, below = [1] * n, [0] * n
        for v in reversed(order[1:]):  # children before parents
            p = parent[v]
            count[p] += count[v]
            below[p] += below[v] + count[v]

        answer = [0] * n
        answer[0] = below[0]
        for v in order[1:]:  # reroot from parent to child
            answer[v] = answer[parent[v]] - count[v] + (n - count[v])
        return answer
```
