# 632. Smallest Range Covering Elements from K Lists

**🔗 Link:** [LeetCode 632](https://leetcode.com/problems/smallest-range-covering-elements-from-k-lists/)
**🟢 Status:** 🔄 Need Review


## 🔹 Problem Statement

You get `k` lists of integers, each sorted in non-decreasing order. Find the narrowest range `[a, b]` that contains at least one number from every list. If two ranges have the same width, the one with the smaller start wins.

* **Example:** `nums = [[4,10,15,24,26],[0,9,12,20],[5,18,22,30]]` → `[20,24]`
* **Constraints:** `nums.length == k`, `1 ≤ k ≤ 3500`; `1 ≤ nums[i].length ≤ 50`; `-10⁵ ≤ nums[i][j] ≤ 10⁵`; every list is sorted non-decreasingly.

## 🔹 Quick Breakdown

* **Difficulty Level:** Hard
* **Main Approach:** **Min-heap holding one element per list.** Keep the current element of every list in a min-heap and track the largest of them. The window `[heap minimum, maximum]` covers all lists; record it, then advance the list that owns the minimum — only that move can shrink the window.
* **Core Concept:** k-way merge where the "state" is a window with one element from each list
* **When to Use This Pattern?** "Find a range / window that touches every one of k sorted sequences" — smallest range, minimum window over several lists, merging k sorted streams.
* **Mistakes to Avoid:**
  * Advancing a list other than the one with the minimum — the window cannot get smaller, you only skip candidates.
  * Not stopping as soon as one list is exhausted: a window without that list is invalid.
  * Tie-breaking: on equal size the problem wants the smaller start, so only replace the best on a strictly smaller range.

## 🔹 Optimization Path

* **Brute Force:** try every element as the left end; for each list take the smallest element `≥` it (binary search) and the window is up to the largest of those — O(N · k · log m).
* **Optimized Solution:** heap of k elements, each step pops and pushes once — O(N log k), with `N` the total number of elements.
* **Further Improvements Possible?** Flattening into one sorted `(value, list)` array and sliding a two-pointer window costs O(N log N) for the sort, slightly worse than the heap's O(N log k); the heap avoids materialising all N pairs.

## 🔹 Solution Breakdown

* **Optimal Approach:** push `(nums[i][0], i, 0)` for each list and keep `hi = max` of the firsts. Loop: the heap top `lo` gives window `[lo, hi]`; if it is strictly smaller than the best, store it. If the list of `lo` has no next element, stop. Otherwise replace the top with that list's next element and update `hi`.
* **Why This Works?** For any fixed minimum `lo` the best window has `hi` = the largest of each list's smallest element `≥ lo`, which is exactly what the heap holds. Moving the minimum's list forward is the only way to raise `lo` without losing coverage, so every candidate minimum is examined once, in increasing order.
* **Edge Cases Considered:**
  * Equal values in several lists (`[[1,2,3],[1,2,3],[1,2,3]]` → `[1, 1]`).
  * Lists of length 1 — the loop ends right after the first window.
  * Duplicates inside a list — they are just consecutive equal elements.

## 🔹 Tricks & Patterns Used

* **Track the maximum separately:** a min-heap gives the minimum for free; the maximum only ever grows as elements are pushed, so a single variable is enough.
* **`heapreplace`:** pop and push in one sift instead of two.

## 🔹 Alternative Data Structures

* Merge all `(value, list_id)` pairs, sort, and slide a window until every list id appears (counter of ids inside the window).
* Pointer per list with `min()`/`max()` over the k pointers each step — O(N · k), the heap makes the minimum O(log k).

## 🔹 Complexity Analysis

* **Time Complexity:** O(N log k) with `N` = total number of elements, `k` = number of lists
* **Space Complexity:** O(k)

## 🔹 Code Snippet (Brute Force)

```python
from bisect import bisect_left
from typing import List


class Solution:
    def smallestRange(self, nums: List[List[int]]) -> List[int]:
        best = None
        for low in sorted({x for row in nums for x in row}):
            high = low
            for row in nums:
                pos = bisect_left(row, low)
                if pos == len(row):
                    break  # this list has nothing >= low, and larger lows will not either
                high = max(high, row[pos])
            else:
                # Strictly smaller only: lows come in increasing order, so ties keep the smaller start.
                if best is None or high - low < best[1] - best[0]:
                    best = [low, high]
        return best
```

## 🔹 Code Snippet (Optimized)

```python
import heapq
from typing import List


class Solution:
    def smallestRange(self, nums: List[List[int]]) -> List[int]:
        heap = [(row[0], i, 0) for i, row in enumerate(nums)]
        heapq.heapify(heap)
        high = max(row[0] for row in nums)
        best = [heap[0][0], high]
        while True:
            low, i, j = heap[0]
            if high - low < best[1] - best[0]:
                best = [low, high]
            if j + 1 == len(nums[i]):
                return best  # a list ran out: no later window can cover it
            nxt = nums[i][j + 1]
            high = max(high, nxt)
            heapq.heapreplace(heap, (nxt, i, j + 1))
```
