# 🔹 Problem Name: 137. Single Number II (Bit Manipulation, Medium)

**🔗 Link:** [LeetCode 137](https://leetcode.com/problems/single-number-ii/)
**🟢 Status:** 🔄 Need Review

## 🔹 Quick Breakdown

* **Difficulty Level:** Medium
* **Main Approach:** **Count each bit modulo 3 with two bitmasks.** For every bit position, keep a counter that cycles 0 → 1 → 2 → 0. Store all 32 counters in parallel: `ones` holds positions whose count is 1, `twos` positions whose count is 2. On each number `x`: `ones = (ones ^ x) & ~twos`, then `twos = (twos ^ x) & ~ones`. Every triple returns its bits to state 0, so `ones` ends as the single number.
* **Core Concept:** a number seen three times contributes a multiple of 3 to every bit count; what survives `mod 3` is the lone number
* **When to Use This Pattern?** "Every element appears `k` times except one" — count bits modulo `k` (per bit with 32 counters, or as a small state machine over bitmasks).
* **Mistakes to Avoid:**
  * Plain XOR (136) cancels pairs, not triples.
  * Per-bit counting with 32-bit signed results: bit 31 means negative. Python needs `res − 2³²` when bit 31 is set; the `ones/twos` version needs no fix because Python bitwise ops act like infinite two's complement.
  * Updating `twos` with the **old** `ones` — the order of the two lines is what makes the state machine work.

## 🔹 Optimization Path

* **Brute Force:** hash-map counts, return the key with count 1 — O(n) time, O(n) space.
* **Better:** for each of 32 bits, sum that bit over all numbers, keep `sum % 3` — O(32n) time, O(1) space.
* **Optimized Solution:** `ones/twos` state machine — O(n) time, O(1) space, one pass.
* **Further Improvements Possible?** No; every number must be read.

## 🔹 Solution Breakdown

* **Optimal Approach:** apply the two update lines to each number; return `ones`.
* **Why This Works?** Per bit, track state `(twos, ones)` and feed it the bit `b` of `x`. With `b = 0` nothing changes. With `b = 1`: `(0,0) → (0,1)`, `(0,1) → (1,0)`, `(1,0) → (0,0)` — exactly counting mod 3. After all numbers, each bit sits in state 1 iff the single number has that bit, so `ones` is the answer and `twos` is 0.
* **Edge Cases Considered:**
  * `n = 1` → the only element.
  * Negative single number — handled by two's-complement behaviour of Python ints.

## 🔹 Tricks & Patterns Used

* **Bit-parallel counters:** two masks implement 32 independent mod-3 counters in O(1) ops per number.
* **Per-bit sums:** `sum((x >> i) & 1 for x in nums) % 3` recovers bit `i` of the answer.

## 🔹 Alternative Data Structures

* `Counter` (brute force); `(3 · sum(set(nums)) − sum(nums)) // 2` — O(n) space.

## 🔹 Code Snippet (Brute Force)

```python
from collections import Counter
from typing import List


class Solution:
    def singleNumber(self, nums: List[int]) -> int:
        return next(num for num, count in Counter(nums).items() if count == 1)
```

## 🔹 Code Snippet (Optimized)

```python
from typing import List


class Solution:
    def singleNumber(self, nums: List[int]) -> int:
        ones = twos = 0
        for x in nums:
            # per bit: state (twos, ones) advances 00 -> 01 -> 10 -> 00 on every 1-bit
            ones = (ones ^ x) & ~twos
            twos = (twos ^ x) & ~ones  # must see the already-updated `ones`
        return ones
```
