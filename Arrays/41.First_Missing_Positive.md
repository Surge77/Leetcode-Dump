# 🔹 Problem Name: 41. First Missing Positive (Cyclic Sort, Hard)

**🔗 Link:** [LeetCode 41](https://leetcode.com/problems/first-missing-positive/)
**🟢 Status:** 🔄 Need Review

## 🔹 Problem Statement

Given an unsorted integer array, return the smallest positive integer that does not appear in it. The solution must run in O(n) time and use only O(1) auxiliary space.

* **Example:** `nums = [1,2,0]` → `3`
* **Constraints:** `1 ≤ nums.length ≤ 10⁵`, `-2³¹ ≤ nums[i] ≤ 2³¹ - 1`

## 🔹 Quick Breakdown

* **Difficulty Level:** Hard
* **Main Approach:** **Index as a hash (cyclic sort).** With `n` numbers the answer is in `[1, n + 1]`. Swap every value `v` with `1 ≤ v ≤ n` into slot `v − 1`; afterwards the first slot `i` with `nums[i] != i + 1` gives the answer `i + 1`, or `n + 1` if all slots fit.
* **Core Concept:** the array itself is the "seen" table, so O(1) extra space
* **When to Use This Pattern?** Values are bounded by (or can be clipped to) the array length and you need missing/duplicate numbers in O(n) time with O(1) space.
* **Mistakes to Avoid:**
  * `if nums[i] != i + 1` as the swap condition loops forever on duplicates (`[1, 1]`); compare with the **target slot** (`nums[j] != nums[i]`).
  * Writing `nums[i], nums[nums[i] - 1] = ...` — the index changes mid-assignment; store `j` first.
  * Sorting (O(n log n)) or a hash set (O(n) space) — both violate the intended limits.

## 🔹 Optimization Path

* **Brute Force:** try `1, 2, 3, ...` and linear-scan the array for each — O(n²).
* **Optimized Solution:** place each value at its index, then one scan — O(n) time, O(1) space.
* **Further Improvements Possible?** No; every element must be read.

## 🔹 Solution Breakdown

* **Optimal Approach:** for each `i`, while `nums[i]` is in `[1, n]` and not already at its home slot, swap it there. Then scan for the first misplaced slot.
* **Why This Works?** Each swap puts one value in its final slot permanently, so at most `n` swaps happen in total (amortised O(n)). Values `≤ 0` or `> n` can never be the answer, so they are left anywhere.
* **Edge Cases Considered:**
  * Duplicates (`[1, 1]`) — the `nums[j] != nums[i]` guard stops the swap.
  * `[1, 2, 3]` → `4` (all slots full, answer is `n + 1`).
  * All negatives → `1`.

## 🔹 Tricks & Patterns Used

* **Answer range clamp:** the answer is at most `n + 1`, so anything outside `[1, n]` is noise.
* **Swap-to-home loop:** a `while` (not `if`) because the swapped-in value may also need moving.

## 🔹 Alternative Data Structures

* Hash set of all values, then count up from 1 — O(n) time but O(n) space.
* Sign marking: make non-positives `n + 1`, then negate `nums[v − 1]` for each `|v| ≤ n`; first positive slot is the answer.

## 🔹 Complexity Analysis

* **Time Complexity:** O(n)
* **Space Complexity:** O(1) (the input array is modified in place)

## 🔹 Code Snippet (Brute Force)

```python
from typing import List


class Solution:
    def firstMissingPositive(self, nums: List[int]) -> int:
        candidate = 1
        while candidate in nums:  # list membership is a full scan
            candidate += 1
        return candidate
```

## 🔹 Code Snippet (Optimized)

```python
from typing import List


class Solution:
    def firstMissingPositive(self, nums: List[int]) -> int:
        n = len(nums)
        for i in range(n):
            while 0 < nums[i] <= n and nums[nums[i] - 1] != nums[i]:
                home = nums[i] - 1  # compute first: nums[i] changes during the swap
                nums[i], nums[home] = nums[home], nums[i]
        for i in range(n):
            if nums[i] != i + 1:
                return i + 1
        return n + 1
```
