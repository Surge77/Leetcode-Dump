# 1768. Merge Strings Alternately

**🔗 Link:** [LeetCode 1768](https://leetcode.com/problems/merge-strings-alternately/)
**🟢 Status:** 🔄 Need Review


## 🔹 Problem Statement

Combine two strings into one by taking letters alternately, beginning with the first string. When one string runs out, the remaining letters of the other string are added to the end. Return the combined string.

* **Example:** `word1 = "abc", word2 = "pqr"` → `"apbqcr"`
* **Constraints:** `1 ≤ word1.length, word2.length ≤ 100`; lowercase letters only

## 🔹 Quick Breakdown

* **Difficulty Level:** Easy
* **Main Approach:** **Interleave up to the shorter length, then append the leftover tail.** `zip` pairs the characters of both words positionally; join each pair, then add whichever suffix is left over.
* **Core Concept:** walk two sequences in lock-step and handle the remainder of the longer one separately
* **When to Use This Pattern?** Merge or interleave two sequences — merge sorted arrays, zip lists, alternate nodes of two linked lists.
* **Mistakes to Avoid:**
  * Stopping when the shorter word ends and dropping the rest of the longer one.
  * Appending both tails unconditionally without slicing from the shorter length (it would duplicate characters).
  * Building the result with `+=` in a loop on very long strings (fine at length 100, but join is the habit).

## 🔹 Optimization Path

* **Brute Force:** repeatedly take the first character of each word and slice it off (`word = word[1:]`) — every slice copies the rest, O(n²).
* **Optimized Solution:** `zip` + one `join` — O(n).
* **Further Improvements Possible?** No; the output has `n + m` characters.

## 🔹 Solution Breakdown

* **Optimal Approach:** `common = min(len(word1), len(word2))`; `"".join(a + b for a, b in zip(word1, word2)) + word1[common:] + word2[common:]`.
* **Why This Works?** For the first `common` positions both words have a character, so alternating is just pairing; after that at most one of the two slices `word1[common:]`, `word2[common:]` is non-empty, and it is exactly the unmatched tail.
* **Edge Cases Considered:**
  * One word much longer than the other.
  * Equal lengths → the tails are empty.
  * Single-character words.

## 🔹 Tricks & Patterns Used

* **Slice from `common`:** the empty-slice behaviour of Python makes the "no tail" case free.
* **`join` over concatenation:** one allocation for the final string.

## 🔹 Alternative Data Structures

* `itertools.zip_longest(word1, word2, fillvalue="")` joined — handles the tail automatically.
* Two index pointers with a `while i < n or j < m` loop — the form to use in languages without `zip`.

* **Time Complexity:** O(n + m)
* **Space Complexity:** O(n + m) for the output

## 🔹 Code Snippet (Brute Force)

```python
class Solution:
    def mergeAlternately(self, word1: str, word2: str) -> str:
        merged = ""
        while word1 or word2:
            if word1:
                merged += word1[0]
                word1 = word1[1:]
            if word2:
                merged += word2[0]
                word2 = word2[1:]
        return merged
```

## 🔹 Code Snippet (Optimized)

```python
class Solution:
    def mergeAlternately(self, word1: str, word2: str) -> str:
        common = min(len(word1), len(word2))
        interleaved = "".join(a + b for a, b in zip(word1, word2))
        return interleaved + word1[common:] + word2[common:]
```
