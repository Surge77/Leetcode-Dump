# 377. Combination Sum IV

**🔗 Link:** [LeetCode 377](https://leetcode.com/problems/combination-sum-iv/)
**🟢 Status:** 🔄 Need Review


## 🔹 Problem Statement

Given distinct positive integers `nums` (each reusable) and a `target`, count the ordered sequences of numbers that sum to `target`; different orders count as different answers. The result is guaranteed to fit in a 32-bit integer.

* **Example:** `nums = [1,2,3], target = 4` → `7`
* **Constraints:** `1 ≤ nums.length ≤ 200`; `1 ≤ nums[i] ≤ 1000`, all distinct; `1 ≤ target ≤ 1000`.

## 🔹 Quick Breakdown

* **Difficulty Level:** Medium
* **Main Approach:** **Count ordered sequences with `dp[t]`.** `dp[0] = 1`; `dp[t] = Σ dp[t − x]` over every `x ∈ nums` with `x ≤ t`. The answer is `dp[target]`.
* **Core Concept:** "number of ways to reach a total" where **order matters** — outer loop over the total, inner loop over the items (permutations); the opposite nesting counts combinations (518).
* **When to Use This Pattern?** Counting compositions / sequences that sum to a target with reusable items.
* **Mistakes to Avoid:**
  * Swapping the loops (items outside, totals inside): that counts each multiset once, giving 4 instead of 7 for `[1, 2, 3], 4`.
  * Plain recursion: exponential.
  * Despite the title, `[1, 1, 2]` and `[1, 2, 1]` are different answers here.

## 🔹 Optimization Path

* **Brute Force:** recurse `ways(remaining) = Σ ways(remaining − x)` without caching — exponential.
* **Optimized Solution:** bottom-up table — O(target · n) time, O(target) space.
* **Further Improvements Possible?** Sorting `nums` lets the inner loop break at the first `x > t`; the asymptotics stay the same.

## 🔹 Solution Breakdown

* **Optimal Approach:** `dp = [1] + [0] * target`; for `t` in `1..target`, add `dp[t − x]` for each `x ≤ t`.
* **Why This Works?** Condition on the **last** number of the sequence: if it is `x`, the rest is any sequence summing to `t − x`. These cases are disjoint and exhaustive, so the sums add up exactly.
* **Edge Cases Considered:**
  * No `x` fits (`nums = [9], target = 3`) → `0`.
  * `target` smaller than every number → `0`.
  * The answer is guaranteed to fit in 32 bits, but intermediate `dp` cells for unreachable-in-answer states are not — Python's big ints make that safe.

## 🔹 Tricks & Patterns Used

* **Loop order decides the semantics:** totals outside = permutations, items outside = combinations.
* **`dp[0] = 1`:** the empty sequence is the single way to make 0.

## 🔹 Alternative Data Structures

* Top-down memoisation with `functools.lru_cache` on the remaining sum — same complexity, recursion depth up to `target / min(nums)` (≤ 1000), so raise the limit or prefer the table.

## 🔹 Complexity Analysis

* **Time Complexity:** O(target · n)
* **Space Complexity:** O(target)

## 🔹 Code Snippet (Brute Force)

```python
from typing import List


class Solution:
    def combinationSum4(self, nums: List[int], target: int) -> int:
        def ways(remaining: int) -> int:
            if remaining == 0:
                return 1
            return sum(ways(remaining - x) for x in nums if x <= remaining)

        return ways(target)
```

## 🔹 Code Snippet (Optimized)

```python
from typing import List


class Solution:
    def combinationSum4(self, nums: List[int], target: int) -> int:
        dp = [1] + [0] * target
        for total in range(1, target + 1):  # total outside: different orders count separately
            for x in nums:
                if x <= total:
                    dp[total] += dp[total - x]
        return dp[target]
```
