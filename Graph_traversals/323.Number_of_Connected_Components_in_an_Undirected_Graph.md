## 🔹 Quick Breakdown

* **Difficulty Level:** Medium
* **Main Approach:** **Union-Find, counting successful merges.** Start with `n` components (every node alone). Each edge whose endpoints have different roots merges two components into one: `components −= 1`. Edges inside a component change nothing.
* **Core Concept:** components = `n − (number of merges)`
* **When to Use This Pattern?** Counting groups formed by pairwise links — friend circles, provinces, networks, accounts sharing an email; especially when edges arrive one at a time.
* **Mistakes to Avoid:**
  * Answering `n − len(edges)`: an edge inside an existing component (a cycle) does not reduce the count.
  * Forgetting isolated nodes — they never appear in `edges` but each is a component.
  * Recursive DFS on a 2000-node path → deeper than Python's default limit of 1000.

## 🔹 Optimization Path

* **Brute Force:** label propagation — every node starts with its own label; sweep all edges giving both ends the smaller label until nothing changes; count distinct labels. Up to `n` sweeps: O(n · E).
* **Optimized Solution:** Union-Find with path halving + union by size — O(n + E · α(n)).
* **Further Improvements Possible?** No; every edge must be read. BFS/DFS over an adjacency list is equally fast.

## 🔹 Solution Breakdown

* **Optimal Approach:** `parent = list(range(n))`, `components = n`. For each edge `(a, b)`: `ra, rb = find(a), find(b)`; if `ra != rb`, attach the smaller tree under the larger and decrement `components`.
* **Why This Works?** Union-Find keeps one root per current component. A merge happens exactly when an edge joins two different components, and each merge reduces the count by one; the final count is the number of roots left.
* **Edge Cases Considered:**
  * Isolated nodes — counted from the start.
  * A cycle (`0–1, 1–2, 2–0`) — the third edge finds equal roots and is ignored.

## 🔹 Tricks & Patterns Used

* **Count down from `n`:** no final pass over the roots needed.
* **Path halving** (`parent[x] = parent[parent[x]]`) — an iterative path compression, no recursion.

## 🔹 Alternative Data Structures

* Adjacency list + BFS/DFS from every unvisited node, counting the starts.

## 🔹 Complexity Analysis

* **Time Complexity:** O(n + E · α(n))
* **Space Complexity:** O(n)

## 🔹 Code Snippet (Brute Force)

```python
from typing import List


class Solution:
    def countComponents(self, n: int, edges: List[List[int]]) -> int:
        label = list(range(n))
        changed = True
        while changed:  # each sweep pushes a component's smallest label at least one edge further
            changed = False
            for a, b in edges:
                low = min(label[a], label[b])
                if label[a] != low or label[b] != low:
                    label[a] = label[b] = low
                    changed = True
        return len(set(label))
```

## 🔹 Code Snippet (Optimized)

```python
from typing import List


class Solution:
    def countComponents(self, n: int, edges: List[List[int]]) -> int:
        parent, size = list(range(n)), [1] * n

        def find(x: int) -> int:
            while parent[x] != x:
                parent[x] = parent[parent[x]]  # path halving
                x = parent[x]
            return x

        components = n
        for a, b in edges:
            ra, rb = find(a), find(b)
            if ra != rb:  # this edge joins two different components
                if size[ra] < size[rb]:
                    ra, rb = rb, ra
                parent[rb] = ra
                size[ra] += size[rb]
                components -= 1
        return components
```
