# 1431. Kids With the Greatest Number of Candies

**🔗 Link:** [LeetCode 1431](https://leetcode.com/problems/kids-with-the-greatest-number-of-candies/)
**🟢 Status:** 🔄 Need Review


## 🔹 Problem Statement

Each kid holds some candies, and you have a pile of extra candies. For every kid, decide whether handing them the whole extra pile would leave them with at least as many candies as any other kid. Return one boolean per kid; ties for the lead count as having the greatest number.

* **Example:** `candies = [2,3,5,1,3], extraCandies = 3` → `[true,true,true,false,true]`
* **Constraints:** `2 ≤ n ≤ 100`, `1 ≤ candies[i] ≤ 100`, `1 ≤ extraCandies ≤ 50`

## 🔹 Quick Breakdown

* **Difficulty Level:** Easy
* **Main Approach:** **Compare against the current maximum.** A kid can end up with the most candies iff `candies[i] + extraCandies >= max(candies)` (ties count as "greatest"). Compute the maximum once, then test each kid.
* **Core Concept:** hoist a loop-invariant (`max`) out of the per-element check
* **When to Use This Pattern?** "Can element `i` reach/beat the best after a bonus" — answer depends on one global statistic.
* **Mistakes to Avoid:**
  * Using `>` instead of `>=`: the problem allows ties for the greatest.
  * Recomputing `max(candies)` inside the loop: O(n²) instead of O(n).

## 🔹 Optimization Path

* **Brute Force:** for each kid, compare their boosted total against every other kid — O(n²).
* **Optimized Solution:** one pass for the max, one pass for the answers — O(n).
* **Further Improvements Possible?** No; the output has `n` entries.

## 🔹 Solution Breakdown

* **Optimal Approach:** `top = max(candies)`; answer is `[c + extraCandies >= top for c in candies]`.
* **Why This Works?** Only the other kids' maximum matters, and giving all extra candies to kid `i` makes them at least as large as every kid `j` iff it is at least as large as the overall maximum (kid `i` themself is `≤ top`, so the global max is the right bar).
* **Edge Cases Considered:**
  * `extraCandies = 1` with everyone equal → all `True`.
  * A tied maximum (`[12, 1, 12]`, `extraCandies = 10`) → `[True, False, True]`; `n ≥ 2`, so there is no single-kid case.

## 🔹 Tricks & Patterns Used

* **List comprehension of booleans:** the comparison itself is the answer, no `if` branch needed.

## 🔹 Alternative Data Structures

* Sorting a copy to read the maximum — works but O(n log n) for no gain.

## 🔹 Complexity Analysis

* **Time Complexity:** O(n)
* **Space Complexity:** O(1) extra (O(n) for the returned list)

## 🔹 Code Snippet (Brute Force)

```python
from typing import List


class Solution:
    def kidsWithCandies(self, candies: List[int], extraCandies: int) -> List[bool]:
        return [all(mine + extraCandies >= other for other in candies) for mine in candies]
```

## 🔹 Code Snippet (Optimized)

```python
from typing import List


class Solution:
    def kidsWithCandies(self, candies: List[int], extraCandies: int) -> List[bool]:
        top = max(candies)
        return [mine + extraCandies >= top for mine in candies]  # ties count as greatest
```
