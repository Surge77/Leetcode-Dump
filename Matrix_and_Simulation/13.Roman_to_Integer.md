# 13. Roman to Integer

**🔗 Link:** [LeetCode 13](https://leetcode.com/problems/roman-to-integer/)
**🟢 Status:** 🔄 Need Review


## 🔹 Problem Statement

Convert a Roman numeral string to its integer value. Symbols are normally added from left to right, but six pairs are subtractive: a smaller symbol directly before a larger one (`I` before `V`/`X`, `X` before `L`/`C`, `C` before `D`/`M`) is subtracted instead. The input is guaranteed to be a valid numeral.

* **Example:** `s = "III"` → `3`
* **Constraints:** `1 ≤ s.length ≤ 15`; `s` uses only `I V X L C D M`; `s` is a valid numeral in `[1, 3999]`

## 🔹 Quick Breakdown

* **Difficulty Level:** Easy
* **Main Approach:** **One pass with a one-symbol lookahead.** Add each symbol's value, except when the symbol to its right is larger — then subtract it (`I` before `V`/`X`, `X` before `L`/`C`, `C` before `D`/`M`).
* **Core Concept:** in a valid numeral the only place a smaller symbol precedes a larger one is a subtractive pair, so "smaller than my right neighbour" identifies the subtracted symbol locally
* **When to Use This Pattern?** Parsing a token stream where a token's meaning depends on its neighbour — Roman numerals, signs in expressions, "current vs next" comparisons in a single scan.
* **Mistakes to Avoid:**
  * Comparing with the **left** neighbour but forgetting that the smaller symbol was already added: `IV` gives 1 + (5 − 1) = 5 instead of 1 + (5 − 2·1) = 4. Comparing to the right avoids the correction.
  * Reading `s[i + 1]` on the last symbol — guard the index.

## 🔹 Optimization Path

* **Brute Force:** rewrite the six subtractive pairs into their additive spelling (`IV → IIII`, `CM → DCCCC`, …), then sum the symbol values — six extra passes and a longer string.
* **Optimized Solution:** single pass with the lookahead rule — O(n).
* **Further Improvements Possible?** No; every symbol must be read. (Scanning right to left and subtracting when the value is below the running maximum is an equivalent single pass.)

## 🔹 Solution Breakdown

* **Optimal Approach:** `total += -v if next symbol is larger else v` for every position.
* **Why This Works?** A subtractive pair `ab` means `b − a`. Adding `−a` for the smaller first symbol and `+b` for the second gives exactly that, and every other symbol is followed by an equal or smaller one, so it is added as-is.
* **Edge Cases Considered:**
  * A single symbol (`"I"` → 1) — no right neighbour.
  * Consecutive pairs `"MCMXCIV"` → 1000 + 900 + 90 + 4 = 1994.

## 🔹 Tricks & Patterns Used

* **Signed contribution:** decide each symbol's sign locally instead of matching two-character tokens.
* **Value map** `{"I": 1, "V": 5, …}` — O(1) lookups.

## 🔹 Alternative Data Structures

* A token table that tries the two-character pairs before single symbols — same O(n), more code.
* `str.replace` rewrites (the brute force) — simple but builds new strings.

## 🔹 Complexity Analysis

* **Time Complexity:** O(n), `n ≤ 15`
* **Space Complexity:** O(1)

## 🔹 Code Snippet (Brute Force)

```python
VALUE = {"I": 1, "V": 5, "X": 10, "L": 50, "C": 100, "D": 500, "M": 1000}


class Solution:
    def romanToInt(self, s: str) -> int:
        for short_form, long_form in (("CM", "DCCCC"), ("CD", "CCCC"), ("XC", "LXXXX"),
                                      ("XL", "XXXX"), ("IX", "VIIII"), ("IV", "IIII")):
            s = s.replace(short_form, long_form)
        return sum(VALUE[ch] for ch in s)
```

## 🔹 Code Snippet (Optimized)

```python
VALUE = {"I": 1, "V": 5, "X": 10, "L": 50, "C": 100, "D": 500, "M": 1000}


class Solution:
    def romanToInt(self, s: str) -> int:
        total = 0
        for i, ch in enumerate(s):
            value = VALUE[ch]
            if i + 1 < len(s) and value < VALUE[s[i + 1]]:
                total -= value  # subtractive pair: the larger neighbour is added next
            else:
                total += value
        return total
```
