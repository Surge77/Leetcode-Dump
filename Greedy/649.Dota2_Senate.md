# 🔹 Problem Name: 649. Dota2 Senate (Greedy Queue, Medium)

**🔗 Link:** [LeetCode 649](https://leetcode.com/problems/dota2-senate/)
**🟢 Status:** 🔄 Need Review

## 🔹 Quick Breakdown

* **Difficulty Level:** Medium
* **Main Approach:** **Two queues of indices.** Each senator bans the *next* opposing senator who would still act. Keep the indices of `R` and `D` senators in two queues; compare the fronts: the smaller index acts first, bans the other, and re-enters its own queue at `index + n` (its position in the next round). The party whose queue empties loses.
* **Core Concept:** greedy — always ban the nearest enemy that would vote next; simulate rounds with indices instead of a circular array
* **When to Use This Pattern?** Turn-based elimination in a circle where each actor removes the earliest threatening opponent.
* **Mistakes to Avoid:**
  * Banning an arbitrary enemy or the first enemy in the string — it must be the next enemy in turn order after the actor.
  * Re-adding the winner with `index + 1`: it must go behind everyone of the current round (`index + n`).
  * Deleting elements from a list inside a loop with a stale index — O(n²) and bug-prone.

## 🔹 Optimization Path

* **Brute Force:** keep the senators in a list, walk around the circle and delete the next opposing senator each time — O(n²) because of removals and scans.
* **Optimized Solution:** two queues — O(n).
* **Further Improvements Possible?** No.

## 🔹 Solution Breakdown

* **Optimal Approach:** `radiant = deque(positions of "R")`, `dire = deque(positions of "D")`. While both are non-empty: pop `r` and `d`; the smaller one survives and is pushed back with `+ n`. Return the party of the non-empty queue.
* **Why This Works?** In turn order the senator with the smaller index acts first, and banning the opponent whose turn is next is optimal (it removes the vote that would hurt soonest). The survivor moves to the same relative place in the next round, which `index + n` encodes.
* **Edge Cases Considered:**
  * `"RD"` → `"Radiant"`, `"RDD"` → `"Dire"`.
  * Only one party present → that party wins immediately.
  * Ties in index are impossible: indices are unique.

* **Index + n re-enqueue:** a circular order becomes a monotone order.
* **Compare queue heads** instead of scanning the circle.

## 🔹 Alternative Data Structures

* Single pass with two ban counters (count pending bans per party) over repeated rounds of the string — O(n) too, but the queue version is easier to justify.

## 🔹 Code Snippet (Brute Force)

```python
class Solution:
    def predictPartyVictory(self, senate: str) -> str:
        line = list(senate)
        i = 0
        while len(set(line)) == 2:
            me, n = line[i], len(line)
            target = next((i + step) % n for step in range(1, n) if line[(i + step) % n] != me)
            del line[target]
            if target < i:  # everything after the removed seat shifted left
                i -= 1
            i = (i + 1) % len(line)
        return "Radiant" if line[0] == "R" else "Dire"
```

## 🔹 Code Snippet (Optimized)

```python
from collections import deque


class Solution:
    def predictPartyVictory(self, senate: str) -> str:
        n = len(senate)
        radiant = deque(i for i, s in enumerate(senate) if s == "R")
        dire = deque(i for i, s in enumerate(senate) if s == "D")
        while radiant and dire:
            r, d = radiant.popleft(), dire.popleft()
            if r < d:
                radiant.append(r + n)  # survives, acts again in the next round
            else:
                dire.append(d + n)
        return "Radiant" if radiant else "Dire"
```
