# 🔹 Problem Name: 912. Sort an Array (Merge Sort, Medium)

**🔗 Link:** [LeetCode 912](https://leetcode.com/problems/sort-an-array/)
**🟢 Status:** 🔄 Need Review

## 🔹 Quick Breakdown

* **Difficulty Level:** Medium
* **Main Approach:** **Merge sort.** Split the range in half, sort each half recursively, then merge the two sorted halves with two pointers. It is O(n log n) on every input — which matters here, because LeetCode's tests include sorted and all-equal arrays that push a naive quicksort to O(n²).
* **Core Concept:** divide and conquer — `T(n) = 2T(n/2) + O(n)` = O(n log n)
* **When to Use This Pattern?** You need a guaranteed O(n log n) or stable sort, you are sorting a linked list, or you need to count something about pairs across the two halves while merging (inversions, reverse pairs, smaller-after-self).
* **Mistakes to Avoid:**
  * Quicksort with a fixed first/last pivot — O(n²) on sorted input; even a random pivot with a two-way partition is O(n²) on all-equal input — use a three-way partition.
  * Calling `sorted()` / `.sort()` — the statement asks for no built-in sort.

## 🔹 Optimization Path

* **Brute Force:** insertion sort — O(n²), about 6·10⁸ shifts on random input at `n = 5·10⁴` → TLE.
* **Optimized Solution:** merge sort — O(n log n) time, O(n) extra space.
* **Further Improvements Possible?** Heap sort reaches O(1) extra space (the statement's "smallest space possible") at the cost of stability and cache locality; counting sort runs in O(n + 10⁵) because values lie in `[−5·10⁴, 5·10⁴]`.

## 🔹 Solution Breakdown

* **Optimal Approach:** `merge_sort(lo, hi)` sorts `nums[lo:hi]`. To merge, copy only the left half out, then fill `nums[lo:hi]` from that copy and the right half (read in place). When the copy runs out, the rest of the right half is already where it belongs; when the right half runs out, append the rest of the copy.
* **Why This Works?** By induction both halves are sorted, so the smaller of the two front elements is the smallest remaining one. Writing in place is safe: `j − k` equals the number of elements still in the left copy, so while the copy is non-empty the write index `k` stays strictly left of the right-half pointer `j`.
* **Edge Cases Considered:**
  * `n = 1` — already sorted.
  * Duplicates — `<=` takes the left element first, so the sort is stable.
  * Already sorted, reverse sorted, all equal — still O(n log n).
  * Recursion depth is only `⌈log₂ n⌉ ≈ 16`.

## 🔹 Tricks & Patterns Used

* **Copy only the left half for the merge:** half the buffer traffic, and the right half's leftovers need no copying at all.
* **`<=` when merging** keeps equal keys in input order (stability).

## 🔹 Alternative Data Structures

* Heap sort — in place, O(1) extra, not stable.
* Randomized quicksort with a three-way (Dutch flag) partition — O(n log n) expected, O(log n) stack.
* Counting sort over the value range — O(n + range), not comparison based.

## 🔹 Complexity Analysis

* **Time Complexity:** O(n log n)
* **Space Complexity:** O(n) for the merge buffer, plus O(log n) recursion

## 🔹 Code Snippet (Brute Force)

```python
from typing import List


class Solution:
    def sortArray(self, nums: List[int]) -> List[int]:
        for i in range(1, len(nums)):
            key, j = nums[i], i - 1
            while j >= 0 and nums[j] > key:
                nums[j + 1] = nums[j]
                j -= 1
            nums[j + 1] = key
        return nums
```

## 🔹 Code Snippet (Optimized)

```python
from typing import List


class Solution:
    def sortArray(self, nums: List[int]) -> List[int]:
        def merge_sort(lo: int, hi: int) -> None:
            if hi - lo <= 1:
                return
            mid = (lo + hi) // 2
            merge_sort(lo, mid)
            merge_sort(mid, hi)
            left = nums[lo:mid]  # the merge overwrites this range, so save it first
            i, j, k = 0, mid, lo
            while i < len(left) and j < hi:
                if left[i] <= nums[j]:  # <= keeps equal keys in input order
                    nums[k] = left[i]
                    i += 1
                else:
                    nums[k] = nums[j]
                    j += 1
                k += 1
            nums[k:k + len(left) - i] = left[i:]  # right-half leftovers are already in place

        merge_sort(0, len(nums))
        return nums
```
