# 567. Permutation in String

**🔗 Link:** [LeetCode 567](https://leetcode.com/problems/permutation-in-string/)
**🟢 Status:** 🔄 Need Review


## 🔹 Problem Statement

Given two strings `s1` and `s2`, return `true` if some substring of `s2` is a rearrangement of `s1`, otherwise `false`.

* **Example:** `s1 = "ab"`, `s2 = "eidbaooo"` → `true`
* **Constraints:** `1 ≤ s1.length, s2.length ≤ 10^4`, lowercase English letters only

## 🔹 Quick Breakdown

* **Difficulty Level:** Medium
* **Main Approach:** **Fixed-size sliding window with letter counts.** A permutation of `s1` is a window of length `m = len(s1)` with the same 26 letter counts. Slide a window of length `m` over `s2`, updating counts in O(1) per step (one letter in, one out), and keep `matches` = how many of the 26 letters currently have equal counts; answer `True` when `matches == 26`.
* **Core Concept:** anagram check = equal frequency vectors; maintain the comparison incrementally
* **When to Use This Pattern?** "Does / where does some window of length `m` have the same multiset as a pattern" — anagrams, permutations, fixed-length frequency constraints.
* **Mistakes to Avoid:**
  * Sorting or rebuilding a counter for every window: O(n · m).
  * `len(s1) > len(s2)` → `False` immediately (no window fits).
  * Updating `matches` wrongly: check equality **before and after** changing a letter's count.

## 🔹 Optimization Path

* **Brute Force:** compare `sorted(window)` with `sorted(s1)` for every window — O(n · m log m).
* **Optimized Solution:** sliding counts with a `matches` counter — O(n + 26).
* **Further Improvements Possible?** No; every character of `s2` must be read.

## 🔹 Solution Breakdown

* **Optimal Approach:** `need` and `have` are 26-slot arrays; fill both with the first `m` letters, compute `matches`. For each next index `i`, add `s2[i]` and remove `s2[i - m]`, adjusting `matches` for each letter touched; return `True` whenever `matches == 26`.
* **Why This Works?** Two strings of equal length are permutations of each other iff every letter count is equal. Each slide changes exactly two counts, so only those two letters can change their "equal / not equal" status.
* **Edge Cases Considered:**
  * `m > len(s2)` → `False`.
  * `m == len(s2)` → a single window.
  * The match is the very first window (checked before sliding).

## 🔹 Tricks & Patterns Used

* **Match counter over the alphabet:** turns an O(26) vector comparison per step into O(1).
* **`ord(c) - ord('a')` indexing** — the strings are lowercase only.

## 🔹 Alternative Data Structures

* Compare the two 26-slot lists directly each step (`have == need`) — O(26 · n), simpler and still fast.
* `Counter` with deletion at zero and an equality check — same idea, more overhead.

## 🔹 Complexity Analysis

* **Time Complexity:** O(n + m + 26), n, m ≤ 10⁴
* **Space Complexity:** O(26)

## 🔹 Code Snippet (Brute Force)

```python
class Solution:
    def checkInclusion(self, s1: str, s2: str) -> bool:
        m, target = len(s1), sorted(s1)
        return any(sorted(s2[i:i + m]) == target for i in range(len(s2) - m + 1))
```

## 🔹 Code Snippet (Optimized)

```python
class Solution:
    def checkInclusion(self, s1: str, s2: str) -> bool:
        m, n = len(s1), len(s2)
        if m > n:
            return False
        need, have = [0] * 26, [0] * 26
        for a, b in zip(s1, s2):
            need[ord(a) - 97] += 1
            have[ord(b) - 97] += 1
        matches = sum(need[i] == have[i] for i in range(26))
        for i in range(m, n):
            if matches == 26:
                return True
            for idx, delta in ((ord(s2[i]) - 97, 1), (ord(s2[i - m]) - 97, -1)):
                matches -= have[idx] == need[idx]  # its status may flip, so re-evaluate it
                have[idx] += delta
                matches += have[idx] == need[idx]
        return matches == 26
```
