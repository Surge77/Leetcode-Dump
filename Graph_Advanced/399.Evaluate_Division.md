# 399. Evaluate Division

**🔗 Link:** [LeetCode 399](https://leetcode.com/problems/evaluate-division/)
**🟢 Status:** 🔄 Need Review


## 🔹 Problem Statement

You are given equations of the form `A / B = value` between named variables, and a list of queries `C / D = ?`. Using the equations, return the answer to each query as a float, or `-1.0` when it cannot be determined, for example when a variable never appears in any equation. The input is consistent and never divides by zero.

* **Example:** `equations = [["a","b"],["b","c"]], values = [2.0,3.0], queries = [["a","c"],["b","a"],["a","e"],["a","a"],["x","x"]]` → `[6.0, 0.5, -1.0, 1.0, -1.0]`
* **Constraints:** `1 ≤ equations.length ≤ 20`, `1 ≤ queries.length ≤ 20`, `0.0 < values[i] ≤ 20.0`, variable names are 1 to 5 lowercase letters or digits

## 🔹 Quick Breakdown

* **Difficulty Level:** Medium
* **Main Approach:** **Weighted Union-Find.** Every variable stores `weight[x] = x / parent[x]`. `find` compresses the path and multiplies weights so that afterwards `weight[x] = x / root`. Two variables in the same set answer `c / d = weight[c] / weight[d]`; different sets or unknown names → `-1.0`.
* **Core Concept:** an equation `a / b = v` is a weighted edge; ratios multiply along a path, and the root is a common unit
* **When to Use This Pattern?** Relations that compose along paths — ratios, currency exchange, "x is k more than y" (offsets instead of products), parity relations.
* **Mistakes to Avoid:**
  * `["x", "x"]` with `x` never seen → `-1.0`, not `1.0`.
  * Linking roots with the raw `v`: the roots are not `a` and `b`, so the edge weight must be corrected — `root(a) / root(b) = v · weight[b] / weight[a]`.
  * Multiplying the weight **after** overwriting `parent[x]` in `find`.

## 🔹 Optimization Path

* **Brute Force:** build a graph with edges `a → b` (weight `v`) and `b → a` (`1 / v`); BFS from `c` per query multiplying weights until `d` — O(Q · (V + E)).
* **Optimized Solution:** weighted Union-Find — O((E + Q) · log V) amortized.
* **Further Improvements Possible?** With ≤ 20 equations both are instant; Union-Find wins when there are many queries on a big graph. Floyd–Warshall precomputes all ratios in O(V³).

## 🔹 Solution Breakdown

* **Optimal Approach:** new variables start as their own root with weight `1.0`. For `a / b = v`: find both roots; if different, set `parent[ra] = rb` and `weight[ra] = v · weight[b] / weight[a]`. For a query: both known and `find(c) == find(d)` → `weight[c] / weight[d]`.
* **Why This Works?** After `find`, `a = weight[a] · ra` and `b = weight[b] · rb`. From `a = v · b`: `ra / rb = v · weight[b] / weight[a]`, which is exactly the weight of the new link. Within one set every variable is a known multiple of the root, so any ratio is the quotient of two weights.
* **Edge Cases Considered:**
  * Query on an unknown variable (even `x / x`) → `-1.0`.
  * Variables in different components → `-1.0`.
  * `a / a` for a known `a` → `1.0`.

## 🔹 Tricks & Patterns Used

* **Weights relative to the parent, compressed to the root:** `weight[x] *= weight[parent[x]]` during `find`.
* **Root as common unit:** any two variables in a set are comparable through it.

## 🔹 Alternative Data Structures

* Graph + BFS/DFS per query (the brute force) — simplest to write in an interview.
* Floyd–Warshall over the ratio matrix when every pair is asked for.

## 🔹 Complexity Analysis

* **Time Complexity:** O((E + Q) · log V) amortized with path compression
* **Space Complexity:** O(V)

## 🔹 Code Snippet (Brute Force)

```python
from collections import defaultdict, deque
from typing import List


class Solution:
    def calcEquation(self, equations: List[List[str]], values: List[float],
                     queries: List[List[str]]) -> List[float]:
        graph = defaultdict(list)
        for (a, b), v in zip(equations, values):
            graph[a].append((b, v))
            graph[b].append((a, 1 / v))

        def evaluate(src: str, dst: str) -> float:
            if src not in graph or dst not in graph:
                return -1.0
            ratio = {src: 1.0}  # ratio[x] = src / x
            queue = deque([src])
            while queue:
                x = queue.popleft()
                if x == dst:
                    return ratio[x]
                for y, v in graph[x]:
                    if y not in ratio:
                        ratio[y] = ratio[x] * v  # src/y = src/x · x/y
                        queue.append(y)
            return -1.0

        return [evaluate(c, d) for c, d in queries]
```

## 🔹 Code Snippet (Optimized)

```python
from typing import List


class Solution:
    def calcEquation(self, equations: List[List[str]], values: List[float],
                     queries: List[List[str]]) -> List[float]:
        parent, weight = {}, {}  # weight[x] = x / parent[x]

        def find(x: str) -> str:
            # recursion depth ≤ number of variables ≤ 40
            if parent[x] != x:
                root = find(parent[x])
                weight[x] *= weight[parent[x]]  # x/p · p/root, read before parent[x] changes
                parent[x] = root
            return parent[x]

        for (a, b), v in zip(equations, values):
            for x in (a, b):
                if x not in parent:
                    parent[x], weight[x] = x, 1.0
            ra, rb = find(a), find(b)
            if ra != rb:
                parent[ra] = rb
                weight[ra] = v * weight[b] / weight[a]  # ra/rb, from a = v·b

        answers = []
        for c, d in queries:
            if c not in parent or d not in parent or find(c) != find(d):
                answers.append(-1.0)
            else:
                answers.append(weight[c] / weight[d])
        return answers
```
