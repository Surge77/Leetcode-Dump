# 328. Odd Even Linked List

**🔗 Link:** [LeetCode 328](https://leetcode.com/problems/odd-even-linked-list/)
**🟢 Status:** 🔄 Need Review


## 🔹 Problem Statement

Reorder a singly linked list so all nodes at odd positions (1st, 3rd, ...) come first, followed by all nodes at even positions, keeping the relative order inside each group. This is about positions, not values. It must run in `O(n)` time and `O(1)` extra space.

* **Example:** `head = [1,2,3,4,5]` → `[1,3,5,2,4]`
* **Constraints:** `0 ≤ n ≤ 10^4`; `-10^6 ≤ Node.val ≤ 10^6`.

## 🔹 Quick Breakdown

* **Difficulty Level:** Medium
* **Main Approach:** **Two interleaved chains.** Keep `odd` and `even` tails. Each step, `odd` skips over `even` to the next odd-position node and `even` skips over that to the next even-position node. At the end, hook the odd chain's tail to the saved `even_head`.
* **Core Concept:** split a list by position into two chains in one pass, then concatenate
* **When to Use This Pattern?** Partition a linked list while keeping relative order — by position (here), by value (86 Partition List), by parity of value.
* **Mistakes to Avoid:**
  * Grouping by **value** parity — the problem is about **positions** (1st, 3rd, 5th…).
  * Losing the start of the even chain — save `even_head` before rewiring.
  * Wrong loop condition: `while even and even.next` covers both odd and even lengths; `while odd.next` can dereference `None`.

## 🔹 Optimization Path

* **Brute Force:** collect all nodes in an array, then relink `nodes[0::2] + nodes[1::2]` — O(n) time, O(n) space.
* **Optimized Solution:** rewire in place with two tails — O(n) time, O(1) space (required by the problem).
* **Further Improvements Possible?** No; every node must be relinked.

## 🔹 Solution Breakdown

* **Optimal Approach:** `odd.next = even.next; odd = odd.next; even.next = odd.next; even = even.next`, then `odd.next = even_head`.
* **Why This Works?** Invariant: `odd` is the last node of the finished odd chain, `even` the last of the even chain, and `even.next` is the first unprocessed node (an odd position). The loop stops when there is no next odd node; `even` ends pointing at `None`, so the final list has no stale links.
* **Edge Cases Considered:**
  * Empty list, one node, two nodes — returned unchanged.
  * Odd vs even length — the even chain's tail always ends with `None`.

## 🔹 Tricks & Patterns Used

* **Leapfrogging pointers:** each tail jumps over the other's next node.
* **Saved head of the second chain** for the final splice.

## 🔹 Alternative Data Structures

* Two dummy heads (`odd_dummy`, `even_dummy`) with a position counter — same complexity, more general for value-based partitions.
* Array of nodes — simplest, but O(n) memory.

## 🔹 Complexity Analysis

* **Time Complexity:** O(n)
* **Space Complexity:** O(1)

## 🔹 Code Snippet (Brute Force)

```python
from typing import Optional


class Solution:
    def oddEvenList(self, head: Optional[ListNode]) -> Optional[ListNode]:
        nodes = []
        while head:
            nodes.append(head)
            head = head.next
        order = nodes[0::2] + nodes[1::2]
        for a, b in zip(order, order[1:]):
            a.next = b
        if order:
            order[-1].next = None
        return order[0] if order else None
```

## 🔹 Code Snippet (Optimized)

```python
from typing import Optional


class Solution:
    def oddEvenList(self, head: Optional[ListNode]) -> Optional[ListNode]:
        if not head:
            return None
        odd, even = head, head.next
        even_head = even
        while even and even.next:
            odd.next = even.next
            odd = odd.next
            even.next = odd.next
            even = even.next
        odd.next = even_head
        return head
```
